## 3. ★訳すと壊れるもの（いちばん大事な制約）

### 3-1｜日本語が「鍵」になっている

```js
const ACTIVITY_LOAD_WEIGHT = { "休養": 0, "自主練習": 1.0,
                               "レッスン": 1.2, "リハーサル": 1.3, "本番": 1.6 };
{ key: "休養", icon: Moon, labelKey: "activityRest" }
if (row.activity_type === "休養") { ... }
```

「本番」「休養」などは **`entries.activity_type` に保存されている値**で、
発声負荷の重みを引く鍵でもあります。

★これを翻訳してはいけません。訳した瞬間に、
　過去の記録が引けなくなり、負荷の計算が壊れます。

**正しい形は既にあります。** `key`（保存する値）と
`labelKey`（表示に使う翻訳キー）が分かれています。
③の用語辞書も、この形の上に載せました。
**同じ分け方を、残りの直書きにも適用するだけです。**

### 3-2｜③の用語辞書は日本語だけ

`lib/vocabulary.js` は職業ごとの言い換え（本番→収録 など）を
持ちますが、**日本語だけ**です。`termLabel()` は
日本語以外では `translations.js` の訳語に落ちます。

★つまり、英語話者の声優には「収録」ではなく "Performance" と出ます。
　職業ごとの言い分けを多言語でもやるなら、辞書を9言語に広げる
　必要があり、これは**別の作業**です（今回の対象外を推奨）。

### 3-3｜日付

`toLocaleDateString("ja-JP")` の直書きが2箇所あります。
表示言語ではなく日本語固定です。小さいですが直す対象です。

### 3-4｜利用者が入れた自由文は訳せません

`profiles.occupation`（登録時の職業）、メモ、曲目名などは
本人が書いた文字です。★翻訳の対象外であり、
翻訳しようとしてはいけません。

## 4. 品質の抜き取り検査

既存の it / en / zh を8キー見ました。**機械翻訳の投げっぱなしではありません。**

| キー | ja | it | zh |
|---|---|---|---|
| labelThroatCondition | 喉の状態 | Condizione della gola | 喉咙状态 |
| sectionVoiceThroat | 声・喉 | Voce e gola | 嗓音与喉咙 |
| professionSinger | 声楽家 | Cantante lirico | 声乐家 |
| activityRehearsal | リハーサル | Prova | 彩排 |
| labelResonanceScore | 声の出来（0〜10） | Resa della voce (0–10) | 嗓音状态（0〜10） |

専門用語も妥当です。長文（`explainHeavyVoiceUse`）も
"corde vocali"「声带」と正しく訳されており、文体も自然です。

★ただし私は it / zh の母語話者ではありません。
　**「完璧」を目指すなら、母語話者の確認は必須です。**
　いま言えるのは「置き換えのやり直しが要る品質ではない」までです。

### 気になった1点

`labelResonanceScore` が ja「声の出来」/ it「Resa della voce」/
zh「嗓音状态」で、**3言語で少しずつ意味がずれています**。
この項目は今日も「同じ数字が2つの名前で呼ばれている」問題が
出たところです。★用語の統一を、翻訳の前に決めてください。

## 6. おすすめ

**ライブラリは入れないでください。**

既存の仕組みは719キーで動いており、3言語100%です。
next-intl などに移すと、ルーティングの作り直しと、
719キーの移行が必要になります。**得るものが翻訳の質ではありません。**

いま足りないのは翻訳基盤ではなく、
**直書き1,389箇所を `t()` に通す作業**です。
これはライブラリを変えても減りません。

★そして、この作業には**書かれた作業指示が要ります。**
①〜④はすべて仕様書に沿って進めました。1,389箇所を触る作業を
会話の記憶だけで進めると、どこまでやったかが追えなくなります。
