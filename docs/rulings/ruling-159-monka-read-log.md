# RULING 159 — 門下を開いた記録（monka_read_log）が書かれていなかった

```yaml
ruling: 159
date: 2026-09-21
version: design-v19
severity: ★最優先（利用者への約束が事実と違っていた）
from: Code「monka_read_log への書き込み処理が存在しない（insert のポリシーはあるが呼び出すコードが無い）」
related: 仕様シート②（開いた記録：生徒・先生の画面に出さない。求められたら30日以内に開示。消せない）／③（開いた記録は消せない）
```

## 1. すぐに

```yaml
STEP_0: 書き込みができるまで、monka_read で他人の門下の中身を返す経路を止める（台帳の側で）
  reason: 「見ると記録に残る」が偽の間、読める状態を残さない。本番は0件なので影響なし
  画面: 「いまは 調整中のため 門下を 開けません」（理由を技術的に書かない）
```

## 2. 作り

```yaml
Q1_何を開いたとするか: 門下のやりとりの中身が返ったとき、門下ごとに1行。門下の一覧（名前だけ）は数えない
WHERE: 中身を返す処理（RPC）の中で、台帳が先に記録を書き、書けたら中身を返す。書けなければ返さない（fail closed）。画面からの呼び出しに任せない
Q2_理由: 空を許さない。選ぶ形 ①事故・苦情の調べ ②ご本人からの求め ③法令に基づく求め ④その他（短文必須・100字まで）
Q3_同じ日に何度も: 開くたびに1行。まとめない。画面で日ごとにまとめて見せるのは可
列: 誰（user_id）・そのときの役職・いつ・org_id・どの門下・理由の種類・理由の短文
ポリシー: insert は RPC だけ。update・delete を作らない。select は monka_read を持つ人と運営だけ
文言: 実装の「ご本人にも伝わります」を直す
  正: 「見ると 記録に 残ります（誰が・いつ・どの 門下を）。消せません。ご本人から 求められたら、30日以内に お見せします」
```

## 3. 過去の分

```yaml
STEP_2: Supabase のログが残っている範囲で、monka_read を持つ人が他人の門下の中身を取得した跡を確かめる
RECORD: 結果にかかわらず「修正の記録」（消せない）に1行 ── いつから約束と実装が違っていたか・いつ直したか・過去の読み取りの有無・確かめた方法
IF_FOUND: Code は DECISION_NEEDED で報告。本人への伝え方は Opus が決める
```

## 4. VERIFY

```yaml
- 中身を開くと1行増える／一覧だけでは増えない
- 理由が空だと開けない（④で短文が空でも）
- 記録の書き込みを失敗させると中身が返らない
- update・delete が台帳で拒否される
- 生徒・先生の画面に開いた記録が出ない
```

## 5. 繰り返さないために

```yaml
- 「記録に残ります」「消せません」「伝わります」など、画面が約束している文を一覧にし、それぞれを実装のどこが守っているかを台帳に1行ずつ（約束の台帳）。守る処理が無い約束を0件にする
- insert のポリシーだけがあって呼び出しが無い表を探す検査を1本
```
