## 1. レッスンが実施されたか（`lessons.held`）　★【会話のみ】

**決めたこと**

- `lessons` に **`held boolean`** を足す。**null 可・既定値なし・埋め戻しなし**
- **2値**（実施した／しなかった）。★**3値にしない**
- 数えるのは**回数だけ**。★**金額は1円も扱わない**
- 集計は **`held = true` の行だけ**。`null` は★どちらにも数えない

**なぜ3値にしないか**　【文書あり】

「欠席」という値を作ると、そこが★**理由の入口**になります。

- `docs/lavoce-教室運営の範囲とカレンダー書き出し.md` §4-3「★欠席理由を聞かない」
  （同 §414 の表：「要配慮個人情報。連絡時刻で運用は回る」）
- `docs/lavoce-作業指示-レッスンの希望申告と月の組み立て.md:317
  「★先生の画面に、生徒の欠席理由を出さない（そもそも持っていない）」

**なぜ埋め戻さないか**

`null` は「まだ誰も答えていない」であって、「実施しなかった」ではありません。
既定値を入れると、★「答えた」と「答えていない」が混ざります。
（この repo の決めごと：新しい列は埋め戻さず、読むときに解く）

**★数えるときに、必ず未回答の数も出すこと**

「今月3回」とだけ出すと、★3回で全部なのか、10件のうち3件しか
答えていないのかが分かりません。表示ゲートで守っている
「分からないことを、分かったように見せない」と同じ線です。

## 4. 退会の止め方（4つの仕分け）　★【会話のみ・実装ずみ】

| 場面 | ふるまい |
|---|---|
| ほかに誰もいない | 教室ごと消す |
| ★運営できる人が0になる | 止める（二択：閉じる／残す） |
| ★オーナーが抜けるが運営者は残る | 止めない。契約者の知らせを1行 |
| 責任者・生徒が抜ける | そのまま抜ける |

★**「教室を動かせるか」と「誰が払うか」は、別の問い**です。
止めるのは前者が0になるときだけ。後者は知らせるだけ。

★`listOwnedOrgs`（閉じてよいのは誰か＝オーナーだけ）と
`listOperatedOrgs`（抜けると困る教室＝オーナーと責任者）は、
**別の関数**です。★兼ねると、片方を広げたつもりで
「責任者が教室を消せる」ようになります。

## 5. 役割の書き換え（順位で見る）　★【会話のみ・実装ずみ】

順位：`owner(3) > admin(2) > teacher(1)`、それ以外 `0`

- UPDATE で `owner` は★誰も書けない（教室を作るときだけ）
- 書ける役割は、★自分がいま持っている順位まで
- `owner` の行に触れるのは★本人だけ（共同オーナー同士も不可）
- ★知らない役割は書けない（順位0は「最下位だから安全」ではない）
- 譲渡の仕組みは★作らない

★**役割の名前で場合分けしないこと。** この2日で、同じ形の欠陥が
**4回**出ました（共同オーナー／最後の運営者／自己昇格／退会の止め方）。
順位で数えれば、1つの規則で足ります。憲章 §9 に記載。
