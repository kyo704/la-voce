## 1. 年齢確認 ── ② を維持する

### 1-1｜★論拠を差し替えます

**あなたの「②の論拠はいまや弱い」という指摘は正しいです。**
「集める情報が最小限だから」という理由は、`profiles.age` を既に集めている以上、成り立ちません。

**結論は変わりませんが、理由を入れ替えます。**

```
✗ 旧：集める情報が最小限だから

○ ★新：安全に関わる判定を、他の目的の欄と混ぜないため
```

**★この新しい論拠を、文書に書き残してください。**
そうしないと、次に読む人が同じ疑問（「年齢欄があるのになぜ？」）を踏みます。

### 1-2｜理由

#### ① 間違えたときの害が、まったく違う

```
age を間違える        → 栄養計算がずれる。★小さな害。あとで直せる
未成年判定を間違える  → 未成年が教師と紐付く。★取り返しがつかない
```

**性質の違う2つを、同じ欄で兼ねてはいけません。**

**あなたの原則2（1つの欄に2つの意味を持たせない）は、①を選ぶ場合の注意点として
書かれていましたが、★これは①を選ばない理由です。**

`lib/ageGate.js` で読み取りを一元化しても、**書き込みが1箇所である危険は消えません。**
「体重が変わったからプロフィールを更新した」つもりで年齢を直した瞬間に、
**安全ゲートが静かに開きます。**利用者にも、こちらにも、その瞬間が見えません。

#### ② 安全ゲートを、埋まっていない欄に依存させない

**`profiles.age` は任意で、記入率が低い**（2026-08-30 のあなたの充足率調査）。

フェイルクローズは効きますが、**成人のテスターも全員が弾かれます。**
教室機能を試してもらう人が、年齢欄を埋めていないという理由で入れない。
**★配布の障害になります。**

#### ③ 生年月日は、このアプリでは特に危険

**このアプリは、名前も住所も集めていません。**そこに生年月日を足すと、識別性が一気に上がります。

そして周期の記録と組み合わさると——**要配慮個人情報 ＋ 強い識別子**という、
いちばん避けたい組み合わせになります。

#### ④ 「古くならない」は、この用途では利点ではない

**17歳が18歳になった瞬間に、自動で教師と紐付けられるようになる。**
これは望ましくありません。**そのとき本人に聞き直すほうが安全です。**

**勝手に開くゲートより、本人が開けるゲートのほうがいい。**

### 1-3｜やること

```
□ ② を維持。★論拠を §1-1 の新しいものに差し替えて文書に残す
□ 判定は lib/ageGate.js に一元化（★あなたの原則2はそのまま採用）
□ ★各画面が profiles.age も is_under_18 も直接読まない
□ 本人が設定で is_under_18 を変更できるようにする
     → 19歳になった人が永久に弾かれないため
□ ★変更したら監査ログに残す（いつ、どちらからどちらへ）
□ profiles.age は栄養計算専用のまま。★未成年判定に使わない
□ §7-2② のトリガーは is_under_18 のまま。★変更不要
```

### 1-4｜★これは配布前の暫定です

**一般公開のときに保護者同意（案D ⑤）を作ります。そのときに、
生年月日を含めて設計し直します。**

**いまは配布に必要な最小の形で構いません。★このことも文書に書いてください。**
「暫定である」と書かれていない暫定は、恒久になります。

## 2. アカウント削除 ── ★文言が実態と合っていません

**パスワード再入力を「今すぐ」「30日猶予」の両方に付ける判断は、妥当です。**
猶予中でも共有切断という不可逆な害が即座に出る以上、「今すぐ」だけ守っても意味がありません。

**ただし、あなたの報告の中に、判断が要るものが1つ混じっていました。**

> 30日間の猶予をつけた削除でも、**先生との共有だけは即座に切断され、復元されない**

**利用者は「30日以内なら元に戻る」と読みます。戻りません。**

### 2-1｜挙動は正しい。直すのは説明のほう

**削除を選んだ人が、30日間も先生に見られ続けるほうが本末転倒です。**
`severConnections` の即時実行は、正しい実装です。

**★直すのは文言です。**

```
いま    「30日間の猶予があります」

★あと  「30日間、記録は残ります。その間なら戻せます。
         ★ただし、先生との共有はすぐに切れます。これは戻せません。」
```

### 2-2｜なぜこれが重要か

**この製品は、事実を正確に書くと決めています。**

```
分析      「効果がありません」と書かない（★分からなかった、であって、無い、ではない）
分析      通らなかったら数字も出さない（★文章を止めても数字が語る）
本番の重さ 判定を出さない（★仮置きの係数の上に断定を重ねない）
削除      ★「戻せる」と書いて、一部戻せないのは、これらと同じ種類の不正確さ
```

**実装ではなく文言なので、すぐ終わります。配布前に直してください。**
