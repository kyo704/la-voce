# La Voce ／ 収益化のために足りない要素

声のプロ向け体調管理アプリ「La Voce」を収益化するために必要な機能・サービス・体制の整理。
実装は Claude Sonnet 5 に任せる前提で、**Sonnet が現実的に書ける範囲**に絞っています。

---

## 結論から

**機能を足すより先に「誰が払うのか」を決めるべきです。**

いまのアプリは、個人の声楽家・声優・アナウンサーが自分のために使う設計になっています。
しかし日本でこの層だけを対象にすると、母数が小さく、可処分所得も潤沢とは言えず、
月額課金は伸びにくい。**本命は「先生・教室・養成所が払い、生徒は無料で使う」形**です。

理由は単純で、

- 先生1人あたりの支払額が個人の5〜10倍にできる
- 生徒がいる限り解約されない（個人課金の解約率とは桁が違う）
- 生徒が卒業しても先生は残る＝チャーンが構造的に低い
- 生徒獲得コストがゼロになる（先生が配ってくれる）

そして何より、**すでに設計した分析指標が、指導者にとってそのまま価値になります。**
「この生徒は今週、睡眠が3日連続で崩れている」がレッスン前にわかる、というのは
声楽教師が喉から手が出るほど欲しい情報です。生徒本人の自己申告より正確でもあります。

## 1. 収益の柱（優先順）

### 柱A ｜ 指導者プラン（本命）

先生が生徒の記録を見るダッシュボード。生徒はアプリを無料で使い、先生が払う。

| | |
|---|---|
| 価格の目安 | ¥3,980/月（生徒15人まで）／¥9,800/月（生徒50人まで） |
| 対象 | 個人の声楽・ボイストレーニング教室、音大の教員、声優養成所、合唱指導者、劇団 |
| 実装規模 | 2〜3週間（Sonnet 5 で十分可能） |
| LTV | 個人課金の10倍以上。解約率は構造的に低い |

**必要な機能**

- 招待コードによる先生↔生徒の紐付け（生徒側から承認する 双方向承認方式にする）
- 生徒一覧ダッシュボード（今週の記録率／総合スコアの変化／要注意フラグ）
- 生徒個人ページ（既存の分析画面を読み取り専用で表示）
- 生徒側の公開範囲設定（メンタルの日記は共有しない、など）← **これは必須**
- 先生からのコメント欄（レッスン記録として残る）

**設計上の注意**

生徒のメンタル日記まで先生が読めると、生徒は正直に書かなくなり、データが死にます。
共有する項目を生徒が選べることを、最初から前面に出すべきです。

### 柱B ｜ 個人サブスク（フリーミアム）

| | |
|---|---|
| 価格の目安 | ¥580/月 ／ ¥5,800/年（2ヶ月分お得） |
| 実装規模 | 3〜5日（Stripe Checkout + Customer Portal + Webhook + プランフラグ） |

**無料と有料の線引き（前回の指標設計と対応）**

| | 無料 | 有料 |
|---|---|---|
| 記録 | 全項目・無制限 | 同じ |
| 履歴の閲覧 | 直近30日 | 無制限 |
| 指標 Lv.1〜2 | ✓ ウォームアップ効率、症状カレンダー、音域マップ、今日のサマリー | ✓ |
| 指標 Lv.3〜6 | ロック（予告表示のみ） | ✓ 偏差値、予報、ラグ相関、効いた習慣、ACWR、環境の快適帯、ピーキング曲線 |
| 書き出し | — | PDF・CSV（通院・レッスン用） |
| 週次メール | — | ✓ |

**線を引く場所の考え方**

無料でも「毎朝ひらく理由」が残るようにするのが重要です。記録だけできて何も見えないアプリは
そもそも続かず、有料転換の母集団が育ちません。**無料に"習慣"を、有料に"発見と本番"を**置く。

すでに設計したレベル解放の仕組みが、そのまま課金導線として使えます。
「Lv.3 が解放されました → 見るには有料プランへ」という流れは、
唐突なペイウォールより自然で、しかも解放の瞬間がいちばん課金意欲が高いタイミングです。

**声のプロ特有の事情**

本番シーズンの前だけ課金したい、というニーズが必ずあります。
月単位で気軽に解約・再開できることを**むしろ売りにする**ほうが、
囲い込もうとするより結果的に収益は伸びます（年額は割引で誘導）。

### 柱C ｜ 書き出しと医療連携（差別化と信頼）

すでに設計した「週次ボイスカルテ」を PDF で出せるようにする。

- 耳鼻咽喉科・音声外来に持っていける形式（症状の経過、発声負荷、睡眠）
- 声楽教師に見せる形式（コンディションと練習量）
- 実装は 3〜4日。`@react-pdf/renderer` か印刷用CSS で十分

将来的には提携クリニックへの送客や掲載料も考えられますが、
**規制の線引きに注意が必要**です（後述）。まずは「持っていける紙が出る」だけで、
有料プランの説得力が大きく上がります。

### 柱D ｜ アフィリエイト（低労力・低単価）

加湿器、パーソナル加湿器、湿度計、のど飴、ネブライザー、蜂蜜製品。

**強みは文脈です。**「今日の会場はあなたの快適帯より 4.2 g/m³ 乾いています」の
直後に置かれた加湿器のリンクは、通常のバナー広告とは比較にならない転換率になります。

ただし単価が低く、やりすぎると分析結果の信頼性を疑われます。
**「快適帯を外れたときだけ、1つだけ」**に絞るのが正解です。実装は数時間。

### 柱E ｜ 一回売り切りのコンテンツ

- 「本番前1週間のピーキングプラン」（¥1,500 の買い切り）
- 声種別・職業別のセルフケアガイド

サブスクに抵抗がある層の受け皿として。実装は Stripe の単発決済なので軽い。

### 柱F ｜ 遠い将来：声を使う職業全般

コールセンター、教員、営業職、接客業。音声疲労は労務問題として企業が金を出す領域で、
市場規模は歌手の比ではありません。ただし製品としては別物になるので、
いまは考えなくてよい。**ただし設計を歌手専用に固めすぎないこと**は意識しておく価値があります。

## 2. 収益化の前に、必ず要るもの

ここを飛ばすと、後から作り直しになります。**課金を始めた瞬間に「事業者」になる**ため、
無料で個人運用していたときとは求められる水準が変わります。

### 2-1. 健康データの扱い（最重要）

このアプリが集めているのは、日本の個人情報保護法における **要配慮個人情報** です。
自己申告の健康情報も、健康診断の結果と同様にこれに含まれると解されています。

課される義務は具体的です。

- **あらかじめ本人の同意を得ないで取得してはならない** — 利用規約に埋め込むのではなく、
  取得目的を示した上での明示的な同意フローが要る
- **オプトアウトによる第三者提供は認められない** — 匿名化してもデータ販売の類は慎重に
- **1件でも漏えいしたら**、個人情報保護委員会への報告と本人への通知が義務

**Sonnet に作らせるもの**

- 初回起動時の同意フロー（取得項目・目的・保存先を明示、同意日時をDBに記録）
- プライバシーポリシー（ドラフトまで。**最終確認は専門家に**）
- データの一括書き出し機能（JSON / CSV）
- アカウントと全データの削除機能（論理削除ではなく実削除、猶予期間つき）

出典: [要配慮個人情報とは？該当する／しない具体例、取扱い規制など — BUSINESS LAWYERS](https://www.businesslawyers.jp/practices/271)

### 2-2. 医療機器プログラム（SaMD）該当性の線引き

これは**知らずに踏むと事業が止まる**類の話なので、先に押さえるべきです。

厚生労働省のガイドラインでは、プログラムが医療機器に該当するかは
**「使用目的」と「処理方法」**で決まります。

| | |
|---|---|
| **該当しない**（安全圏） | 個人の健康記録の保存・管理・表示／**時系列や統計処理をした値の表示**／医療者や家族とのデータ共有／スポーツのトレーニング管理・競技力向上 |
| **該当する**（規制対象） | 疾病の診断／病態の評価／**疾病の兆候の検知**／疾病リスクの表示 |

いまの La Voce は完全に安全圏です。記録・統計処理・共有しかしていません。
**危ないのは、これから足そうとしている機能のほうです。**

- 「声帯のむくみを検知しました」→ **兆候の検知**にあたる可能性が高い
- 「s/z比が1.4を超えています。声帯の器質的問題が疑われます」→ 同上
- 「逆流の疑いがあります」→ 同上

同じデータを見せるにしても、**「記録上の事実の提示」に徹すれば安全圏に留まれます**。

> ✗ 「声帯のむくみが疑われます」
> ✓ 「弱声の最高音が、あなたの平常値より3半音低い日が4日続いています」
>
> ✗ 「逆流の可能性があります」
> ✓ 「夕食から就寝までの間隔が2時間未満の日が、今週5日ありました」

判断は事実だけを示し、受診するかどうかは本人に返す。この一線を、
**全画面の文言ルールとして明文化**しておくべきです（前回の設計書の「数字の作法」7番がこれに当たります）。
迷う機能が出てきたら PMDA の相談窓口で確認できます。

出典: [医療機器への該当性を調べよう — 日本医療機器産業連合会](https://www.jaame.or.jp/program/investigate.html) ／
[プログラムの医療機器該当性に関するガイドライン — PMDA (PDF)](https://www.pmda.go.jp/files/000240233.pdf)

### 2-3. 商取引まわり

- **特定商取引法に基づく表記** — Stripe の審査でも実質的に必須。事業者名、連絡先、
  価格、支払時期、解約・返金の条件を明記したページが要る
- 利用規約（免責、サービス変更・終了の条件）
- 返金ポリシー（サブスクなら「日割り返金しない」等を明記）
- インボイス・適格請求書の扱い（法人顧客＝指導者プランを取るなら特に）

Sonnet はこれらのページのドラフトを書けますが、**内容の妥当性の最終判断は人間の仕事**です。

## 3. 収益化の土台になる「サービス」要素

課金機能そのものより、**解約されない仕組み**のほうが収益を左右します。
どれだけ良い分析でも、記録が途切れれば何も出ません。

### 3-1. LINE通知（日本市場では最優先）

日本のユーザーにメールやWeb Pushは届きません。**LINE公式アカウント**からの
毎朝のリマインドが、リテンションに最も効きます。

- LINE Messaging API + Webhook。Sonnet で 3〜5日
- 「おはようございます。今朝の起き抜けの声はどうですか？」＋記録画面への1タップリンク
- リッチメニューから記録・分析に直行
- **LINEから直接、簡易記録もできるようにするとさらに強い**（喉の調子だけ5段階で返信）

### 3-2. 入力を30秒で終わらせる

いまの記録画面は項目が非常に多く、これが最大の離脱要因です。

- **「前日をコピー」ボタン** — 食事・身体データはほぼ同じ日が多い。実装は1日
- **超簡易モード** — 喉・声・睡眠時間の3つだけ入れれば「記録した」ことになる
- 音声入力でのメモ
- PWA化してホーム画面に置く（ネイティブアプリは要らない）

### 3-3. 週次メールと共有カード

- **週次カルテのメール送信**（Resend + Vercel Cron）。開封がそのまま再訪になる
- **共有カード画像の生成**（`@vercel/og`）— 「今週の声」を1枚の画像にして
  X や Instagram に貼れるようにする。**無料の獲得経路として最も費用対効果が高い**
- 声楽家・声優は発信する人が多い層なので、ここは効きます

### 3-4. オンボーディング

初回に声種・職業・目標を聞いて、**「3日記録すると何が見えるか」を約束する**。
いまは記録しても何が起きるのかがわからないので、初日で離脱します。

## 4. Sonnet 5 に任せられる範囲 / 任せてはいけない範囲

### 任せられる（実績のある領域）

| 領域 | 具体 | 目安 |
|---|---|---|
| 決済 | Stripe Checkout / Customer Portal / Webhook（冪等処理込み）/ プランフラグ | 3〜5日 |
| 権限 | 先生↔生徒の関係モデル、Supabase なら RLS ポリシー | 3〜5日 |
| 招待 | 招待コード生成・有効期限・上限管理 | 1〜2日 |
| ダッシュボード | 生徒一覧、要注意フラグ、読み取り専用の分析画面 | 1〜2週間 |
| 書き出し | PDF（`@react-pdf/renderer`）、CSV、JSON一括 | 3〜4日 |
| 通知 | LINE Messaging API、Resend メール、Vercel Cron | 3〜5日 |
| 画像生成 | `@vercel/og` での共有カード | 1〜2日 |
| 統計 | 前回設計した指標すべて（相関、効果量、EWMA、回帰、CPPS計算） | 指標ごとに1〜3日 |
| 文書 | 規約・特商法表記・プライバシーポリシーのドラフト | 1日 |

### 任せてはいけない

- **決済の本番検証** — テストモードで動いても、本番の失敗パターンは別。少額で自分で通す
- **税務・インボイス・法人化の判断**
- **医療機器該当性の最終判断** — 迷ったら PMDA の相談窓口へ
- **プライバシーポリシーの法的妥当性** — ドラフトは書けても、責任は取れない
- **価格の決定** — 実際に声楽の先生3人に聞いたほうが、どんな分析より正確です

### Sonnet 5 への渡し方のコツ

- **1機能1PR**。「Stripe を入れて」ではなく「Checkout セッション作成のAPIルートだけ」から
- Webhook は**冪等性を必ず明示**して依頼する（同じイベントが2回来ても壊れないこと）
- 権限まわりは**「この操作を誰ができるか」の表を先に書いて渡す**。曖昧だと事故る
- 既存のコードベースの規約（ディレクトリ構成、命名、状態管理）を最初に読ませる

## 5. 90日の最短ルート

| 週 | やること | ねらい |
|---|---|---|
| 1–2 | 同意フロー、規約・特商法・プライバシーポリシー、データ書き出し／削除 | 課金の土台。ここを飛ばすと後で作り直し |
| 3–4 | 「前日をコピー」＋簡易記録モード＋PWA化 | 記録が続かないと何も売れない |
| 5–6 | LINE通知＋オンボーディング | リテンション。ここが効かないと課金母集団が育たない |
| 7–8 | Stripe 個人プラン、Lv.3以降のペイウォール、PDF書き出し | 最初の売上 |
| 9–12 | 指導者プラン（招待コード＋生徒ダッシュボード） | 本命。ここから収益が階段状に変わる |

並行して、**声楽の先生3人と声優養成所1つに話を聞く**。
90日のうちで最も投資対効果が高い行動はこれです。

## 6. 現実的な数字感

甘い数字を出しても意味がないので、保守的に。

**個人プランのみの場合**
月額¥580 × 有料転換率5% で、月10万円に届かせるには**登録3,500人**が要ります。
日本の声のプロだけを相手にすると、これは相当に厳しい数字です。

**指導者プランを入れた場合**
月額¥3,980 × 25人の先生 = 月約10万円。
先生25人は、音大の教員・声楽教室・養成所を地道に回れば手が届く範囲です。
しかも**その先生の生徒が数百人、無料ユーザーとして入ってくる**ので、
そこから個人プランへの転換も生まれます。

**桁が違います。** 指導者プランを先に作るべき、という結論はここから来ています。

---

## まとめ：足りないもの3つ

1. **払う人の設計** — 個人ではなく指導者。招待コードと生徒ダッシュボード
2. **課金の土台** — 同意フロー、規約類、データ書き出し／削除。課金前に必須
3. **記録が続く仕組み** — LINE通知、前日コピー、簡易モード。分析は記録がなければゼロ

機能追加のうち**いちばん収益に効くのは、実は「前日をコピー」ボタン**かもしれません。
どれだけ精緻な分析を作っても、記録が7日で途切れれば何も表示されないからです。
