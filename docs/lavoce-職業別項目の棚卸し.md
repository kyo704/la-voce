# 職業別項目の棚卸し（§3 の表との突き合わせ）

**作り方**：`node scripts/profession-field-inventory.js` で再生成できます。
ソースを読んで機械的に判定しているので、実装が変われば結果も変わります。

**4つの列の意味**

| 列 | 判定 |
|---|---|
| DBに列がある | 専用の列 ／ マスタ（レパートリー・役・案件） ／ detailの中（JSONB） ／ — |
| 入力画面に出る | その項目を書き換える入力が、画面に描かれているか |
| 分析で使われる | 分析の計算がその値を読んでいるか |
| 学ぶ記事から参照される | 学ぶ記事・健康情報の本文が、その語に触れているか |

★「detailの中」は、保存はされるが専用の列は無い、という意味です。
消すときは列の drop ではなく、JSON のキーの話になります。

★この棚卸しの目的は「作ったが誰も読んでいない項目」を見つけることです。
入力画面に出るのに分析で使われない、あるいはその逆が、いちばん危険な組み合わせです。


## ★この表が見つけたこと

**1. パッサッジョは2つある。** §3.1 の「看板」は **通過感（passaggioFeel, 1–5）** で、
これは入力画面に出て、分析（passaggioStability）が読み、学ぶ記事も触れています。**生きています。**
死んでいるのは **通過数（passaggioCrossings）** という別の項目で、
§3 の表には載っていません。名前が似ているだけの別物です。

**2. 死んでいる3つは、同じ場所にあります。**
音域（vocalRangeLowUsed / vocalRangeHighUsed）・ダイナミクス（dynamicsRange）・
通過数（passaggioCrossings）は、すべて `LOAD_FIELDS_BY_PROFESSION` の中だけにあり、
**この定義を描く画面がどこにもありません。** コード全体で1回ずつしか出てきません。

**3. §3.4（ポップス／ロック）は、ほぼ何も入っていません。**
セットリスト・ベルト・シャウト・ツアー日数・MC時間・弾き語り — どれも
DBにも画面にも分析にもありません。モニター環境と移動手段だけが動いています。

**4. 「分析は読むが、入力画面に無い」項目が7つあります。**
テッシトゥーラ・歌唱言語・番組案件・生放送か・原稿の種類は、マスタに登録する
設計なので、日々の入力に出ないのは正しい姿です。ただし **マスタに登録する画面が
無ければ、分析は永久に空を読みます。** ここは別途の確認が要ります。
