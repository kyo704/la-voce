## 1. 見直しの基準：3つの関門

**項目を1つ増やすことは、全ユーザーの毎日に操作を1つ足すことです。**
次の3つを全部通ったものだけ残しました。

| 関門 | 問い | 落ちる例 |
|---|---|---|
| **① 測らずに答えられるか** | 本人が見ればすぐ分かるか | ブースの湿度（測定器がない） |
| **② 日によって変わるか** | 毎日同じなら、それは設定であって記録ではない | 話速（番組ごとに固定） |
| **③ 返ってくる分析があるか** | この項目が無いと成立しない分析が §4 にあるか | 立ち位置（対応する分析がない） |

**②で落ちたものは消すのではなく、マスタ（案件・役・曲）へ移します。** 一度登録すれば以後ずっと効きます。

## 2. ★ 共通コアへ引き上げるもの

**いま職業別に散らばっている3つは、全職業に共通です。第1層へ移してください。**

### 2.1 本番外の発話時間 ← いちばん重要

いまアナウンサーにしかありません。**これは4職種すべてにあります。**

```
声楽家    → レッスンをする側の時間。1日6時間教える人がいます
アナウンサー → 会議・電話・打合せ
声優      → 現場での待機中の雑談、養成所の講師業
ポップス   → MC、ラジオ出演、物販での会話
```

**「歌っていないのに声が出ない」の最大の原因がここです。**
本人は「今日は歌っていない＝休養日」と記録しますが、実際には4時間しゃべっています。
**この項目が無いと、負荷モデルが常に過小評価になります。**

| 項目 | 型 |
|---|---|
| 本番・収録の発話 | 分 |
| **本番外の発話**（レッスン・会議・電話・授業・打合せ） | 分 |

**2つだけにしてください。** 元の4分割（放送/収録/会議/電話）は入力が重すぎます。

### 2.2 環境タグ（複数選択）

```
乾燥を感じた ／ 空調が直接あたる ／ マスク着用 ／
大声を出す場所にいた（居酒屋・現場） ／ 喫煙環境 ／ 粉塵・スモーク
```

**職業ごとに別々に持っていたものを1つに統合します。**
スモークはロック向けですが、オペラでも舞台で使います。**出し分けないでください。**

### 2.3 発声ルーティンの長さ（分）

全職業がウォームアップします。**ウォームアップ効率の分析の分母になります。**

## 3. 職業別の追加入力（改訂版）

**すべて活動ブロックの中に置きます**（曲目複数化パッチ §2.0.2）。

記号：**＋** 追加　**−** 削除　**→** マスタへ移動　（無印）据え置き

### 3.1 声楽家・ミュージカル

| | 項目 | 型 | 備考 |
|---|---|---|---|
| | 演目・役 | レパートリー参照 | 実装済み |
| | テッシトゥーラ / 最高音 | MIDI | レパートリーに登録済み |
| | **パッサッジョの通過感** | 1–5 | **この職業の看板。既存 LoadTracker にあり** |
| **−** | ~~声区の切り替えの滑らかさ~~ | | **パッサッジョの通過感とほぼ同じものを測っています。**2つの1–5は相関しあうだけで、入力コストが倍になります |
| **−** | ~~立ち位置~~ | | 対応する分析がなく、動き回るので日ごとの値として意味を持ちません |
| | 会場の響き | 3択 デッド/普通/ライブ | **本番・リハのときだけ表示** |
| | 衣装の締め付け | 3択 なし/やや/強い | **本番・GPのときだけ表示。**コルセットは呼吸を制限します |
| **＋** | **歌唱言語** | 選択（伊/独/仏/露/英/日/西/チェコ/その他） | **レパートリーに登録。日々の入力は不要** |
| **＋** | **伴奏** | 3択 ピアノ/オーケストラ/なし | **オケ合わせの初日に張り上げるのは、この職業の定番の事故です** |

> **歌唱言語を足す理由**：子音の量と母音の置き方が言語ごとに違い、
> 「ドイツ語ものの翌日に落ちる」といった傾向が実際にあります。
> **レパートリーに1回登録するだけで、以後ずっと分析に効きます。**
> そして **他のどのアプリにも無い分析**になります。

### 3.2 アナウンサー・ナレーター

| | 項目 | 型 | 備考 |
|---|---|---|---|
| | 番組・案件 | レパートリー参照 | |
| **→** | 発話時間の内訳 | | **§2.1 で共通コアへ。**4分割はやめて2つに |
| **−** | ~~話速~~ | | **番組ごとに固定です。**案件マスタへ移してください |
| | 生放送か | boolean | |
| | **話声位（SFF）** | Hz | **この職業の看板。**§10 で最後に実装 |
| | 周囲騒音 | 3択 スタジオ/中継/屋外 | ロンバード効果 |
| **→** | 環境（乾燥/空調/マスク） | | **§2.2 の共通タグへ** |
| | 読み間違い・噛み | **3択 なし/数回/多かった** | **数値をやめる。**誰も数えていません |
| **＋** | **原稿の種類** | 選択（ニュース/情報/スポーツ実況/ナレーション/CM/司会/朗読） | **案件マスタに登録** |
| **＋** | **最長の連続発話ブロック** | 分（＋詳しく の中） | 合計より、休みなしで話し続けた長さが効きます |

> **原稿の種類を足す理由**：**スポーツ実況は、同じ「アナウンサー」でも別の競技です。**
> 張り上げる時間が長く、興奮で声が高くなり、翌日への影響がまるで違います。
> いまの仕様では、ニュース読みと実況が同じ負荷として扱われています。**ここが最大の穴でした。**

### 3.3 声優

| | 項目 | 型 | 備考 |
|---|---|---|---|
| | 収録種別 | アニメ/ゲーム/吹替/ナレーション/ラジオ/イベント | ゲームのバトルボイスが突出して重い |
| **＋** | **喉に負担のある演技**（複数選択） | 叫び / がなり・エッジ / 泣き・嗚咽 / 咳・えずき・呼吸音 / ささやき / 悲鳴 | **★これが最大の追加** |
| | 叫び・悲鳴のテイク数 | 数値 | **上の「叫び」を選んだときだけ表示** |
| **−** | ~~声質の種類（6択）~~ → **4択に** | 地声寄り / 高め / 低め / 特殊 | **6択×複数選択だと、どの組み合わせも件数が5に届かず、分析が一度も動きません** |
| | 役・作品 | レパートリー参照 | |
| **→** | 役のピッチ帯 | | **役マスタへ。**声優はMIDIで考えません。役の登録時に1回だけ |
| | 収録時間 / 拘束時間 | 分 / 分 | **待機だけで疲れるかを分離できます。良い項目です** |
| **−** | ~~ブースの湿度~~ | | **測れません。**§2.2 の「乾燥を感じた」で代替 |
| | 歌の仕事 | boolean | 歌手側のエンジンに切り替える |

> **「喉に負担のある演技」を足す理由**：叫びのテイク数だけでは足りません。
> **がなり（エッジ）と、咳・えずきの演技**は、叫びと同じかそれ以上に来ます。
> そして **ささやきと息多用**も入れてください。
> 息を多く混ぜた発声は乾燥を招き、**「今日は静かな芝居だったから楽なはず」という思い込みと実際がずれる**、
> いちばん気づかれにくい負荷です。**この気づきを与えられるアプリは他にありません。**

### 3.4 ポップス／ロック

| | 項目 | 型 | 備考 |
|---|---|---|---|
| | セットリスト | レパートリー配列（順序つき） | 実装済み |
| | 曲の最高音 / ベルト有無 | MIDI / boolean | レパートリーに登録 |
| | シャウト・グロウル | **3択 なし/少し/多い** | 回数入力をやめる |
| | **モニター環境** | 3択 インイヤー/ウェッジ/なし | **効果が大きい。残します** |
| **−** | ~~ステージ音量（dB）~~ | | **判断できません。**モニター環境と役割が重複します |
| | ツアー何日目 | 自動計算 | 開始日だけ入力 |
| **−** | ~~移動時間（分）~~ → **手段だけ** | 3択 なし/日帰り/夜行（バス・車中泊） | 効いているのは睡眠で、それは共通コアにあります |
| **→** | 会場環境 | | **§2.2 の共通タグへ**（スモークを含む） |
| | **打ち上げ** | 参加 3択（なし/静か/騒がしい）＋ 飲酒 3択 | **仕様全体でいちばん良い項目です。残してください** |
| **＋** | **MC・しゃべりの時間** | 分 | **§2.1 の「本番外の発話」に入れる。**爆音の中でのMCは相当な負荷です |
| **＋** | **弾き語りか** | boolean | 楽器を持つと姿勢と呼吸が変わります。1タップ |

## 4. 差し引きの結果

```
削除 7 ／ マスタへ移動 4 ／ 共通コアへ 3 ／ 追加 6

日々の入力の手数は 減ります。
分析の解像度は 上がります。
```

**特に大きいのは3つです。**

1. **本番外の発話を共通コアへ**（負荷モデルの過小評価が直る）
2. **アナウンサーに原稿の種類**（実況とニュース読みが同じ負荷だったのが直る）
3. **声優に「喉に負担のある演技」**（叫び以外が見えていなかったのが直る）

## 5. マスタに移した項目の扱い

**「登録は1回、以後ずっと効く」形にしてください。** ここが La Voce の資産になります。

| マスタ | 追加するフィールド |
|---|---|
| レパートリー（曲・演目） | 歌唱言語 / ベルト有無 / 最高音 |
| **役**（新規） | 役名 / 作品 / ピッチ帯 / 声質 |
| **案件**（新規） | 番組名 / 原稿の種類 / 話速 / 生放送か |

**役と案件のマスタは、レパートリーとまったく同じ仕組みで作ってください。**
新しい設計を起こさないこと。**「1回登録すれば、次から選ぶだけ」**が守れていれば十分です。

## 6. 発声理論（学ぶ）の構成

**いまは「発声理論」と「健康情報」が別々の読み物です。これを職業別の体系にします。**

### 6.1 すべての職業で共通の骨組み

**同じ7章立てにして、中身だけ職業ごとに入れ替えてください。**
骨組みが同じだと、兼業の人が別の職業のページを読んでも迷いません。

| 章 | 内容 |
|---|---|
| **1. この仕事の声** | 何をしている器官なのか。その職業の声の使われ方 |
| **2. 何が声を削るか** | この職業に特有の負荷。**ここがいちばん読まれます** |
| **3. アプリの数字の読み方** | 偏差値・発声負荷・ウォームアップ効率が何を意味するか |
| **4. 整える** | ウォームアップとクールダウン |
| **5. 守る** | 休養・水分・環境・生活 |
| **6. 続くときは** | 受診の目安。**§9 の書き方を厳守** |
| **7. 用語** | この職業の言葉の説明 |

### 6.2 職業ごとの記事一覧

**声楽家・ミュージカル**

```
1  声区とパッサッジョ ― 通過点で何が起きているか
2  テッシトゥーラという考え方 ― 最高音より大事なもの
3  支えと呼吸 ― 「お腹で支える」の中身
4  共鳴 ― なぜオーケストラの上で声が届くのか
5  劇場の声とマイクの前の声 ― 使い分けの負担
6  歌唱言語による違い ― 子音の量と母音の置き方
7  衣装と姿勢 ― コルセットが呼吸に与えるもの
8  本番までの2週間の作り方
9  年齢とともに変わる声
10 月経周期と声（読むかどうかは本人が選ぶ）
```

**アナウンサー・ナレーター**

```
1  話声位（SFF）とは ― あなたが普段しゃべっている高さ
2  長時間しゃべるということ ― 歌より過酷な理由
3  ロンバード効果 ― うるさい場所で声が大きくなる仕組み
4  滑舌と早口の生理
5  実況の声 ― 同じ職業の中でいちばん重い仕事
6  マイクとの距離、そして声の大きさ
7  スタジオの乾燥
8  本番外の発話 ― 会議と電話が声を削る
9  声の疲れが「噛み」として出るとき
```

**声優**

```
1  叫びの生理と、そこからの戻り方
2  がなり・エッジ ― 何が起きているのか
3  ささやきと息漏れ ― 「楽な芝居」という誤解
4  役の声を作り続けるということ ― 常用音域からの乖離
5  収録種別ごとの負担の違い（ゲームのバトルボイス）
6  ブースという環境
7  拘束時間と待機 ― 使っていないのに疲れる理由
8  歌の仕事が入る日
```

**ポップス／ロック**

```
1  ベルティングの仕組み
2  ミックスボイス ― 言葉の整理から
3  モニター環境 ― 聞こえないと、人は張り上げる
4  シャウトとグロウル ― 負担の大きい技術について
5  ツアー中の声の管理
6  弾き語りの姿勢と呼吸
7  ライブハウスの環境（スモーク・乾燥・音量）
8  打ち上げという最大の落とし穴
```

**全職業共通（「からだ」の章に置く）**

```
・声帯という器官のこと
・水分と粘膜
・睡眠と声
・逆流性食道炎と声（★既存の関心事）
・栄養とエネルギー不足
・風邪のときの声の使い方
・専門家にかかるという選択肢
```

### 6.3 記事の書き方

| ルール | 内容 |
|---|---|
| 長さ | **1記事 800〜1,500字。**それ以上は分割 |
| 冒頭 | **3行で結論**。読まない人にも要点が残るように |
| 図 | 1記事に1枚まで。**無いなら無いでよい** |
| 語り口 | その職業の言葉で。声楽家に「発話」、アナウンサーに「パッサッジョ」と言わない |
| 出典 | **記事末に置く。**本文中に散らさない |

### 7.3 メモ機能

**2種類あります。混ぜないでください。**

| | ハイライトメモ | 記事メモ |
|---|---|---|
| 起点 | 本文を選択 | 記事の末尾のボタン |
| 紐づく先 | **選択した文字列** | 記事全体 |
| 表示 | 該当箇所に下線＋アイコン | 記事末に一覧 |
| 用途 | 「ここが分からない」 | 「先生に聞く」 |

**共通の規則**

- **上限500字。** それ以上は稽古ノートへ誘導
- **編集・削除ができる**（本人のみ）
- **オフラインで書ける。** 学ぶは移動中に読まれます
- **メモは「ノート」タブにも集約表示する。** 記事の中だけに埋もれさせない
- **先生には既定で見せない**（指導者プラン実装仕様 §4 の `ShareScope` に `articleNotes: false` を追加）

> **メモを先生に既定で見せない理由**：
> 「ここが分からない」というメモは、**分からないと書ける場所だから書かれます。**
> 見られる前提だと書かれなくなり、機能ごと死にます。
> 本人が記事ごとに「先生に見せる」を選べる形にしてください。

### 7.4 検索

- **記事タイトル・本文・自分のメモ**を横断
- 職業をまたいで検索する（絞り込みは後から）
- **用語（§6.1 の第7章）は検索で最優先に出す。**「パッサッジョとは」で来た人を待たせない

## 8. データモデル

```ts
type ProfessionKey = 'classical' | 'announcer' | 'voiceActor' | 'popRock'

interface Article {
  id: string
  professions: ProfessionKey[] | 'all'   // 'all' = からだ の章
  chapter: 1|2|3|4|5|6|7
  order: number
  title: string
  lead: string                  // 3行の結論
  bodyMd: string                // Markdown
  readMinutes: number
  terms?: string[]              // 用語集への索引
  relatedField?: string         // 記録画面の該当欄（?focus= に渡す）
  sources?: { label: string; url?: string }[]
  updatedAt: string
}

interface ArticleProgress {
  articleId: string
  userId: string
  readAt?: string
  bookmarked: boolean
}

interface ChapterState {
  userId: string
  professionKey: ProfessionKey | 'body'
  chapter: number
  isOpen: boolean               // ★開閉状態を保存する
}

interface ArticleNote {
  id: string
  userId: string
  articleId: string
  kind: 'highlight' | 'article'
  anchorText?: string           // kind==='highlight' のとき、選択された文字列
  anchorOffset?: number         // 本文中の位置（同じ文字列が複数あるとき用）
  body: string                  // 上限 500 文字
  sharedWithTeacher: boolean    // 既定 false
  createdAt: string
  updatedAt: string
  deletedAt?: string
}
```

**記事の本文はコード内に持たず、データファイル（またはCMS的な1箇所）にまとめてください。**
**記事を1本足すのに、コードを触らなくて済む形**にすること。

**`anchorText` が本文の更新で見つからなくなった場合**、メモは消さないこと。
「この記事は更新されました」と添えて、記事末のメモとして残してください。

## 9. ★ 表現の境界（ここだけは厳守）

**学ぶ記事には、文献の基準値を書いてよい唯一の場所です。**
ただし条件があります。

```
✅ 記事の中で「一般に◯◯とされています」と書く
✅ 出典を明記する

❌ 記事の中に、そのユーザーの数値を差し込む
❌ 「あなたの値は◯◯で、基準を下回っています」
❌ 記事から「受診してください」と個別に判定する
```

**この一線を越えると、プログラム医療機器の該当性の問題になります。**

**記事＝一般的な知識の解説。分析画面＝自分比だけの提示。**
**この2つを、画面の上でも決して混ぜないでください。**

第6章「続くときは」の書き方も同じです。

```
✅ 「4週間以上続く声のかすれは、専門医に相談することがすすめられています」
❌ 「あなたは症状が15日続いています。受診してください」
```

★2026-09-02、この例文の数字を 2週間 → 4週間 に直しました。
　例文であって数字の出どころではありませんが、そのまま記事へ写されると
　★誤った目安が読者に届きます。
　★数字の正は、記事②（いつ耳鼻咽喉科に行くか）です。
　lib/learnContent.js にも 2週間 と書いた記事が2本あります（661行・2095行）。
　★そちらは、出典を確かめてから直すこと。「もっと待ってよい」と
　　伝える向きの変更なので、こちらの判断だけで動かしません。

**症状の日数を数えて記事を出し分ける、といった実装をしないこと。**
