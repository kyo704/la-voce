# La Voce ／ 声を使う全職業への拡張設計

声楽家に加えて、**アナウンサー・声優・ポップス／ロック歌手**を本格的に対象にするための
収集項目・分析・サービス・収益化の設計。既存の職業フィールド（声楽家／アナウンサー／
声優／ポップス・ミュージカル歌手）を実際に機能させる方針です。

---

## 設計の中心にある考え方

4職種ぶんのアプリを4つ作るのではありません。**1つのエンジンに、職業ごとの
「翻訳レイヤー」を1枚かぶせる**構造にします。

```
┌─ 第4層 ｜ 職業別の「答え」画面 ──────────────────────┐
│  声楽家：本番ピーキング曲線                          │
│  アナウンサー：声のゴールデンタイム                  │
│  声優：役ごとの負荷ランキングと回復日数              │
│  ポップス/ロック：ツアー耐久曲線とセットリスト診断   │
├─ 第3層 ｜ 職業別の追加入力 ──────────────────────────┤
│  曲目 / 番組・原稿 / 役とテイク数 / セットリスト     │
├─ 第2層 ｜ 負荷の翻訳（ここが肝）─────────────────────┤
│  同じ ACWR エンジンに、職業別の L_d 計算式を差し込む │
├─ 第1層 ｜ 共通コア（全職業で同一）───────────────────┤
│  睡眠・水分・栄養・環境・症状・メンタル・体重        │
│  起き抜けの声・弱声の最高音・CPPS                    │
│  → 偏差値・予報・ラグ相関・効いた習慣・症状カレンダー│
└──────────────────────────────────────────────────────┘
```

**第1層と第2層は完全に共通で、第2層の関数を1つ差し替えるだけ**。
これがこの設計の要で、職業を増やすコストが劇的に下がります。

疲労したとき音域は上下とも狭くなり、声量の幅も減る——これは職業を問いません。
だから共通コアは本当に共通にできます。違うのは**何をどれだけやったか（負荷）**と、
**何を知りたいか（答え）**だけです。

出典: [Vocal loading — Wikipedia](https://en.wikipedia.org/wiki/Vocal_loading)

## 第2層：職業別の負荷計算

すでに設計した **ACWR（急性:慢性負荷比）** はそのまま使い、
1日の負荷 `L_d` の出し方だけを職業ごとに変えます。

```
共通： A_t = λ_a·L_t + (1−λ_a)·A_{t−1}    λ_a = 2/(7+1)
       C_t = λ_c·L_t + (1−λ_c)·C_{t−1}    λ_c = 2/(28+1)
       ACWR = A_t / C_t          ← ゾーン判定も共通
```

| 職業 | `L_d` の計算式 |
|---|---|
| **声楽家** | Σ（時間 × 活動係数 × テッシトゥーラ逸脱度） |
| **アナウンサー** | 発話時間 × 話速係数 × 常用ピッチ逸脱 × 騒音係数 ×（生放送 1.2） |
| **声優** | Σ（テイク数 × 声質係数）＋ 拘束時間 × 0.2 |
| **ポップス/ロック** | Σ（曲の最高音逸脱 × ベルト係数 × 曲長）× モニター係数 × 連戦係数 |

**声質係数（声優）の例** — ここが他のアプリにない部分です。

| 発声 | 係数 |
|---|---|
| ナレーション | 0.8 |
| 通常の芝居 | 1.0 |
| 張り上げ・怒鳴り | 3.5 |
| 叫び | 5.0 |
| 悲鳴・断末魔 | 6.0 |
| ダミ声・エッジ多用 | 4.0 |

係数はまず文献と現場感覚で置き、**データが貯まったら本人の実測から回帰で推定し直す**
（前回設計した経験ベイズ縮約と同じ仕組みで、一般値から個人値へ寄せていく）。

## 職業別の設計

### ■ アナウンサー・ナレーター・声を使う会社員

話し声の職業は、歌手と根本的に違います。**長時間・連続・同じ高さ**。
歌のような瞬間的な高負荷ではなく、じわじわ削られる。

連続発話では声帯が1時間に3万回以上ぶつかると言われます。
歌のように「山」があるのではなく、平坦にひたすら積み上がるのが特徴です。

#### 収集するもの

| 項目 | 入力 | なぜ |
|---|---|---|
| 発話時間の内訳 | 放送／収録／会議・打合せ／電話 の分数 | **放送外の発話が抜けると負荷を大きく見誤る** |
| 生放送 or 収録 | トグル | 緊張と一発勝負で発声が硬くなる |
| 原稿量 or 話速 | 文字数、または3択（早口／普通／ゆっくり） | 話速は負荷に直結 |
| 常用ピッチ（話声位） | 毎朝、定型文を3秒録音 → SFF を自動算出 | **この職業で最も鋭い指標**（後述） |
| 周囲騒音 | 中継／スタジオ／屋外 の3択 | うるさいと無意識に声を張る（ロンバード効果） |
| スタジオ環境 | 乾燥／空調直撃／マスク着用 | 放送スタジオは極端に乾燥している |
| 喉のケア | ネブライザー／加湿マスク／うがい | 効果測定の対象に |

#### 分析と、返す結果

**1. 話声位の日内変動**（この職業の看板機能）

朝と夕方で話し声の基本周波数がどう動くかを測ります。疲労で上がる人と下がる人がいて、
**その方向自体が個人の特性**です。毎朝＋仕事終わりの2回、定型文を読むだけ。

> 「あなたは仕事終わりに話声位が平均12Hz下がります。今日は28Hz下がっていて、
> この2週間で最大の落ち方です。」

**2. 声のゴールデンタイム**

既存の「朝／昼／晩」の時間帯別記録がそのまま使えます。
時間帯別の声の質を集計して、**大事な収録・生放送をいつ入れるべきか**を返す。
フリーランスのアナウンサー・ナレーターには、これがそのままスケジュール管理になります。

**3. 音域幅のトレンド**

疲労すると音域は上下とも狭くなります。歌わない職業でも、
週1回「一番低い声」「一番高い声」を記録するだけで、蓄積疲労の指標になります。

**4. 番組別・案件別の負荷ランキング**

「この番組の翌日は必ず落ちる」。声楽家の「役ごとの負荷」と同じエンジン。

#### サービスと収益化

**この職業がいちばん金になります。**理由は、払うのが本人ではなく**会社**だからです。

- 放送局・制作会社への導入（アナウンス部単位）
- 企業の健康管理室・産業医との連携 —— **産業保健の予算が使える**
- 声を主な道具にする労働者は労働人口の約13%と言われ、
  コールセンター・教員・営業職まで広げれば市場は歌手の比ではありません
- ディレクターと共有する「声のコンディション表」

個人向けの月額数百円ではなく、**組織向けの年間契約**が狙える唯一の職種です。

### ■ 声優（アニメ・ゲーム・吹替）

声優の負荷は、歌手ともアナウンサーとも違います。**極端な発声を、短時間に、繰り返す**。

海外の声優組合 ACTRA Toronto の調査では、
**74%** が「大声・攻撃的・声を酷使する仕事をとても頻繁に経験する」と答え、
**40%** が収録中の声の疲労を頻繁に感じ、**20%** が収録後の回復に苦しみ、
そして **42% が、激しい収録のあと声が元に戻るまで2日以上かかる**と答えています。

**この「42%が2日以上」を、自分の数字にして返すのが、この職業向けの中核機能です。**

#### 収集するもの

| 項目 | 入力 | なぜ |
|---|---|---|
| 収録種別 | アニメ本編／ゲーム／吹替／ナレーション／ラジオ／イベント | ゲームのバトルボイスが突出して重い |
| **叫び・悲鳴のテイク数** | 数値（概算でよい） | **最重要**。これ1つで翌日がほぼ決まる |
| 声質の種類 | 地声寄り／高め／低め／裏声／エッジ・フライ／ダミ声（複数選択） | 負荷係数の算出に |
| 役名 | テキスト（初回にピッチ帯を登録） | 役ごとの負荷分析に |
| 収録時間・拘束時間 | 分 | 拘束時間中の待機も疲労になる |
| ブースの湿度 | 数値または3択 | 収録ブースは乾燥しがち |
| 歌の仕事 | トグル | 声優は歌う仕事も多い。歌手側のエンジンに切り替える |

#### 分析と、返す結果

**1. 回復曲線（この職業の看板機能）**

激しい収録日を 0 として、翌日・翌々日・3日後にどこまで戻るかを重ね合わせ平均で出す。
声楽家のピーキング曲線と**まったく同じエンジン**で、時間の向きが逆なだけです。

> 「あなたは叫びの収録から**完全に戻るまで平均2.3日**かかります。
> （声優全体の平均は約2日）明後日のオーディションまでには戻り切りません。」

これはスケジュールを組む判断に直結します。

**2. 叫びテイク数の閾値**

何テイクを超えると翌日に響くのか、変化点検出で個人の閾値を出す。

> 「あなたの限界は**叫び18テイク**あたりです。それを超えた5回の収録では、
> すべて翌日の声が2段階以上落ちています。」

現場で「あと5テイクいけますか」と聞かれたときに、根拠を持って答えられる。
声優にとって、これは金銭的価値のある情報です。

**3. 役ごとの負荷ランキング**

「この役は翌日必ず落ちる」「この役は3本続けても平気」。
既存の「曲目・演目」欄と同じ仕組みで実装できます。

**4. 収録前の逆算**

明日バトルボイス3時間 → 今夜の睡眠目標・水分目標を提示。
ACTRA の調査では「きつい仕事はセッションの後半に回す」という現場の工夫も挙がっており、
**その日の中での順番**まで提案できると価値が上がります。

#### サービスと収益化

- **事務所・養成所プラン**（指導者プランの応用）。マネージャーが所属声優の状態を見る
- マネージャーにとっての価値は明確で、**「この日は叫び収録を入れない」という
  スケジューリング判断**ができるようになること。仕事の質と、事故の防止に直結します
- 養成所は生徒数が多く、指導者プランの単価を上げやすい
- 音声外来との連携（既に設計済みの PDF 書き出しがそのまま効く）

出典: [ACTRA Toronto survey finds video game work impacting vocal health — Broadcast Dialogue](https://broadcastdialogue.com/actra-toronto-survey-finds-video-game-work-impacting-vocal-health/) ／
[Understanding the Vocal Health of Voice Actors in the Video Game Industry — Journal of Voice](https://www.sciencedirect.com/science/article/pii/S0892199725002966)

### ■ ポップス／ロック／ミュージカル歌手

クラシックとの最大の違いは、**ベルティングとシャウト、そして連戦**です。
ツアーは「毎日が本番」で、声楽家の「本番ピーキング」の考え方が通用しません。

#### 収集するもの

| 項目 | 入力 | なぜ |
|---|---|---|
| 活動種別 | ライブ／リハ／サウンドチェック／レコーディング | 1日に3つ重なる日がある |
| **セットリスト** | 曲名（初回に最高音・キー・ベルト有無を登録） | 負荷計算と、後述のセトリ診断に |
| シャウト・グロウルの有無 | トグル＋回数 | ラフな発声は別カテゴリの負荷 |
| モニター環境 | インイヤー／ウェッジ／なし | **モニターが悪いと声を張る**。効果が大きい |
| ステージ音量 | 3択（大／中／小）または dB | ロンバード効果 |
| ツアー何日目か | 自動計算（連戦の開始日だけ入力） | 耐久曲線の軸 |
| 移動時間・移動手段 | 分＋3択 | 車中泊・夜行バスは睡眠に直撃 |
| 会場環境 | 乾燥／スモークマシン／空調 | スモークは実際に喉に来る |
| **打ち上げ** | 参加の有無／騒がしさ／飲酒 | **実はここが最大の隠れ負荷** |

#### 分析と、返す結果

**1. ツアー耐久曲線（この職業の看板機能）**

ツアー初日を 0 として、何日目に落ちるかを重ね合わせ平均で出す。
声楽家のピーキング曲線と同じエンジンです。

> 「あなたはツアー**4日目に落ちる型**です。過去3本のツアーすべてで同じ形が出ています。
> 今回のツアーは4日目が大阪。その前日の移動日に休養を厚くしましょう。」

**2. セットリスト診断（いちばん実用的）**

曲ごとの負荷（最高音の逸脱 × ベルト係数 × 曲長）を足し上げ、
**曲順による負荷の偏り**を見ます。

> 「3曲目と4曲目が連続で重く、ここで一度声が消耗します。
> 5曲目の『◯◯』と入れ替えると、後半の負荷が15%下がります。」

これは**リハの前に見たくなる画面**で、バンドやボーカルディレクターに直接刺さります。

**3. キー下げの提案**

> 「『◯◯』のサビは、あなたの快適音域の上限を2半音超えています。
> 半音下げると収まります。」

キーを下げるかどうかは歌手にとって重い決断で、**根拠のある数字があると決めやすい**。
ツアー後半だけキーを下げる、という運用の判断材料にもなります。

**4. モニター環境と打ち上げの効果量**

すでに設計した「効いた習慣ランキング」に、この2つを入れるだけです。

> 「インイヤーの日は、ウェッジの日より翌日の声が平均0.7段階良い（★★★☆）」
> 「打ち上げに出た日の翌日は、平均1.1段階落ちる（★★★★）」

打ち上げを数字で突きつけられると、行動が変わります。
本人が薄々わかっていることを、確度つきで示すのが効きます。

#### サービスと収益化

- **バンド・ユニット単位のプラン**（メンバー全員＋ボーカルディレクター）
- ツアーマネージャー向けダッシュボード——「4日目に落ちる」がわかれば、
  スケジュールの組み方が変わります。**制作費に対して月額は誤差**なので通りやすい
- ボイストレーナー連携（指導者プランと同じ）
- 事務所・レーベル単位の契約

## 職業をまたぐことの、隠れた価値

4職種を1つのアプリで扱うと、**職業別のベンチマーク**が手に入ります。

> 「叫び収録からの回復日数：声優の中央値 2.1日。あなたは 2.8日」
> 「ライブ翌日のコンディション低下：ロック −1.3段階、ミュージカル −0.8段階」

こうした数字は、どの職業のユーザーにも刺さり、メディアにも取り上げられます。
**日本にこのデータを持っている人は、たぶん誰もいません。**

ただし、これは要配慮個人情報の統計利用にあたります。
オプトアウトによる第三者提供は法律で認められていないため、
**「統計に自分のデータを使ってよいか」を明示的に同意で取る**設計が必須です。
匿名加工の手続きも含め、公表を始める前に整えてください。

## UI の方針

### 画面は「増やす」のではなく「入れ替える」

職業を選ぶと、**入力項目と分析画面が丸ごと切り替わる**。
全職業の項目を並べると、誰にとっても使いにくいアプリになります。

### 用語を翻訳する

同じデータ構造でも、呼び名は職業の言葉に合わせます。

| 内部の概念 | 声楽家 | アナウンサー | 声優 | ポップス/ロック |
|---|---|---|---|---|
| イベント | 本番 | 放送・収録 | 収録 | ライブ |
| 演目 | 曲目・役 | 番組・案件 | 役・作品 | セットリスト |
| 練習 | 自主練習 | 原稿読み | 練習・レッスン | リハ |
| 逆算画面 | ピーキング曲線 | ゴールデンタイム | 回復曲線 | ツアー耐久曲線 |

### 兼業を前提にする

**これは必須です。**声優が歌う、ミュージカル俳優が吹替もやる、
アナウンサーがナレーションと司会を掛け持つ——兼業が普通の業界です。

- 職業は**複数選択**できるようにする
- **その日の活動ごとに種別を選ぶ**（今日はアフレコ、明日はライブ）
- 負荷計算は、その日の活動種別に応じた式を使って合算する

## 収益化の設計

### 価格は職業で変えない

個人プランの価格を職業別に変えても、複雑になるだけで収益は増えません。
機能の差は「職業別の答え画面」で自然に付きます。

### B2B の入口が職業ごとに違う（ここが本質）

| 職業 | 払う組織 | 予算の出どころ | 取りやすさ |
|---|---|---|---|
| **アナウンサー・会社員** | 放送局、制作会社、一般企業 | **産業保健・労務** | ◎ 最も金がある |
| **声優** | 事務所、養成所 | 育成費・タレント管理費 | ○ 養成所は生徒数が多い |
| **ポップス/ロック** | 事務所、レーベル、ツアー制作 | 制作費 | ○ 単価は高いが数は少ない |
| **声楽家** | 音大、声楽教室 | 教育費 | △ 単価は低いが数は多い |

**アナウンサー・企業の声を使う職種が、収益的には本命です。**
産業保健の予算は個人の可処分所得とは桁が違い、
「従業員の声の健康管理」という名目は通りやすい。

一方で**プロダクトとして磨くなら声優**です。回復曲線と叫びテイク閾値は
明確に金銭的価値のある情報で、口コミが回りやすい業界でもあります。

### おすすめの順番

1. **声優**から作る。機能のインパクトが最も大きく、既存の実装（役＝曲目、回復＝ピーキングの逆）を流用できる
2. 次に**ポップス/ロック**。セットリスト診断は口コミが起きやすい
3. **アナウンサー**は最後だが、B2B の営業は並行して始めておく。導入は遅く、契約は大きい

## 実装の順番（Sonnet 5 での現実性）

| Phase | やること | 規模 |
|---|---|---|
| 1 | 職業フラグによる画面出し分け（既存の職業フィールドを使う）。用語の翻訳テーブル | 3〜5日 |
| 2 | 負荷計算のプラグイン化（`calculateDailyLoad(profession, record)` の1関数に集約） | 2〜3日 |
| 3 | 声優：役マスタ＋叫びテイク数の入力、回復曲線、テイク閾値の変化点検出 | 1〜2週間 |
| 4 | ポップス/ロック：曲マスタ（最高音・キー）、セットリスト診断、キー下げ提案 | 1〜2週間 |
| 5 | アナウンサー：定型文録音→SFF算出、日内変動、ゴールデンタイム | 1〜2週間 |
| 6 | 兼業対応（複数職業＋日ごとの種別切り替え） | 1週間 |

**Phase 2 の設計が最重要です。**ここを1関数に集約しておかないと、
職業を増やすたびに全画面を触ることになります。Sonnet に依頼するときは、
**「職業ごとの負荷計算を差し替え可能にする」ことを明示的に要件として書いて**ください。

### 最初に作るなら

**声優の「叫びテイク数 → 翌日のコンディション」**の1画面です。

- 新しい入力は数値1つ（テイク数）
- 分析は既存の効果量エンジンを流用
- 出てくる答えが具体的で、その日から行動が変わる
- 「これがあるから使っている」と言われる機能になり得る
