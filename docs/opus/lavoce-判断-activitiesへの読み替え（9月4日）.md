## §1 確認1 ── 条件が4つあります

### 条件1 ★★これがいちばん重要です ── 二重になります

```
activities[] は、★その日の活動係数の計算に使われているはずです
　　（休養0／自主練1.0／レッスン1.2／リハ1.3／本番1.6）
```

```
★生徒が、すでに手で「レッスン 60分」を入れていたら
　　→ 取り込むと、★同じレッスンが2ブロックになります
　　→ ★その日の負荷が、2倍で計算されます
　　→ ★分析が狂います。そして誰も気づきません
```

★仕様§4の端の場合5（「既に手で入れている → 加算する」）は、
　**activities では成り立ちません。撤回します。**

★正しい形

```
取り込みのカードを出す前に、★その日に "レッスン" のブロックが
すでにあるかを見ます

　ある場合   ★カードの文面を変える
　　　　　　「きのうのレッスン（60分）が記録されています。
　　　　　　　先生の記録は 55分 でした。」
　　　　　　　［先生の記録に合わせる］［このままにする］

　無い場合   ★これまでどおり ［足す］［足さない］
```

★**「足す」ではなく「合わせる」です。**同じ出来事が2つ並ぶことを、防いでください。

### 条件2 ── source の既存の値を、先に確かめてください

```
既存の値   "migrated" / "timer"
　　★どちらも、どこからも読まれていません
```

```
確かめること
　　★"migrated" と "timer" は、それぞれ何を意味しますか
　　★実データに、いま何件ずつ入っていますか
```

★意味が合わないなら、**同じ欄に 'lesson' を足さないでください。**

```
（良い）source は「この記録がどこから来たか」を表す欄である
　　　　→ 'lesson' を足してよい

（悪い）source は別の意味で使われている
　　　　→ ★意味の違うものを、同じ欄に入れることになります
```

★そして——**これは「書いているのに読まれていない」列でした。**
　`#34` が最初の読み手になります。**良い形です。**
　ただし、読み手が付く以上、**書かれている値の意味を確定させてください。**

### 条件4 ── lesson_imports は、そのまま必要です

