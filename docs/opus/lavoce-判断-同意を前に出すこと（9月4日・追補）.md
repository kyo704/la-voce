# 判断（追補）── 同意を前に出すこと

全 361 行 / 末尾は「申告を、確認と呼ばないこと。名前を間違えると、あとで信じてしまいます。」

作成 2026年9月4日 ／ 「未成年に売ること」への追補

---

## §0 結論

```
① 前倒し           ★してよいです。方向は正しい
② 1つにまとめる     ★できません。★接続の同意は前に出せません（§2）
③ 無料利用の停止    ★しないでください。逆効果です（§3）
④ 同意の形式        民法に方式の定めはありません。有効性ではなく★立証の問題（§4）
                    ★メールの往復は作らないでください
⑤ 同意文の書き方    「契約に同意」ではなく★「毎月◯◯円まで使ってよい」（§5）
⑥ 返金              ★全額。日割りにしないでください（§6）
⑦ 期間制限          ★規約に書かないでください。書けません（§7）
⑧ 前倒し＋返金      ★矛盾しません。補い合います（§8）
```

---

## §1 前倒しの方向は、正しいです

理由を1つ足します。運営者は言っていませんが、これが本当の効き目です。

```
決済の直前に保護者を出せと言うと、
★いちばん買いたい瞬間に、いちばん高い壁を置くことになります。
　そのとき人は、★嘘をつきます。
```

何も懸かっていないときに聞けば、正直な答えが返ります。
**前に出す理由は、法律ではなく、これです。**

---

## §2 ★ただし、1つにまとめることはできません

同意は2種類あります。**性質が違います。**

```
① 使うことへの同意（有料を含む）
   相手      サービス
   範囲      ★決まっています（毎月◯◯円・記録する項目）
   前倒し    ★できます

② 接続への同意（教室・先生）
   相手      ★特定の先生・特定の教室
   範囲      ★まだ決まっていません
   前倒し    ★できません
```

**範囲が決まっていない同意は、同意になりません。**

使い始めの時点では、どの先生とつながるか、その先生に何が見えるかが決まっていません。
そこで「将来つながる誰かに、何かが見えることに同意します」と取っても、
それは同意の形をした空白です。

★9月4日の「保護者の同意」設計は、接続に紐づけてありました。**そのままにしてください。**

```
使い始め   ①を取る（有料の許可を含む）
接続のとき ★②を、接続ごとに取る
```

2本になります。それでよいです。**1本にすると、②が壊れます。**

---

## §3 ★無料の利用は、止めないでください

前倒しは「早く聞く」ことであって、「通さない」ことではありません。

```
15〜17歳と答えた   → ★「保護者の方へ」のページを渡す（ブロックしない）
記録を続ける       → ★止めない
教室につなぐ       → ②の同意を取る（ここで止める）
有料を申し込む     → ①の同意を確認する（ここで止める）
```

### 理由は3つ

```
① 法律が求めていません
   個人情報保護委員会の Q&A は、法定代理人の同意が必要な年齢を
   ★「一般的には12歳から15歳までの年齢以下」としています。
   ★15〜17歳は、本人の同意で足りるという整理です

② 無料の利用に、取り消すものがありません
   お金が動いていないので、取り消されても戻すものがありません

③ ★止めると、嘘をつく動機が上がります
   通れない壁の前で、人は「はい」を押します。
   ★止めないほうが、正直な答えが返ります
```

★そして、こう書かないでください。

```
✕ 「法律で決まっているため、保護者の方の同意が必要です」
◯ 「私たちの決まりとして、保護者の方の同意をお願いしています」
```

**15〜17歳について、法律はそこまで求めていません。**
求められていないことを「法律で決まっている」と書くのは、嘘です。
これは「断言をやめる」と同じ系列の話です。

---

## §4 同意の形式 ── 有効性ではなく、立証の問題です

**民法に、法定代理人の同意の方式は定められていません。**
口頭でも、書面でも、画面のチェックでも、**同意そのものは有効に成立します。**

問題は、**あとで「あった」と示せるか**です。

```
証明力  強  ★保護者名義のカードで支払われている事実（Stripe に残ります）
        中  保護者の電話番号への SMS
        中  保護者のメールアドレスへのリンク
        弱  ★アプリ内のチェックボックス（本人が押す）
```

### ★メールの往復は、作らないでください

```
・外に出る経路が1本増えます（台帳05に載ります）
・★保護者の個人データを持つことになります
  → 開示・訂正・削除・漏えい報告の対象が増えます
・そして★証明力は、思ったほど上がりません
  子が親のアドレスを入れれば、同じことです
・45日しかありません
```

**証明を強くする道より、証明が要らない道を選びます。** それが §6 の返金です。

なお、保護者名義のカードで支払われた事実は、**作らなくても Stripe 側に残ります。**
何も実装しなくてよいですが、**あることは知っておいてください。**

## §5 ★同意文を、こう書き換えてください

これが、この追補でいちばん価値のある部分です。

```
✕ 「この契約に同意します」
◯ ★「毎月◯◯円まで、このアプリで使ってよいと認めます」
```

### なぜか

民法5条3項です。

```
法定代理人が★目的を定めて処分を許した財産は、
未成年者が自由に処分できる ＝ ★取り消せない
```

「契約に同意する」は、5条1項の同意です。**あったことを証明しなければ効きません。**
「毎月◯◯円まで使ってよい」は、**5条3項の許可そのもの**です。
金額の上限が定まった、目的の定まった処分の許可になります。

**同じチェックボックスで、条文の当てはめが変わります。**

### 画面（保護者向けページの中に置く）

```
　保護者の方へ

　このアプリを、お子さまがお使いになります。

　・記録するもの   睡眠、声を使った時間、のどの調子など
　・毎月のお支払い ◯◯円（年ごとのお支払いはありません）
　・やめ方         アプリの中から、いつでも
　・お申し出があれば、直近のお支払いを返金し、すぐに解約します
　　　お問い合わせ：woolsong.app@gmail.com

　［　］ 毎月◯◯円まで、このアプリで使ってよいと認めます
```

★このチェックを押すのは、結局その端末を持っている人です。
**それは変えられません。** 変えられないことを前提に、§6 で受けます。

## §6 返金 ── ★全額です。日割りにしないでください

条文がそう決めています。

```
民法121条の2第3項
　制限行為能力者は、その行為によって★現に利益を受けている限度において、
　返還の義務を負う
```

つまり、取り消されたとき、

```
事業者    ★受け取った金額を返す
未成年側  ★使った分を返さなくてよい（現存利益の限度）
```

**日割りにすると、法律より不利な扱いになります。** そして争点が1つ増えます。
**法律と同じにしておくのが、いちばん安くて、いちばん揉めません。**

```
返金の範囲   ★直近のお支払い（全額）
返金の先     決済に使われたカード
理由         ★伺わない
```

## §7 ★期間制限は、規約に書けません

ここは運営者が知らない可能性が高いので、はっきり書きます。

```
民法126条
　取消権は、★追認をすることができる時から5年で時効消滅する。
　★行為の時から20年を経過したときも、同様とする。

　未成年者の「追認をすることができる時」＝ ★成年に達した時
```

**つまり、17歳のときの契約は、22歳まで取り消せます。**

```
✕ 「お申し出は30日以内にお願いします」
✕ 「返金は購入後◯日以内に限ります」
```

★これを書くと、**取消権を制限する条項に読めます。**
取消権は契約で縮められませんし、消費者契約法10条の問題にもなりかねません。

### 書き方

**期限ではなく、範囲で限ります。**

```
◯ 「直近のお支払いを返金します」
```

これは「いつまで」の話ではなく、「いくら」の話です。
そして、それを超える申し出が来たときは、

```
★規約には書かず、★内部の方針として決めておく。
　「少額なら、そのときも払う」
```

**書かないことと、しないことは違います。**
書かなければ義務にはなりませんが、来たときに払わない理由にもなりません。

---

## §8 「前倒しの同意 ＋ 取消し時の返金」は、矛盾しません

```
返金しても、★取消権は消えません（放棄させられません）
同意を取っても、★取消権は消えません（立証できなければ同じです）
```

**どちらも取消権を消しません。だから両方やります。**

```
同意   取り消される★確率を下げる
返金   取り消されたときの★損害を消す
```

役割が違います。重複していません。

そして**全額返せば、原状回復が終わります。**
取り消しても、取り戻すものが残りません。
**②のほうが、①より確実です。** そう理解して、返金の約束のほうを大事にしてください。

---

## §9 ★フラグの名前を、間違えないでください

前倒しにすると、アカウントに状態が1つ立ちます。**ここに罠があります。**

```
✕ guardian_consent_obtained   （保護者の同意を★得た）
◯ ★guardian_consent_declared  （保護者の同意を得たと★申告された）
```

得たかどうかを、アプリは知りません。**申告されたことだけを知っています。**

名前を間違えると、半年後に誰かがこう言います。
「このユーザーは保護者の同意を得ています」──**得ていないかもしれません。**

★「確かめられないことを、表示しない」。
★内部の列の名前にも、同じ規則を通してください。

そして、このフラグを**判断の根拠にしないでください。**
記録として持ちますが、これを見て「だから大丈夫」とはしません。

## §10 この形に固有のリスク


```
① ★保護者の個人データを持ってしまう
   メールや氏名を取ると、開示・削除・漏えい報告の対象が増えます
   → §4 のとおり、取らない

② ★離脱
   前倒しで止めると、15〜17歳の無料利用が消えます
   → §3 のとおり、止めない

③ ★同意が広すぎて弱くなる
   1本にまとめると、②（接続）の範囲が空白になります
   → §2 のとおり、2本にする

④ ★15歳未満への圧力
   前倒しの同意フローができると、
   「保護者が同意すれば15歳未満も」という話が必ず出ます
   → ★受け入れない、を維持してください。
     理由：15歳未満は、個人情報保護委員会が法定代理人の同意を
     求める帯に入ります。仕組みが重くなり、45日では作れません

⑤ ★申告を確認と呼んでしまう
   → §9
```

```
★私が決めたこと（条文にはありません）
  ・月額1,000円未満に保つ、という線
  ・「毎月◯◯円まで認めます」という文の形
  ・無料利用を止めない、という方針
```

★弁護士相談の項目に、もう1行足してください。

```
□ 保護者の同意を、アプリ内の申告だけで足りるとしてよいか。
  返金の約束を併せて置く前提で。
```
