# 教室の機能の守りの確認（2026-09-23・Opus が本番を読み取りだけで）

対象: 名簿・在籍・役職・行事・連絡・請求・門下・学科・場所・時限・学生の値段の同意ほか
結果: ★新しい穴は 見つからなかった（今日ここまでで 唯一）

## 1. 正しい形だったもの

```yaml
役職の更新（memberships の UPDATE）:
  ポリシーが2本 並んでいる。片方が緩ければ そちらで通ってしまう形 ★ではなかった
  ★memberships_update_needs_can_post は ★制限つき（RESTRICTIVE）＝ ★必ず AND で効く
  → can_grant_post（自分が持っていない札は渡せない）を ★迂回できない。裁定その19・その53 のとおり
役職そのもの（org_posts）:
  ★読むポリシーだけ。書くポリシーは0本。書く関数も0本
  → ★書けるのは サーバ（service role）だけ＝ app/api/org/posts/route.js
  ★これは正しい形。ただし ★守りはその1本に集まる → sql/35（can_grant_post_user）が効いているか Code が確かめる
記録の表（門下を開いた記録・年齢の答えの変更・学年の変更・学生の値段の同意）:
  ★読むだけのポリシー。書くのは 関数かサーバ。★消すポリシーは 1本も無い（消せない）
門下（assignments）: 先生本人・生徒本人・名簿の札 の3つだけ
門下を開いた記録: ★見た本人 か master だけ（他の先生からは見えない）
連絡（org_messages）: 取り消し（withdrawn_at）だけ できる。★消すポリシーは無い＝消えない
行事: 行事の札（gyoji）。学科・場所・時限: 名簿の札
請求: 読むのは bill、直すのは bill_pay（★分けてある）
```

## 2. 今日 全体で見つけたものとの関係

```yaml
公演で5件・レッスン割で1件・書き込みで1件・削除の連鎖で1件・索引で多数 見つかった
★教室は0件だった。理由は はっきりしている:
  ★教室は いちばん長く作っていて、★裁定その19・その53・A13 で 何度も見直されている
  新しく書いたところ（公演・レッスン割・作品）に 穴が集まっていた
→ ★教訓: 新しく書いたところを 先に見る。古くて何度も見たところは 後でよい
```
