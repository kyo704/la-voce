## §1 「一字も変えず」の意味

あの指示は、**文体を守るため**のものでした。
私の文を、要約したり、言い換えたり、丁寧にしたりしないでください、という意味です。

**中身を守るためのものではありませんでした。**

判断が変わったら、文も変わります。
このとき変わらないほうがおかしい。

だから、これは規則にします。

```
「一字も変えず」は、写した時点の指示です。
後から裁定が出たら、裁定が勝ちます。
```

そして、今回の報告の仕方は正しいです。
勝手に直さず、案を出して、承認を求めた。この順番でよいです。

## §2 なぜ「機能を持ちません」なら書いてよいのか

ここは、今後も何度も出てくるので、理由を残します。

9月3日に、profiles が接続先の先生から読めていました。
このとき、

```
「先生は見られません」          → 嘘になりました
「参照する機能を持ちません」    → 嘘になりませんでした
```

前者は**結果**の話です。実際に見えたら、その瞬間に嘘です。
後者は**作ったもの**の話です。あれは機能ではなく、ポリシーの穴でした。

私たちが断言できるのは、後者だけです。
何を作ったかは知っています。何が起きるかは知りません。

この差が、9月4日の禁止形の理由です。
`lib/linkConsent.js` の FORBIDDEN_LINK_PHRASES は、この差を機械で守っています。

## §3 足りない1行

案の一覧に、もう1つ足してください。

```
・あなたが送った連絡（欠席、遅れます、相談したいことがあります）
```

理由は、案の §2 で書いてくれたものと同じです。

「相談したいことがあります」の宛先は責任者です。担当の先生ではありません。
一方、この見出しは「指導者・運営者」とまとめて書いてあります。

つまり、この1行を足すと、**実装より少しだけ多めに**書くことになります。
それが正しい向きです。

宛先の違いまで政策文に書く必要はありません。
書くと細かくなりすぎて、かえって読まれません。
「誰に伝わるか」の器を大きめに取り、中の分け方は仕様と画面で守ります。

## §6 3か所目への手当て

「これが3か所目です」と書いてくれました。ここが一番大事です。

いままでの直し方は、こうでした。

```
正が動く → 写した先を思い出す → 探す → 直す
```

「思い出す」が入っています。だから3回とも漏れました。

これを逆にします。

```
正の側に、写した先の一覧を持つ。
```

`docs/legal/consent-scope-ja-2026-09-v1.md` の末尾に、こう足してください。

```
## この文書を写している場所

  docs/legal/terms-ja-（版）.md          第5条
  docs/legal/privacy-ja-（版）.md        第5項
  （画面）接続の同意                      lib/linkConsent.js
  （画面）（該当があれば追記）

  ここを直したら、上の全部を同じ日に直すこと。
```

これで、正を直そうとした人の目の前に、直す先の一覧が出ます。
思い出す必要がなくなります。

もし他にも写している場所があれば、いま数えて、この一覧に入れてください。
数え漏れがあってもかまいません。一覧があること自体が効きます。

なお、これは新しい台帳ではありません。既存の文書の末尾です。
台帳を8本目にしないでください。

## §7 隣に、仕組みを書く

「9月4日の決まり」をもう1つ思い出してください。

```
約束を書いたら、それを守っている仕組みを、その場で隣に書く。
```

「参照する機能を持ちません」は約束です。
では、その通りでなかったときに何が起きるかも、近くに書いてあるべきです。

新しい文は作らないでください。
プライバシーポリシーには、すでに不具合・漏えいのときの項があるはずです。
第5項の末尾から、その項へ**参照だけ**張ってください。

```
（この通りでない状態が見つかったときの扱いは、第◯項に書いています。）
```

項番は、いまの版を見て入れてください。私は版を見ていません。
