## 1. 決定

```yaml
段階は4つ:
  off       誰にも見えない（既定。★台帳に無い鍵も off と同じ＝勝手に開かない）
  internal  運営（is_internal）だけ
  beta      内輪の試しの人だけ（利用者ごとに印）
  on        全員
開ける条件（★これが揃うまで on にしない）:
  1 その機能の VERIFY（sql/ の「確かめ」）が全部通っている
  2 画面と見本が一致している（段3a）
  3 記録が要る機能は、★記録が残ることを確かめてある（門下を開いた記録の教訓）
  4 書類が要る機能は、書類が公開されている（値段・さがす）
判定は1か所: feature_on(鍵)。画面ごとに条件を書かない
切り替えるのはサーバだけ: 画面からは変えられない（権限を渡さない）
出発の朝: features_hidden() で「切ってある機能の一覧」を見る（裁定171 §5・10月19日の朝の確認 #18）
```

## 3. やらないこと

```yaml
- 画面の中で「if 坂本さんのアカウントなら」と書く（切り替えが散らばる）
- 台帳に無い鍵を「たぶん大丈夫」で開ける（★無い鍵は必ず off）
- 利用者に「近日公開」と見せる（★隠すとは、存在を見せないこと。期待を作らない）
- 切ってある機能の画面を、入口だけ出す（押せない入口は不具合に見える）
```

## 4. VERIFY

```yaml
- ふつうの利用者: feature_on('koen') が false。公演の画面に入口が無い

- 無い鍵: false（勝手に開かない）
- 画面から feature_flags を update → 権限エラー
- features_hidden(): off・internal・beta の機能が並ぶ
```
