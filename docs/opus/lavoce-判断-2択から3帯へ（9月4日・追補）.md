## §1 ★2択から3帯へ ── 既存の答えを、移行しないでください

```
いまの答え   「18歳未満」／「18歳以上」／未回答（＝未成年扱い）
これから     「15歳未満」／「15〜17歳」／「18歳以上」
```

★**「18歳未満」と答えた人が、15歳未満なのか15〜17歳なのかは、分かりません。**

```
（誤）「18歳未満」を「15〜17歳」に自動で移す
　　　→ ★答えていないことを、答えたことにします
　　　→ 15歳未満の人が、15〜17歳として扱われます
```

★正しい形

```
2択の答え   ★そのまま残す（履歴として）
3帯の質問   ★新しい質問として、あらためて聞く

　「18歳以上」と答えている人  → ★聞き直さない
　「18歳未満」と答えている人  → ★連携しようとしたときに聞く
　未回答の人                  → ★同じく、そのときに聞く
```

★**聞くのは、連携しようとした瞬間で足ります。**
　いま全員に聞き直す必要はありません。**理由なく質問を増やさないでください。**

★`age_answer_changes` があるので、**履歴は続きます。**
　2択の答えと3帯の答えが、**別の質問として並ぶ形**にしてください。

## §2 ★自己申告の限界 ── 教室経由が強い理由が、もう1つ

```
本人申告である以上、★17歳が「18歳以上」と答えれば、通ります
　　→ ★これは、防げません
```

★防げないことを、設計に織り込みます。

```
（できないこと）★嘘を見抜く
（できること）　★嘘をつく必要をなくす／嘘の影響を小さくする
```

### 2.1 教室経由なら、そもそも自己申告に依存しません

```
教室は、★入会のときに本当の年齢を知っています
　　→ 教室が「保護者の同意を確認しました」と記録する形なら
　　→ ★生徒の自己申告は、経路に入りません
```

★§3.1（教室経由）を先に作る判断が、**ここでも効きます。**
　理由が3つになりました。

```
1  教室は保護者を知っている（本人確認が強い）
2  責任の所在がはっきりする
3  ★生徒の自己申告に依存しない  ←★今回、追加
```

### 2.2 変更を、止めないでください

```
「18歳未満 → 18歳以上」への変更が、連携の直前に起きたら？
```

★**止めないでください。**

```
誕生日で18歳になる人がいます
　　→ 正当な変更と、抜け道の変更は、★区別できません
　　→ 止めると、★正当な人を締め出します
```

★代わりに、**記録するだけにしてください。**

```
age_answer_changes に残っていれば、あとから見られます
　　→ ★何か起きたときに、経緯をたどれます
　　→ それで足ります
```

★フェイルクローズ（未回答＝未成年扱い）は、**そのまま維持してください。**正しい形です。

## §3 ★「生年月日は取得しません」を、書いてください

★B-3 の第2項（お預かりする情報）に、年齢の記述がありません。**足してください。**

```
（足す）
　・年齢の区分（15歳未満／15〜17歳／18歳以上）

　　★生年月日は、お預かりしません。
　　　年齢の区分だけをお聞きし、それ以外は記録しません。
```

★**これは強みです。**書かないと、誰にも伝わりません。

```
学校の情報システム部門は、★「何を取っていないか」を見ます
　　→ 「生年月日を取りません」は、★そのまま安心材料になります
　　→ ★取っていないものは、漏れません
```

★`ageGate.js` に識別性の抑制が明文化されている、というのは
　**設計として正しく、かつ売り物になる判断です。**

★営業の資料（学校向けページ）にも、1行入れてください。

```
　生年月日は取得しません。年齢の区分だけをお聞きします。
```
