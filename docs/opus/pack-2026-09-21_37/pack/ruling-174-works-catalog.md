# RULING 174 — 作品のカタログ（オペラ・交響曲・器楽曲をできる限り入れる）

```yaml
ruling: 174
date: 2026-09-23
version: design-v24
from: 坂本さん「できる限りのオペラのデータを入れたい。交響曲やありとあらゆる器楽曲も」
builds_on: 裁定152 R2（作品の雛形。20作品が未作成のまま）／sql/20（works・work_roles・work_scenes）
```

## 1. 分けて考える（ここが決め手）

```yaml
★3つの層があり、手に入りやすさが まったく違う:
  層1 作品の名前・作曲家・種類      → ★公開のデータで まとめて入る（数万件）
  層2 楽章・曲・番号（場面にあたる） → ★公開のデータで かなり入る（交響曲の楽章、オペラの番号）
  層3 ★場面 × 役 の対応            → ★公開のデータに ほぼ無い。楽譜・台本を見て人が作る
  ★香盤表の下書きに本当に効くのは 層3。層1・2 だけでは「曲名が選べる」までで、入力の手間はあまり減らない
```

## 2. 決定

```yaml
入れる:
  層1・層2: まとめて入れる。出どころは ★CC0（公共のもの）に限る
    - MusicBrainz の中心のデータ（CC0。作品・楽章の親子関係）
    - Wikidata（CC0。作曲年・編成・登場人物が入っていることがある）
    ★IMSLP からの取り込みはしない（ページの文章の扱いが場所により違う。楽譜そのものは要らない）
  層3: 人が作る。★よく使う作品から順に（下の順番）
出どころを必ず残す: 作品ごとに「どこから来たか」「どこまで揃っているか」を持つ
  揃い方: title（名前だけ）／movements（楽章・番号まで）／roles（役まで）／full（場面×役まで）
  ★画面は「full の作品だけ」を「下書きを作る」に出す。ほかは 曲名を選ぶだけに使う
入れない: 楽譜・歌詞・対訳・あらすじ（著作権。裁定157 E3 と同じ）
量の見当: 作品5,000・楽章6万で 台帳は 約14MB（いまの本番 19MB・Free の上限 500MB）→ ★容量は問題にならない
```

## 3. 層3（場面×役）を作る順番

```yaml
1 坂本さんがこれから関わる作品（10月11日の本番・イタリアで見る作品）
2 日本の音大の実習でよく出るオペラ 10作（フィガロ・魔笛・ドン・ジョヴァンニ・コジ・カルメン・椿姫・ボエーム・蝶々夫人・ヘンゼルとグレーテル・こうもり）
3 合唱つきの大曲 5作（モーツァルト レクイエム・フォーレ レクイエム・メサイア・第九・カルミナ・ブラーナ）
4 それ以降は、使った人が作った雛形を「自分の雛形」として残し、★運営が確かめて みんなの雛形に上げる
★20作品を急いで揃えるより、5作品を正確に。間違った雛形は、直す手間のほうが大きい
```

## 4. 交響曲・器楽曲の扱い（オペラと違う）

```yaml
交響曲・協奏曲・室内楽には「役」が無い。あるのは 楽章 と 編成
  → 場面＝楽章、枠＝パート（第1ヴァイオリン・ホルン…）として同じ形で扱える
  → 「何人かの枠」（sql/12 の many）がそのまま使える
編成（何人・どの楽器）は Wikidata に入っていることがあるが、抜けが多い
  → 揃い方は movements 止まりにして、人数は公演ごとに入れてもらう
★演奏会形式（ガラ・リサイタル）は、曲を並べるだけ。雛形は「曲目リスト」として使う
```

## 5. 取り込みの作り（Code）

```yaml
- 取り込みは ★本番に直接入れない。まず試しの環境に入れて、数と見た目を確かめてから
- 1回で全部入れない。作曲家ごと・種類ごとに分けて入れる（失敗したときに戻しやすい）
- 同じ作品を2回入れない（外部の id で一意にする）
- 取り込んだ行は「どこから来たか」で見分けられるようにする（あとでまとめて消せる）
- ★利用者が作った雛形は 取り込みで上書きしない
```

## 6. VERIFY

```yaml
- 取り込みのあと、works の件数・揃い方ごとの件数が出る
- 「下書きを作る」に出るのは full の作品だけ
- 同じ外部 id の作品が2つ無い
- 利用者の雛形（is_public=false）が1件も変わっていない
- 台帳の大きさが Free の上限の半分を超えていない
```
