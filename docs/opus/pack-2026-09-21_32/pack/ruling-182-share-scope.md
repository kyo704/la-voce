# RULING 182 — 生徒の共有の範囲は、生徒だけが変えられる

```yaml
ruling: 182
date: 2026-09-23
version: design-v27
from: Opus が本番の 書き込みのポリシーを洗って発見（2026-09-23）
sql: sql/49
```

## 1. 見つけたもの

```yaml
teacher_student_links の UPDATE のポリシー:
  名前は ★「Students can update share scope」（生徒が共有の範囲を変える）
  ところが using は ★（先生 または 生徒）→ 先生も share_scope を書き換えられた
share_scope（jsonb・本番に11行）:
  ★いまは どのポリシーも どの関数も見ていない（0本）＝効いていない列
  ただし ★残っている限り「先生が生徒の共有を決められる」形が 台帳に残る
```

## 2. 決定

```yaml
★A（いま当てる・sql/49）: 書き換えられるのは ★生徒だけ
  先生は つながりを切ること（status・revoked_at）はできる。
  ★ただし share_scope を変えない更新だけ通す
★B（Code の確認のあと）: 画面が share_scope を読んでいないなら ★列ごと消す
  理由: 裁定138 で「shareScope は 権限で隠すのではなく ★列ごと消す」と決めている。
        その決まりを、個人どうしのつながりにも揃える
  Code に確かめてほしいこと: 画面が share_scope を ★読んでいるか／書いているか
```

## 3. なぜ重いか

```yaml
この製品の背骨は ★「先生は生徒の記録を見られない」。
share_scope は「生徒が何を見せるか」の列であり、★先生が触れてよいものではない。
いま効いていなくても、後から この列を読む実装が入れば、★先生が自分の見える範囲を広げられる。
★「効いていないから よい」ではなく、★形として残してはいけない。
```

## 4. VERIFY

```yaml
- 生徒が share_scope を変える → 通る
- ★先生が share_scope を変える → 止まる
- 先生が つながりを切る → 通る（share_scope は変えない）
- 身元（先生・生徒）を変える → LINK_IDENTITY_IMMUTABLE（引き金）
```
