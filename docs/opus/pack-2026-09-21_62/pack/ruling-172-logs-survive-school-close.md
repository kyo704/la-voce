# RULING 172 — 学校を閉じても、記録は消さない

```yaml
ruling: 172
date: 2026-09-23
version: design-v24
from: Sonnet（緊急）。学校を閉じると monka_read_log・org_billing_log・score_log・export_log が連鎖で消える
conflict: 「見た記録は消せません」「求められたら30日以内にお見せします」（仕様シート②③・裁定159）と正面から食い違う
related: 束0（人の退会は SET NULL に直した）── 学校の削除だけ見落としていた
```

## 1. 決定

```yaml
DECISION: Sonnet の推奨を採る。4つの表の org_id を SET NULL にし、そのときの学校名を写す列を足す
対象と理由:
  monka_read_log   : ★必須。学生の「誰がいつ私の門下を開いたか」を、学校が閉じたあとでも答えられるようにする（30日以内の開示の約束）
  score_log        : 必須。点を直した記録。学生の成績に関わる
  org_billing_log  : 必須。お金に関わる変更の記録。請求の争いは学校が閉じた後にも起こりうる
  export_log       : 必須。誰が何を書き出したか。漏えいの調べに使う
対象外（いまのままでよい）:
  org_post_perm_log : もともと外部キーが無い（Code の作り。正しい）
  contract_owner_log: ★これも消える側。同じ直しを足す（お金の責任者の移り変わり）→ ★5つ目として直す
  ops_audit_log     : まだ本番に無い。修正版は最初から外部キーなし
保存の期間:
  学校が閉じたあと（org_id が null になったあと）1年で消す。無期限には持たない
  ★門下を開いた記録だけは、閉校後も3年（開示の求めが遅れて来ることがある）
  → 消す処理は、閉校の日ではなく「行の日付」で数える（閉校の日を持たないため）
```

## 2. 見落としの型（繰り返さないために）

```yaml
束0 では「人が消えるとき」だけを見て、「学校が消えるとき」を見なかった。
消える親は2つある（人・学校）。これからは、記録の表を作る・直すときに 必ず両方で確かめる:
  ☐ その人が退会しても残るか
  ☐ その学校が閉じても残るか
  ☐ どちらでも残すなら、名前（人・学校）をそのとき写しているか
```

## 3. VERIFY（実在の試しの利用者で）

```yaml
- 試しの学校を作り、門下を開く・点を直す・請求の宛名を変える・書き出す → それぞれ記録が1行ずつ
- その学校を閉じる → 4つ（＋contract_owner_log）の行が残り、org_id が null・org_name_at にそのときの名前
- 閉じたあと、学生が自分の「門下を開いた記録」を見る → 残っている（いつ・どの門下）
- 1年より古い行が purge で消える（門下を開いた記録は3年）
```
