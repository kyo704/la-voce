## §1 「前からあった穴」── ★半分だけ正しいです

正確に書きます。

```
パスワードのとき
　　メールを失った          → ★入れます（パスワードがあれば）
　　メールを失った＋忘れた  → ★締め出し

6桁のとき
　　メールを失った          → ★★それだけで締め出し
```

★**同じではありません。6桁は、条件を1つ減らします。**

★だから「前からあった穴だから、6桁でも同じ」は、**成り立ちません。**

```
★「前からあった穴だ」は、穴を広げてよい理由になりません。
```

### ★ただし、運営者の直感には実がある

```
「パスワードを覚えている人が、実際にどれだけいるか」
```

★小さなアプリのパスワードを覚えている人は、多くありません。
　多くの人にとって、**パスワードは実質もう機能していません。**

★つまり ── **構造の上では悪くなる。実際の効果では、あまり変わらない。**
　そして**どちらにしても、直すべきです。**

★結論だけ見れば、運営者の判断は正しいです。**理由づけだけ、直させてください。**

## §2 「復旧」を、2つに分けてください

★ここが、この判断書でいちばん大事な線引きです。

```
① メールアドレスの変更   ★まだ入れるうちに、新しいメールに移す
　　　　　　　　　　　　  ★簡単です。必ず作ってください

② アカウントの復旧       ★入れなくなってから、本人だと名乗り出る
　　　　　　　　　　　　  ★★これは、作らないでください
```

### ★なぜ②を作らないのか

```
②は「★本人確認の窓口」です。
そして本人確認の窓口は、★なりすましの入口でもあります。
```

★「メールを失いました」と言ってきた人が本人かどうか、**アプリには確かめられません。**
　9月4日の決まりです ── **確かめられないことを、しない。**

★そして、この製品が預かっているのは**体調と既往症**です。
　★乗っ取られたときの被害が、いちばん重い種類のデータです。

★さらに ── **9か月、判断する人が国外にいます。**
　★窓口を作って、答える人がいない。**いちばん悪い形です。**

### では、②の代わりに何を置くか

```
★復旧コード（§3）
```

## §3 ★復旧コード ── これが答えです

```
登録したとき、★12桁ほどのコードを1つだけ表示する。

　　　あなたの控え

　　　★ WOOL-3F7A-92KD-1XQP

　　　メールが使えなくなったとき、これで入れます。
　　　★どこかに書き写しておいてください。
　　　この画面を閉じると、二度と表示できません。
```

### なぜこれが正しいのか

```
・★新しい経路が0本      メールも電話も業者も増えません
・★個人データが0件増える  コードは個人情報ではありません
・★本人確認の窓口が要らない  ★コードを持っている人が本人です
・★9か月不在でも動きます  人の判断が要りません
・★実装が半日〜1日
```

★9月3日以降ずっと守ってきた決まりに、**1つも触れません。**

### 決めごと

```
□ サーバには★ハッシュだけ保存する（元のコードを持たない）
□ ★1回使ったら無効。使ったら、その場で新しいコードを出す
□ ★再発行できる（ログインできているうちなら、いつでも）
□ 台帳03（auth参照）に★登録する
□ ★書き出し（台帳04）には含めない
　　→ コードは本人が持っているものです。こちらの控えではありません
```

### ★正直に書く文言

```
　このコードを無くすと、
　メールも使えなくなったときに、★入れなくなります。

　★私たちの側で、元に戻すことはできません。
```

★**これを書いてください。** 書かないと、後で「何とかしてください」が来ます。
　そして、そのとき何ともできません。**先に書いておくのが、いちばん親切です。**

## §4 ★長いセッション ── 賛成。ただし線を2つ

```
◯ 一度入ったら、★自分で出るまで入ったまま
```

★賛成です。理由：**再認証の回数が減れば、メールを失う場面も減ります。**

### ★ただし、線その1 ── 「持ち出す」ときだけ、確かめる

```
★見るだけなら、長く。
★持ち出すときと、消すときだけ、確かめる。
```

```
長いセッションでよい   記録する ／ 見る ／ 装いを変える ／ 予定を入れる
★もう一度確かめる      ・データの書き出し
                       ・アカウントの削除
                       ・メールアドレスの変更
                       ・復旧コードの再発行
```

★盗まれた端末で、**記録を読まれるのは防げません**（端末のロックの話です）。
　でも、**丸ごと持ち出されるのと、消されるのは、防げます。**

★この4つのときだけ、6桁をもう一度送る。**それで足ります。**

### ★線その2 ── 「このデバイスを信頼する」を作らない

```
✕ ［ このデバイスを信頼する ］のチェック
```

★共用の端末で、押されます。押した人は、押したことを覚えていません。
　**既定で長い**にして、**選ばせないでください。**

### ★もう1つ、正直に

```
長いセッションは、★メールを失う問題を解決しません。★先送りにするだけです。
```

```
機種を変えた ／ 端末を初期化した ／ ★iOSが保存を消した
　　→ ★もう一度ログインが要ります
```

★とくに iOS です。9月4日に書いたとおり、**しばらく開かないと保存が消える**仕組みがあります
（★日数は確かめていません）。★「長いセッション」が、iOS では長くない可能性があります。

★だから、**§3 の復旧コードが要ります。** 長いセッションは、その代わりにはなりません。

## §5 ★パスワードとの併存は、反対です

```
（提案）メール＋パスワード ★と 6桁の両方を持つ
（私の答え）★片方にしてください
```

理由。

```
① ★入口が2つになります
　　9月3日の不具合の多くは「2つあること」から来ていました。
　　★これは本当にゲートです。9月4日の「1つなら間違えようがない」が、ここでは効きます

② ★パスワードは、それ自体が守るものです
　　強さの判定・使い回しの危険・保存・再設定の導線。★全部増えます

③ ★パスワードの再設定は、結局メールを使います
　　★メール依存は、1ミリも減りません

④ ★復旧コードがあれば、パスワードにできることは1つもありません
```

### ★ただし、いまパスワードを持っている人からは取り上げないでください

```
新しい人   ★パスワードを作らせない（6桁のみ）
いまの人   ★パスワードを消さない。★そのまま使えるようにしておく
```

★9月4日の決まりです ── **一度あげたものを、取り上げない。**
　パスワードを消すと、**その瞬間に締め出す人が出ます。**

★消すのは、帰国後でよいです。**急がないでください。**

## §7 メールアドレスの変更（①）── 作るもの

```
・ログインできているうちに、新しいメールに移せる
・★新旧の両方に、変更のお知らせを送る
・変更の履歴を残す（★いつ・どのアドレスから・どこへ）
```

### ★「通知メールを作らない」との関係

★9月4日に「通知メールを作らない」と決めました。**これは例外です。**

```
お知らせのメール   ★作らない（催促になります）
安全に関わるメール ★送る（乗っ取りに気づく唯一の手です）
```

★そして、**新しい経路ではありません。** 6桁を送るのに、もうメールを使っています。
　★台帳05（外に出る経路）に、行は増えません。

### 履歴を残す理由

★乗っ取られたとき、**「いつ変えられたか」だけが手がかり**になります。
　★台帳06（起きたことの記録）に、この変更を含めてください。

## §8 まとめ ── 作るもの

```
① メールアドレスの変更（新旧に通知・履歴を残す）      半日〜1日
② ★復旧コード（1回きり・ハッシュ保存・再発行可）      半日〜1日
③ 長いセッション（既定で長く・信頼チェックを作らない） 半日
④ ★4つの操作だけ、もう一度確かめる                   半日
　　書き出し／削除／メール変更／復旧コードの再発行

　　　　　　　　　　　　　　　　　　　　　合計 ★2〜2.5日
```

★6桁の実装（2〜2.5日）と合わせて、**4.5〜5日**です。

### 置き場所

★作業指示 v3 の **第3段⑪（ホーム画面までの導線）と同じ塊**にしてください。
　★ログインと導線は、同じ画面のかたまりです。**別々にやらないでください。**

★そして、**②を落とさないでください。**
　①③④は便利さの話ですが、**②だけが、締め出しを本当に防ぎます。**
