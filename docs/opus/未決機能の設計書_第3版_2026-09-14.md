## 1 二層の整理 ── 全機能の土台

### 1-1 何を守っているか

```
学務の層   名簿・出欠・日程・実技試験の成績
           ★学校からの委託。学校に監督義務と安全管理措置の書面が発生する

健康の層   声・体・眠り・食事・受診の記録
           ★学生本人と当社の直接の契約。学校は委託元ではない
           ★教職員は1件も見られない。そのための画面が存在しない
```

### 1-2 ★この整理を否定しうる3つの事情

法務調査で分かったことです。

| | 事情 | 対応 |
|---|---|---|
| 1 | 学校が費用を負担している | ★400円を運営のみにする（§1-4） |
| 2 | 学校の名簿で招待している | ★招待コード方式（§1-5） |
| 3 | 学校が事実上強制している | ★同意で教室機能を止めない（§1-6） |

### 1-3 ★突合の禁止（ガイドラインQ&A A7-41）

> 委託先は、委託に伴って委託元から提供された個人データを、
> 独自に取得した個人データ又は個人関連情報と本人ごとに突合することはできません

**★守るべきは保管ではなく結合です。**

A7-41 の例は2つとも「照合した結果を**使って**いる」（広告の表示／DMの除外）。
同じ鍵の下に別の表として置くことは、突合ではありません。

```
○ 委託データ同士の結合
  名簿 × 出欠 × 日程 × コマ × 請求 × 行事 × 連絡
  学年別の出席率／先生ごとのコマ数／請求人数／空きコマの重ね合わせ

✕ 層をまたぐ結合
  名簿・出欠・日程 × entries（健康記録）
  ★「3年生の記録率」は結合。禁止
  ★出席率と声の調子を並べることも禁止
```

**★見張りを1本作ります。**

```
entries と org 系の表が、1つのクエリ・関数・ビュー・書き出しに
同時に現れたら失敗する
★表で見る。関数名で見ない
```

これが代償措置です。もし突合の読みが外れても、
★「同じ鍵の下に置いていた」で止まります。「結合していた」にはなりません。

### 1-4 ★学校の400円は運営のみ

```
いま   400円 ＝ しらべる（580円相当）＋ 運営
       ★学校が学生の健康記録機能を買っている外形

これから 400円 ＝ 運営だけ（日程・出欠・名簿・連絡）
       ★個人の有料機能は、学生が自分で買う
       ★学校は健康記録に1円も払っていない
```

- ★値段は下げません。運営だけで400円は市場範囲内（他社は1人200〜800円）
- ★営業資料から「400円の中身」「24%／34%／53%」の節を削除

### 1-5 ★招待コードと一括読み込み

**一括読み込みは残せます。** CSVでも画面入力でも、
★学校が個人データを提供する点は同じです。方法に法的な意味はありません。

**残す条件は4つ。**

```
1 ★層をまたぐ結合の見張りを先に作る
2 ★自動照合をしない
   ✕ 氏名・メールで既存アカウントを自動で探して結び付ける
   ○ 学生が招待コードを入れたとき、★自分で自分の行を選ぶ
3 ★学務の列だけ取り込む。健康に関わる列は1つも受け取らない
4 ★札は meibo だけ（いまは meibo かつ master）
```

★2がいちばん大事です。自動照合は A7-41 の例1そのものです。
本人が選ぶなら、それは本人の行為です。

### 1-6 ★同意画面

```
1 招待コードを入れる
2 名簿から自分の行を選ぶ
3 ★教室の機能が使える ── ここまで同意は不要
4 ★記録を書き始めようとしたとき、1回だけ

   「この記録は、学校には 見えません。
    あなたと Woolsong の あいだのものです。
    学校から お預かりしている 在籍の情報と、
    あなたが 書く 記録が、同じ あなたのものとして
    つながります。それに 同意しますか」

   [ はい ] [ いいえ ]

5 ★「いいえ」でも、教室の機能はそのまま使える
```

- ★「いいえ」で教室機能まで止めると、同意が実質的に強制になります
- ★強制は、二層の整理を否定する事情そのものです

**★この1画面に、同意が2つ入ります。**

| 何 | 根拠 |
|---|---|
| 突合の同意 | ガイドラインQ&A A7-41 ② |
| 要配慮個人情報の取得同意 | 法20条2項 |

要配慮のほうは ★利用目的・取得する項目・取扱方法を示す必要があります。
★同意の記録（日時と文言の版）を残します。

## 2 分析の拡張

### 2-1 何を作るのか（4つ。順番はこの通り）

| | 何 | 置き場所 | 無料/有料 |
|---|---|---|---|
| ① | まだ分からないことを見せる | ふりかえる → くらべる の最上部 | 無料 |
| ② | 自分で問いを立てる | 歯車 → しらべていること | 無料1組／有料5組 |
| ③ | 遅れて効くもの | ふりかえる → くらべる（組の設定内） | 有料 |
| ④ | 本番の前の1週間 | ふりかえる → 本番のふりかえり | 有料 |

★①を最初にやる理由：③で組が増えるほど「まだ言えません」が増えます。受け皿が先。

### 2-2 ① まだ分からないことを見せる

```
くらべる（画面の最上部）

  眠った時間 × 声の調子       10日のうち 7日 たまりました
  夕食から寝るまで × 声の調子  10日のうち 4日 たまりました
```

- ★進んだ側から書く（授かり進捗／Nunes & Drèze 2006）
- ★0日目に埋めて見せない。「登録した日を1日目として数える」までが許される範囲
- 全員に出す。有料の壁の外

### 2-3 ② 自分で問いを立てる

```
歯車 → しらべていること

  組1   [眠った時間      ▼] × [声の調子 ▼]
  ＋足す                          （無料は1組まで）
```

- ★組を作るのは利用者。機械は提案も並べ替えもしない
- 生活側：眠った時間／夕食から寝るまで／食べたもの／お酒／体重／湿度
- 声側：★列名の直し（§6-2）が済んでから確定
- 画面に1文：「たくさん 選ぶほど、はっきり 言えるまでの 日数が 延びます」

**なぜ機械が選ばないのか**

- 固定順序法は「見る前に順番を決める」ことで成立します
- 自己決定理論（Ryan & Deci 2000）。選ぶ行為そのものが続ける力になります

### 2-4 ③ 遅れて効くもの

```
組の設定の中

  いつの声と くらべますか
    ● 同じ日      （無料）
    ○ 翌日        （有料）
    ○ 2日後       （有料）
    ○ 3日後       （有料）
```

- ★欠けた日は組にしない。埋めない
- ★ずらしの本数は k に数える
- 出す文：「〜の 翌日と 一緒に 出ています」
- ★「〜のせいで」「〜が原因で」「検出されています」は書かない

### 2-5 ④ 本番の前の1週間

```
ふりかえる → 本番のふりかえり

  10月11日の 本番
    7日前 ── 1日前 の 眠り・声・夕食の 並び
    （2回目から、前回と 重ねられます）
```

- ★判定しない。並べるだけ
- ★本番の前日・当日は何も出さない。出すのは終わった翌日から
- ★**学生が自分で登録した本番だけ**を使う。`org_events` から日付を引かない
  （層をまたぐ結合になるため。§1-3）

### 2-6 ★門と効果量

```
門（くらべる側）
  各群   n ≥ 10
  効果量 |g| ≥ 0.50
  多重比較 0.50 + 0.12 × (k − 1)
  固定順序法

k の数え方
  k ＝ 宣言した組 × ずらしの本数
  ★期間（1か月／3か月／1年）は k を増やさない。窓であって比較ではない
  ★一度に有効なのは1つの期間だけ。分析の前に確定する
  ★3つ計算して通ったものを出すのは禁止
  ★使っている窓を、実際の日付で表示する

効果量の単位
  ★Hedges' g に統一
  連続量（睡眠・体重・分数・音高）→ g
  2値（有無・フラグ）→ Cohen's h。★g の閾値に入れない
  ★h を較正できなければ、2値は門の対象外。件数表示のみ

読む列
  ★entries.resonance_score（その日の中央値・0〜10）
  ★resonance_score が空の行は除く（逆算値のため）
  ✕ voice_quality（5段の表示用の写し）
  ★n は日数で数える。記録の回数で数えない
```

### 2-7 いまの実装との差

```
くらべる（V2）   n≥10 ／ |g|≥0.50 ／ 生p<0.10 ／ 固定順序法（1番目のみ）
分析タブ（38人） n≥10 ／ |g|≥0.50 ／ BH-FDR ／ ★k段補正なし
```

- ★同じ製品の中で、門が画面ごとに2つ動いています
- 新しい分析は ★くらべる側の門に乗せます
- ★分析タブ側を寄せるのは、①が出たあと。
  いま寄せると38人の画面から文章が消えます。①があれば「進み具合」に変わります

### 2-8 決まっていないこと

| # | 何 | 誰が |
|---|---|---|
| 1 | ★選択項目のうち、どれが2値か | Code報告 → Opus |
| 2 | ★`deltaST` を選択項目にするか | Code報告 → Opus |
| 3 | 列名の直し（§6-2） | 9/15後 |

## 3 ポートフォリオ

### 3-1 何を作るのか

```
ノート → レパートリー → 曲を選ぶ → 「録画を 足す」

  冬の旅 第1曲
    2026年10月11日  千葉文化会館     [YouTube ▸]
    2026年 7月20日  学内演奏会       [YouTube ▸]
```

### 3-2 決まっていること

- ★動画のアップロードをしない。YouTube / Vimeo の限定公開URLを貼るだけ
  - 委託先が増えない。安全管理の書類を書き換えずに済む
  - ★DSA 16条（ホスティングの通知・行動メカニズム）の義務が生じにくい

```
visibility
  private  自分だけ                    ← ★既定
  org      同じ学校の 在籍者だけ
  link     URLを 知っている人だけ
```

- ★`link` は成人のみ
- ★`share_token` の既定は null。`link` に変えたときだけ発行。戻したら破棄
- ★`USING (true)` を書かない

### 3-3 ★守り方（3枚重ね）

```
1 画面   18歳未満には link の選択肢を出さない（無効化ではなく、無い）
2 表     visibility='link' への書き込みをトリガで拒否
3 RPC    公開の瞬間にもう一度確かめる    ← ★ここがいちばん大事
```

- ★年齢の判定は `lib/ageGate.js` を使う。新しい列を作らない
  - `isAdultConfirmed`（明示回答した人だけ true）を見る
  - ★`!isTreatedAsMinor` ではない
- ★`age_band` は別概念。触らない

### 3-4 QR

- ★`link` を選んだときだけ出る
- ★中身はポートフォリオのURLのみ。SNSのQRは置かない
- ★印刷を前提に、白背景・十分な大きさで
- 理由：紙に印刷したらURLは誰も打たない

### 3-5 見た目

```
優雅 ／ まじめ ／ 綺麗 ／ 清ら ／ かっこいい
```

- 5つから選ぶ。★自由に作らせない
- 色は tokens の中から。★新しい色を作らない
- 「かっこいい」は、写真を大きく・文字を少なく（国際的な演奏家のサイト型）
- ★判定の語が名前に入っていない（「おすすめ」「人気」がない）

### 3-6 決まっていないこと

|---|---|

★実質ゼロです。

## 4 伴奏マッチング

### 4-1 考え方

**Woolsong の役割は「相手を見つけて、時間を合わせる」ところまで。**

```
探す            Woolsong
時間を合わせる   Woolsong
学内で会う      Woolsong（日時だけ）
細かい相談      ★外（SNS）
楽譜のやりとり   ★外
```

### 4-2 探す側／選ぶ側に分ける

```
探す側（歌い手）   募集を出す。応募を受ける。1人を選ぶ
選ぶ側（伴奏者）   募集を見る。応募する
```

★片側からしか始まりません。押し売りが構造で止まります。

### 4-3 募集に載せるもの

```
曲名      冬の旅 第1曲
版        ★IMSLP / CPDL / 出版社の URL、または 版の名前を文字で
希望の時期 10月中
回数      3回ほど
```

- ★ファイルを置かない。PDFも音源も。全機能を通じて禁止
- ★楽譜は URL のみ。理由：
  - 保管すると委託先が1社増える（書類4つの書き換え）
  - ★EU DSA 16条の削除受付窓口が要る。窓口を設けない方針と衝突
  - ★ドイツ UrhG 70条は学術版を発行後25年保護。原典版は保護されうる
  - ★IMSLP はカナダ基準（死後50年）。日本は死後70年＋戦時加算
  - ★URLなら、IMSLP 側がその国での可否を表示する。判断が正しい場所で行われる

### 4-4 応募・成立

```
応募する  ★定型のみ。「この日で 応募します」＋ 選んだ日
選ぶ      歌い手が1人選ぶ。★落選者には何も送らない
成立      お互いの status='free' の枠だけが見える
```

- ★自由記述をどこにも作らない
- ★授業（class）は見せない。何の授業を取っているかは要らない情報

### 4-5 成立後に見えるもの

```
名前 ／ 門下 ／ 専攻楽器
```

- ★成立前は名前も出ない
- 専攻楽器が要るのは、チェンバロ・オルガン・ギターが実際にあるため
- ★3つとも学校が既に持っている情報。新しく聞かない

### 4-6 ★学内で会う（全員に出す）

```
成立した相手の画面

  合う 空きコマ
    10月15日（水）3限   9:00-10:30
    10月17日（金）2限  13:00-14:30

  ［この枠で 誘う］
```

- 相手に届くのは ★日時だけ
- 返事は ★「はい」「都合が つかない」の2つ
- 断られたら、別の枠を選び直す画面に戻る

**★場所は決めません（推奨により確定）**

- 学校の場所マスタは★存在しません。作りません
- ★日時だけ決めて、場所は当日に相談してもらう
- 理由：表が1つ増えず、学校の設定作業も増えない。
  同じ学校の中なので、場所は当人どうしで決まる

**歯止め3つ**

| 何 | なぜ |
|---|---|
| ★誘いは3回まで | 断る側が「断り続ける」役をやらされない |
| ★同時に1件だけ | 枠を押さえたまま連発するのを防ぐ |
| ★練習室の予約はしない | 「学生からの予約申し込みは作りません」を守る |

- 成立後も、催促・数え上げ・すっぽかしの記録をしない

### 4-7 外へ移る（SNS ID）

```
種類  Instagram ／ X ／ LINE ／ その他
ID    文字列のみ
```

- ★成立した相手にだけ見える。募集には出ない
- ★お互いが入れていたら、お互いに見える。片方だけは見せない
- 任意。空でも成立する
- ★IDだけ。URLもQRもメールも電話も置かない
- 「その他」は種類の名前も本人が書く（Discord・WeChat など）

```
長さの上限   種類 20文字 ／ ID 50文字
改行        ★禁止（1行だけ）
```

★文章が書ける長さにしません。連絡欄に化けるのを防ぎます。

**変更できる。ただし黙って変えない**

- ★変えたら、成立中の相手の画面に1行：「連絡先が 変わりました」
- ★通知は送らない。次に開いたときに見える

**画面に1文**

```
ここから先は Woolsong の 外です。
やりとりの 内容は、こちらでは 分かりません。
```

★免責の文言ではなく、事実の説明です。

### 4-8 18歳未満

- ★参加できます。文章がなく、共有が日程だけなので
- ★ただし SNS ID の欄は出しません
- ★未成年だけ別の道にしないのは、誰が未成年かが相手に分かってしまうため

### 4-9 通報・退出・寿命

```
通報  ★1タップ。理由を書かせない。相手に知らせない
退出  いつでも片方から。理由を聞かない
寿命  ★90日で自動的に閉じる（連絡と同じ）
```

★文章がなくても危険は残ります。応募の連発、会って嫌な思いをする、外で起きること。

### 4-10 表の作り

- ★全表に `org_id`。学校の中で閉じる
