# §0 この文書の使い方

```
★守る線     数字・タップ数・文言・禁止事項。★変えないでください

```

★「良さそうだから足す」を、この文書に対してはしないでください。

# §2 5画面に共通する決まり（★守る線）

## 2-1 第1層に、グラフを置かない

```
Whoop の第1層　　グラフ 0個
Oura の第1層　　 今日の数字が2〜3個
```

★グラフは第2層（タップして開いた先）に置いてください。
　ホームを開いた瞬間にグラフが出るアプリは、調べた中で高評価のものにありません。

## 2-2 数字は「最新値」と「自分の平均」の2つだけ ── ★Oura Trends 方式

これが今回の調査でいちばん大きい発見です。

```
Oura Trends のグラフに置かれている数字は、たった2つ。
　　★最新の値（大きく）
　　★自分の90日平均（小さく、同じグラフの中に）

スコア化しない。「先週より」と言わない。良い悪いを言わない。
それでも、意味は伝わる。
```

**これは、うちの「予測も評価もしない」という制約に、唯一そのまま合う形です。**
「72点」も「先週より悪化」も出さずに、数字に意味を持たせられます。

★全画面で、この形を使ってください。

```
◯ 睡眠　6時間20分　　（あなたのふだん　6時間45分）
✕ 睡眠スコア 68点
✕ 睡眠　6時間20分　↓ 先週より25分短い
```

## 2-3 文言は「評価語を避けた事実」で書く ── Gentler Streak 方式

```
◯ 「いつもの木曜より、少なめでした」（Below Typical Thursday）
✕ 「今週は運動不足です」
✕ 「よく頑張りました！」　←★ほめるのも評価です
```

★比較対象は**他人でも理想でもなく、その曜日のその人**です。

## 2-4 気づきの文は、1文・全角40〜60字

```
Oura Discoveries の実測　英語48〜81字（＝日本語で全角40〜60字）
主語　　「あなたの◯◯」
動詞　　自動詞、または「〜と一緒に出ています」
```

★2文以上書かない。★「だから、こうしましょう」を付けない。

## 2-5 出せるようになる日数を、先に公表する

Oura は公表しています。

```
週の傾向　　2週間ぶん貯まってから
月の傾向　　1か月ぶん貯まってから
季節の傾向　30日ぶん貯まってから
年の傾向　　60日ぶん貯まってから
```

★業界がいちばん批判されているのは「最初の週はスコアが推測なのに、黙って数字を見せること」です。

うちの数字（★これを画面に出してください）：

```
「あと ◯日ぶん たまると、ここに出せるようになります」
　★進捗バーは出さない（進捗バーは催促です）
　★「◯日たまりました」の言い切りだけ
```

# §3 ホーム

## 3-1 画面の構成（上から順に、★この順番）

```
1  羊　　　　　　　　★いちばん大きい。おうちの中にいて、こちらを見る
2  ひとこと帯　　　　羊のことば1文（本番があれば「あと n日」もここ）
3  今日の数字　2〜3個 ★最新値＋自分のふだん（2-2の形）
4  今日の記録ボタン　★1つだけ。大きく
5  （区切り）
6  このごろ、よく書いていること　　★2項目だけ、並べるだけ
```

★グラフは1つも置きません。
★「今日やるといいこと」は、6に置き換えます（別紙・声の予報の判断を参照）。

## 3-2 開いた瞬間

```
ログイン済み　★自分の羊が出る。ロード中も羊の輪郭は先に出す
未ログイン　　説明は出さない。ログインだけ
```

## 3-3 ★空のとき（記録が0件）

NN/g の空状態3原則（①状態を伝える ②学びの手がかり ③主要タスクへの導線）に沿います。

```
羊　　　「はじめまして。」
帯　　　「まだ、何も書いていません。」　　　　　　　　←①状態
本文　　「書いたことは、あとで、あなたに返ってきます。」←②手がかり
ボタン　「今日のことを、書く」　　　　　　　　　　　←③導線
```

★「はじめよう！」「さっそく記録しましょう！」は使いません（催促です）。

# §4 今日の記録

## 4-1 ★2タップで1件が完成すること ── Daylio 方式

これが今回の調査で2番目に大きい発見です。

```
Daylio　　　 ★2タップで1エントリ完成
　　　　　　 App Store 4.8／61,000件、Google Play 4.7／462,000件、1,000万DL+
Oura　　　　 6ステップ
あすけん　　 7ステップ
```

★**Daylio が、調べた記録系アプリで最高評価です。そして最も書かせません。**

## 4-2 うちの設計

```
タップ1　ホームの「今日の記録」
タップ2　★3つ並んだ大きな絵のどれか（出た／ふつう／出づらい）
　　　　 → ★この時点で保存されます。「完了」を押させない
```

★2タップで**もう終わっている**こと。以降はすべて「足したい人だけ」です。

```
（保存後、同じ画面が続く。閉じてもいい）
＋ 声のこと　　　（選択肢）
＋ からだのこと　（選択肢）
＋ 眠り　　　　　（数値／スライダー）
＋ 今日やったこと（選択肢）
＋ ノート　　　　（自由記述・§7へ）
```

## 4-3 ★聞く項目を、本人に先に選ばせる ── Whoop ジャーナル方式

Whoop は100種類超の項目を持っていますが、**全部は聞きません。**
**毎日聞く質問を、ユーザーが事前に選んでおきます。**

```
設定画面：「毎日、聞いてほしいこと」
　全項目の一覧から、★最大5つまで選ぶ
　選ばなかった項目は、記録画面に出ない（＋から手で開けば使える）
　★いつでも変えられる。変えても過去の記録は消えない
```

★これは、声のプロが職種でバラバラ（声楽家・声優・アナウンサー・落語家・教師）
　という、うちの前提にそのまま効きます。全員に同じ項目を聞く必要がありません。

## 4-4 ★休む日の扱い ── Gentler Streak 方式

```
Gentler Streak には Sick / Injured / On a Break がある。
★これを選んだ日は、記録が「欠けた」ことにならない。
```

うちの実装：

```
記録画面の下に、小さく1つ
　「今日は、書かない」
　→ ★押すと、その日は「書かなかった日」ではなく「休むと決めた日」になる
　→ ★分析の分母から外す。★カレンダーで色を落とさない
```

★Finch（4.9★／748,000件）の思想がこれです：**「スキップしても鳥は死なない」。**

## 4-5 ★禁止

```
✕ 連続日数の表示（決まり：連続記録をやめる・9月1日）
✕ 進捗バー、達成率、％
✕ 「今日はまだ書いていません」という通知
✕ 数値の入力を必須にする
✕ 保存ボタン（★自動保存。§7-4 と同じ）
```

# §5 分析

## 5-1 グラフの形（★Oura Trends 方式・2-2 の再掲）

```
1本のグラフに置く数字は2つだけ
　★最新の値（大）
　★自分の90日平均（小・同じグラフ内に薄い横線＋数字）

　✕ スコア化　✕「先週より」　✕ 良い悪いの色分け（赤を使わない）
```

## 5-2 ★因子の効き方の見せ方 ── Bearable 方式

Bearable の Factor Effect が、この問題のいちばん良い答えを出しています。

```
★期間で切るのではなく、「効果が出るまでの日数」を 0〜7日で切り替えさせる。
　（「昨日の◯◯」が「今日の声」に効いているのか、
　　「3日前の◯◯」が効いているのかを、本人が動かして見る）

★表示は「その因子があった日 上位3件」と「なかった日 上位3件」を並べるだけ。
　★どちらが良い・悪いとは言わない。
```

そして Bearable は**公式に**こう書いています。

> 「結果に対して批判的であることが重要です」

★うちも同じ文を、分析画面の**いちばん上**に置いてください。

```
「ここに出るのは、あなたが書いたことの並びです。
　原因かどうかは、分かりません。疑いながら見てください。」
```

## 5-3 分析画面の構成

```
1  上の注意文（5-2の3行）　★折りたためない。常に出す
2  気づき　最大3つ　　　　 各1文・全角40〜60字（2-4の形）
3  グラフ　1つずつ　　　　 最新値＋90日平均（5-1）
4  因子の効き方　　　　　　遅延日数スライダー0〜7日（5-2）
5  「あと◯日ぶんで、◯◯が出せるようになります」（2-5）
```

## 5-4 ★禁止（実際に起きた失敗から）

```
✕ 総合スコア
　　→ Visible では、スコアが本人の感覚と食い違ったとき
　　　「ガスライティングされた気がした」というユーザー報告が出ています。

✕ AIの長い説明文で生データを覆う
　　→ Google Health（旧Fitbit）のリデザインで、
　　　★利用者の51%が「見た目は良くなったが、使い勝手は悪化した」と回答。
　　　「基本的な指標を見つけるのが、ほぼ不可能なクエストになった」
　　　「AIの冗長な文章が、生のデータを覆い隠している」

✕ 指標を探させる
　　→ Apple ヘルスケアは App Store 3.0★／8,900件。
　　　★プリインストールの標準アプリで3.0★は、異常な低さです。
```

# §6 レッスン

## 6-1 ★骨格は Hevy から取ります

Hevy（4.9★／91,000件・米App Store ヘルス&フィットネス30位）が、
「日付＋やった内容＋メモ」を最小のタップで積む形の完成品です。
**公式が機能ページのタイトルに「Only 2 Taps」と掲げています。**

```
タップ1　レッスンタブ
タップ2　画面★最上部の「レッスンを記録」
　　　　 → ★この時点で記録が始まっている
```

## 6-2 ★前回の値を、最初から入れておく

Hevy は前回の重量とレップ数を自動で埋め、**ユーザーは違うところだけ直します。**
Strong も同じです。

```
レッスンを記録　を押した時点で、すでに入っている：
　先生　　　　★前回と同じ
　レッスン種別★前回と同じ
　日付　　　　★今日
　場所　　　　★前回と同じ

　→ ユーザーがすることは「違うところだけ直して、閉じる」
```

★あるレビューは Hevy を「最初の1セットを90秒以内に記録できる」と計測しています。
　うちの目標は **1件30秒**です。

## 6-3 ★先生が未登録でも記録できること

Studyplus は「教材を本棚に登録しないと1件も記録できない」作りです。
**これがレッスンアプリだと「先生を登録しないと記録できない」に化けます。初回で離脱します。**

```
★先生・種別が空でも保存できる。あとから紐づけられる。
★「先生を登録してください」というブロックを作らない。
```

## 6-4 履歴は3系統（Hevy 準拠）

```
1  時系列のカード一覧　　　★既定。新しい順
2  先生ごとの履歴　　　　　その先生と何回やって、何を扱ったか
3  実施日のカレンダー　　　★空白日を赤や欠損として色づけしない（2-3）
```

## 6-5 ★申し送りを、次回に持ち越す

Hevy への実際の不満：

> 「種目メモが1回のワークアウトで消えて、次回に残らない」

★レッスンアプリでは、これは致命傷です。
　「前回、先生に言われたこと」が次回に出ないなら、記録する意味の半分が消えます。

```
記録の最後に　「次に見てもらいたいこと」　★選択肢から選ぶ（自由記述にしない）
　→ ★次回の記録画面の一番上に、そのまま出る
　→ ★答えなくてもよい。答えなかったら、次回も出さない
```

★**なぜ選択肢か**：TimeTree の実際の不満が
　「過去のコメントや相談を検索できない」です。
　自由記述で書かせておいて検索も構造化もしないと、書いた本人が二度と取り出せません。
　**アプリが読んで返すものに、自由記述を作らない**という決まりの根拠がここにあります。

## 6-6 ★入力項目

```
先生　　　　　選択肢（マスタ＋履歴からの再選択）
日付　　　　　カレンダー
種別　　　　　選択肢（レッスン／リハ／自主練 など）
扱った曲・課題 選択肢＋履歴（★曲名は本人が一度作れば以後は選ぶだけ）
状態タグ　　　選択肢（任意）
次に見てもらいたいこと 選択肢（任意）
──────────
備考　　　　　★自由記述1枠。★アプリは集計も要約も検索もしない
```

## 6-7 ★空のとき

Hevy は新規ユーザーに白紙を見せません。
「経験・目標・器具で絞れるルーティン一覧」か「空から始めて途中で組み立てる」の**2択**を出します。

```
「まだ、レッスンの記録がありません。」
［直近のレッスンを、記録する］　←★主導線・大きく
　先生を登録しておく　　　　　　←★副導線・小さく
```

## 6-8 ★禁止（実例つき）

```
✕ 達成度パーセンテージ
　　→ Studyplus の「今週の目標」達成率。うちの「評価しない」と正面衝突。

✕ 終了画面で自己採点させる
　　→ Modacity は finish 画面で「どうだったか」を rate させます。採用不可。

✕ 連続日数
　　→ Duolingo の実測：ストリーク維持条件を1レッスン（1〜2分）に下げたら
　　　★7日以上続く人が40%超増えた。★条件を緩めるほど続く、という向きです。
　　　うちは連続日数そのものを置きません。
　　　（UX Magazine は confirmshaming と「ストリークが切れた時に課金させる仕組み」を
　　　　「ユーザーの不安の収益化」と断じています）

✕ 表示するなら★減らない数だけ
　　◯ 今月 3回　／　この先生と 通算12回
　　✕ 連続 5日　／　目標達成率 60%
```

## 6-9 ★参考：レッスンの記録が先生に届くこと

島村楽器「音楽日記」（3.6★／8件と極小ですが、一次情報として重い）のレビュー：

> 「先生と練習記録や目標を共有できるのは、レッスンで伝えきれなかった情報が届いて、
> 　講師の指導の参考にもなる」

★この方向は、うちの教室プランでそのまま生きます。
　同レビューの要望は「カレンダー表示がほしい」「入力項目を自動補完してほしい」
　── ★どちらも 6-2 と 6-4 で先に満たしてあります。

# §7 ノート

## 7-1 ★開いてから1文字目までを、最短にする

| アプリ | タップ数 |
|---|---|
| **Drafts** | **0**（起動＝新規ページ＋キーボード表示済み） |
| Google Keep | 1 |
| Apple メモ | 1〜2 |
| Day One | 2 |
| Apple ジャーナル | 2（「白紙」か「提案」かの二択が挟まる） |

★うちは **1タップ**にします。ノートタブ →（新規があれば即カーソル）。

国内の実務者記録（OneTapLog）：
> 「アプリを開く → 今日のページを探す → 日付を確認 → 入力欄をタップ」
> この数秒のあいだに離脱点が生まれる

★ユーザーインタビューには「日記アプリを10個は消してきた」という証言があります。

## 7-2 ★タイトル欄を作らない ── Apple メモ方式

```
Apple メモ公式：「The first line of the note becomes the note's title」
　★1行目が自動的にタイトルになる。タイトル入力欄が存在しない。
```

★一覧にもその1行目をそのまま出します。

## 7-3 ★執筆画面のアイコンは3つまで

```
Apple ジャーナル　キーボード上に 写真／音声／位置 の★3つだけ
Bear　　　　　　　キーボード上のバー1段に集約
Simplenote　　　　画面下端にタグ欄1行のみ
```

うちの3つ：

```
写真　／　音声　／　（今日の記録に、このノートを結びつける）
```

★4つ目を足すときは、どれを外すかを先に決めてください。

## 7-4 ★保存ボタンを作らない

```
Apple メモ公式：「Your note saves automatically as you work」★保存ボタンは存在しない
Simplenote　　：自動同期。明示的な保存操作なし
Bear／Drafts　：同様
Google Keep　 ：「完了」があるが、これはカードUIゆえの例外で、保存ではなく「閉じる」
```

★フルスクリーンの編集画面に保存ボタンを置くと、それだけで古く見えます。

## 7-5 ★構造化フィールドを足さない ── ここに一次文献があります

**Rosenbloom et al., JAMIA 2011;18(2):181-186**
「臨床記録における、構造化と柔軟な記述のあいだの緊張」

> 構造化を強制するのではなく、記述の方法に柔軟性を認めよ。
> 構造化データが必要なら、★事後のテキスト処理で抽出せよ。

**AMA Journal of Ethics 2017**

> 構造化では「用意された枠の外に出る手段がない」。
> 自由記述は★否定・時間表現・ぼかし（negation, temporal expressions, hedging）を扱える。
> 「a few months ago」「more or less resolved」のような言い方が、構造化では落ちる。
> ★EHR情報の約70%は、非構造の自然言語として存在している。

★これが、うちのノート設計の核心的な根拠になります。

```
声のプロが書くことは、こういう文です：

　「高音が引っかかる感じが、先週よりは少しマシ」
　「先生に喉を開けと言われたけど、たぶん舌根の話だと思う」

　★これはまさに hedging と temporal expression の塊で、
　　選択肢では原理的に落ちます。
```

**そして、うちはノートを解析しません。**
解析しないなら、構造化する唯一の見返り（機械可読性）が存在しません。
**Rosenbloom の「柔軟性を認めよ」が、うちには無条件で当てはまります。**

★§6-5 と矛盾しません。
```
アプリが読んで返すもの　　　　→ 選択肢（レッスンの項目、記録の項目）
本人が本人のために書くもの　　→ 自由記述（ノート、備考）
　★境目は「アプリが読むかどうか」です
```

## 7-6 ★プロンプト（書き出しの問い）── 出すが、既定にしない

```
Day One　　　　 プロンプトは500種以上あるが、★「More…」の奥に隔離されている。
　　　　　　　　押して初めて、その問いを冒頭に据えた新規エントリーが立ち上がる。
　　　　　　　　★＝デフォルトではなく「救済策」として設計されている。

★ただし隠しすぎの危険もある：
　第三者レビュー（ChoosingTherapy）は Day One を
　「no journal prompts or guidance about how to journal」と評価している。
　★機能があるのに、レビュアーが気づかなかった。
```

**MindScape 研究（Dartmouth）の前提記述**：
> 汎用プロンプトは有用だが、その広さゆえに内省の質を下げうる

★＝**汎用プロンプトは無害ではありません。**

### うちの結論

```
★空のときにだけ、薄く1つ置く。書き始めたら消える。
★問いは汎用にしない。★その日の記録から作る。

例　今日「出づらい」を選んだ日
　　「どんなふうに、出づらかったですか」

例　今日レッスンがあった日
　　「先生に言われたことで、覚えておきたいことはありますか」

例　何も記録がない日
　　★何も出さない（白紙のまま）
```

## 7-7 ★後から見つけられること

Apple メモの検索は完全一致に依存し、意味的な関係を理解しません。
実例：**「doorbell」で検索すると出るが、「Bell」では何も出ない。**

★日本語は分かち書きがないので、もっと厳しくなります。

```
うちの3本立て：
1  日付から引く　　　★カレンダーから
2  ★その日の記録から引く　←うちだけができること
　　　「出づらいと書いた日のノート」「この先生のレッスンの日のノート」
3  文字で引く　　　　部分一致でよい。★ただし2があるので、これは3番目でいい
```

★2が、メモアプリに勝てる唯一の場所です。**ノートを体調と日付に結びつけて引けること。**
　Apple メモにも Day One にもできません。

## 7-8 ★ノートは、常に任意であること

**Epstein et al., CHI 2016（元トラッカー193名の調査）**
記録をやめた理由の**第1位は、一貫して「記録コスト」**でした。

```
運動トラッキング　　★45.6%
家計トラッキング　　★57.1%
位置情報トラッキング★42.9%
```

証言：「I got behind on keeping up with it and couldn't find the time to start back up.」

★うちは体調記録アプリで、ノートは手入力です。**この45〜57%は、他人事ではありません。**
　**ノート欄が「重い」と感じられた瞬間、ノートだけでなく記録全体が落ちます。**

```
★ノートは、記録画面の「＋」の中。最初から開いていない。
★ノートが空でも、記録は完成している。
★「ノートも書きませんか」と誘わない。
```

## 7-9 ★空のとき

```
「まだ、ノートがありません。」
「ここに書いたことは、あとで、その日の記録から引けます。」
［書く］
```

# §8 やってはいけないこと ── 実例つき

| やってはいけないこと | 実例 |
|---|---|
| **既存レイアウトの作り直し** | Studyplus は2025年4月のUI刷新に対し、運営が**公式に「お詫びとお知らせ」を出し**、その後「デザイン改善 第1弾」で戻した。レビュー分布は肯定35%に対し**不具合・UI/UXの不満54%**、深刻な問題11%。★機能追加より、慣れたレイアウトの変更のほうが強く反発される |
| **AIの説明文で生データを覆う** | Google Health（旧Fitbit）リデザインで**51%が「見た目は良くなったが使い勝手は悪化」**。「基本的な指標を見つけるのがほぼ不可能なクエスト」 |
| **機能を足し続ける** | Day One の13年ユーザー：「far too bloated and feature rich, which I don't need 90% of」。★同ユーザーは**多機能版とは別にシンプル標準版を用意すべき**だと要求している |
| **同上** | Evernote：Trustpilot 3.6／3,454件、うち**1★が26%**。「the application has become far too expensive」「頻繁なUI変更で、constantly have to learn new processes」 |
| **整理の道具にする** | Notion 離脱者の記録：「more than 90% of my Notion pages are just really well organised」──整理は完璧だが成果物がない。30本以上の下書きが未完成のまま。★その人は Day One に移った |
| **計測の経路を1本しか作らない** | Studyplus の不満「タイマーを使わずに合計時間だけを入力できないのが不便」。★うちも「その場で記録」と「あとから入力」の両方を最初から用意する |
| **添付物起点の導線を潰す** | Day One は以前「画像を追加すると EXIF の日時からエントリーを自動生成」できたが、「先に日付を選んでエントリーを作ってから写真を追加」に変更し、**「a step backward」**と批判された |
| **モバイルを後回しにする** | Obsidian のコミュニティ評価「desktop 10、mobile 4」。1,500以上のプラグインのうち**約30%がモバイル非対応**。★うちはPWA。モバイルが本体です |
| **SNS機能を混ぜる** | Studyplus の不満「勉強と無関係な雑談がアプリ内で起きる」。Hevy の不満「デフォルトタブがソーシャル寄りで、自分の履歴が遠い」 |

# §9 実装の順番（★上から）

```
1  §4-2   今日の記録を2タップにする　　　★いちばん効きます
2  §2-2   数字を「最新値＋自分のふだん」に統一（ホーム・分析の両方）
3  §7-4   ノートの保存ボタンを外す／自動保存
4  §7-2   ノートのタイトル欄を外す（1行目がタイトル）
5  §3-1   ホームからグラフを外し、第2層へ
6  §6-1/2 レッスンを2タップ化、前回値の自動投入
7  §4-4   「今日は、書かない」を足す
8  §5-2   分析の上に注意文3行を固定
9  §7-7   ノートを「その日の記録」から引けるようにする　★うちだけの機能
10 §4-3   毎日聞く項目を本人に選ばせる（最大5つ）
11 §5-2   因子の遅延日数スライダー（0〜7日）
12 §2-5   「あと◯日ぶんで出せます」の表示
```

★1〜5 は、どれも**引き算**です。作るものより、外すもののほうが先に効きます。
