## 1. ★5つの問いへの答え

```yaml
Q1 ICS を ISR・CDN から外し、no-store＋ETag にしてよいか:
  ★はい。1人1つのフィードは小さく、転送量は問題にならない
  ★条件: フィードに 体調は1文字も入れない（いままでどおり）／ETag は ★中身から作る（時刻ではない）
    時刻で作ると、中身が同じでも毎回変わり、購読側が「変わった」と誤解します
Q2 「予定の景色」を 組織の階層（裁定98）の実装に含めるか:
  ★いいえ。★別に作る
  理由: 98 は「組織の形」、景色は「時間の並べ方」。別のものです。
    混ぜると ★世界へ出る工事（階層の抽象化）が重くなり、どちらも遅れる
  ★ただし 同じ時期にやる（11〜12月）。景色は 98 の完成を待たずに作れる
Q3 「5人未満は出さない」を 全項目に当てるか:
  ★はい、全項目に当てる
  理由: 記録日数の分布だけ隠しても、★ほかの項目から人が特定できます
    （先生3人の学校で「先生の打刻数」を出せば、誰のことか分かる）
  ★出す数そのものを 5人未満で伏せる。件数が0でも「0」と出さず「―」にする
Q4 P5 を 139 の画面の流用で作ることに異論はあるか:
  ★異論なし。試験に固有なのは ★4点だけ:
    ① 置くものが 10〜15分の枠（レッスンは30〜60分）
    ② ★審査員が自分の門下を審査する枠に「門下」と出す（★自動で断らない・運営が決める）
    ③ ★伴奏者が 別の枠として要る（レッスン割には無い）
    ④ ★確定した順に 採点の画面が並ぶ（二重入力をなくす）
  → ★この4点だけを 139 に足す形にしてください
Q5 「変わったもの」を 直近48時間で 帯の1本目に上げてよいか:
  ★よい。★ただし 帯の優先順に 新しい行を足さない
  Fable の言うとおり「今日のレッスン／行事」の ★中身が変わった扱いにする
  → 裁定の文言を 変える必要はありません（帯は増えない）
  ★条件: 上がるのは ★自分が関わる稽古が変わったときだけ。他人の変更では上がらない
```

## 2. ★1つだけ 直してほしいところ（P2）

```yaml
「予定の景色」に ★個人の公演を入れないでください
  公演には ★学校の公演（org_id あり）と ★個人の公演（org_id なし）があります
  個人の公演は ★学校の層の外です。これを学校の衝突検出に入れると、
  ★学校が「この学生は その時間 別の本番がある」と知ることになります
  → ★景色に入れるのは org_id のある予定だけ（授業・レッスン・学校の行事・学校の公演・部屋）
  ★個人の公演の衝突は、★本人の画面の中だけで見せる
これは 層をまたぐ結合の禁止（その55・その57）の 延長です。
  結合していなくても、★「見える」だけで同じことが起きます
```
