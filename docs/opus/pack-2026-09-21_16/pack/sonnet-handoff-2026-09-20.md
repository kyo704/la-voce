## 1. Sonnet の役割（変更）

```yaml
before:
  中継。Opus と Code のあいだ

after:
  ★タスクの分割と依頼文
  ★台帳の3分類の管理
  ★待ち一覧の解消順
  ★★要約しない。原文を渡す

reason: |
  要約で理由が落ちると、実装で手加減される。
  「24時間は厳しすぎる」と誰かが思う余地が生まれる
```

## 2. 依頼文の型（★必ずこの形）

```yaml
TASK: <1画面 / 1検査 / 1修正。混ぜない>
VERSION: design-v7          # ★必須。版タグ
SCOPE_IN: <やること>
SCOPE_OUT: <やらないこと>   # ★必須。範囲外を書く
EVIDENCE_REQUIRED:          # ★必須。完了の証拠
  - docs/design/compare/<screen>.png
  - <実行するテスト>
REFERENCE: docs/rulings/ruling-NN.md   # @ で読ませる

★1依頼1タスク。まとめて頼まない
ref: Fable F10（文脈窓は最も重要な資源）
```

---

## 3. Code からの報告の型（★これ以外を受け取らない）

```yaml
EVIDENCE:     画像のパス・テストのログ
DIFFS_I_SEE:  自分で見えた差分
NOT_DONE:     残り

★禁止: 「一致」「完了」「問題なし」「対応済み」
reason: |
  2026-09-20、「文言・構造レベルで完了」とした画面に
  17〜92件の差分が出た

★Sonnet がすること:
  型に合わない報告を、★そのまま Opus に回さない
  「EVIDENCE がありません」と Code に返す
```

---

## 4. 台帳の3分類（★Sonnet が管理）

```yaml
差分1件ごとに分ける:
  ㋐ 実装が足りない  → Code へ
  ㋑ 見本が古い      → ★Opus へ
  ㋒ 意図的に違う    → ★台帳に理由を書く

★㋒を放置しない
reason: 書かないと、次の人が同じ差分を見て迷う

★Sonnet が持つもの:
  差分の一覧（画面 / 内容 / 分類 / 状態）
  ★未分類が0件になるまで、次へ進まない
```
