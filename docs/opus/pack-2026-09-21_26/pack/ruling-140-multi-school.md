```yaml
DECISION: 学校を選べるようにする。1校ずつ見る

rejected_C_後回し:
  reason: |
    2校在籍はふつうに起きる（音大と音楽教室、学部と大学院、音大と養成所）。
    いまの挙動は「開くたびに違う学校が出る」。
    どの募集が見えるかが偶然で決まり、L1 の前提を揺らす

FIX_NOW:
  order by enrolled_at asc, org_id asc   # limit(1) に並び順を付ける

RULE:
  1校: 選ぶ場所を出さない
  2校以上:
    さがすの先頭に学校の札 ［○○音楽大学］［△△音楽教室］
    既定: 前回選んだ学校（端末に覚える。台帳には持たない）
    はじめて: 最初に入った学校
  do_not: 複数校の募集を混ぜて1つの一覧にする
    reason: L1 は学校ごとに閉じるという意味。所属が曖昧になる

POSTING:
  2校以上: 出す画面に「○○音楽大学の 方に 出します」と必ず書く
  既定: いま選んでいる学校
  do_not: 1つの募集を2校に同時に出す

SERVER:
  画面から来た org_id を信用しない
  get_postings(p_org_id) は enrollments（active）を確かめる（既存）

CUT_AND_REPORT:
  切る・通報で止まる: 学校をまたいで効く
  reason: 切った理由は人であって、学校ではない

TEST_ACCOUNT:
  +forcode（11校）: 札が11並んでも横にはみ出さない（横にずらせる）

VERIFY:
  Q1: 1校の人に札が出ないこと
  Q2: 開き直しても同じ学校が出ること
  Q3: B校を選んでいるとき、A校の募集が0件
  Q4: 在籍していない org_id で0件
  Q5: A校で切った相手が、B校でも見えない
  Q6: 募集を出す画面に、出す先の学校名が必ず出る
  Q7: 札が11並んでも横にはみ出さない
```
