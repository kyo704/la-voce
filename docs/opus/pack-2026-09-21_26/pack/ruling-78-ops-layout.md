## 1 ★左の ナビは 残します ── 捨てません

### 1-1 調べたこと

★**NN/g（Nielsen Norman Group）**

```
「垂直・左ナビは、★広い／成長する IA に 適合する。
　ただし 水平ナビより 場所を 取る」
　　Page Laubheimer「Left-Side Vertical Navigation on Desktop」2021
　　https://www.nngroup.com/articles/vertical-nav/
```

★34画面を 水平に 並べると ★「極端に 小さい フォント、項目の 密集、
不自然に 短い ラベル」を 招く、と 同じ 記事が 警告しています。

★★**視線の 実測**

```
「Horizontal Attention Leans Left」2017・★120名超・13万超の 視線停留
　→ ★一般の ページで、視線の ★80% が 画面の 左半分に 集まる
　https://www.nngroup.com/articles/horizontal-attention-leans-left/
```

★★★**ただし 欠点も 明記されています。**

```
Nua Bikes の 例：
　垂直ナビ  内容 対 枠 ＝ ★5：1
　水平ナビに 作り替え ＝ ★12：1
```

★★★これが ★坂本さんの ご指摘（210px 問題）です。★実在する 欠点です。

★★NN/g は こうも 書いています。

```
「★非常に 大きい 画面では、垂直ナビの 影響は 無視できる（左右に 余白が 入る）」
```

★→ ★PC（1280px 以上）では 問題に なりません。★★iPad（834px）では 深刻です。

### 1-2 裁定

```
★左の ナビは ★残す
★★ただし ★たためるように する（§2）
```

★理由：★34画面を 横に 並べる 案は、★NN/g が 正面から 警告している 形です。

　★ラベルは 読み上げに 残す（sr-only）

★★Fluent の Auto と 同じ 考えです。★ただし ★**幅では なく 画面で** 決めます。
★理由：★幅が 足りないのは ★表の 画面だけ だからです。

## 5 ★表

### 5-1 入れたもの

```
★見出しの 行を 貼り付ける
★★左の 列（名前）を 貼り付ける ── ★これが「錨」
```

★調べたこと

```
★NN/g「画面より 大きい 表では、★ヘッダー行・ヘッダー列を 固定せよ」
　https://www.nngroup.com/articles/data-tables/

★実務の 定説
　「ユーザーが 最初に 見る 列が 錨（★正しい 行を 見ている 確証）。
　　★名簿なら 氏名。★横に すべって 錨が 流れると 位置を 見失い、
　　★行ごとに 戻って 確かめる 手間が 生じる」

　「スクロールで 列ラベルが 消えると『ラベル なしで 数値を 読む』
　　ことに なり、★似た 数値の 列で 取り違えが 起きる」
```

★★実装は `.tblwrap` に 当てました。★★**運営の 全ての 表に 一度に 効きます。**

### 5-2 ★密度切替は ★入れませんでした

★Carbon は 32 / 40 / 48px の 3段を 持っています。

★★★それでも ★入れません。

```
理由
　★つまみが 2つに なります（★文字4段 ＋ 行の 高さ）
　★★Woolsong は 設定を 増やさない 製品です
　★★★50〜60代の 方には、★1つの つまみで 両方 動くほうが 分かります
```

★代わりに ★**文字の 大きさに 連動**させました。

```css
.tblwrap td,.tblwrap th{ height: calc(40px * var(--z,1)) }
```

★文字を「大きめ」に すると、★行も 高くなります。

## 10 ★判断を 変える しきい値

```
★iPad たて（834px）で、★ナビ展開 ＋ 表が ★常に 横すべりを 強いるなら
　→ ★その 画面を ★強制レール化（★WIDE の 一覧に 足す）

　「★画面幅 − レール幅（68px）」を 超えるなら
　→ ★列固定 ＋ 横すべり 前提の 設計へ

　かつ ★探索に 時間が かかるなら
　→ ★「最近 使った もの」「留めておく」を 足す（★Atlassian の 知見）
```
