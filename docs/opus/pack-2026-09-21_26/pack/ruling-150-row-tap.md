# 裁定その150 — 押せる行は、行全体が1つのボタン

2026-09-21 ／ Opus ／ design-v10
きっかけ：Code 報告「見本は行の中に『なおす ›』ボタン。実機は行全体が押せて『なおす』は表示文字」

```yaml
decision: 実装が正。行全体が1つの押せるもの

finding:
  - 見本も動きは同じだった。<tr class="click" onclick=…> で行全体が押せる
  - 違っていたのは見た目だけ。「なおす ›」が処理を持たないのにボタンの形をしていた
  - 分類は ㋑ 見本が古い。Code が検査に手を加えなかったのは正しい

rule:
  - 押せる行の右端は「なおす ›」「書く ›」などの文字。› が押せるしるし
  - 押せる行の中に、自分の処理を持たないボタンの形を置かない（押せそうで押せないを作らない）
  - 行の中に本物のボタンを置くのは、行を押すのと別の処理のときだけ
    例：自分のコマの「消す」。行の処理を止める（stopPropagation）。見て別のものと分かる形に

reason:
  - 押せる面が大きい。50〜60代・指の太い人・学校の iPad で外しにくい
  - 同じ処理が2か所にあると、読み上げで2回出る。「同じ決めが2か所」を作らない
  - 携帯の一覧（.li の <s>なおす ›</s>）とすでに同じ形。PC の表だけずれていた

sample_fixed:
  file: 00-動く見本-PC・iPad（運営）.html
  where: 授業の型（P_presets・stJugyo）2か所
  change: <span class="btn g sm">なおす ›</span> → <span class="usu">なおす ›</span>

code:
  - 実装はそのまま
  - 台帳の差分は ㋑ として解消に
  - 同じ形（押せる行の中の、処理のないボタンの形）を見つけたら DIFFS_I_SEE に。まとめて直さない
