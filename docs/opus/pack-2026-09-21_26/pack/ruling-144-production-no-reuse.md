# RULING 144 — 公演を 使い回せない 仕組み

```yaml
ruling: 144
date: 2026-09-21
extends: 裁定その143（公演の料金）
from: 坂本さんの指摘（題名と期間を変えて、1回の支払いで使い回せてしまう）
```

```yaml
WHY_NOT_LOCK_TITLE:
  題名を変えられないようにしても効かない
  reason: 誤字・邦題の変更は正当。同じ題名で別の公演もある

RULE:
  1_期限を固定:
    払った時点で「使える期限」を決める = 本番の最後の日＋30日
    ★あとで本番の日・題名を変えても、期限は自動では延びない
  2_延期は1回:
    1回だけ、90日まで延ばせる。無料。理由は聞かない
    2回目は無い。次は新しく作る
  3_期限を過ぎたら読むだけ（運営の側）:
    できない: 新しい稽古を置く／招く／配役を変える／公演の情報を直す
    できる: 読む／香盤表・出欠を PDF で書き出す
  4_出演者の記録は残る: 期限に関係なく本人のもの（取り上げない）
  5_無料（15人まで）も同じ: 期限が来たら読むだけ。次の公演はまた無料で作れる
     reason: 公演は「始まりと終わり」があるもの。教室の代わりに使わせない
  6_学校の教室プランの中の公演: 0円。同じく期限あり（数は制限しない）

SERVER:
  ★期限は台帳で確かめる。画面だけで止めない
  productions.paid_until（date）
  書き込み（稽古・呼び出し・配役・招く）の関数で now() <= paid_until を確かめる
  延期: productions.extended_at（null なら未使用）。2回目は関数で弾く
  ★paid_until を画面から直せないこと（update の権限を渡さない）

REFUND（裁定その143 と合わせる）:
  月割りの「残り」は paid_until までで数える
  延期で延びた分は返金の対象にしない（無料で延ばしたため）

MOCK（2026-09-21）:
  公演の運営 →「公演の 情報・使える 期限」
  公演の情報: 題名・本番の日は直せる／期限は変わらないと書く／延ばす（1回・たずねる）
  期限が過ぎたら: 公演の運営・稽古を組む・招く・配役に「読むだけ」の帯。操作の札が消える
  ★ブラウザで確かめた（延ばす → 2回目は出ない／過ぎたら3画面とも操作が消える。エラー0）

VERIFY:
  Q1: 本番の日を後ろへ動かしても paid_until が変わらない
  Q2: 延期は1回だけ。2回目は台帳で弾かれる
  Q3: 期限後、関数を直接呼んでも稽古・招く・配役が1件も書けない
  Q4: 期限後も PDF の書き出しはできる
  Q5: 期限後も、出演者の記録・本番の履歴が1件も消えない
  Q6: paid_until を画面・API から直せない
```
