## §2 そして Deci & Ryan も、私は読み違えていました

原典を取りました。**Deci, Koestner & Ryan (1999)『Psychological Bulletin』128研究のメタ分析**（自由選択行動の測度101研究、自己報告84研究）。

| 報酬の種類 | 自由選択行動 d | 自己報告の興味 d |
|---|---|---|
| すべての報酬 | −0.24 | 0.04（有意でない） |
| **言語的報酬（褒め言葉）** | **+0.33** | **+0.31** |
| 有形の報酬（全体） | −0.34 | −0.07 |
| **予期される有形報酬・従事に随伴** | **−0.40** | −0.15 |
| 予期される有形報酬・完了に随伴 | −0.36 | −0.17 |
| 予期される有形報酬・出来ばえに随伴 | −0.28 | ─ |
| **★予期しない有形報酬** | **+0.01**（影響なし） | **+0.05**（影響なし） |

そして著者はこう明記しています。

> 一次のメタ分析には、**対象の課題の興味の値が少なくとも中立以上である**研究・条件だけを含めた

### ★これが意味すること

> **もともと興味がある活動ほど、アンダーマイニングは起きる。**
> 私は今日「記録の動機はもともと内発的だから、ポイントの心配は小さい」と書きました。**逆です。**

### ★さらに、私の今日の提案も弱い

私は「原資を**項目数**から**日数**に変える」と提案しました。メタ分析の区分に当てると：

```
項目数で貯まる = 従事に随伴（engagement-contingent）  d = −0.40
日数で貯まる   = 完了に随伴（completion-contingent）  d = −0.36
```

**−0.40 が −0.36 になるだけです。ほとんど何も変わりません。**

### ★では、何が答えか

表の中で、ただ一つ影響がなかったものがあります。**予期しない報酬（d = +0.01）**。

```
悪い形：「あと13ポイントで服が買えます」と数字を見せる
　　　　→ 予期される・従事に随伴。最も強く損なう（−0.40）

良い形：予告しない。ある日、羊のところに服が届いている。
　　　　数字も、あと何日も、見せない
　　　　→ 予期しない（0.01）。損なわない
```

★これは「羊は一生しあわせに生きている」とも合います。羊は、こちらの努力の対価として服を着るのではない。ただ季節が来たから、新しいものを着ている。

### ★そして、続けさせる力は、どこから取るか

正直に書きます。**予告しない報酬には、続けさせる力がありません。** 続けさせる報酬と、内発的動機は、両立しません。これは価値の選択です。

このアプリで続ける理由は、報酬ではなく **記録が溜まること自体** であるべきだと思います。

```
「あと13ポイント」ではなく
「出なかった日が、あと4日たまると、くらべられます」
```

これは報酬ではなく **事実の提示** です。しかも坂本さんの目的（原因を見つける）と完全に一致しています。

## §4 時間差の関連 ── ★ここで私は、事実を書き換えました

今日の仕様書に、私はこう書きました。

> 9 症状の連鎖 → **n=7で確率14%と出していたのが誤りであって**、時間差を見るという発想自体は正しい

**これは、私が9月7日の朝に書いた削除リストと違います。** 朝のリストにはこう書いてありました。

```
9 症状の連鎖の確率14%（★n≥10でも消す）
```

**★私は「n≥10でも消す」と書いていました。** それを今日「n=7だったのが誤り」と言い換えた。**朝の自分の指示を、書き換えています。**

朝に「n≥10でも消す」と書いた理由は、Ferrari & Russell 2010（健常者が症状を毎日記録すると想起頻度 1.3→2.6日、強度 3.1→5.1、対照群は変化なし）です。**症状の連鎖を提示すること自体が、症状への注意を増やす**、という懸念でした。

**この懸念は、今も消えていません。**

### では、どう解くか

私が今日書いた区別が、そのまま効くかもしれません。ただし**これは私の推測で、実証はありません**。

```
アプリが告げる ： 「違和感の翌日に、喉の張り感が出やすいようです」
　　　　　　　 → 注意を、症状のほうへ向ける。Ferrari & Russell の懸念に当たる

本人が探しに行く： 「くらべる」を開いて、自分で並びを見る
　　　　　　　 → 注意は「原因」のほうへ向く。症状は、原因を探す材料
```

**★この区別が本当に効くかどうかを示した研究を、私は持っていません。** 出どころは「推測」です。仕様書 §9 の一覧に、この行を足してください。

## §5 体重の推移 ── ★理由が成り立っていません

今日の私の理由：

> このアプリの出発点そのものが体重です。しかも坂本さんの用途は減量ではなく**増量**

**これは坂本さん一人の理由であって、アプリの理由になっていません。** 利用者には減量したい人もいます。「作った人が増量したいから、全員に体重を見せる」は通りません。

**★正しい理由は、別にあります。**

```
体重は、逆流にも、発声にも関わる。
そして数日で動いたときは、脂肪ではなく体液が動いている（Verdolini 2002：
体重が1%減った状態で、発声閾値圧が約23%上昇。n=4）。

つまり体重は「見せる指標」ではなく「原因を探すための一本の列」である。
記録しなければ、原因の候補から永久に抜け落ちる。
```

**この理由なら、増量の人にも減量の人にも成り立ちます。**

そして、この理由から出てくる設計は、今日私が書いたものと**同じ**です（判定しない・目標を提案しない・BMIも標準帯も出さない・体重だけのグラフにしない）。

★結論は変わりませんが、**理由が変わると、次に迷ったときの答えが変わります。** 「坂本さんが増量したいから」を理由にしていると、次に「減量したい利用者が来たらどうする」で崩れます。「原因の列だから」なら崩れません。
