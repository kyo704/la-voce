## 2. CORRECTIONS（Fable 案から直すもの）

```yaml
C1_連絡は消えない:
  fable: 公演の連絡は「90日で消える」
  correct: 90日で「画面から外れる」。台帳からは消さない
  ref: 裁定その77（HIDE_AFTER_DAYS）
  reason: ハラスメントの調査は、公演が終わってから表面化する

C2_配布物の既読を数えない:
  fable: 既読は数だけ運営に
  correct: 数も出さない。出すのは「配った日」だけ
  ref: 裁定その87（既読を作らない・未読も数えない）
  reason: 数は、見た人・見ていない人を探す圧になる

C3_「ご相談」を置かない:
  fable: 120人超は「ご相談」
  correct: 決まった値段を置く（300人まで 100,000円）
  reason: 窓口を設けない方針と衝突する

C4_子どもの出演者:
  fable: 記載なし（学生公演・合唱・子役がありうる）
  correct:
    15〜17歳: 保護者の同意（裁定その107）を通す
    15歳未満: 入れない（裁定その107）
    note: 子役・少年少女合唱は対象外になる。公演側の画面に明記する

C5_時期:
  fable: P1 を 2027-04〜06
  correct: P1 は 2027-07〜
  reason: |
    2027-04〜06 は 学校向けの開始・ホームページ PHASE_2・R2〜R4 と重なる。
    設計が実装を追い越している。これ以上、同じ時期に積まない
```

## 3. ANSWERS（Fable の6問）

```yaml

Q5_対象: 最初はオペラと合唱。ミュージカル・演劇はことばの出し分けで後から

  do_not: 源泉徴収の計算・決済
```

## 4. KEEP（Fable 案のまま）

```yaml
- 制作側は出演者の体調を見られない（結合の見張りを公演の表にも）
- DM を作らない。連絡は一方向
- 楽譜を配らない
- チケット・座席・予約・自動配置を作らない
- 公演が終わっても、出演者の記録は本人に残る
- 本番日は出演者の個人アプリに source='org' で入り、本人は日時を変えられない
- 本番の3日前〜翌々日、個人の分析は静かになる（公演の予定表は静かにしない）
```
