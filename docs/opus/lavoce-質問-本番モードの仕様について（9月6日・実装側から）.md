## ① 表の名前 ── ★これがいちばん大事です

**すでに `events` という表があります。まったく別のものです。**

```
いまの events   … 行動ログ。どの画面を開いたか、保存できたか、
                   どこで諦めたか。★健康の値は入れません。
                   出どころ：計測とユーザー調査仕様.md §3
本番モードの表  … 本番の日と種類。★人の予定そのものです。
```

**混ぜると、法的な重さが変わります。**

`lib/events.js` は、健康の値が入ってきたら**実行時に弾く**作りになっています。

```js
const health = Object.keys(props).filter((k) => HEALTH_PROP_KEYS.includes(k));
if (health.length > 0) {
  return { ok: false,
    problems: health.map((k) => `健康の値「${k}」は行動ログに入れられません`) };
}
```

ファイルの冒頭には、こう書かれています。

> ★行動ログと健康データは、まったく別のものです。
> 健康の値そのものを持たなければ、要配慮個人情報にあたりません。
> ★この境界を守るのは、このファイルの責任です。
> 「便利だから」と props に値を入れたくなりますが、入れた瞬間に
> 行動ログ全体の法的な重さが変わります。実行時に弾きます。

**この境界は、名前が同じだと守れません。**

★お願い：**別の名前をお決めください。**
　（実装からの案：`performances`／`stage_dates`）

★★「本番に出たかどうか」は、★声を使う方にとって、体調と地続きの情報です。
　★行動ログの側に置くべきものではない、と考えています。

## ② D+1 の答えは、取り消せますか

D+1 に「出た／出なかった／途中まで」を1つ押していただきます。

**誤って押したとき、直せますか。**

```
案あ　直せる（あとから押し直せる）
案い　直せない（1回だけ）
```

★実装の側からは、**案あ**を推します。
　この企画には「★書いたものを取り上げない」という決まりがあります。
　★押し間違いを直せないのは、その決まりと、向きが合いません。

★ただし「出なかった」を選んだ方に、★あとで押し直させる導線を
　目立たせるのは、酷かもしれません。**そこは仕様でお決めください。**

## ③ 「あと n日」の帯は、いつ消えますか

本番の日を過ぎたあと、帯をいつ引っこめるかです。

```
案あ　D+1 の質問に答えたら消える
案い　日付を過ぎたら、すぐ消える
案う　D+1 まで出して、答えても答えなくても、D+2 で消える
```

★案いだと、★D+1 の質問を出す場所がなくなります。
★案あだと、★答えない方の画面に、帯が残り続けます。

**答えない自由を残したいので、実装からは案うを推します。**
　★ただし、これは「催促しないこと」の決まりに関わるので、
　★お決めいただきたいところです。

---

## ④ 本番の日は、1つだけですか

```
案あ　1つだけ（次の本番）
案い　複数を同時に持てる
```

★声を使うお仕事なので、**連日ということもあり得ます**
　（本番が3日続く、リハと本番が別の日にある、など）。

★1つだけにすると、**2つ目を入れた瞬間に1つ目が消えます。**
　★これも「取り上げない」に触れます。

★実装からは**案い**を推しますが、
　★帯に何を出すか（いちばん近い1つだけか、複数か）が決まりません。
　**そこまで含めて、お決めください。**
