# 判断 ── ボタン1つで、ホーム画面に置けるか

全 220 行 / 末尾は「iOSは自動化できません。だから入口を、QRに変えます。」

作成 2026年9月4日 ／ 「ボタンで自動アプリ化できないか」への回答

---

## §0 結論

```
Android   ★できます。ボタン1つ ＋ OSの確認1回。それが上限です
iOS       ★できません。★APIが存在しません

　　　　　★これは私の知識不足ではなく、Apple が塞いでいます
```

**そのかわり、iOS でいちばん効く手が1つ見つかりました。§4 です。**

## §1 Android ── できます

```js
// 形だけ示します
let deferred = null
window.addEventListener('beforeinstallprompt', e => {
  e.preventDefault()
  deferred = e            // ★保留しておく
})

// 「ホーム画面に置く」ボタンを押したとき
if (deferred) { deferred.prompt() }
```

```
利用者の操作   ボタンを1回 ＋ OSの確認を1回
```

★完全に無言では置けません。OS が必ず確認を出します。**それが上限です。**
そして、それで十分短いです。

★`beforeinstallprompt` が来ない端末では、**ボタンを出さないでください。**
押せないボタンを見せないこと。

## §2 iOS ── できません

```
beforeinstallprompt          ★Safari は対応していません
プログラムから置くAPI        ★ありません
navigator.share() で出せるか  ★出せません
```

`navigator.share()` が開くのは「その URL を共有するシート」です。
**「ホーム画面に追加」は Safari 自身の項目**であって、共有される内容の項目ではありません。
だから、あのシートには出てきません。

利用者は、**共有ボタン → 一覧を下にたどる →「ホーム画面に追加」→ 追加**をするしかありません。

### iOS 26 で変わったこと（★こちらに有利です）

```
（以前）manifest などの設定が正しくないと、ブックマークとして開く
（iOS 26）★ホーム画面に追加したサイトは、既定でアプリとして開く
```

**追加したあとの挙動は、確実になりました。**
ただし、**追加する操作そのものは、何も変わっていません。**

---

## §3 抜け道が1つありますが、★使わないでください

構成プロファイル（`.mobileconfig` の Web Clip）というものがあります。
技術的には、ファイルを配ってホーム画面にアイコンを作れます。

★却下します。理由は4つ。

```
① iOS 12.2 以降、★設定アプリで手で入れる必要があります
   「ダウンロード → 設定 → プロファイルがダウンロードされました
    → インストール → パスコード → 警告を承諾 → インストール」
   ★共有シートの3タップより、長いです

② ★「このプロファイルはデバイスを管理する可能性があります」と警告が出ます
   体調を預かるアプリで、これを出させてはいけません

③ 署名していないと、警告がさらに強くなります。署名には証明書が要ります

④ ★1つも良いことがありません
```

**短くするための手が、長くて怖いなら、それは手ではありません。**

## §4 ★かわりに ── いちばん効く手が、これです

自動化はできません。**でも、入口を変えれば大きく縮みます。**

### 問題 ── LINE で URL を送ると、追加できません

```
坂本さんが LINE で URL を送る
　　↓
利用者は★LINE の中のブラウザで開きます
　　↓
★そこからは「ホーム画面に追加」ができません
```

アプリの中のブラウザ（LINE・Instagram・X など）は、Safari ではありません。
**共有シートに「ホーム画面に追加」が出ません。**
Android でも同じで、**`beforeinstallprompt` が来ません。**

★**営業でいちばん使う経路が、いちばん詰まっています。**

### 手その1 ── ★QRコードにする（対面）

```
QR をカメラで読む → ★Safari が開く → LINE を経由しない
```

★対面の営業なら、**リンクを送らず QR を見せてください。** これが最短です。
名刺の裏、チラシ、iPad の画面。**それだけで、いちばん大きい詰まりが消えます。**

### 手その2 ── アプリ内ブラウザを見つけて、案内する

送るしかない場合のために、検知して1行出します。

```
　　　この画面のままでは、ホーム画面に置けません。

　　　右下の　⋯　を押して、
　　　「Safariで開く」を選んでください。

　　　　　［ URL をコピー ］
```

★「Safariで開く」の場所は LINE の版で変わります。
**スクショを撮って、それを出してください。**

### ★1分で確かめてください

```
□ 自分の LINE に URL を送って、自分で開く
□ 共有ボタンを押して、「ホーム画面に追加」が★あるかどうか見る
```

**これは実機でしか分かりません。Sonnet にはできません。**
私は「無いはず」と書きましたが、**確かめていません。**

## §5 では、どこまで短くできるか

```
（いちばん短い）
　QR を読む → Safari が開く → 共有 → ホーム画面に追加 → 追加
　　★利用者の操作 4回

（LINE から・案内あり）
　リンク → LINE内 → ⋯ → Safariで開く → 共有 → 追加 → 追加
　　★利用者の操作 6回

（Android・QR）
　QR を読む → ［ホーム画面に置く］ → 確認
　　★利用者の操作 2回
```

★**iOS の4回が、いまの世界の下限です。** これより短くはできません。

だから、残っている仕事は2つだけです。

```
① ★4回を、迷わず4回にする（実物のスクショ・矢印・アイコンの絵）
② ★6回にならないようにする（QR を使う・アプリ内ブラウザを案内する）
```

## §6 足すもの（設計への追加）

先の仕様（9月4日）に、3つ足してください。

```
① ★QRコードを作る                          対面営業の標準の入口にする
② ★アプリ内ブラウザの検知と、案内の1行      LINE・Instagram・X
③ ★案内を、短い動画（またはGIF）にする      静止画3枚より速く伝わります
                                             ★坂本さんの iPhone で撮ってください
```

★③は、②の「Safariで開く」の案内にも要ります。合わせて2本撮ってください。
