# 段3a ── 見本の側で分かること（Opus が先に分けたもの）

2026-09-23 ／ Opus ／ design-v23。道具 `tools/route_map.py`（`tools/経路一覧.md`）から

## 1. Code への渡し方

```yaml
道具: python3 tools/route_map.py            → tools/経路一覧.md（全画面の 入口 › 押す文字 › 引数・前提）
     python3 tools/route_map.py 画面名      → その画面の道すじだけ
使い方: 「比べられない」とした画面は、まずこの一覧で道すじを引く。
  それでも開けないときだけ、下の分類（㋐㋑㋒）を見て、どれかを選んで報告する
分類:
  ㋐ 実装が足りない（見本にあり、実装に無い）      → 作る
  ㋑ 見本が古い（実装のほうが新しい・正しい）      → 見本を直す（Opus）
  ㋒ 意図的に違う（どちらも正しい。理由がある）    → 台帳に1行書いて終わり
```

## 2. 入口が見つからない8画面（Opus の分類・見本の側から）

| 画面 | 見本での姿 | Opus の見立て | Code がすること |
|---|---|---|---|
| こまったこと（スマホ） | さがすの「こまったことが ありました」（通報）。引数に相手の名前が要る | ㋐ 実装が足りない見込み。さがすの相手の画面から開く | さがすの相手の画面に入口があるか確かめる |
| ページをたしかめる（スマホ） | ページの型 → 仕上がりを見る画面。`PF_WEB` を使う | ㋐ ポートフォリオ実装時に作る（今回の sql/11 の後） | 実装時に作る |
| 整える（スマホ） | 「ページをたしかめる」の中から開く（色・書体・節の順） | ㋐ 同上 | 同上 |
| 学科を決める（スマホ） | 行事を出す → 対象を決める → 学科の一覧（`mstEdit`） | ㋒ 実装は運営（PC）側の設定にある見込み | 実装の場所を確かめて台帳に1行 |
| 本番の予定（スマホ） | 本番モードの中から開く（日・会場・集合） | ㋐ 公演の実装（sql/12）と一緒に | 公演の実装時に |
| 自動の条件（スマホ・PC） | 行事を出す → 自動の条件（`AUTO`）。PC は `P_autoSet` として一覧に載っている | ㋑ 見本の入口が細い（道具が辿れないだけ）。PC は実在 | PC で「行事を出す → 自動の条件」を開けるか確かめる。開ければ㋒ |
| 授業の型（PC） | 設定の「授業」の節の中に直接出している（別画面に移らない） | ㋒ 意図的に違う（実装は別画面） | 台帳に1行 |

## 3. 残り18画面（Code が「比べられない」とした分）の進め方

```yaml
Opus からの前提:
  - 見本は 127画面（スマホ）・51画面（運営）。道具で入口が出ない画面は 上の8つだけ
  - つまり「比べられない」理由の多くは、★前提の状態（誰で・どの札で・どのデータで開くか）
  - 経路一覧の「前提」の欄に、その画面を開く直前の onclick の中身（S.… の値）をそのまま出している
Code がすること（1画面ずつ）:
  1 経路一覧で道すじと前提を見る
  2 その前提を試しの環境で作って開く
  3 それでも違う → ㋐㋑㋒ のどれかを選んで、1行で報告（Opus が㋑なら見本を直す）
★報告の形: 画面名 / 分類 / 根拠（画像か、台帳の行）／直す人
```
