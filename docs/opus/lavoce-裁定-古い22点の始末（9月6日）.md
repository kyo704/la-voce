# 判断4 ── ★「いずれなくなります」とは、言いません

## ★言う必要が、無くなるからです

判断3で食器2点を作ると、こうなります。

```
22点ぜんぶに、代わりがある
　→ 全員に代わりを配る
　→ 身につけている方は、付け替える
　→ そのあとで、絵の分岐を消す
　→ ★このとき、★誰も、何も失っていません
　　　（記録は残る／代わりは手元にある／身につけたまま）
```

**無くなるものが無いので、「無くなります」は正確ではありません。**

## ★正確な言い方は、これです

```
✕ 「これまでのものは、いずれなくなります」　←　★不安にさせるだけで、事実でもない
✕ 何も言わずに絵を差し替える　　　　　　　←　★驚かせる
◯ ★「描き直しました」
```

★実際そうです。**同じ品を、新しい絵柄で描き直しています。**
　消えるのは絵柄であって、品ではありません。

## ★お知らせの文（案・差し替え）

```
着せかえが、新しくなりました。

これまでお持ちの帽子・服・持ちものは、
新しい絵で描き直して、そのままお持ちの扱いにしてあります。
身につけていたものは、そのまま身につけたままです。

★絵柄が変わります。★前の絵に戻すことはできません。
```

★最後の一行は、**入れてください。** 聞かれてから答えるのでは、遅いです。
　★「なくなります」と違って、これは**もう終わったことの説明**なので、
　　人を待たせません。不安が続きません。

★★そして、**22点ぜんぶをお持ちの1人**について。
　★その方は、いちばん熱心なお客さまです（ためしに全部買っておられる）。
　★その方の画面には、1行だけ足してください。

```
「22点ぜんぶ、引き継いであります。」
```

# 判断5 ── ★承諾。SQLに3つ足してください

照会そのものは、よくできています。**読むだけ・氏名なし・頭8文字だけ。**

## ★足す1 ── ③のクエリが、新しい品も拾います

```sql
-- ✕ いまの③
where character_equipped->>'hat' is not null ...
　　→ ★新しい217点を身につけている方も、全員ここに出ます。
　　　 ★「古い品を身につけている方」が分かりません。
```

```sql
-- ◯ 直したもの

  left(id::text, 8) || '…'        as "方",
  character_equipped->>'hat'       as "帽子",
  character_equipped->>'outfit'    as "服",
  character_equipped->>'accessory' as "持ちもの"
from public.profiles
where character_equipped->>'hat'       = any($1)   -- ★22点の配列
   or character_equipped->>'outfit'    = any($1)
   or character_equipped->>'accessory' = any($1);
```

## ★足す3 ── ★いつ手に入れられたか

```sql

       item_key as "品",
       created_at as "手に入れた日"
from public.character_inventory
where item_key = any($1)

```
