## 1. 組織的安全管理措置（7項目）

| # | 項目 | 内容 |
|---|---|---|
| 1-1 | 取扱いの体制 | 運営は1名（坂本 響）。個人データを扱えるのはこの1名のみ。代行・外注はしない |
| 1-2 | 責任者 | 同上（個人情報の取扱責任者を兼ねる） |
| 1-3 | 取扱いの記録 | 学校の管理の操作（名簿・役職・招待・請求・レッスン割）は台帳が自動で記録する。記録は90日保存。変わった列の名前のみで、値は残さない |
| 1-4 | 台帳を変える手続き | 本番のデータベースの変更は移行ファイル（apply_migration）のみ。手作業の変更を禁止。権限に関わる変更は、影響の一覧と確かめ方を書面にし、運営者の承認を得てから適用する |
| 1-5 | 漏えい等が起きたときの対応 | ①止める ②範囲を数える ③本人と学校に知らせる ④個人情報保護委員会へ報告（速報3〜5日・確報30日以内）。★連絡の様式は 1-6 で用意 |
| 1-6 | 報告・連絡の道 | 台帳の失敗は自動で記録し、運営者のメールへ通知（同じ種類は1時間に1通）。毎朝7時に前日分のまとめを送る（0件なら送らない） |
| 1-8 | ★障害時の連絡の約束 | 一次報告：発生から12時間以内（止まっていること・調べていること。原因は書かない）／経過報告：1日1回（直っていなくても伝える）／復旧の報告：直り次第すぐ（いつから・いつまで・何が使えなかったか）／原因と再発防止の報告：10営業日以内。★年間の稼働率は保証しない。代わりに、止まったことを隠さず公開する |
| 1-7 | 点検 | 毎日：台帳の目録の変化を機械で確認（権限・ポリシー・関数）。配布前：release_check 一式。年1回：この文書の見直し |

## 2. 人的安全管理措置（4項目）

| # | 項目 | 内容 |
|---|---|---|
| 2-1 | 従業者の教育 | 従業者なし（運営1名）。第三者に個人データを取り扱わせない |
| 2-2 | 秘密保持 | 業務委託先とは契約により秘密保持を定める（現在の委託先は §5） |
| 2-3 | 認証 | 運営者のアカウントはすべて多要素認証（データベースは2026-09-22 設定済み。★配信・コード・決済・メールは 5-1） |
| 2-4 | 端末 | 業務に使う端末は運営者のもののみ。画面ロックと暗号化を有効にする |

## 3. 物理的安全管理措置（5項目）

| # | 項目 | 内容 |
|---|---|---|
| 3-1 | 保管場所 | 自社サーバを持たない。データは委託先の設備（日本・東京リージョン）に保管 |
| 3-2 | 入退室管理 | 委託先（クラウド事業者）の管理による |
| 3-3 | 持ち運び | 個人データを端末に保存しない。書き出したファイルは作業後に削除する |
| 3-4 | 書類 | 紙で個人データを保管しない |
| 3-5 | 機器の廃棄 | 端末の廃棄時は暗号化消去を行う |

## 4. 技術的安全管理措置（12項目）

| # | 項目 | 内容 |
|---|---|---|
| 4-1 | アクセス制御 | すべての表（104表）で行単位のアクセス制御（RLS）を有効にする。画面の出し分けではなく、データベースの層で遮断する |
| 4-2 | 権限の設計 | 役職ごとの「できること」で制御する。役職に無い権限は渡せない（権限の持ち上げが起きない設計） |
| 4-3 | 先生・学校からの遮断 | 健康の記録（entries）は本人のみ。先生・学校・運営の画面からたどり着く経路を設けない。記録を読める特別な関数は2本のみで、いずれも利用者の画面からは呼べない |
| 4-4 | 認証 | メールとパスワード。パスワードは委託先の認証基盤で保管（当方は平文を持たない） |
| 4-5 | 保存時の暗号化 | AES-256（委託先の設備による） |
| 4-6 | 通信の暗号化 | TLS |
| 4-7 | 合言葉・招待 | 招待コードは総当たりを防ぐ回数制限つき。失敗時に理由を返さない |
| 4-8 | 記録の改ざん防止 | 記録の表は更新・削除の権限を与えない。書き込みは台帳の引き金と専用の関数のみ |
| 4-9 | バックアップ | ★毎日1回、構造とデータを書き出し、データベースとは別の場所に暗号化して保管する。復旧の手順書を用意し、年1回以上の復旧訓練を行う |
| 4-10 | 復旧の目標 | 移行の誤りは10分以内、表単位の復旧は30分以内、全体の復旧は半日以内を目標とする（訓練で実測し記録する） |
| 4-11 | 不正アクセスの検知 | 委託先の提供する記録を用いる。台帳側では、権限や関数の変化を毎日機械で照合する |
| 4-12 | 脆弱性への対応 | 依存する部品の更新を定期的に適用する。委託先からの通知に従う |

## 4b. 漏えい等が起きたときの報告（法律の義務。約束ではない）

| 相手 | 期限 | 根拠 |
|---|---|---|
| 個人情報保護委員会（速報） | 気づいてから3〜5日以内 | 個人情報保護法26条・規則8条 |
| 個人情報保護委員会（確報） | 30日以内（不正アクセスなど故意によるものは60日以内） | 同上 |
| ご本人 | 速やかに（内容が定まり次第） | 個人情報保護法26条2項 |
| 委託元の学校 | 速やかに（学校から預かったデータのとき） | 委託契約 |

★1-8 の「12時間以内」は、止まったことの連絡。漏えいの報告は上の期限による（混ぜない）
