## 1. 正直な評価

```yaml
結論: 5つとも「作り終えて、試しで証明し、本番には隠して置く（利用者には見せない）」までなら、届く見込みがある。
  5つとも「本番で利用者が使える・安全を証明し終えた」までは、27日では届かない。とくに公演の子ども（裁定147）は、急ぐと危ない

理由:
  - 量: 作業の目安（Code の1日を1として）── 安全の束 9・値段 5・段3a 5・レッスン割 5・ポートフォリオ 4・ホームページ 4・公演 14（うち子ども・保護者・緊急の連絡先 4）＝ 約46日ぶん
    Code は並べて進められるので、書く量そのものは27日に収まりうる
  - ★詰まる所は「書く」ではなく「確かめる」と「承認」:
    - 権限を変えるたびに 権限変更の型 → 坂本さんの承認（新しい5機能で表が約20・ポリシー約60 → 承認は30回を超える見込み）
    - 今日1日だけで、すでにある機能から穴が10件以上見つかった。新しい機能を急いで作れば、同じ割合で穴が入る
    - 試しの環境が本番と違う（FX7）うちは、新しい機能の証明ができない → 第1週はここが先
  - 子ども（147）・緊急の連絡先・保護者: 未成年の情報。「約束と実装の乖離」（裁定159）を最初から作らない設計（裁定167 C）が要り、急ぐと一番事故になる
  - 坂本さんの時間: 10/11 の本番の週は判断を入れられない。承認が詰まる

提案（坂本さんの決定を守りつつ、事故を避ける形）:
  A ★「完成」の定義を2段にする
     作り終える＝画面と台帳ができ、試しで証明し、本番に「隠して」置く（機能の切り替えで利用者には見えない）
     公開する＝販売開始のときに切り替えを入れる（そのときに最後の点検）
     → 5つとも出発の前に「作り終える」。公開は販売の予定のまま
  B 公演は2つに分ける
     公演の本体（第1群：オペラ・合唱。表・稽古・変わったもの・当日・雛形）＝出発の前に作り終える
     子ども・保護者・緊急の連絡先（147）＝出発の前は「設計と台帳だけ」。画面と公開は出発の後（見張りつき）
  C 順番は裁定170 のまま「安全が先」。新しい機能は、試しの作り直し（FX7）が済んでから台帳を作る
```
