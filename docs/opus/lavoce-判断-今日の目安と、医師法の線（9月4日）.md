# 判断 ── 「今日の目安」と、医師法の線

全 426 行 / 末尾は「医学の一般論として書くと線に近づく。歌い手の慣行として書くと、線から離れる。」

作成 2026年9月4日 ／ 「今日の目安」「本番からの逆算」設計v0への回答

---

## §0 結論

```
1  医師法の線        設計v0は越えていません。ただし守っているのは
                     「一般論の形式」ではなく、別のものです（§1〜§2）
                     カードごとの注記は  ★要りません（むしろ有害）

2  症状ゲート        条件つきで可。★助言を足す方向ではなく、
                     ★引く方向にだけ動かしてください

3  本番日の登録      ★個人の登録が正。org_events からは「取り込む」

4  無料/有料         平常時カード＝無料 ／ 本番モード＝有料
                     ★症状ゲートは無料側に置いてください

5  弁護士との順番    ★設計・実装は進めてよい。売り出しの前に確認。
                     ★弁護士より先に使える制度があります（§8）
```

まず言っておきます。**この設計は良いです。**
「初日から価値を返すもの」という問いに、正面から答えが返ってきました。
本番日を登録した瞬間に価値が出る、というのは、私が探していた形そのものです。

## §1 線はどこにあるか

法律は2本あります。混ぜないでください。

### 医師法17条

医行為とは「医師が行うのでなければ保健衛生上危害を生ずるおそれのある行為」です。
そして**最高裁（令和2年9月16日）**が、これに条件を1つ足しました。

```
医療及び保健指導に属する行為であること（医療関連性）
```

つまり、危険そうに見えても、**そもそも医療の話でなければ医行為ではありません。**
入れ墨の判決です。技芸は技芸だ、という判断でした。

そして、行政の整理はこうです。

```
医行為にあたる     利用者の具体的な情報に基づいて、病状について判断を示す
医行為にあたらない 統計データとの単純な比較にとどまる
                   一般的な情報提供にとどまる
```

### 薬機法（プログラム医療機器の該当性）

こちらのほうが、実は近いです。厚労省のガイドラインは2点で判断します。

```
① 疾病の診断・治療等に、どの程度寄与するのか
② 不具合が起きたとき、生命・健康にどう影響するか
```

該当しない例として挙がっているもの。

```
・個人の健康記録を保存、管理、表示するプログラム
・統計情報の提供、統計情報と入力値との比較のみ
・自らの記録の表示、保管、転送のためだけのプログラム
```

★ただし、ガイドラインには**次の一文があります。**

```
「書籍などに記載の統計学的な計算式により疾病リスクなどを判定するものは
  単なる電子化ではない」
```

**ACWR は統計学的な計算式です。** ここが唯一の危ないところです。
危なくなるのは、その結果を「**疾病リスクの判定**」として見せたときです。

だから、v0 の書き方が効いています。

```
✕ 「危険域です」「けがのリスクが高い状態です」
◯ 「きのうまでの7日間、声の使用はふだんの◯割です」
```

後者は**自分の過去との比較**です。疾病の判定ではありません。
これは v0 のいちばん良いところなので、**この形を固定してください。**

## §2 最強の一手 ── 「医学の一般論」ではなく「歌い手の慣行」として書く

ここが本丸への回答です。

いま v0 は「一般論の形式」で守ろうとしています。
それも効きますが、**もっと強い守り方があります。**

```
医療関連性のない話は、そもそも医行為ではない。
```

「本番3日前は積み上げるより確かめる時期」「前日は通し1回まで」
「当日朝は体から始める」──**これは医学ではありません。技芸です。**

だから、こう書いてください。

```
✕ 「一般に、本番前は声帯の負担を減らすことが推奨されます」
◯ 「本番の3日前からは、新しく積み上げるより確かめる、
     という進め方をする歌い手がいます」
```

前者は医学の話に見えます。後者は**稽古の話**です。
同じ内容でも、置き場所が違います。

この書き分けを、全文言に通してください。

```
体・病気の言葉で書くと    → 医療の話になり、線に近づく
声・稽古の言葉で書くと    → 技芸の話になり、線から離れる
```

「消化のよい食事」も、「胃腸に負担をかけない」ではなく
「本番前はこう食べる人が多い」と書けば、稽古の話のままです。

## §3 裁定① ── 注記は、カードごとに要りません

```
カードごとの小さな注記   ★置かないでください
```

理由は3つ。

```
① 毎回出る注記は読まれません（催促禁止と同じ理屈）
② 注記が多いほど「これは医療的なものだ」という印象が強まります。逆効果です
③ 守っているのは注記ではなく、★文そのものが判断を含まないことです
```

代わりに、3つ置いてください。

```
・本番モードを初めて開いたとき、一度だけの説明
・「学ぶ」画面に、常設の1ページ「この目安について」
・各カードの下に、★1行の静かなリンク（「この目安について」）
```

注記ではなくリンクです。読みたい人だけが読みます。

そして、**第7条の免責文を画面に貼らないでください。**
規約は規約として残します。画面には画面の言葉を置きます。
規約の文をそのまま画面に出すと、それ自体が「医療的なもの」の合図になります。

## §4 裁定② ── 症状ゲートは、引く方向にだけ動かす

ご指摘のとおり、ここがいちばん危ういです。
そして危ういのは「トーン」ではありません。**反応の向き**です。

```
✕ 症状を見て、助言を★足す      →「◯◯があるので、控えめに」＝個別の判断
◯ 症状を見て、助言を★引く      → 目安を短くする、または出さない
```

**足すほうは判断です。引くほうは判断ではありません。**
黙ることは、誰の病状についても何も述べていません。

具体的には、こうしてください。

```
ふだんの日   事実の行 ＋ 目安の文（2〜3行）
記録がある日 事実の行 ＋ 「無理のない範囲で。」だけ
```

目安の文が消えるだけです。理由も、原因も、病名も言いません。

守ってほしい条件は4つ。

```
① 症状の名前を、アプリが新しく付けない
   利用者が選んだ語を、そのまま返すだけ（「今日の記録に、のどの乾きがあります」）
② 原因を言わない（「〜のせいで」を作らない）
③ 病名・疾患名を1つも出さない
④ 「歌うな」「休め」と言わない。これは既に守られています
```

### 受診の導線について

1つだけ、**常設で**置いてください。

```
「気になる状態が続くときは、耳鼻咽喉科（音声外来）に相談する人が多いです」
```

★症状で出し分けないでください。**いつも同じ場所に、いつもある**形にします。
出し分けると、それ自体が「あなたは受診が必要だ」という判断になります。

例外を1つだけ認めます。**日数の提示**です。

```
「同じ記録が14日続いています」
```

これは記録の数え上げであって、病状の判断ではありません。
原因も、病名も、緊急性も付けないこと。**そして一度だけ出すこと**（催促禁止）。

## §5 使わない語

`lib/linkConsent.js` の禁止語と同じ仕組みで、目安の文言にも禁止語を置いてください。

```
危険   リスク   異常   判定   診断   障害   疾患
予防   改善     治る    悪化   症状   安全
```

★とくに「リスク」と「予防」です。
この2語が入った瞬間、薬機法の①「疾病の診断・治療等への寄与」に近づきます。

そして、**売り文句にも同じ禁止語を通してください。**
ここが見落とされます。

```
プログラムが医療機器かどうかは、★何を目的として標榜しているかも見られます。
```

アプリの中で慎重に書いても、**販売ページに「声のトラブルを防ぐ」と書いたら、
そちらが効きます。** 営業ツールの文言にも、同じ禁止語を通してください。

## §6 裁定③ ── 本番日は、個人の登録が正

```
正      個人の本番登録（personal）
従      org_events の kind「本番」からの★取り込み
```

理由は3つ。

```
① 利用者の大半は、教室に属していません。教室に依存させると、
   ★売り物が教室機能に縛られます
② org_event_participants は先生から見えない設計です（9/4 §4）。
   ここに乗せると、見え方の設計が2重になります
③ 課金の中核を、いちばん複雑な機能の上に建てないこと
```

取り込みの形は、**#34 のレッスン取り込みと同じ**にしてください。
自動で入れず、利用者が「取り込む」を押す。断ったことは先生に見えない。
同じ形を2つ作らないでください。

なお、本番日そのものは体調の情報ではありません。
ただし「本番日 ＋ 体調」は個人を絞り込みます。分析に回すときは k-anonymity の側で見てください。

## §7 裁定④ ── 無料と有料の切り方

```
無料   平常時カード（事実の行「ふだんの◯割です」）
       ★症状ゲート
       受診の導線

有料   本番モード（本番日の登録と、段階別の逆算）
```

### なぜ平常時カードは無料か

これは**自分の記録の要約**です。記録の見返しの一部です。
ここを有料にすると、最初の1週間に「記録する意味」がなくなります。

### なぜ本番モードは有料か

3つそろっています。

```
① 本番がある人＝払う人（プロ・セミプロ・受験生）
② ★本番日を登録した瞬間に価値が出る＝初日に返せる
③ 「数か月使わないと使えない」問題を、完全に回避します
```

9月4日に「売るのは助言」と決めました。**その実体が、これです。**
探していたものが出てきました。

### 課金の導線

いちばん良い場所は、**本番日を登録した瞬間**です。

```
「本番まで、あと18日です。」
「その日から逆算した目安を、日ごとに出せます。」
```

その日に価値が生まれるので、その日に聞けます。

### ★症状ゲートを有料の壁の向こうに置かないこと

これは裁定です。理由は2つ。

```
① 静かにする方向の文言に、金を取らない
② 「金を払わない人には黙っている」形を、絶対に作らない
```

安全に寄る側の挙動は、常に無料側です。ここは動かさないでください。

## §8 裁定⑤ ── 進めてよい。ただし、弁護士より先に使える制度があります

```
設計・実装   ★進めてよいです
売り出し     ★その前に確認してください
```

そして、確認の相手は弁護士だけではありません。

### グレーゾーン解消制度

産業競争力強化法にもとづく制度です。事業者が
「この事業は◯◯法に当たりますか」と**所管省庁に直接照会**して、
**書面で回答**をもらえます。

```
費用    無料
期間    標準1か月
強さ    ★所管省庁自身の回答です。弁護士の意見書より強い
```

医療・ヘルスケア分野の回答事例は多数公表されています。
「健康アプリが医行為に当たるか」は、まさにこの制度がよく使われる論点です。

**注意が2つ。**

```
① 回答は、★照会文に書いたことにしか効きません。
   照会文を作るのが仕事の8割です
② ★公表されます。事業の内容が世に出ます
   → だから、★商標の出願を先にしてください
```

### 順番

```
今週      先行商標の調査 → 出願
9月中     照会文を作る（Opus が下書きできます）→ グレーゾーン解消制度に提出
10月中    回答（イタリア出発 10/19 に間に合います）
その前後  弁護士（回答を持って行くと、短く・安く済みます）
```

★ただし、この制度を使わない選択もあります。手間はそれなりです。
使わない場合は、弁護士への相談項目に「グレーゾーン解消制度に出すべきか」を1行足してください。

**どちらにしても、実装は今日から進めてよいです。**
確認が必要なのは「売ること」であって「作ること」ではありません。

## §9 もう1つ ── 由来のタグを持たせてください

これは私からの追加です。

いま文言は「運営者の実践知の一般化」です。それは強みです。
ただし、**一人の歌手の経験を「一般論です」と書くと、それは一般論ではありません。**

文言のデータに、出どころのタグを持たせてください。

```
source: "practice"     歌い手の慣行（運営者の実践知）
source: "literature"   文献にあるもの
source: "calculation"  記録からの計算（ACWR など）
```

画面に出さなくてよいです。**データとして持つ**だけです。

効くのは3か所。

```
① グレーゾーンの照会文に、そのまま使えます
② 弁護士に「これは何に基づくか」と聞かれたとき、答えられます
③ ★「歌い手の慣行」と書くための根拠になります（§2）
```

そして `practice` のものは、§2 のとおり
「〜という進め方をする歌い手がいます」の形で書いてください。
匿名の「一般論」より誠実で、しかも法的に安全です。

## §10 まとめ

```
① 全文言を「稽古の言葉」に置き換える（体・病気の言葉を使わない）
② カードごとの注記をやめ、1行のリンクに変える
③ 症状ゲートは「引く」だけ。名前を付けない、原因を言わない
④ 受診の導線は常設。症状で出し分けない
⑤ 禁止語を置く。★販売ページにも同じ禁止語を通す
⑥ 本番日は個人登録が正。org_events からは取り込み（#34と同じ形）
⑦ 平常時＝無料 ／ 本番モード＝有料 ／ ★症状ゲートは無料
⑧ 文言に source タグを持たせる
⑨ 実装は進める。売る前に、商標出願 → グレーゾーン照会 → 弁護士
```

最後に。この設計で私がいちばん安心したのは、

```
「歌わずにできる練習」を出していることです。
```

「歌うな」と言わずに、歌わない選択肢を渡している。
禁止せずに、別の道を置いている。**これは法律の話ではなく、良い設計です。**
