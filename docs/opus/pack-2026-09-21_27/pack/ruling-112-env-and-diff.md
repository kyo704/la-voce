## 2. DETAIL_SCREEN_COMPARISON（要求1）

```yaml
problem:
  一覧経由の20画面（役職の中身・その人の詳細など）は、
  一覧から押さないと辿り着けない。
  DOM を取るには、まず一覧を出し、行を押す必要がある

---

METHOD: 見本側と実装側で、取り方を分ける

mihon_side:
  ★見本は静的HTML。関数を直接呼べる
  手順:
    1: ブラウザで見本を開く
    2: コンソールで SC['役職の中身'](0) を呼ぶ
    3: 返ってきた文字列が、その画面のHTML
    4: ★引数を変えれば、別のデータの姿も取れる
  ★遷移の必要がない

  一括で取る:
    Object.keys(SC).forEach(k => {
      try { out[k] = SC[k](0) } catch(e) { out[k] = 'ERR:'+e.message }
    })
  ★引数が要る画面は 0 を渡す。ダメなら 1, -1 も試す

implementation_side:
  ★React。遷移が要る
  手順:
    1: Playwright で test 環境にログイン
    2: 一覧の画面へ
    3: ★1行目を押す
    4: document.body.innerHTML を取る
    5: 戻る
  ★行が0件だと押せない → テストデータが要る

---

TEST_DATA: 最小限で足りる

  ★各一覧に 1行あれば足りる
  reason: |
    比べるのは「構造」であって「件数」ではない。
    216人分は要らない

  要るもの:
    名簿:      学生 1人
    役職:      ひな型10役職（★既にある）
    門下:      学生 1人が所属
    日程:      レッスン 1件
    連絡:      お知らせ 1件
    行事:      行事 1件
    採点:      評価の型 1つ ＋ 点 1件
    請求:      org_billing 1行

  ★test 環境に seed として1本のSQLで入れる
  ★毎回作り直せる形にする（冪等に）

---

COMPARE_TARGET: 段階を守る（裁定その111）

  段階1: 題（h2 / .h3 / .sh3）だけ
  段階2: 注記（.note / .usu / .warn）だけ
  段階3: 札（.btn / .pill）のラベルだけ
  ★段階4: 入力欄（label / placeholder）

  ★いきなり全要素を比べない
  ref: 9月20日、全要素で92件の差分が出て何も分からなかった

---

ARGUMENT_MAPPING: 見本の引数と、実装のデータを対応させる

  問題: 見本 SC['その人'](3) の 3 は MEI[3]
        実装は user_id
  解決:
    ★見本の1件目（index 0）と、実装の1行目を比べる
    ★中身（名前・学年）は違ってよい
    ★比べるのは「どんな節があるか」「何と書いてあるか」

  ★do_not: データの中身を比べる
  reason: 見本は作りもの。一致するはずがない

---

OUTPUT_FORMAT: 差分1件ごとに3分類（裁定その111）

  ㋐ 実装が足りない  → 実装を直す
  ㋑ 見本が古い      → 見本を直す（Opus）
  ㋒ 意図的に違う    → ★台帳に理由を書く

  ★㋒を放置しない
```
