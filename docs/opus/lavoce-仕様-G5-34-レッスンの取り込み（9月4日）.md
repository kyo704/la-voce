# 仕様 ── G5 #34 レッスンの取り込み

## §0 ★着手の前に、1つだけ確かめてください

```
★レッスンの時間は、entries の★どの列に足すのですか
```

★指示には「発話時間」とあります。**しかし、私が知っている中核5項目には、
　こういう列があります。**

```
offStageVoiceMinutes  ★「舞台の外で声を使った時間」＝ 話し声
```

★レッスンは、**歌っている時間**です。話し声ではありません。

```
（危険）レッスンの60分を offStageVoiceMinutes に足す
　　　　→ ★話し声の項目に、歌唱の時間が入ります
　　　　→ 中核5項目の1つが汚れます
　　　　→ ★分析の結果が変わります。そして誰も気づきません
```

★**確かめてから始めてください。**

```
確認1  レッスンの時間を足す先の列名（実装のとおりに）
確認2  その列の定義（何を数える列か）
確認3  ★歌唱の時間を入れる列が、そもそも存在するか
```

★確認3が「無い」なら、**この機能は列の新設から始まります。**
　そして新しい列は、7つの台帳への登録が要ります。

★私はこの列を確認していません。**以下の仕様では `<対象列>` と書きます。**

## §1 4点への回答

### ①プロンプトの置き場所 ── ★衝突なし。そのとおりです

```
ホーム／今日の記録に、静かなカード1枚
プッシュ通知なし、バッジなし
```

★羊のおうち仕様の禁止事項（「通知で急かす」）と整合します。
　**そのまま採用してください。**

★1つだけ足します。

```
★カードは、★1日1枚まで
　　レッスンが2件あった日でも、カードは1枚
　　中で2件を並べる
```

★理由：カードが積み上がると、それ自体が催促になります。

### ②断りの扱い ── ★衝突なし。むしろ、これがいちばん良い判断です

```
同じレッスンについて、二度と促さない
断ったことを★記録する
　　★「断った」と「答えていない」を、区別できるようにする
```

★**「空欄は『考えなかった』と読まれます」**── 今日の規則そのものです。

★ただし、1つ分けてください。

```
★「促さない」と「できなくする」は、別です

促さない    ★はい。カードは二度と出しません
できなくする ★いいえ。レッスンの詳細から、あとで取り込めます
```

★理由：**押し間違いは起きます。**取り返せる道を、静かに1つ残してください。

### ③取り込んだ値の印 ── ★条件つきで採用。1つ、罠があります

```
「レッスンから」の小さなタグを付ける
本人の通常の書き込み経路を通す（★entriesへの第2の道を作らない）
```

★後半は完全に正しいです。**第2の道を作らないでください。**
　（今日ずっと見てきた「経路が2つあると、片方だけ塞がる」の形です）

★罠は前半です。

```
★取り込んだあとに、本人が値を編集したら、タグはどうなりますか
```

```
（誤）タグが残る  → ★タグが嘘をつきます
（正）★編集された時点で、タグを外す
```

★推奨する持ち方

```
entries に、★対象列ごとの出所を1つだけ持たせる
　　例：<対象列>_source   'self' | 'lesson'
　　★本人が編集したら、必ず 'self' に戻す

★出所は、値と同じ行に置いてください（別テーブルにしない）
　　→ 値と出所がずれることが、原理的になくなります
```

★新しい列なので、**7つの台帳に登録してください。**
　そして★分析のコードが、この列を無視することを確認してください。

### ④先生側の記録 ── ★採用。ただし列が足りません

```
開始／終了のタップではなく、終了時に「実施した・何分」を1回
```

★正しいです。**開始／終了は、終了の押し忘れを必ず生みます。**

★衝突

```
lessons が持っている列（私の把握）
　　id / link_id / scheduled_at / duration_minutes / note
　　created_by / created_at / org_id / teacher_id / student_id

　　★duration_minutes は「予定の長さ」です
　　★「実際に何分だったか」を入れる列が、ありません
　　★「実施したかどうか」を入れる列も、ありません
　　　（status 列は存在しません。★9月1日に確認済みです）
```

★必要な追加

```
lessons.held_at         timestamptz  ★実施を記録した日時（nullなら未記録）
lessons.actual_minutes  int          ★実際の長さ
```

★`duration_minutes` を上書きしないでください。

```
予定と実際は、別のものです
　　→ 予定を上書きすると、★「予定より長引いた」が見えなくなります
```

## §2 データの形

### 2.1 取り込みの記録 ★追記のみ

```
lesson_imports
　　id            uuid
　　owner_id      uuid   ★生徒本人（RLSはこれで絞る）
　　lesson_id     uuid
　　action        text   ★'imported' | 'declined'
　　minutes       int    ★imported のときの値（あとで編集されても、ここは動かない）
　　occurred_at   timestamptz
　　created_at    timestamptz
```

★**行を書き換えないでください。**断ったあとに取り込んだ場合は、行を足します。

```
declined → imported   ★2行。これが履歴です
```

★これで②の「断った／答えていない」が区別できます。

```
行がある、action='declined'   ★断った
行がある、action='imported'   ★取り込んだ
★行が1つも無い                ★答えていない
```

### 2.2 権限

```
lesson_imports
　　SELECT  自分の行だけ（owner_id = auth.uid()）
　　INSERT  自分の行だけ（WITH CHECK: owner_id = auth.uid()
　　　　　　★かつ、その lesson の student_id が自分であること）
　　UPDATE  ★ポリシーを作らない ＋ 権限を落とす
　　DELETE  ★同上（ユーザー削除のときだけ、削除処理から消える）
```

★**先生は、この表に一切触れません。**これが #34 の核心です。

## §3 画面と流れ

```
1  先生が、レッスンの終了後に「実施した・◯分」を押す
　　　→ lessons.held_at と actual_minutes が入る
　　　→ ★生徒の entries には、何も起きません

2  生徒が次にアプリを開いたとき、ホームにカードが1枚

　　　┌──────────────────────────────┐
　　　│ きのうのレッスン                 │
　　　│ 9月3日（水）14:00 ／ 60分        │
　　　│                                  │
　　　│ 声を使った時間に、足しますか？   │
　　　│                                  │
　　　│   ［足す］      ［足さない］     │
　　　└──────────────────────────────┘

3  ［足す］  → 通常の書き込み経路で <対象列> に加算
　　　　　　　→ <対象列>_source = 'lesson'
　　　　　　　→ lesson_imports に 'imported' を1行

　　［足さない］→ lesson_imports に 'declined' を1行
　　　　　　　　→ ★カードは二度と出ません
　　　　　　　　→ ★レッスンの詳細からは、あとで取り込めます

4  何も押さない → ★何も起きません。カードは残ります
　　　　　　　　  ★ただし、★14日たったら消えます（§4-6）
```

★文言について

```
（×）「レッスンの時間を記録しましょう」  ← 催促です
（○）「声を使った時間に、足しますか？」  ← 質問です
（×）「まだ記録していません」            ← ★「まだ」は禁止語です
```

## §4 端の場合 ── 決めておくこと

```
1  同じ日にレッスンが2件      ★カードは1枚。中に2件を並べる。個別に足せる
2  先生が実施を取り消した     ★取り込み済みなら、生徒に通知しない。値も戻さない
　　　　　　　　　　　　　　  　（★本人が入れた値を、先生の操作で戻さない）
3  先生が分数を後から直した   ★取り込み済みなら、反映しない。カードも出し直さない
4  生徒がその日を記録していない ★カードは出す。［足す］でその日の記録を作る
5  生徒が既に手で入れている   ★カードは出す。★加算する（置き換えない）
6  ★古いレッスン              ★14日より古いカードは出さない
7  生徒が同意を撤回している   ★★カードを出さない（entriesへの書き込みが止まっているため）
8  生徒が教室を離れた         ★離れる前のレッスンのカードは、出さない
9  先生が実施を記録しない     ★何も起きない。生徒には何も見えない
10 取り込んだあと本人が編集   ★_source を 'self' に戻す。lesson_imports は動かさない
```

★7と10が、いちばん間違えやすいところです。

## §5 やらないこと ★明示

```
★先生の操作で、生徒の entries に書き込まない
★プッシュ通知・バッジ・赤い印を出さない
★「まだ」「あと◯件」を書かない
★取り込みを既定にしない（押さなければ何も起きない）
★取り込まなかったことを、先生に見せない
　　　→ 生徒が断ったことは、★先生には分かりません
★entries への第2の書き込み経路を作らない
```

★5つ目が重要です。**「生徒が断った」が先生に見えると、断れなくなります。**

## §6 確認の手順 ★実装後に、実物で

```
1  先生役で実施を記録し、★生徒の entries が変わっていないことを確認する
2  生徒役でカードを見て、［足さない］を押す
3  ★もう一度アプリを開き、カードが出ないことを確認する
4  レッスンの詳細から、あとで取り込めることを確認する
5  取り込んだあと値を編集し、★タグ（_source）が外れることを確認する
6  ★同意を撤回した状態で、カードが出ないことを確認する
7  lesson_imports に UPDATE と DELETE を試み、★どちらも失敗することを確認する
```

★7を飛ばさないでください。**「ポリシーが無いから大丈夫」で済ませない**── 今日の規則です。

```
④  ★列が不足　held_at と actual_minutes の追加が要ります
　　　　　　　　duration_minutes を上書きしないこと

★別に、いちばん大きい確認が §0 にあります（どの列に足すのか）
```

先生の操作で、生徒の記録を書き換えないこと。
