## 1. 書き出す（Code）

```bash
# 構造だけ。データは入れない
supabase db dump --linked --schema public -f supabase/migrations/00000000000000_base_schema.sql
# ★ロール・権限（GRANT）・RLS のポリシー・関数・引き金・索引が含まれることを目で確かめる
#   含まれないときは --keep-comments や role 用の dump を足す。必要なら Opus に相談
```

```yaml
★必ず入っていること（1つでも抜けたら やり直し）:
  - create table 104本
  - alter table ... enable row level security（104表すべて）
  - create policy 182本
  - create function 99本（security definer・set search_path つきのもの）
  - create trigger 24本
  - 索引 216 と 制約（主キー104・外部キー185・CHECK109・UNIQUE27）
  - ★grant / revoke の行（authenticated・anon・service_role）
  - ★拡張: pg_trgm は public に入れる（create extension if not exists pg_trgm with schema public）
★2026-09-23 に Code が見つけた抜け（私の道具の抜けでもある）:
  - ★auth.users の引き金（on_auth_user_created）── public スキーマだけを数えていたので見えなかった
    → base_manifest.sql に auth の引き金を足した（いまの本番: 1本）
  - ★既定の権限の差（新しいプロジェクトは anon を含む／本番は含まない）
    → base_manifest.sql に pg_default_acl を足した（いまの本番: 24行）
  - CHECK 制約の文言の差 → 11通りで同じ意味であることを確かめて合わせた（Code）
★入れてはいけないもの:
  - データ（insert）・storage/auth スキーマの中身・利用者の情報
```
