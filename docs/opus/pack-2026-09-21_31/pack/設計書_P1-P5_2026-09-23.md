## 0. 全体の形

```yaml
新しい仕組み: ★0。既存の台帳・画面・道具の上に置く
```

## 1. P1 ── 変更がすぐ届く

```yaml
問題: ICS の反映は最大24時間。当日の変更に間に合わない
できること: ★取りに来たとき 必ず最新を返す（購読の間隔は こちらから短くできない）
やること:
  ① ICS のフィードを ★no-store にし、ISR・CDN から外す
  ② ★ETag を 中身から作る（時刻ではない。時刻だと 中身が同じでも毎回変わる）
  ③ アプリの中の「変わったもの」を ★きょうの帯の下に常設（裁定152 で設計済み）
  ④ ★自分が関わる稽古が 直近48時間で変わったときだけ、
     「今日のレッスン／行事」の中身として 帯の1本目に上げる（★帯は増やさない）
台帳: ★要らない（koen_session_changes・koen_change_seen が既にある）
★体調は フィードに1文字も入らない（いままでどおり）
```

## 2. P2 ── 重なりの検出を1本に

```yaml
問題: 授業・レッスン・稽古・部屋の重なりが ★別々に4つ。学生の一日は1つなのに
やること:
  ★「予定の景色」を1つ作る（表ではなく ★ビュー）
    形: 誰（user_id）／どこ（place_id）／いつ（開始・終了）／何（種類だけ）／org_id
    元: 授業のコマ・レッスン・学校の行事・★学校の公演の稽古・部屋の記入
  ★関数1本: busy_at(人 or 部屋, 開始, 終了) → 重なっているものの一覧（種類と相手だけ）
  既存の3か所（レッスン割の自動×・稽古を組む・部屋の記入）は ★この1本を呼ぶだけにする
★入れないもの（裁定183）:
  ★個人の公演（org_id が無いもの）→ 学校に「別の本番がある」と知らせないため
  ★授業名・教室名 → 「授業」の語だけ
  ★健康・門下 → 当然入れない
判断は変えない: ★教えるだけ。自動で動かさない（裁定112）
```

## 3. P3 ── 学校に見せる数字

```yaml
問題: 2027年1月の1枚が 手作業の予定。数字が無いと 4月の有料化が通らない
やること:
  ★org_monthly_stats（学校×月）に 毎月1日 1行
  中身（★数だけ・健康の中身は入れない）:
    先生の打刻数／学生の登録率／記録した日数の分布（★人数のみ）／行事の回答率／
    ICS の購読数／くばりものの配布数
  ★5人未満は 全項目 伏せる（「0」ではなく「―」）── 少人数だと 人が特定できるため
  集計は ★毎日の掃除と同じ定期実行に相乗り（sql/42 の run_retention と同じ道）
画面: 運営のPCに 印刷用1枚
★出さないもの: 学生個人の順位／先生ごとの比較／点数
```

## 4. P4 ── 導入を人手なしで

```yaml
問題: 窓口を持たない以上、学校が ★自分だけで導入を終えられる必要がある
流れ:
  申込 → ★契約書・個人情報の1枚・料金の確定文書を PDF で作る（★出すのは坂本さん）
  → 名簿 CSV の取込（その56：自動照合なし・学務の列だけ・札は meibo）
  → 先生と事務の合言葉 → 学生の合言葉
  → ★「最初の1週間の確かめ」（名簿が入った・先生が打刻した・ICS を購読した・行事を1件出した）
     ★終わると自動で消える。★催促しない
台帳: org_onboarding_checks（学校×項目×済んだ日）
★作らないもの: チャット・電話・訪問の約束
★裁定183 の注文: 契約書は 自動で作ってよいが ★「結ぶ」のは自動にしない
```

## 5. P5 ── 実技試験の割り当て

```yaml
問題: 学生×審査員×部屋×伴奏者×時間。★音大固有で 他社に無い
やること: ★レッスン割（139）の部品をそのまま使う。★新しい仕組みは作らない
  違うのは4点だけ（裁定183）:
    ① 置くものが ★10〜15分の枠
    ② ★審査員が自分の門下の枠に置かれると「門下」と出る（★自動で外さない）
    ③ ★伴奏者が別の枠として要る
    ④ ★確定した順に 採点の画面が並ぶ（二重入力をなくす）
台帳: jury_slots（行事×枠×学生×審査員×部屋×伴奏者×時刻）
並び: 学年 → 声種 → 五十音（運営が並べ替えられる）。★順位や成績で並べない
出力: 時間割の紙／学生の個人アプリに「実技試験 10/14 13:20 小ホール 伴奏：○○」（source='org'）
```

## 6. 確かめること（全部に共通）

```yaml
★層をまたぐ結合の見張り（その55・57）が 0件のまま
★健康の列が 1つも出ない（景色・集計・割り当て・紙）
★通知が1件も増えない（送信の記録0）
★5人未満のとき「―」（0ではない）
★自動で動かさない（教えるだけ）
```
