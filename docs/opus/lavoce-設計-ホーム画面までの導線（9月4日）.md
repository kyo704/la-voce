# 設計 ── ホーム画面までの導線

全 274 行 / 末尾は「iOS では、追加してから登録させる。順番を変えるだけで、脱落が1つ減ります。」

作成 2026年9月4日 ／ 「登録とホーム画面追加を簡略化する」への回答

---

## §0 結論

```
Stripe に誘導      ★ストアに出さないなら、そもそも誘導ではありません（§1）
導線の簡略化       ★正しい。ここが急所です
iOS と Android     ★同じ設計にできません（§4）
順番               ★iOS は「追加してから登録」。Android は「登録してから追加」
```

---

## §1 「支払いを Stripe に誘導」── 1つだけ訂正します

ストアに出した場合、**外部への誘導にも手数料がかかります。**

```
Apple（日本）   外部へ誘導する   15%
Google（日本）  外部へ誘導する   20%（年商100万ドル未満なら10%）
```

★**「外に出せば手数料はゼロ」ではありません。**
しかも、外部誘導するには申請（entitlement）が要ります。

ただし ── **ストアに出さないなら、この話は全部要りません。**

```
ウェブで配る PWA には、Apple も Google も関係しません。
　→ 手数料は Stripe の3%台だけです
```

「Stripe に誘導する」のではなく、**最初から Stripe で売っています。**
いまの路線が、いちばん安いです。変えなくてよいです。

---

## §2 ご指摘は正しく、しかも急所です

PWA の弱点は、性能でも見た目でもありません。**入口です。**

```
ネイティブアプリ   「入手」を押す。★1タップ
PWA（iOS）        共有ボタン → 「ホーム画面に追加」 → 追加
                   ★3タップ。しかも★どこにあるか分からない
```

**ここで落ちる人の数が、他のどの機能より多いはずです。**
2Dの羊も、本番モードも、ホーム画面に入らなかった人には届きません。

★売り出し前に直すべきものとして、これは第3段（売れるようにするもの）に入ります。

---

## §3 iOS と Android は、まったく違います

```
                              Android          iOS
インストールの案内を出せるか   ★出せる         ★出せない
                              beforeinstallprompt   ★対応していません
                              → ネイティブのバナー   → ★自分で案内を作る

ブラウザとの保存場所           ★共有される     ★別（§4）
Safari以外から追加できるか     ─               ★16.4以降・ブラウザが対応していれば
```

**Android は1タップ、iOS は手引きが要ります。**

---

## §4 ★決定的な事実 ── iOS は、保存場所が別です

これを知らずに作ると、必ず失敗します。

```
iOS のホーム画面から開いた PWA と、Safari は、
★cookie も localStorage も IndexedDB も、共有されません。
```

つまり、こうなります。

```
Safari で登録する
　　↓
ホーム画面に追加する
　　↓
ホーム画面から開く
　　↓
★ログアウトした状態で開きます
```

**いちばん嬉しい瞬間に、いちばん冷たいことが起きます。**
「アプリになった！」と思って開いたら、ログイン画面です。

★ここで落ちます。そして、その人は二度と開きません。

---

## §5 だから、順番を変えます

```
Android   登録 → 記録を1つ → ★インストールのバナー（1タップ・ログイン維持）
iOS       ★ホーム画面に追加 → ★そこで登録する
```

**同じ画面にしないでください。** iOS だけ、順番を入れ替えます。

### なぜ iOS は先に追加させてよいのか

```
・冷たい客ではありません。★紹介で来た人です（営業で連れてきます）
・登録より前なので、★失うものがありません
・脱落点が★3つから2つに減ります

  （いまの形）到達 → 登録 → 追加 → ★再ログイン → 記録   脱落点4つ
  （新しい形）到達 → 追加 → 登録 → 記録                  脱落点3つ
```

### 判定

```js
// 形だけ示します。実装は Sonnet の側です
const isIOS = /iPad|iPhone|iPod/.test(navigator.userAgent)
const isStandalone =
  window.navigator.standalone === true ||
  window.matchMedia('(display-mode: standalone)').matches
```

```
iOS ＆ standalone でない   → ★「まず、ホーム画面に置きましょう」
iOS ＆ standalone          → ★登録の画面
Android                    → 登録 →（記録1つ）→ バナー
```

## §6 iOS の案内画面

**文章で説明しないでください。絵で示します。**

```
　　　Woolsong を、ホーム画面に。

　　　　［ 共有ボタンの絵 ］
　　　　　　　　↓
　　　　［ 「ホーム画面に追加」の絵 ］
　　　　　　　　↓
　　　　［ 「追加」の絵 ］

　　　下の　⬆　を押してください
```

★守ること

```
・★実物のスクリーンショットを使う（描いた絵ではなく）
・共有ボタンの位置を★矢印で指す（画面の下です。上ではありません）
・★スキップできるようにする（「あとで」）
　　→ 出口のない画面を作らないこと
・★1回だけ出す。断ったら、もう出さない（催促禁止）
　　→ 代わりに、設定の中に「ホーム画面に追加する方法」を常設で置く
```

★Safari 以外のブラウザ（Chrome など）で開かれた場合、
iOS 16.4 以降なら、そのブラウザが対応していれば追加できます。
対応していない場合に備えて、**「Safari で開く」の案内も1行**置いてください。

---

## §7 ★再ログインを、軽くしておく

順番を変えても、**再ログインが必要になる場面は残ります。**

```
・iOS で、先に登録してしまった人
・保存されたものが消えた人
　（iOS には、しばらく開かないと保存が消える仕組みがあります）
```

だから、**ログイン状態がローカルにしか無い設計にしないでください。**

★推奨する形

```
・パスワードを作らせない
・メールアドレスだけで入れる（1通のリンク、または6桁の数字）
・★「6桁の数字」のほうが、iOS では確実です
　　メールのリンクを押すと、★Safari が開いてしまうことがあります
　　（ホーム画面版ではなく）
```

★これは大事です。**マジックリンクは、ホーム画面の PWA と相性が悪いです。**
リンクは既定のブラウザで開くので、せっかく追加したアプリの外に出てしまいます。

**6桁の数字なら、ホーム画面版の中で完結します。**

---

## §8 数えること

直したかどうかは、**数えないと分かりません。**

```
到達した       人
登録を始めた   人
登録を終えた   人
★追加を見た    人
★追加した      人（standalone で開かれた回数）
記録を1つ入れた 人
```

★外部の解析サービスを入れないでください。**経路が増えます。**
自分のサーバに、日ごとの数だけを持てば足ります（★個人を特定しない形で）。

**いちばん大きい落ち込みが、次に直す場所です。**

---

## §9 やらないこと

```
✕ ★出口のないインストール画面（「あとで」を必ず置く）
✕ ★何度も出す（1回だけ。断ったら設定の中に置く）
✕ 「アプリをインストール」という言い方
　　→ ★「ホーム画面に置く」。インストールと言うと、ストアを探されます
✕ 外部の解析サービス
✕ ★ストアに出す（9月4日の判断のとおり）
```

## §10 順番（第3段に入れてください）

```
① iOS / Android / standalone の判定を1本作る       半日
② iOS の追加案内の画面（実物のスクショ3枚）        1日
③ ★順番の入れ替え（iOSは追加が先）                半日
④ 6桁の数字での再ログイン                          1〜2日
⑤ 数えるところ                                      半日
```

**合計3〜4日です。** 本番モード（有料の中核）より前でも、後でもかまいません。
ただし、**売り出しより前に**入れてください。
入口が詰まっていると、売るものが良くても届きません。

## §11 確かめたこと／確かめていないこと

```
確かめました
  ・iOS の Safari は beforeinstallprompt に対応していないこと
  ・★ホーム画面の PWA と Safari で、保存場所が共有されないこと
  ・iOS 16.4 以降、Safari 以外のブラウザからも追加できること
    （そのブラウザが対応していれば）

★確かめていません
  ・保存が消えるまでの日数（「7日」と書いている記事がありますが、
    ★ホーム画面に追加した場合に同じかどうかは分かりません）
  ・出どころは技術記事であって、★Apple の1次資料ではありません
```

★§7 は、この不確かさに対する備えです。
**消えるかどうかを確かめるより、消えても軽く戻れるほうが、確実です。**
