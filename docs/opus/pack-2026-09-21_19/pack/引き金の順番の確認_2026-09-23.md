## 2. 順番の確認（複数の引き金がある13表）

```yaml
PostgreSQL は BEFORE → AFTER、同じ段では ★名前の順に動く
確かめた結果: ★順番で守りが抜ける組み合わせは 無い
  org_events: 身元の固定（BEFORE U）→ 帳簿づけ（BEFORE U）
    身元が先に見られるが、帳簿づけが触るのは updated_at と previous_date で ★org_id を触らない → 抜けない
  assignments / teacher_student_links: 身元の固定と 18歳未満の遮断。互いに別の列 → 抜けない
  memberships: 学年の見張り（BEFORE）→ 記録（AFTER）→ 役職の記録（AFTER）→ 妥当
  koen_members: ★期限の見張り → 人数の確かめ（名前の順）→ 期限が先で正しい
  monka_read_log / score_log: 学校の印 → 人の印（どちらも BEFORE I・互いに独立）
  evaluation_scores: 直しの見張り（BEFORE U）と 人の印（BEFORE I）→ 事象が違う
  org_billing / org_posts: 記録（AFTER）が2本。順番に意味なし
```
