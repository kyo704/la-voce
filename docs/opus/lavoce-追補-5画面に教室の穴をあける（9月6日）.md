# 0. 正直に書きます

**5画面の仕様書は、個人で使う人だけを見て書きました。教室機能は入っていません。**

そして、1か所、**はっきり間違えています。**

## ★間違い ── §6-9「レッスンの記録が先生に届く」

本体の §6-9 に、島村楽器「音楽日記」のレビューを引いて、こう書きました。

> 「先生と練習記録や目標を共有できるのは、レッスンで伝えきれなかった情報が届いて、
> 　講師の指導の参考にもなる」
> ★この方向は、うちの教室プランでそのまま生きます。

**生きません。9月1日に、逆の決定が出ています。**

```
「教室機能の全体（9月1日現在）」§0
　★先生は、生徒の記録の中身を1件も見られません

同 §7（もう無いもの）
　✗ shareScope（常時アクセス）　✗ 記録へのコメント　✗「先生に送る」ボタン
　→ ★作りません。作ると常時アクセスが復活します
```

★私は、**すでに消した機能を、良いことのように書きました。** §6-9 は撤回します。

**そして、これは文章だけの問題ではありません。**
§6-5 で「次に見てもらいたいこと」を作りました。
**この言い方だと、先生に送られると読めます。送られません。**

```
✕ 「次に見てもらいたいこと」　　　←　先生に届くように読める
◯ ★「次に、自分が言うこと」
◯ ★「レッスンで、聞きたいこと」
　　＋ 画面に1行：「これは、あなたのメモです。先生には届きません。」
```

★**この1行は、必ず入れてください。**
　入れないと、生徒は「書いたのに先生が見てくれない」と受け取ります。
　いちばん起きてほしくない誤解です。

# 1. 今あける穴（★3つだけ。ここは今やってください）

理由は1つです。**この3つは、あとから直すとレッスン画面を作り直すことになります。**
残り（§2）は、あとから足せます。

## 穴1 ── レッスンを「予定」と「実施」の1つの表にする

教室機能の `Lesson` は、**先生・教室の側から降ってくる予定**です。

```
Lesson ＝ 教室 × 先生 × 生徒 × 時刻
　状態：予定 ／ 実施 ／ 中止 ／ 無断欠席
　teacherNote ★先生専用。生徒に見せない
```

私が §6 で設計したのは、**生徒が自分で書く「実施の記録」だけ**でした。
2つは別物ですが、**生徒の画面では1つの並びに見えなければいけません。**

```
★1つの表に、2つの出どころを持たせる

source = 'org'   教室が入れた　→ ★生徒は日付・先生・時刻を編集できない
source = 'self'  自分で書いた　→ ★全部編集できる

　どちらも同じカードで並ぶ。★見た目で区別しない（source は小さな印だけ）
```

### ★記録の入り口が、2つになります

```
入口A（自分で）　「レッスンを、記録する」ボタン
　　　　　　　　 → ★前回と同じ先生・種別が入っている（本体§6-2のまま）

入口B（教室から）予定のカードを開く
　　　　　　　　 → ★先生・日付・時刻は入っていて、★動かせない
　　　　　　　　 → ★埋めるのは「扱った内容」と「状態タグ」だけ
　　　　　　　　 → ★これは1タップで開き、2タップ目で終わる
```

★入口Bで「前回と同じ先生」を入れてはいけません。**その予定の先生が正です。**
　本体 §6-2 は、入口Aだけの決まりです。

### ★状態の扱い

```
教室が「中止」にした　→ ★生徒の記録は消さない。カードに「休講」と出すだけ
教室が「無断欠席」　　→ ★生徒の画面には出さない（★評価語です）
　　　　　　　　　　　　生徒の画面では、ただ記録が無い日として扱う
```

★「無断欠席」は運営のための語で、本人に見せる語ではありません。

## 穴2 ── ホームの帯の、優先順位を決める

いま、帯を取り合うものが**5つ**あります。決まっていません。

```
1  ★本番の「あと n日」　　　　　（本番モード）
2  教室の行事「実技試験まで あと n日」（org_events）
3  今日のレッスンの予定　　　　　（Lesson）
4  声の予報　　　　　　　　　　　（訂正後）
5  羊のふつうのことば
```

★**帯は1本です。** 全部出すと、ホームが帯だらけになります。

### ★私の裁定（この順で、上から1つだけ出す）

```
1  今日のレッスン／行事が「これから」ある　→「今日 18時 A先生」
2  本番が3日以内　　　　　　　　　　　　　→「本番まで あと 2日」
3  教室の行事が7日以内　　　　　　　　　　→「実技試験まで あと 5日」
4  声の予報　　　　　　　　　　　　　　　→「あした　☁ くもり」
5  羊のふつうのことば

★D-1・D-0（本番の前日・当日）は、2 が出て、4 は出ない（判断済み）
★同じ日に複数あるときは、★時刻の早いものだけ
★2つ目以降は、帯の下に★小さく1行だけ（「ほかに 1件」）
```

★この順は「近いものほど上」です。理由が要るときは、それだけ言えば通ります。

## 穴3 ── タブを、役割で差し替えられる形にする

**5つのタブは、個人の使う人の並びです。** 役割が変わると、成り立ちません。

| 役割 | 見えるもの | ★問題 |
|---|---|---|
| 個人 | ホーム／記録／分析／レッスン／ノート | 本体の設計どおり |
| 生徒（教室に所属） | 同上 ＋ ★門下の連絡板・行事 | 5つに入りきらない |
| teacher | 担当生徒／レッスン／連絡板 ＋ ★自分の記録 | ★先生も声を使う人です |
| admin | ＋ 週表示・席・招待 | ★スマホに載りません |
| staff | 日程と出欠★だけ | ★5画面のうち4画面が見えない |

### ★今やること（これだけ）

```
1  ★タブを配列で持つ。役割ごとに配列を差し替えられるようにする
　　（画面をハードコードで5つ並べない。★これだけが、あとから直せない部分です）

2  ★staff は「日程」1タブだけ。★健康に関わる画面を1つも出さない
　　（事務の人に見えてはいけないものが見えるのが、いちばん重い事故です）

3  ★admin の週表示は、★スマホに載せない。
　　「この画面は、パソコンでご覧ください」と出して終わり。
　　★無理に縦に入れると、Google Health と同じ失敗（51%が「使い勝手は悪化」）になります

4  ★先生も、自分の記録を持ちます。
　　teacher の並びに、★ホーム・記録・分析・ノートを残してください。
　　「先生＝管理する人」ではありません。★先生も声を使う人です
```
