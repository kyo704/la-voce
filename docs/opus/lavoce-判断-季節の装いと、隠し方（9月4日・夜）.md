## §2 ★流行は追ってよい。ただし年を書いてください

流行を追うと、**アセットが古くなります。** ふつうはそうです。
そして坂本さんは9か月、直せません。

★**でも、年を書けば古くなりません。**

```
✕ 「秋のよそおい」          → 来年には古い服になります
◯ ★「2026年 秋のよそおい」  → ★その年に居たことの記念になります
```

★おうちは「経歴の棚」だと決めました（9月4日）。
　**流行りものは、そこに年号を持ち込みます。**

```
　2026年秋に始めた人の部屋には、★2026年秋のモカのコートがある。
　2029年に始めた人には、それがない。
　★それは「古い」のではなく、「その年に居た」ということです。
```

★毎年、新しい年のセットを出します。**去年のは、去年のものとして残ります。**

### 2026年の流行（調べたもの）

```
秋冬 26-27   ★モカブラウン ／ チェリーレッド ／ オリーブグリーン
             クレイピンク ／ ネイビー ／ ダークグレー ／ 温かみのある白
             素材：ボア・シアリング ／ ベロア ／ レース
             柄：グレンチェック ／ ハウンドトゥース ／ タータン

春夏 26      ★シトラスイエロー ／ 白 ／ ライトピンク ／ レッド
             ディープブルー ／ マンダリンオレンジ ／ モカブラウン
             素材：シアー ／ サテン ／ ツイード
```

★**そのままの色は使っていません。** この製品の色に翻訳しました。
　シトラスイエローもマンダリンも、**くすませて**あります。
　★流行色をそのまま入れると、`#F7F2E6` の部屋から浮きます。

## §3 ★メンズ／レディスで分けないでください

```
✕ ［ メンズ ］［ レディス ］のタブ
```

理由は2つ。

```
① ★羊に性別はありません。羊は羊です

② ★選ぶ前に、自分を分類させることになります
　　9月4日に「選ぶことを増やさない」と決めました。
　　★タブが1つ増えるのではなく、★問いが1つ増えます
```

★**服の種類は、両方作ります。** ベストもトレンチもセーラーもエプロンもあります。
　**ただ、並べるだけにしてください。** 誰でも、どれでも着せられます。

★分けたくなったら、`theme`（和・洋・中・季節・舞台）で分けてください。
　**そこに性別を足さないこと。**

## §4 世代もの ── ★年齢で出し分けないでください

「90歳までの人が懐かしめるもの」。**良い案です。作ります。**

★声のプロには、年配の先生がたくさんいます。
　そして「懐かしい」は、この製品のどの機能とも競合しません。

### ★ただし、出し分けないでください

```
✕ 年齢を推測して、その世代のものを出す
　　→ ★9月4日に「生年月日は取得しない」と決めました
　　→ ★年齢を聞かないと、出し分けられません
```

★**全部、同じ棚に並べてください。**

```
懐かしむ人は  ★懐かしくて選びます
知らない人は  ★「レトロ」として選びます
```

★どちらにも売れます。**年齢を聞かずに済みます。**
　そして、9月4日に決めた「確かめられないことを表示しない」にも合います。

### 作るもの（案）

```
1950〜60年代   ちゃぶ台 ★あります／ラジオ／黒電話／ホーロー看板
1970年代       レコードプレーヤー／回転式の扇風機／ステレオ
1980年代       ラジカセ／ブラウン管テレビ／カセットテープの棚
1990年代       ポータブルCD／ブリキの筆箱／ダイヤル式ストーブ
2000年代       ノートパソコン（分厚いもの）／MDのケース
```

★`theme` に `retro` を1つ足してください。年代でさらに分けなくてよいです。
　★**「昔のもの」という1つの棚**で足ります。増えたら分ければよいです。

## §5 ★★ネタバレ ── 静的アセットは、隠せません

これは、はっきり言っておかなければなりません。

```
★svg/ のファイルは、ブラウザに配られます。
　画面に出していなくても、★URL を打てば見られます。
```

★画面で隠しても、**隠したことになりません。**
　まとめて配置すれば、**全部見られます。**

### 隠す方法は、1つだけです

```
★出す季節のぶんだけ、リポジトリに入れる。
　残りは、坂本さんの手元（この zip）に置いておく。
```

```
いま入れる    ★秋 2026 の4点だけ
手元に置く    冬・春・夏の12点
　　　　　　  ★季節が来たら、そのとき入れる
```

★これが唯一確実で、しかも**無料**です。
　サーバ経由で配る仕組みを作ると、経路が1本増えます（台帳05）。**作らないでください。**

### ★9か月不在のあいだ、どうするか

```
問題   冬・春・夏を出すとき、★入れる人がいません
```

★2つの道があります。

```
A  ★出発前に全部入れて、画面で出し分ける
　　→ ★ネタバレの可能性を受け入れる
　　→ ただし「見つけた人が数人いる」だけの話です

B  ★秋だけで、9か月やる
　　→ 帰国後に冬・春・夏を出す
```

★**Aを勧めます。** 理由：

```
・★見つける人は、ほとんどいません
・見つけた人は、★熱心な人です。悪いことではありません
・そして★季節が来ても新しいものが出ない、のほうが損です
```

★ただし、**Aを選ぶなら「隠せていない」ことを承知の上で選んでください。**
　★「隠した」と思い込むのが、いちばん危ない状態です。

## §6 ★kyo0703opera への解放 ── コードに書かないでください

```
してよいです。ただし★やり方を指定します。
```

### ✕ やってはいけない形

```
✕ if (email === 'kyo0703opera@gmail.com') { 全部持っている }
```

理由。

```
① ★消し忘れます。9月3日に何度も見た形です
② ★コードに個人のメールアドレスが載ります
③ ★仕組みが1つ増えます。あとで「なぜこの人だけ？」を調べる人が出ます
```

### ◯ 正しい形 ── ★データで持たせる

```
character_inventory に、★坂本さんのぶんの行を入れるだけ。

　unlock_rule_id   null
　reason_snapshot  ★「確認のため（2026-09-04）」
```

★**コードに条件分岐を1つも足しません。**
　消したければ、**行を消すだけ**です。

★そして `reason_snapshot` に理由を書いておけば、
　半年後に「なぜこの人は全部持っているのか」が、その場で分かります。

### ★守ること（9月3日の決まり）

```
□ 検証で状態を変えたときは、★必ず記録する
　　→ 台帳06（起きたことの記録）に1行

□ ★集計から除く
　　→ 「◯人が装いを買いました」に、この行を数えない
　　→ 9月3日の「テスターは実在する」と同じ話です

□ ★新しいアカウントを作らない
　　→ 既存の kyo0703opera でやってください
```

★③がとくに大事です。**「確認のために新しい口座や新しい鍵を作らない」**（9月3日）。
