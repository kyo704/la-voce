## 1. ★「その他」の職業に、曲目カードで何を出すか

### いまの状況

曲目カードには、職業ごとに「もう一段の情報」を添えています
（`lib/occupation.js` の `repertoireExtraFor`）。

```
歌唱言語 … classical / musical / pops
役の情報 … voiceActor / actorStage / actorScreen
案件の情報 … narrator / announcer / mc
何も足さない … rakugo / other        ← ★ここ
```

「その他」には、いま**何も足していません**。これは 2026-08-29 に私が置いた
既定値で、設計憲章の「その他には、みんなに共通の内容だけを出す」に
沿わせたものです。

### 選べる道

```
案A そのまま。「その他」には追加項目を出さない
案B 共通の最小セットを作る（例：作品名・言語・ひとことメモ）
案C 「あなたのお仕事では、何を残しておきたいですか」と本人に選ばせる
```

### 私の案：**案A（そのまま）**

「その他」を選ぶ人は、11分類のどれにも当てはまらなかった人です。
その人たちに共通する項目は、定義上ありません。案Bは
「たぶんこれだろう」を全員に押し付けることになります。

### ★なぜ人が決めるべきか

「何も出さない」は、本人からは**機能が足りない**ように見えます。
それを許容するかどうかは、誰に使ってほしいかという製品の判断であって、
コードから導けません。

## 2. ★落語の曲目カードに、何を出すか

### いまの状況

1と同じ理由で、落語にも何も足していません。

3つの欄のどれも当てはまりませんでした。歌ではなく、役でもなく、
「案件の情報」（原稿の種類：ニュース／CM／ナレーション、話す速さ、生か）は
**原稿を読む仕事**のための欄で、落語の演目とは別のものです。

### 選べる道

```
案A そのまま（何も足さない）
案B 「案件の情報」を流用する（朗読・話す速さ・生か、は近い）
案C 落語のための欄を新しく作る（演目・持ち時間・マクラの有無 など）
```

### 私の案：**案A、ただし暫定**

案Bは、いちばん楽ですが**当てはまっていない欄を当てはまったことにします**。
落語家が「原稿の種類：ナレーション」を選ぶ画面は、正しくありません。

### ★なぜ人が決めるべきか

案Cは新しい設計です。落語の稽古で何を記録したいかは、
**落語の人に聞かないと分かりません**（Lane B の専門家ヒアリングの範囲）。
私が想像で欄を作るのが、いちばん良くない結末です。

## 3. ★「セットリスト診断」という名前を、そのまま使うか

### いまの状況

`components/VocalTracker.jsx:11388` に、画面の見出しとして
**「セットリスト診断」**と出ています。中身は曲順と負荷の計算で、
体調や病気の話ではありません。

一方、設計憲章 §2-1 は「疑い／リスク／早期発見／予防」などを
**アプリのどこにも出さない語**としています。「診断」はその一覧には
ありませんが、`:3715` と `:13537` では
「疑いの有無を判定するものではありません」「医学的な診断ではありません」と
**否定するために**使っています。

同じ画面の中に、
「診断ではありません」という否定文と、「セットリスト診断」という機能名が
並んで存在しています。

### 選べる道

```
案A そのまま「セットリスト診断」
案B 「セットリストの組み立て」「曲順の確認」など、診断を外した名前にする
案C 機能名は残し、説明文で「体調の診断ではありません」と補う
```

### 私の案：**案B（名前を変える）**

★配布のときにストアや紹介文へ載る語です。文脈の説明が付かないまま
「診断」だけが独り歩きします。「曲順の確認」なら、失うものがありません。

### ★なぜ人が決めるべきか

これは**製品名の判断**です。坂本さんが「セットリスト診断」という言葉に
愛着や意図をお持ちかもしれず、私が勝手に変えるべきものではありません。
