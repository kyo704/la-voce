# La Voce ／「食事と就寝」の記録・分析・受診用の書き出し

**Claude Sonnet 5 へ。胃からの逆流（咽喉頭逆流）に関わる行動を記録し、
声との関係を本人が見つけられるようにするための仕様です。**

読む順番：**統合実行ルート v4**（§3 ガードレール・§6 表示ゲート）→ 本書。
**周期記録の設計.md と扱いの重さが同じ**なので、そちらの §2（漏えい経路）も併せて読んでください。

**★この機能は、周期より1段階重い扱いが要ります。**
月経周期は厳密には要配慮個人情報に当たらない可能性がありましたが、
**逆流性食道炎は病名なので、病歴として明確に要配慮個人情報です。**

---

## 0. 結論

```
① 記録するのは3つだけ。最後に食べた時刻・就寝時刻・当てはまるチェック。
   ★食事の量・カロリー・体重は扱わない。

② ★一律の「これを食べてはいけません」を出さない。文献の根拠が弱いため。
   その人の記録から、その人に合わないものを3ゲートで見つける。

③ 「受診しましょう」と言わない。代わりに
   ★「受診のときに持っていく1枚」を作る。

④ 課金は「記録は無料・読み解きは有料」。
   ★法律上の書き出し（全データ）は無料のまま。

⑤ 機能名に病名を付けない。名前は「食事と就寝」。
```

---

## 1. なぜ La Voce がこれをやるのか

咽喉頭逆流は、声を使う人の嗄声の主要な原因の1つです。
朝いちばん声が出ない・痰がからむ・咳払いが増える、という形で出ます。

**そして La Voce だけが持っている情報があります。**

```
本番／レッスンの終了時刻 → 打ち上げ・遅い夕食 → 就寝
```

これは声楽・ミュージカル・ライブをやる人の典型的な型です。

```
普通の逆流アプリ  … 本番の予定を持っていない
普通の声のアプリ  … 食事を持っていない
La Voce           … ★両方ある
```

だから「本番の日は食後就寝までの時間が短くなる」という
**その人自身のパターン**を出せます。ここが価値の中心です。

---

## 2. ★文献の状況（設計の前提）

ACG のガイドラインでは、生活習慣についての推奨は次のとおりです。

```
食事から就寝まで2〜3時間空ける    条件付き推奨 / エビデンスの質は低い
頭側挙上（夜間症状のある人）       条件付き推奨 / エビデンスの質は低い
トリガーフードの回避              条件付き推奨 / エビデンスの質は低い
```

**ガイドライン自身が「支持するデータは限定的、小規模で管理されていない研究が多い」
と明記しています。**

**これは機能を作らない理由ではなく、作り方を決める理由です。**

```
✗ 万人向けの禁止リストを出す    → 根拠がない
○ その人の記録から、その人に合わないものを見つける   → ★3ゲートそのもの
```

**万人向けの助言ができない領域だからこそ、個人の記録に意味があります。**
この機能は、La Voce の方法論が最もきれいに当てはまる領域です。

## 3. ★課金の線引き

**無料（ゲートしない）**

```
・食事・就寝の時刻の記録
・チェック項目の記録
・食後就寝までの時間の表示（その日ぶんの事実）
・過去の記録の一覧と編集
・★法律上の書き出し（全データのエクスポート）
```

**プレミアム**

```
・分析（★3ゲートを通った関連の表示）
・チェック項目ごとの比較
・★受診のときに持っていく1枚
・期間を指定した集計
```

**理由：記録を有料にすると、記録が集まらず、分析が成立しません。**
そして**症状がある人ほど記録が必要**なので、
記録そのものに支払いの壁を置くのは、いちばん必要な人を締め出すことになります。

**★法定の書き出しをプレミアムにしないこと。**
個人情報保護法・GDPR の権利に基づく全データの書き出しは、
**支払いの有無にかかわらず無料**です。
「受診のときに持っていく1枚」は診察用に整形した便宜であって、法定の書き出しとは別物です。
**この2つを同じ実装にまとめないでください。**

## 4. 記録するもの

### 4-1｜3つだけ

```
┌─ 食事と就寝 ────────────────────┐
│                                          │
│  最後に食べた時刻      [ 21:40 ]         │
│  ベッドに入った時刻    [ 23:10 ]         │
│                                          │
│   → 1時間30分空きました                  │
│                                          │
│  当てはまるもの（任意）                  │
│   □ 食後すぐ横になった                   │
│   □ 満腹まで食べた                       │
│   □ 遅い時間にお酒                       │
│   □ 前かがみの時間が長かった             │
│   □ 締めつける衣装だった                 │
│   □ 脂っこい食事だった                   │
│                                          │
│             [ 保存する ]                 │
└──────────────────────────────┘
```

**全部任意です。** 時刻を1つだけ入れて閉じても構いません。

### 4-2｜★「締めつける衣装」を入れる理由

コルセット、帯、きつい衣装は腹圧を上げます。
**オペラ・ミュージカル・和装の本番でしか起きない要因**で、
一般の逆流アプリには存在しない項目です。

**これが「声の仕事のためのアプリ」であることを示す項目になります。**

### 4-3｜★量・カロリー・体重を扱わない

ガイドラインは肥満のある人の減量を推奨していますが、
**La Voce では体重も食事量もカロリーも扱いません。**

**理由：声の仕事をしている人は、体型の圧力が強い職業だからです。**
舞台に立つ人に毎日体重とカロリーを入力させる機能は、
摂食障害の側に押す力になります。

**記録できることと、記録させてよいことは違います。**

体重の話は、**学ぶ記事の中で文献として触れるだけ**にしてください
（ガードレール「文献閾値は学ぶ記事のみ」）。

### 4-4｜★食べたものを自由記述で書かせない

食事の自由記録は続きません。そして続かない記録は分析に使えません。
**上のチェック6項目だけにしてください。**

## 5. 導出と日付の境界

### 5-1｜差は保存しない

```
食後就寝までの時間 = bedAt − lastMealAt
```

**周期記録と同じ原則です。導出できる値を保存しないでください。**
時刻を直したら、差も自動で直ります。

### 5-2｜★「その夜」がどの日に属するか

就寝が0時を回る人がほとんどです。**必ず次の規則にしてください。**

```
就寝時刻が 04:00 より前なら、★その前日の記録として扱う
```

これをやらないと、深夜1時に寝た日の記録が翌日に飛び、
「翌朝の声」との対応がずれます。**分析が丸ごと壊れます。**

### 5-3｜本番・レッスンとの接続

その日に本番またはレッスンがあったかは、**既存のデータから自動で付きます。**
ユーザーに入力させないでください。

```
・本番があった日
・レッスンがあった日
・どちらもない日
```

分析の群分けに使います（§7）。

## 6. 区切りマーカー（★理由は書かせない）

薬を飲み始めた、受診した、生活を変えた——
そういう区切りがあると、その前後で記録の意味が変わります。

**しかし、服薬や受診そのものを記録させないでください。**
治療内容は要配慮性がさらに上がり、そのわりに分析には効きません。

代わりに、**理由のない区切りマーカーを1つだけ置けるようにします。**

```
[ ここから区切りをつける ]
   ※ この日から、記録の見方を分けます
   ※ ★理由の入力欄を作らないこと
```

分析はこのマーカーで期間を分割します。
**何があったかは、本人だけが知っていれば足ります。**

## 7. 分析（プレミアム）

### 7-1｜見るもの

```
① 食後就寝までの時間（分） × 翌朝の声の調子     Spearman ρ
② 2時間未満 / 2時間以上 の比較                  Hedges' g
③ チェック項目それぞれ × 翌朝の声の調子         Hedges' g
④ 本番の日 / レッスンの日 / どちらもない日 の
   食後就寝までの時間の分布                     ★これは事実の表示。ゲート不要
```

**「翌朝の声の調子」は、朝の記録の入り口の値を使ってください**
（記録と分析の順番設計 §3）。夜の主観と混ぜないこと。

### 7-2｜★3ゲート

```
① 件数    各群 n ≥ 10、両群が揃っている
② 効果量  |Hedges' g| ≥ 0.4（または |ρ| ≥ 0.3）
③ 多重比較 BH-FDR で q < 0.10
```

### 7-3｜★FDR の族

```
族 = （①連続 ＋ ②二値 ＋ ③チェック6項目）×（対象指標）
     この全体に対して、1回だけ BH-FDR をかける
```

**対象指標は3つまでに絞ってください。**
翌朝の声の調子・RSI・（あれば）CPPS。
思いつきで指標を増やすと族が膨らみ、何も通らなくなります。

### 7-4｜出し方

```
┌────────────────────────────────┐
│  食後就寝までの時間と、翌朝の声                │
│                                                │
│  2時間未満の翌朝は、2時間以上の翌朝にくらべて  │
│  声の調子の記録が低めでした。                  │
│                                                │
│  2時間未満 31回 / 2時間以上 24回               │
│  差の大きさ 中程度                             │
│                                                │
│  ※ 医学的な判断ではありません。               │
│     あなたの記録から見えた傾向です。           │
└────────────────────────────────┘
```

通らないときは、**数字も出さないでください。**

```
  あと12日分の記録で、傾向を出せます
```

## 8. ★受診のときに持っていく1枚（プレミアム）

### 8-1｜なぜこれが中心なのか

耳鼻科や消化器内科では「いつ何を食べて、いつ寝ましたか」と必ず聞かれ、
**誰も覚えていません。**

**アプリは受診を勧めません。行くと決めた人の役に立つだけです。**
それが結果的に、いちばん強く背中を押します。

### 8-2｜書式

```
────────────────────────────────
 食事と就寝の記録        2026年7月1日 〜 8月26日（57日）

 記録した日数                     51 / 57 日

 食後就寝までの時間
   中央値                         1時間15分
   2時間未満だった日              38 / 51 日
   最も短かった日                 20分（7月14日）

 当てはまった日数
   食後すぐ横になった             22日
   遅い時間にお酒                 14日
   締めつける衣装だった            6日

 RSI（自己記入の症状指数）の推移
   7/01  18     7/29  21     8/26  19

 朝の声の調子との関係
   （★3ゲートを通ったときだけ、ここに1文が入る）
   （通っていなければ「まだ判定できません」とだけ書く）

────────────────────────────────
 ※ これは本人が入力した自己記録です。診断ではありません。
 ※ このアプリは医療機器ではありません。
────────────────────────────────
```

### 8-3｜仕様

```
・出力は印刷用HTML または PDF
・★氏名は任意。空欄のままでも出せること
・期間はユーザーが選ぶ（既定は直近8週間）
・★「逆流性食道炎の疑いがあります」と書かない
・★「受診してください」と書かない
・★最後の2行（自己記録である／医療機器ではない）を必ず入れる
・生成はクライアント側で完結させる。★サーバーにPDFを保存しない
```

## 9. RSI との関係

RSI（逆流症状指数）は既に実装されているはずです。

```
RSI      … 症状の側の測定
本機能   … ★行動の側の記録
```

**2つがそろって初めて、「行動を変えたら症状が動いたか」が見えます。**

### 9-1｜★閾値を表示しない

```
✗ 「13点以上は逆流の疑いがあります」
✗ 「あなたのスコアは基準を超えています」
○ 数値の推移のグラフだけ
```

**閾値の話は学ぶ記事に置いてください**（ガードレール「文献閾値は学ぶ記事のみ」）。
スコアの横に閾値を出した瞬間に、それは判定になります。

## 11. データモデル

```ts
interface RefluxSetting {
  userId: string
  enabled: boolean        // ★既定 false
  consentAt: string|null  // ★明示的な同意の時刻。null なら記録させない

  id: string

  bedAt?: string
  flags: string[]         // 'lieDown' | 'full' | 'alcohol' | 'bend' | 'tightCostume' | 'fatty'

interface RefluxMarker {
  id: string
  userId: string
  date: string

  // ★理由のフィールドを作らない

```

```
★教師・管理者・保護者向けのポリシーを1つも作らない
★SECURITY DEFINER 関数からも参照しない
```

## 18. Sonnet への依頼のコツ

**この領域では、親切心が最も危険です。**
実装中に、次を思いつくはずです。

```
・「RSIが13点を超えました。受診を検討しましょう」
・「避けるべき食品リスト」
・「食後2時間は横にならないようにしましょう」という毎日の通知
・体重を入れると精度が上がります、という案内
```

**4つとも §14 で禁止しています。** どれも善意から出てくるので、
