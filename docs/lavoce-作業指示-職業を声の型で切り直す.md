# La Voce ／ 職業を「声の使い方の型」で切り直す

**Claude Sonnet 5 へ。職業カテゴリの土台を入れ替えます。**

読む順番：職業別項目の再設計と学ぶ画面.md §2（共通コア）→
作業指示-分析の検出力と族の設計.md → 本書。

**これは、いま抱えている2つの宿題（死んだコードの扱い／ポップス項目の不足）への
回答でもあります。個別に埋めるのではなく、土台を変えて両方を消します。**

---

## 0. 結論

```
① 職業を増やすたびに項目が増える構造を、★やめる。
② 内部で持つのは★3つの型の配合だけ。職業はその既定値の名前。
③ ★配合は v1 では計算に使わない。使うのは「何を出すか」と「何と呼ぶか」だけ。
④ ★同じ列に、職業ごとに違う言葉を出す（用語辞書）。
⑤ 型ごとの項目は★2〜3個まで。共通コア5項目は全職業で同じ。
⑥ ★職業を変えても、過去のデータを1行も書き換えない。
⑦ ★職業名を分析の文章に使わない。他人と比べない。
```

---

## 1. なぜ土台を変えるのか

**いまの構造では、職業を1つ足すたびに項目が増えます。**

```
5職業 → 項目が増える → 使われない項目が出る（★死んだコード）
     → 8職業にすると、管理できなくなる
     → 分析の族も増え、★検出力が落ちる
```

**職業は増やしたい。項目は増やしたくない。**
この2つを両立させる方法が、型で切ることです。

---

## 2. 3つの型

```
sing     歌う   旋律・音域・持続。songFactor が意味を持つ
speak    話す   台詞・原稿・長時間の連続発話
project  張る   叫ぶ・遠くへ飛ばす。ロンバードと同じ機序
```

**実在の職業は、この3つの配合で表せます。合計は 10 にそろえます。**

```
                        sing  speak  project
声楽家                    9     1       0
ミュージカル               6     2       2
ポップス／ロック           7     1       2
声優                      1     7       2
ナレーター                 0    10       0
アナウンサー               0    10       0
★俳優（舞台）             0     7       3
★俳優（映像）             0     9       1
★落語・講談・話芸          1     9       0
★司会・MC                 0     8       2
その他（声を使う仕事）      3     5       2
```

**★配合は、設定の奥で本人が動かせます。**
ただし最初の画面には出しません。
**「私は話す8・張る2です」と自己申告できる人はいません。**

### 2-1｜★v1 では、配合を計算に使わない

```
配合が決めるもの   ★どの項目を出すか／★何と呼ぶか
配合が決めないもの ★負荷の計算、strain、songFactor、KAPPA、EWMA のλ
```

**既存の計算式と定数に、1つも触れないでください。**
配合を重みとして掛け始めると、**過去の記録の意味が変わります。**
それは v2 以降に、データが貯まってから検討することです。

## 4. ★用語辞書（同じ列、違う言葉）

**これが今回いちばん効く部分です。**
**データも質問も同じで、呼び方だけ変えます。**

```ts
// lib/vocabulary.ts
export const VOCAB: Record<OccupationKey, Record<TermKey, string>> = { ... }
```

| 内部の列 | 声楽 | ミュージカル | 俳優(舞台) | 声優 | ナレーター | アナウンサー | 落語 | ポップス |
|---|---|---|---|---|---|---|---|---|
| `performanceDay` | 本番 | 本番 | 公演 | **収録** | **収録** | **生放送** | 高座 | ライブ |
| `rehearsalDay` | 合わせ | 稽古 | **稽古** | テスト | 下読み | 打ち合わせ | ネタ稽古 | リハ |
| `lessonDay` | レッスン | レッスン | 稽古 | レッスン | レッスン | 研修 | 稽古 | レッスン |
| `offStageVoiceMinutes` | 練習以外で話した時間 | 同左 | **稽古以外で話した時間** | **収録以外で話した時間** | 同左 | **放送以外で話した時間** | 同左 | 同左 |
| `warmupDone` | 発声 | ウォームアップ | 発声 | 喉ならし | 喉ならし | 発声 | 声出し | ウォームアップ |
| `dayAfterPerformance` | 本番の翌日 | 公演の翌日 | 公演の翌日 | **収録の翌日** | 収録の翌日 | 放送の翌日 | 高座の翌日 | ライブの翌日 |

```
・★列名・型・保存形式は、すべて同じ
・★辞書に無い職業は、既定の言葉（声楽の列）にフォールバック
・辞書は1ファイルにまとめる。★画面のあちこちに文字列を散らさない
・多言語（ICU MessageFormat）と、★同じ仕組みの上に載せる
```

**「収録」を「本番」と呼ばれた声優は、自分のためのアプリだと思いません。**
**逆に、言葉さえ合っていれば、中身は一言一句同じで構いません。**

## 5. 出す項目

### 5-1｜共通コア（★全職業で同じ。変えない）

```
sleepHours / offStageVoiceMinutes / absoluteHumidity
dayAfterPerformance / morningEdema
```

**ここは1文字も触らないでください。**
分析の中核5項目であり、族の設計の前提です。

### 5-2｜型ごとの追加項目（★2〜3個まで）

```
sing ≥ 5 の人
  □ パッサッジョの通りにくさ（5段階）
  □ 高音の出しやすさ（5段階）

speak ≥ 6 の人
  □ ★台詞・原稿の分量（時間ではなく「量」。少ない/ふつう/多い）
  □ 連続してしゃべった最長の時間（分）

project ≥ 2 の人
  □ ★遠くへ飛ばした時間（分）
```

```
・★配合が閾値を超えた型の項目だけを出す
・複数の型が閾値を超えたら、両方出す（最大でも4項目）
・★どれも任意。空欄で保存できる
```

### 5-3｜これで宿題が片づきます

```
音域           ★削除（自己申告では測れない）
ダイナミクス     ★削除（同上）
パッサッジョ通過数 ★「通りにくさ」に置き換えて残す（sing 型のみ）
ポップスの不足    ★project 型の項目が入ることで埋まる
```

## 6. ★削除の手順（データを壊さないこと）

**列をいきなり落とさないでください。**

```
① まず数える
     SELECT count(*) FROM ... WHERE 音域 IS NOT NULL;

② 0行だった場合
     → 列を削除してよい

③ 1行以上あった場合
     → ★データは残す
     → 画面から外す
     → 分析から外す
     → 書き出し（法定エクスポート）には★含めたまま
     → deprecated として印を付ける
```

**★本人が入れたデータを、こちらの都合で消してはいけません。**
使わなくなることと、消すことは別です。

## 7. データモデル

```ts
export type OccupationKey =
  | 'classical' | 'musical' | 'pops' | 'voiceActor' | 'narrator'
  | 'announcer' | 'actorStage' | 'actorScreen' | 'rakugo' | 'mc' | 'other'

export interface VoiceMix { sing: number; speak: number; project: number } // 合計10

export const DEFAULT_MIX: Record<OccupationKey, VoiceMix> = {
  classical:   { sing: 9, speak: 1, project: 0 },
  musical:     { sing: 6, speak: 2, project: 2 },
  pops:        { sing: 7, speak: 1, project: 2 },
  voiceActor:  { sing: 1, speak: 7, project: 2 },
  narrator:    { sing: 0, speak: 10, project: 0 },
  announcer:   { sing: 0, speak: 10, project: 0 },
  actorStage:  { sing: 0, speak: 7, project: 3 },
  actorScreen: { sing: 0, speak: 9, project: 1 },
  rakugo:      { sing: 1, speak: 9, project: 0 },
  mc:          { sing: 0, speak: 8, project: 2 },
  other:       { sing: 3, speak: 5, project: 2 },
}

interface UserProfile {
  userId: string
  occupation: OccupationKey
  mix: VoiceMix              // 既定は DEFAULT_MIX[occupation]。本人が変更可
  mixEditedAt?: string
  // ★過去のレコードには一切影響しない
}
```

```
・★mix を日次レコードに保存しない（プロフィール側に1つだけ持つ）
・職業を変えたら mix を既定値に戻すか聞く（★勝手に戻さない）
・★職業・mix を分析の説明変数に使わない（v1）
```

## 8. 既存ユーザーの移行

```
① いまの職業 → DEFAULT_MIX を入れる（5職業ぶん）
② ★過去のレコードは再計算しない・書き換えない
③ 画面の言葉が変わることを、1回だけ知らせる
     「呼び方をお仕事に合わせました。記録はそのままです。」
④ ★分析の結果が変わらないことを、移行前後で確認する
```

**移行のあとに分析結果が動いたら、それはバグです。**
**v1 では、配合は計算に入っていないからです。**

---

## 9. 分析への影響（★ゼロにすること）

```
・中核5項目          変わらない
・族の数             ★増やさない（職業の族を作らない）
・3ゲート            変わらない
・型別の項目          ★explore に入れる（検定しない・文章を出さない）
```

**型別の項目は、当面は記録だけです。**
検定に入れると族が増え、検出力が落ちます。
**N-of-1 試験の指標としてなら、選べるようにして構いません。**

---

## 10. ★禁止事項

```
1.  ★配合を負荷の計算に掛けない（v1）
2.  ★songFactor / strain / KAPPA / EWMA のλを変更しない
3.  ★職業名を分析の文章に使わない
      ✗「声楽家の平均と比べて…」✗「俳優の方はこの傾向が出やすいです」
4.  ★他の職業・他人と比較しない（平均・順位・偏差値を出さない）
5.  ★職業を複数選ばせない
6.  ★職業の変更で、過去のデータを書き換えない
7.  ★型別の項目を必須にしない
8.  ★項目を3つより増やさない（増やしたくなったら、それは新しい型が要る合図）
9.  ★使われていない列を、数えずに削除しない
10. ★職業を先生・教室に見せる範囲を広げない（既存の範囲のまま）
11. ★管楽器・器楽の職業を足さない（声帯を使わず、共通コアが成立しません）
12. ★教員・保育士・コールセンターを職業一覧に足さない（第3層。いまは「その他」で受ける）
```

### なぜ ⑪⑫ を禁止するか

```
管楽器   呼吸と口腔の負荷は近いが、★声帯を使わない
         「朝の声の調子」「むくみ」が意味を持たず、分析が空振りします

教員など 人数は桁違いに多いが、★労働安全衛生の話になります
         導入相手が個人から企業・学校に変わり、製品の焦点がぼけます
         ★いまは「その他」で静かに受けるだけ
```

## 12. テストで固定すること

```
□ 移行の前後で、既存ユーザーの分析結果が★1文字も変わらない
□ 職業を変えても、過去の日次レコードが1行も変わらない

□ 型別の項目が、閾値を超えた型のぶんだけ出る

□ 出力の文言に、職業名を使った比較が1つもない
□ 削除対象の列について、行数を数えるクエリが実行された記録がある
```

## 13. Sonnet への依頼のコツ

**この作業で、いちばん越えやすい線は「せっかくだから」です。**

実装中に、次を思いつくはずです。

```
・配合を重みにして、負荷の計算を職業ごとに調整する
・職業別の平均を出して、位置を見せる
・職業ごとに違う項目を、もっと増やす
・使われていない列を、ついでに消す
```

**4つとも §10 で禁止しています。**

**★この作業の目的は、機能を増やすことではありません。**
**職業をいくつ足しても壊れない土台に、置き換えることです。**

```
★迷ったときの基準

その変更で、既存ユーザーの分析結果は動きますか？
　→ 動くなら、v1 ではやりません。
```
