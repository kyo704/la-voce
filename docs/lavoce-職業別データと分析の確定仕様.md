# La Voce ／ 職業別の収集データと分析 確定仕様

**職業切替ボタンは実装済み**という前提で、
職業ごとに「何を集め、何を返すか」を実装粒度で定義したもの。

職業別設計.md（戦略）を、実装できる形に落としたものです。**そちらより本書が優先します。**

---

## 0. 大前提：切り替わるのは表示だけ

**職業を切り替えても、データは分けないでください。**

声優が歌う、ミュージカル俳優が吹替もやる——**兼業が普通の業界**です。
職業ごとにデータが分かれると、ACWR も偏差値も相関も半分ずつになり、意味を失います。

```
職業の設定    普段の姿。表示のプリセットを決める     → 設定画面（毎日押すものではない）
活動の種別    その日の実態                          → 記録画面の活動ブロックごと
データ        常に1本                               → 分けない
```

「午前はアフレコ、午後はライブ」の日も、**1本のデータのまま**扱えます。

---

## 1. 3層構造

```
第3層  職業別の「答え」（分析画面）      ← §4
第2層  職業別の追加入力                 ← §3
第1層  共通コア（全職業で同一）          ← §2
```

**第1層は全職業でまったく同じです。** ここを職業別に変えないでください。

---

## 2. 第1層：共通コア（全職業で同一）

| 区分 | 項目 |
|---|---|
| 声 | 喉の身体感覚 / 声の出来 / 起き抜けの音名 / ルーティン後の音名 / **弱声の最高音** / 症状8種 |
| 睡眠 | 睡眠時間 / 就寝時刻 / 睡眠の質 |
| 水分 | 合計 ml |
| 食事 | 夕食時刻 / 夕食→就寝の間隔 / 夕食タグ / タンパク質 g/kg / 概算kcal |
| 環境 | 気温 / 湿度 / 絶対湿度 / 気圧（自動取得） |
| 活動 | 種別 / 時間 / レパートリー（活動ブロックごと） |
| メンタル | 心の余裕 |
| 身体 | 体重（週1） |

**共通コアだけで、偏差値・予報・ラグ相関・効いた習慣・症状カレンダー・
ウォームアップ効率・音域マップ・ACWR が動きます。**

## 3. 第2層：職業別の追加入力

**すべて活動ブロックの中に置きます**（曲目複数化パッチ §2.0.2）。
1日に2現場あれば、それぞれのブロックに入ります。

### 3.1 声楽家・ミュージカル

| 項目 | 型 | 備考 |
|---|---|---|
| 演目・役 | レパートリー参照 | 実装済み |
| テッシトゥーラ / 最高音 | MIDI | 実装済み |
| **パッサッジョの通過感** | 1–5 | **声楽家にしかない指標。既存 LoadTracker にあり** |
| 声区の切り替えの滑らかさ | 1–5 | |
| 発声ルーティンの長さ | 分 | ウォームアップ効率と対応 |
| 会場の響き | 3択（デッド/普通/ライブ） | 響かない会場では張り上げる＝負荷増 |
| 衣装の締め付け | 3択（なし/やや/強い） | **コルセット等は呼吸を制限する。見落とされやすい** |
| 立ち位置 | 3択（前方/中央/後方） | オケとの距離 |

### 3.2 アナウンサー・ナレーター

| 項目 | 型 | 備考 |
|---|---|---|
| 番組・案件 | レパートリー参照 | |
| 発話時間の内訳 | 放送 / 収録 / 会議 / 電話（各 分） | **放送外が抜けると負荷を大きく見誤る** |
| 生放送か | boolean | 緊張で発声が硬くなる |
| 話速 | 3択（早口/普通/ゆっくり） | 原稿の文字数でも可 |
| **話声位（SFF）** | Hz | **毎朝＋終業後、定型文3秒の録音から自動算出。この職業の看板** |
| 周囲騒音 | 3択（スタジオ/中継/屋外） | ロンバード効果 |
| 環境 | 乾燥 / 空調直撃 / マスク着用（複数選択） | 放送スタジオは極端に乾燥する |
| 読み間違い・噛みの回数 | 数値（概算） | **疲労の直接的なパフォーマンス指標** |

### 3.3 声優

| 項目 | 型 | 備考 |
|---|---|---|
| 収録種別 | アニメ / ゲーム / 吹替 / ナレーション / ラジオ / イベント | ゲームのバトルボイスが突出して重い |
| **叫び・悲鳴のテイク数** | 数値 | **最重要。これ1つで翌日がほぼ決まる** |
| 声質の種類 | 複数選択（地声寄り/高め/低め/裏声/エッジ・フライ/ダミ声） | 負荷係数の算出に |
| 役・作品 | レパートリー参照 | |
| 役のピッチ帯 | MIDI 範囲 | 常用音域からの乖離を見る |
| 収録時間 / 拘束時間 | 分 / 分 | **待機だけでも疲れるかを分離する** |
| ブースの湿度 | % または3択 | |
| 歌の仕事 | boolean | 歌手側のエンジンに切り替える |

### 3.4 ポップス／ロック

| 項目 | 型 | 備考 |
|---|---|---|
| セットリスト | レパートリー配列（順序つき） | 実装済み |
| 曲の最高音 / ベルト・シャウト有無 | MIDI / boolean | |
| シャウト・グロウル | 有無 ＋ 回数 | ラフな発声は別カテゴリの負荷 |
| **モニター環境** | 3択（インイヤー/ウェッジ/なし） | **モニターが悪いと声を張る。効果が大きい** |
| ステージ音量 | 3択 または dB | |
| ツアー何日目 | 自動計算 | 連戦の開始日だけ入力 |
| 移動時間 / 手段 | 分 / 3択 | 車中泊・夜行バスは睡眠に直撃 |
| 会場環境 | 乾燥 / スモークマシン / 空調 | スモークは実際に喉に来る |
| **打ち上げ** | 参加 / 騒がしさ / 飲酒 | **実はここが最大の隠れ負荷** |

## 4. 第3層：職業別の分析（専門性を出す）

**分析画面の「本番に向けて」セクションの中身が、職業で入れ替わります。**

### 4.1 声楽家・ミュージカル

| 指標 | 内容 | 必要件数 |
|---|---|---|
| **ピーキング曲線** | 本番日を0にそろえた重ね合わせ平均 | 本番 3件 |
| **パッサッジョの安定度** | 通過感の28日中央値と MAD。`z ≤ −1.5` が3日続いたら知らせる | 14日 |
| **弱声の最高音の推移** | 平常値との差。むくみの早期サイン | 3日 |
| **役ごとの負荷ランキング** | 実測の落ち込み順＋計算負荷を併記 | 役ごと3回 |
| **衣装・会場の効果量** | 締め付け強／デッドな会場 の翌日への影響 | 各群3日 |
| 音域の上下端の推移 | 疲労で上下とも狭くなる | 14日 |

**専門性の出し方**：「パッサッジョ」「テッシトゥーラ」という語をそのまま使ってください。
声楽家は日常的に使う言葉で、これがあるだけで「わかっている人が作った」と伝わります。

> 「パッサッジョの通過感が、あなたの平常より低い日が4日続いています。
> 同じ期間、前夜の睡眠が平均5.8時間でした。」

### 4.2 アナウンサー・ナレーター

| 指標 | 内容 | 必要件数 |
|---|---|---|
| **話声位の日内変動** | 朝と終業後の SFF の差。**上がる人と下がる人がいて、方向自体が個人の特性** | 14日 |
| **声のゴールデンタイム** | 時間帯別の声の出来。大事な収録をいつ入れるか | 記録21件 |
| **音域幅の週次トレンド** | 疲労で上下とも狭くなる | 4週 |
| **番組別の負荷ランキング** | この番組の翌日は落ちる | 番組ごと3回 |
| **騒音環境の効果量** | 中継の日 vs スタジオの日 | 各群3日 |
| **噛みの回数との関係** | 睡眠・発話時間・話声位との相関 | 14日 |

**話声位の計算**

```
毎朝と終業後、同じ定型文を3秒読む
  → 自己相関または YIN で F0 を推定
  → 有声区間の中央値を SFF とする（平均ではなく中央値。外れ値に強い）

日内変動 Δ = SFF(終業後) − SFF(朝)

平常値との比較（頑健統計）
  m = 中央値(Δ)  直近28日
  MAD = 中央絶対偏差
  z = 0.6745 × (Δ − m) / MAD
```

> 「あなたは仕事終わりに話声位が平均12Hz下がります。
> 今日は28Hz下がっていて、この2週間で最大の落ち方です。」

### 4.3 声優

| 指標 | 内容 | 必要件数 |
|---|---|---|
| **回復曲線** | 激しい収録日を0として、+1/+2/+3日の戻り | 該当収録 3件 |
| **叫びテイク数の閾値** | 変化点検出で個人の限界を出す | 該当収録 8件 |
| **役ごとの負荷ランキング** | | 役ごと3回 |
| **声質係数の較正** | 叫び5.0などの初期値を実データで推定し直す | 20日 |
| 拘束時間と実発声時間の分離 | 待機だけでも疲れるのか | 14日 |
| 役のピッチ帯の乖離 | 常用音域からの距離が翌日に効くか | 役ごと3回 |

**回復曲線の計算**

```
「激しい収録日」の定義：叫びテイク数がその人の75パーセンタイル以上
  または 声質に「叫び」「悲鳴」を含む

その日を τ=0 として、τ=+1, +2, +3 の喉コンディションの偏差を重ね合わせ平均
完全回復＝偏差が 0 に戻った最初の τ
```

**専門性の出し方**：業界の実感に数字を与えてください。

> 「あなたは叫びの収録から**完全に戻るまで平均2.3日**かかります。
> 明後日のオーディションまでには戻り切りません。」

**叫びテイク数の閾値**

```
テイク数 x と 翌日の偏差 y の散布図に、折れ線（区分線形）を当てる
  y = a            (x ≤ k)
  y = a − b(x − k) (x > k)
k をグリッド探索で推定（1〜50テイク）。b > 0 かつ n ≥ 8 のときだけ表示
```

> 「あなたの限界は**叫び18テイク**あたりです。
> それを超えた5回の収録では、すべて翌日の声が2段階以上落ちています。」

### 4.4 ポップス／ロック

| 指標 | 内容 | 必要件数 |
|---|---|---|
| **ツアー耐久曲線** | ツアー初日を0にそろえた重ね合わせ平均 | ツアー 2本 |
| **セットリスト診断** | 曲順による負荷の偏り。入れ替えの提案 | 即時（計算のみ） |
| **キー下げ提案** | 快適音域の上限を超える曲を指摘 | 即時 |
| **モニター環境の効果量** | インイヤー vs ウェッジ | 各群3日 |
| **打ち上げの効果量** | | 各群3日 |
| 移動の効果量 | 夜行バス・車中泊 | 各群3日 |

**セットリスト診断**

```
曲 i の負荷 L_i（レパートリー負荷パッチ §1.2 の songFactor × 曲長）
連続する3曲の移動和 W_j = L_j + L_{j+1} + L_{j+2} を計算

max(W) が全体平均の 1.4 倍を超える箇所を「山」として指摘
入れ替え候補：山の中の最大 L の曲と、谷の中の最小 L の曲を交換したときの max(W) の改善量
```

> 「3曲目と4曲目が連続で重く、ここで一度声が消耗します。
> 5曲目の『◯◯』と入れ替えると、後半の負荷が15%下がります。」

## 5. 負荷計算（職業別の係数）

**ACWR のエンジンは共通。`L_d` の出し方だけが職業で変わります。**

```
共通： A_t = λ_a·L_t + (1−λ_a)·A_{t−1}    λ_a = 2/(7+1)
       C_t = λ_c·L_t + (1−λ_c)·C_{t−1}    λ_c = 2/(28+1)
       ACWR = A_t / C_t
```

| 職業 | `L` の式（活動ブロックごとに計算して合算） |
|---|---|
| 声楽家 | 時間 × 活動係数 × songFactor × 会場係数 × 衣装係数 |
| アナウンサー | 発話時間合計 × 話速係数 × 騒音係数 × (生放送 1.2) |
| 声優 | Σ(テイク数 × 声質係数) ＋ 拘束時間 × 0.2 |
| ポップス/ロック | Σ(songFactor × 曲長) × モニター係数 × 連戦係数 |

**係数の初期値**

```
活動係数   休養 0 / 自主練 1.0 / レッスン 1.2 / リハ 1.3 / 本番 1.6
会場係数   デッド 1.15 / 普通 1.0 / ライブ 0.95
衣装係数   強い 1.10 / やや 1.05 / なし 1.0
話速係数   早口 1.15 / 普通 1.0 / ゆっくり 0.9
騒音係数   屋外 1.3 / 中継 1.2 / スタジオ 1.0
モニター係数 なし 1.25 / ウェッジ 1.10 / インイヤー 1.0
連戦係数   1 + 0.03 × (ツアー日目 − 1)、上限 1.3

声質係数   ナレーション 0.8 / 通常の芝居 1.0 / 張り上げ 3.5
           叫び 5.0 / 悲鳴 6.0 / ダミ声・エッジ多用 4.0
```

**すべて仮置きです。** データが貯まったら実測から推定し直してください
（レパートリー負荷パッチ §6 と同じ手順）。

## 6. 表示のルール

### 6.1 用語を職業の言葉に翻訳する

| 内部の概念 | 声楽家 | アナウンサー | 声優 | ポップス/ロック |
|---|---|---|---|---|
| イベント | 本番 | 放送・収録 | 収録 | ライブ |
| 演目 | 曲目・役 | 番組・案件 | 役・作品 | セットリスト |
| 練習 | 自主練習 | 原稿読み | 練習 | リハ |
| 逆算画面 | ピーキング曲線 | ゴールデンタイム | 回復曲線 | ツアー耐久曲線 |

**翻訳テーブルは1つの定数ファイルに集約**してください。

### 6.2 専門用語は使ってよい。医学用語は使わない

**その職業の人が日常的に使う言葉は、積極的に使ってください。**
パッサッジョ、テッシトゥーラ、ベルティング、話声位、バトルボイス——
これらは職業の言葉であり、専門性の証明になります。

**一方、医学用語と診断表現は禁止です**（国際展開仕様 §5.2）。

> ✓ 「パッサッジョの通過感が平常より低い日が4日続いています」
> ✗ 「声帯のむくみが疑われます」

### 6.3 件数の門番

**§4 の「必要件数」に達するまでは、ぼかして進捗バーを出す**
（灰色の「データ不足」は禁止）。

## 7. データモデル

```ts
type ProfessionKey = 'classical' | 'announcer' | 'voice_actor' | 'popular'

interface Profile {
  professions: ProfessionKey[]     // ★複数選択
  primaryProfession: ProfessionKey // 表示のプリセットに使う
  // ...
}

// 職業別の項目は、活動ブロックの中に置く
interface Activity {
  id: string
  kind: ActivityKind
  minutes: number
  items: ActivityItem[]

  // 声楽家
  passaggio?: 1|2|3|4|5
  registerSmoothness?: 1|2|3|4|5
  warmupMinutes?: number
  hallAcoustics?: 'dead' | 'normal' | 'live'
  costumeTightness?: 'none' | 'some' | 'tight'

  // アナウンサー
  speechMinutes?: { broadcast?: number; recording?: number; meeting?: number; phone?: number }
  isLive?: boolean
  speechRate?: 'fast' | 'normal' | 'slow'
  noiseEnv?: 'studio' | 'remote' | 'outdoor'
  stumbleCount?: number

  // 声優
  recordingType?: 'anime' | 'game' | 'dub' | 'narration' | 'radio' | 'event'
  screamTakes?: number
  voiceQualities?: VoiceQuality[]
  bookedMinutes?: number
  boothHumidity?: number

  // ポップス/ロック
  monitorType?: 'iem' | 'wedge' | 'none'
  stageVolume?: 'low' | 'mid' | 'high'
  tourDay?: number
  travelMinutes?: number
  travelMode?: 'train' | 'car' | 'night_bus' | 'flight'
  venueEnv?: VenueEnv[]
  afterparty?: { attended: boolean; noisy?: boolean; alcohol?: boolean }
  shoutCount?: number
}

// 話声位は声の記録エントリ側に持つ
interface VoiceEntry {
  // ...
  speakingF0Hz?: number   // 定型文の録音から算出
}
```

**すべて optional。** 職業が違えば埋まらないのが正常です。
**未入力を欠測として扱い、補完しないこと**（記録項目v2 §7 の pairwise deletion）。

## 8. 実装の順番

| 順 | 内容 | 規模 |
|---|---|---|
| 1 | §7 のデータモデル追加（すべて optional・追加のみ） | 2日 |
| 2 | §3 の入力UIを活動ブロックの中に配置（職業で出し分け） | 1週間 |
| 3 | §5 の負荷係数を定数ファイル化し、`L` の計算に反映 | 2〜3日 |
| 4 | **声優：叫びテイク数 → 翌日** の分析（§4.3） | 3〜4日 |
| 5 | **声優：回復曲線** | 3〜4日 |
| 6 | ポップス：セットリスト診断・キー下げ提案 | 1週間 |
| 7 | 声楽家：パッサッジョの安定度・衣装/会場の効果量 | 3〜4日 |
| 8 | アナウンサー：話声位の録音と算出 | 1〜2週間 |
| 9 | アナウンサー：日内変動・ゴールデンタイム | 3〜4日 |

**4 から始めてください。** 新しい入力は数値1つ、分析は既存の効果量エンジンの流用、
それでいて出てくる答えがその日から行動を変えます。

**8 の話声位は最後に。** 録音と F0 推定が必要で、この中では最も重い実装です。

---

## 9. Sonnet 5 への依頼のコツ

- **§0 を最初に読ませる。** 職業でデータを分けさせないこと。
  「職業ごとにテーブルを分けましょうか」という提案が来たら、§0 を根拠に断る
- 職業別の項目は**すべて活動ブロックの中**（§3 冒頭）。`DayRecord` 直下に置かせない
- §5 の係数は**すべて1つの定数ファイル**に。コードに直書きさせない
- §6.2 の言葉の使い分けを、分析画面を触るPRのレビュー観点にする
- §4 の「必要件数」に達しない指標は、**ぼかして進捗バー**。灰色の「データ不足」は禁止

## 注意書き

係数・閾値の初期値はすべて仮置きであり、実データによる較正が前提です。
分析結果は記録上の傾向であり、因果関係を示すものではありません。
職業の専門用語は使ってよいが、医学用語・診断表現は使わないでください。
