# La Voce「学ぶ」コンテンツ一式

「学ぶ」と「健康情報」を統合した学習セクションの記事データです。記事67本と、取り込みに必要な構造化データが入っています。

このREADMEはSonnet（実装担当）向けです。**まず `統合設計書.md` を読んでください。** 何を削除し、何を改題し、どこへ移設するかが書かれています。

---

## 1. 中身

```
README.md              ← このファイル
統合設計書.md          ← 統合の方針・削除判断・移設指示。実装前に必読
執筆規定.md            ← 今後記事を追加するときのトーン規定。踏襲すること
manifest.json          ← 章・職業タブの定義と、記事の並び順
articles.json          ← 全67記事の構造化データ（本文込み・単一ファイル）
content/learn/*.md     ← 記事ごとの個別ファイル（フロントマター付き・67本）
```

`articles.json` と `content/learn/*.md` は **同じ内容**です。取り込みやすいほうを使ってください。

- DBにシードする / APIで配る → `articles.json`
- ファイルベースのコンテンツコレクション（Next.js の MDX など）→ `content/learn/*.md`

## 2. スキーマ

### 記事（articles.json の `articles[]` / 各mdのフロントマター）

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | 記事ID。`C1-1`, `V-2`, `A-5`, `S-3`, `P-8` の形式。**安定キーとして扱ってください**（本文中の相互参照がこのIDを使っています） |
| `title` | string | 記事タイトル |
| `summary` | string | 記事一覧に出す1行説明。28字以内 |
| `chapter` | number | 章番号 1〜7 |
| `chapterId` | string | 章のスラッグ |
| `chapterTitle` | string | 章の表示名 |
| `scope` | `"common"` \| `"profession"` | 全職業共通か、職業別か |
| `professions` | string[] | 表示対象。共通記事は `["*"]`、職業別は職業ID1つ |
| `status` | enum | 下表参照 |
| `body` | string | 本文（Markdown）。個別mdではフロントマター以降が本文 |

### `status` の値と、実装時にすべきこと

| 値 | 件数 | 意味 |
|---|---|---|
| `new` | 58 | 新規記事。`body` をそのまま登録する |
| `existing_move` | 5 | **アプリ内に既存の本文がある。** `body` は指示文なので登録しない。既存本文をこの位置へ移すだけ |
| `existing_retitle` | 2 | 既存記事。本文は流用し、**タイトルだけ `title` の値に差し替える** |
| `existing_merge` | 1 | C2-1のみ。重複していた2記事を統合する。`body` の指示に従うこと |
| `new_replacement` | 1 | C4-8のみ。既存記事を削除して、これに置き換える。`body` の冒頭に理由を記載 |

`new` 以外の5本は `body` が本文ではなく**実装への指示文**です。そのまま記事として公開しないでください。

### 章の定義（manifest.json の `chapters[]`）

| # | chapterId | 表示名 |
|---|---|---|
| 1 | `the-voice-of-this-job` | この仕事の声 |
| 2 | `what-wears-the-voice` | 何が声を削るか |
| 3 | `reading-the-numbers` | アプリの数字の読み方 |
| 4 | `care` | 整える |
| 5 | `protect` | 守る |
| 6 | `when-it-persists` | 続くときは |
| 7 | `glossary` | 用語 |

### 職業タブ（manifest.json の `professions[]`）

| professionId | 表示名 | 記事の接頭辞 |
|---|---|---|
| `classical-musical` | 声楽家・ミュージカル | V |
| `announcer` | アナウンサー・ナレーター | A |
| `voice-actor` | 声優 | S |
| `pops-rock` | ポップス／ロック | P |

共通記事の接頭辞は `C` です。

## 3. 表示のしかた

`manifest.json` の `tabs` に、**職業タブごと・章ごとの記事IDの並び順**が入っています。この順序をそのまま使ってください。

```json
"tabs": {
  "classical-musical": [
    { "chapter": 1, "chapterId": "the-voice-of-this-job",
      "chapterTitle": "この仕事の声",
      "articles": ["V-1", "V-2", "V-3", "C1-1", "C1-2"] }
  ]
}
```

並び順のルールは以下のとおりです。

- **職業別記事が先、共通記事が後。** その職業のユーザーにとって固有性が高いものを上に置きます
- 共通記事には一覧上で「共通」のラベルを付けて区別してください
- 各タブは7章すべてが埋まっています

### 章の非表示ルール（必須）

**記事が0件の章は、章ごと非表示にしてください。** 現在のアプリは7章中5章が空で、
「まだ記事がありません」という表示が5連続で並んでいます。今回の記事投入でこれは解消されますが、
今後タブや章を追加したときに同じ状態が再発しないよう、仕組みとして入れてください。

## 4. 本文中の相互参照

本文には `→ C4-3` `C2-1 をご覧ください` といった形で、他の記事への参照が埋め込まれています。
これらは **記事IDへのリンクとしてレンダリングしてください。**

用語集（C7-1）は特に参照が多く、ほぼ全項目が他記事へのリンクを持っています。

分析カードから記事へのリンク（「これで何が分かるの？」→ 第3章の各記事）の対応表は、
`統合設計書.md` の第5章にあります。

---

## 5. 本文を扱うときの注意

記事は医学・生理学に関わる内容を含みます。以下を守ってください。

- **本文を要約・改変しないこと。** 断定を避ける言い回し（「〜と言われています」）は意図的なものです。
  簡潔にする目的でこれを断定形に直さないでください
- **受診を促す締めの一文を削らないこと**
- **出典や研究を追加しないこと。** 本文には具体的な論文・研究の引用を一切入れていません。
  根拠を補強する目的であっても、確認できない出典を足さないでください
- 新しい記事を書き足す場合は、必ず `執筆規定.md` に従ってください

**公開前に、音声を専門とする医師または言語聴覚士による監修を受けることを推奨します。**
記事は一般に知られている知見の範囲で書かれていますが、専門家の確認を経ていません。

---

## 6. 実装の順序（推奨）

1. `統合設計書.md` を読み、削除・改題・移設の対象を把握する
2. 「健康情報」メニューを廃止し、「学ぶ」に一本化する
3. 「── からだ（全職業共通）──」セクションを削除する（記事重複の原因）
4. 空章の非表示ルールを実装する
5. `articles.json` または `content/learn/*.md` を取り込み、`manifest.json` の順序で表示する
6. `status` が `new` 以外の5本を、指示に従って個別に処理する
7. 本文中の相互参照をリンクとしてレンダリングする
8. 分析カードから第3章の記事へのリンクを張る（設計書 第5章の対応表）
9. 「今日の記録」の音名ルール長文を「？」に畳み、C3-3 へリンクする（設計書 4-3）
