# La Voce ／ 羊のおうち 実装仕様

「おうち」タブのゲーム性と、ビジュアル品質を上げるための仕様。
**方式はプリレンダー3D（Blenderで作り、透過PNGに焼く）を採用します。**

---

## 0. この文書について

### 2つのレーン

| レーン | 担当 | 内容 |
|---|---|---|
| **A** | Claude Sonnet 5 | コード。演出、層構造、アセット差し替え機構、ポイント設計 |
| **B** | 坂本さん | **3Dアセットの制作**（Blender／AI生成／購入）。Sonnet には作れません |

**Sonnet はレーンAだけを実行してください。** アセットが未着でも、
**§2 と §4 は先に実装できます**（現状の2D画像のまま動きます）。

### 進め方

```
Stage A  いまの2Dを直す（アセット不要・今週）      ← ここから
Stage B  プリレンダー3Dへ段階移行（カテゴリ単位）
Stage C  ゲーム性の強化                          ← Stage A と並行可
```

**Stage A の層・影の設計は、Stage B でもそのまま使えます。** 無駄になりません。

## 1. 絶対に壊さない3つの原則

現状の実装には、**すでに正しい判断が含まれています。** 変更しないでください。

### 原則1 ｜ ポイントは体調に連動させない

> 現状の文言：「ポイントは『記録を続けたかどうか』だけで貯まり、
> 体調そのものの良し悪しでは変わりません」

**これは維持します。** 体調でポイントが増減すると、
**調子が悪い日に罰を与えるアプリ**になります。声のプロは本番期に必ず崩れる日があり、
そこで羊がしおれたら記録をやめます。

### 原則2 ｜ 罰を作らない（§5 に詳細）

連続記録が途切れても、**羊はしおれない／去らない／アイテムは失われない／ポイントは減らない。**

### 原則3 ｜ 品位を守る（§6 に詳細）

**レッスンモード・受診用サマリー・指導者ダッシュボードには、羊を出しません。**
医師や先生に見せる場面で羊が出ると、道具としての信頼が落ちます。

## 2. Stage A ｜ いまの2Dを直す（アセット不要・2〜3日）

**アセット制作を待たずに、今週できます。** 効果はこの中で最も大きい部類です。

### 2.1 接地の影（最優先）

現状、家具も羊も床から浮いて見えます。**楕円のソフトシャドウを1枚敷くだけ**で、
劇的に「置いてある」感が出ます。

```
影の仕様
  形    : 楕円
  幅    : アイテム幅 × 0.85
  高さ  : 幅 × 0.22
  位置  : アイテムの接地点（bottom）に中心を合わせ、y を +2px
  色    : rgba(70, 45, 30, 0.18)
  ぼかし : 6px
```

**壁掛け・窓のアイテムには影を付けない**（`anchor: 'wall'`）。

### 2.2 奥行きを3層に固定する

現状は全アイテムが同じ平面にあり、お部屋の床にラグが4枚横一列に並んでいます。

```ts
type Layer = 'back' | 'mid' | 'front'
```

| 層 | 内容 | スケール | z-index |
|---|---|---|---|
| `back` | 壁・窓・木立・柵・壁掛け | 0.85 | 10 |
| `mid` | 家具・噴水・ベッド・本棚 | 1.00 | 20 |
| `front` | ラグ・池・ベンチ・**羊** | 1.15 | 30 |

**アイテムは自分の層の中でだけ左右に動かせる。** 層をまたぐドラッグは禁止。

### 2.3 柵と羊の重なりを直す

**お庭で、柵の線が羊の腰を横切っています。**
羊は必ず `front` 層に固定してください（`z-index: 30`）。

**ここが崩れていると、一気に「作りかけ」に見えます。** 最優先で直すこと。

### 2.4 配置のスナップ

自由ドラッグをやめ、**層ごとに横方向のグリッドへスナップ**させます。

```
グリッド：層の幅を 12 分割
同じマスに2つ置けない（押しのけるか、隣の空きマスへ）
```

これで「ラグが4枚重なって並ぶ」ような状態がなくなります。

### 2.5 光（余裕があれば）

窓から床へ落ちる光の台形を1枚。夜は月明かりの青。

```
昼：rgba(255, 214, 140, 0.16)
夜：rgba(150, 180, 235, 0.12)
```

窓の景色（現状すでに夜空／昼空がある）と同期させること。

## 3. Stage B ｜ プリレンダー3Dへの移行

### 3.1 方式

**「見た目は3D、中身は2D」。** Blender で作り、透過PNGに焼いて、
**ランタイムは現状のまま2D**にします。

- WebGL / Three.js は**導入しません**
- バンドルは増えず、起動は速く、電池も食わない
- **毎朝30秒開くアプリなので、ここは譲れません**

### 3.2 レンダリング規約（レーンB・坂本さん）

**全アイテムを同じシーン設定で撮ることで、スタイルが自動的に揃います。**
これがこの方式の最大の利点なので、**シーンは1つだけ作り、以後変更しないでください。**

```
■ カメラ
  種類    : 正射投影（Orthographic）
  角度    : 正面からわずかに見下ろす（X回転 ≒ 78°）
            ※ 現在の絵の構図に合わせる。アイソメトリックにしない
  Z回転   : 0°（真正面）

■ ライト
  キー    : 左上前方45°、暖色（約5500K）、ソフトシャドウ
  フィル  : 環境光（弱い・やや青）
  ※ この3点を固定。アイテムごとに変えない

■ 出力
  形式    : 透過PNG（@2x／Retina想定）
  影      : 3Dの落ち影は焼き込まない。接地影は §2.1 のCSSで付ける
            （層構造と整合させるため）
  背景    : 完全透過
```

**接地影を焼き込まない**のが要点です。CSSの影なら層とスケールに追随できます。

### 3.3 サイズ規約

カテゴリごとに出力サイズを固定してください。

| カテゴリ | 出力（@2x） |
|---|---|
| 帽子・持ち物 | 128 × 128 |
| 服 | 256 × 256 |
| 家具・庭の置物 | 320 × 320 |
| 床・壁・窓枠・庭の景観 | タイル or 全面。個別に決める |
| 羊 | 384 × 384 |

### 3.4 ファイル名規約

```
/assets/home/{category}/{itemKey}@2x.png
/assets/home/sheep/{state}_{frame}@2x.png
```

### 3.5 アセット差し替え機構（レーンA・Sonnet）

**移行中の混在を管理するための仕組みです。** これを先に作ってください。

```ts
type RenderStyle = '2d' | 'prerender3d'

interface ItemAsset {
  key: string
  category: ItemCategory
  layer: Layer                       // §2.2
  anchor: 'floor' | 'wall' | 'sheep' // 影の付け方（§2.1）
  render: RenderStyle                // ★移行の管理
  src: string
  width: number
  height: number
}
```

**カテゴリ単位で `render` を切り替えます。**

> **混在は危険です。** 半分3D風・半分フラットは安っぽく見えます。
> **アイテム単位ではなくカテゴリ単位で切り替え**、
> そのカテゴリの全アイテムが揃うまで `'2d'` のままにしてください。

**推奨の移行順**

```
1. 羊             ← 主役だけ質感が上がると、全体が引き上がって見える
2. 家具
3. 床・壁
4. 庭
5. 帽子・服・持ち物
```

### 3.6 羊のスプライトアニメーション

**プリレンダーの最大の利点がここです。** 数フレーム書き出すだけで、生きて見えます。

| 状態 | フレーム | 用途 |
|---|---|---|
| `idle` | 3 | 通常。ゆっくりループ（呼吸） |
| `happy` | 4 | 記録した直後、アイテムを受け取ったとき |
| `sleep` | 2 | 深夜 |
| `react` | 4 | タップされたとき |

実装は CSS の `steps()` アニメーションで十分です。動画やWebGLは不要。

**`prefers-reduced-motion` では `idle` の1フレーム目で静止**させてください。

## 4. Stage C ｜ ゲーム性の強化（アセット不要・Sonnet）

### 4.1 記録した瞬間の演出 ★最優先

**いまの最大の機会損失です。** 記録を保存しても、
おうちに移動しないとポイントが増えたことがわかりません。
**行動と報酬が切り離されています。**

```
記録の保存成功 → その場で（おうちに遷移せずに）

  0.0s  「+3pt」のチップが保存ボタンの上に出現
  0.2s  画面右下（おうちタブの方向）へ弧を描いて飛ぶ
  0.6s  画面下端から羊が 0.4s だけひょこっと出て、受け取って引っ込む
  1.0s  下に「あと3ptで麦わら帽子」を表示（§4.2）
```

**合計1秒。おうちタブには遷移させない。** 記録の流れを止めないこと。

`prefers-reduced-motion` では、静的な「+3pt」表示と次の目標だけを出す。

### 4.2 「次の目標」の出し方

**目標が見えていると、次の記録が「あと3ptの行為」になります。**

```
未購入アイテムのうち、(必要pt − 所持pt) が正で最小のものを1つだけ出す。
同点なら、装備カテゴリ（帽子・服・持ち物）を優先する
  → 羊に直接見えるため、動機が強い
```

**必ず1つだけ。** 複数出すと、どれも目指されません。

### 4.3 買う瞬間の儀式

現状はリスト横の「装備する」だけで、**買った実感が薄い**です。

```
  0.0s  購入 → 包みが出る
  0.6s  タップで開く
  1.4s  羊が受け取る／被る（happy アニメーション）
  2.6s  「いま着せますか？」「いま置きますか？」を表示（スキップ可）
```

**購入から装着までを、途切れさせないこと。** いまは分断されています。

### 4.4 羊の反応

**タップで反応する。** 実装が軽く、効きます。

```
react のバリエーションを3〜5種持ち、ランダムに選ぶ
  ただし直前と同じものは出さない（毎回同じだと2日で飽きる）
```

**時間帯で状態が変わる**（ユーザーのローカル時刻で判定）。

| 時間帯 | 状態 |
|---|---|
| 5:00–10:00 | `idle`（起きたところ） |
| 10:00–17:00 | `idle`（座る／立つ） |
| 17:00–23:00 | `idle`（くつろぐ） |
| 23:00–5:00 | `sleep` |

**体調・スコアには一切連動させないこと**（原則1）。

### 4.5 累計で育つ木（新規・強く推奨）

**連続記録は必ず途切れます。** そして途切れた瞬間が、
いちばんアプリを閉じたくなる瞬間です。

**なので、途切れないものを別に持ちます。**

お庭に木を1本。**累計の記録日数**で育ちます。

| 累計記録日数 | 姿 |
|---|---|
| 0–6 | 芽 |
| 7–29 | 若木 |
| 30–99 | 花が咲く |
| 100–364 | 実がなる |
| 365– | 大樹 |

**連続記録が途切れても、木は絶対に後退しません。**

> 「連続記録は途切れるけれど、木は裏切らない」

これがあると、**7日ぶりに開いた人が、責められずに戻ってこられます。**
木は購入不可・移動不可の固定オブジェクトにしてください。

### 4.6 ポイントの貯まり方

**体調に連動させない原則を守ったまま、種類だけ増やします。**

| きっかけ | pt |
|---|---|
| その日の記録 | +3 |
| 7日そろった週 | **+10**（週の初めに予告を出す） |
| 初めて使った項目 | +5（探索を促す） |
| 月初に開いた | +5 |

**「予告しておく」のが重要です。** 予測できる報酬は、待つこと自体が楽しみになります。

**1日の上限を +20 に設定してください**（連打・不正対策）。

### 4.7 表示の階層を直す

現状は「72／6／6」が同じ大きさで並んでいて、どれが主役かわかりません。

```
所持ポイント     72        ← 32px、主役
                            ↑ここだけ大きく

連続 6日 ・ 最長 6日 ・ 累計 6日   ← 14px、muted、1行にまとめる
```

**累計記録日数を追加してください**（§4.5 の木と対応させるため）。

## 5. 罰を作らない設計（明文化）

**以下を実装上の禁止事項として守ってください。**

- ❌ 連続記録が途切れたとき、羊がしおれる・悲しむ・去る
- ❌ ポイントが減る、アイテムが失われる
- ❌ 「連続記録が途切れました」という通知やバナー
- ❌ 「◯日サボりました」「久しぶりですね（責める調子）」
- ❌ 体調スコアが低い日に、羊の様子が悪くなる

**久しぶりに開いた日の扱い**

```
✓ 「おかえりなさい」だけ。日数を数えない
✓ 木は前回のまま（後退しない）
✓ 羊はいつもどおり idle
```

**これは優しさではなく、設計上の要請です。**
体調が悪い日に追い打ちをかけるアプリは、いちばん必要なときに使われなくなります。

## 6. 品位を守る

**次の画面には、羊・ポイント・おうちへの導線を出さないでください。**

- レッスンモード（週次カルテ見直しパッチ §4）
- 受診用サマリー（同 §5）
- 指導者ダッシュボードと、生徒個別ページ
- 達成カードの共有画像（同 §6）

**設定に「おうちを表示しない」を用意**してください。
羊を必要としない層（医師に見せる前提で使う人、指導者）が確実に存在します。
オフにしたらタブごと消す。

## 8. アセット制作について（レーンB・参考）

**Sonnet は3Dアセットを作れません。** ここは坂本さんの作業になります。

- AI生成（Meshy / Tripo / Rodin など）でメッシュを作り、Blenderで整えてレンダー
- ただし**生成されたメッシュはそのままでは使えません**。スケール調整と見た目の整えが要ります
- **プリレンダー方式なら、コリジョン・リグ・エンジンの光との不一致は発生しません**
  （AI生成の面倒な部分の大半を回避できます）
- 見積もり：シーン構築 1〜2日／アイテム1点あたり 20〜60分

**まず羊1体だけ**作って、いまの2D背景に置いてみてください。
主役の質感が上がると、全体が引き上がって見えます。**そこで判断してから広げる**のが安全です。

## 9. Sonnet 5 への依頼のコツ

- **§1 の3原則を、レビュー観点として毎回渡す。**
  特に「ポイントを体調に連動させない」は、
  「調子が良い日はボーナス」という提案が出やすいので明示的に禁止すること
- **§5 の禁止事項を実装前に読ませる。**
  ストリーク系の機能は、罰を作る方向に流れやすい
- **Stage A（§2）と Stage C（§4）を先に。** アセットを待たない
- **§3.5 の `render` フラグはカテゴリ単位。** アイテム単位で切り替えさせない
- 演出はすべて `prefers-reduced-motion` に対応させる
- WebGL / Three.js を**導入させない**（§3.1）。提案が来たら §3.1 を根拠に断る
- レーンB（アセット制作）には手を出させない
