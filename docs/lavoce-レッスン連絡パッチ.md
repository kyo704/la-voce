# La Voce ／ レッスンの連絡（定型連絡とスタンプ）

**指導者プラン実装仕様 §8「メッセージを作らない」を、
「定型連絡は作る／自由記述は作らない」に書き換えます。**

**教室プラン仕様 §12 のスコープ外の記述も、本書に合わせて更新してください。**

| | |
|---|---|
| 統合実行ルート v4 での位置 | **G4 の 27（レッスン日程）の直後。** それより前に着手しない |
| 前提 | `Lesson` が実装済みであること（教室プラン仕様 §5.1） |

---

## 0. 結論

| | 判断 |
|---|---|
| **定型の連絡**（遅れます・到着しました・ありがとうございました） | **作る** |
| **羊のスタンプ**（5種） | **作る** |
| **自由記述のメッセージ・チャット・DM** | **作らない。恒久的に** |
| 欠席の理由の選択 | **作らない**（§4-2） |
| 既読表示 | **作らない**（§5-3） |

---

## 1. なぜ方針が変わったのか（実装者向けの説明）

**指導者プラン実装仕様 §8 で「メッセージ機能を作らない」と決めた理由は5つありました。**
そのうち最も重い理由は、**大人と未成年が1対1でやり取りできる非公開の場を作ってしまうこと**でした。

**本書で作るものは、その場を作りません。**

```
❌ 自由に文章を書ける箱   → 何でも書ける。閉じた1対1の場になる
✅ 決まった連絡を押すだけ  → 「到着しました」で誰かを傷つけることはできない
```

**選択肢が固定されている限り、モデレーション・通報・保護者同意の設計義務は発生しません。**
危険なのは自由記述であって、連絡そのものではありませんでした。

**§8 の他の理由（LINEに勝てない・届いたかの責任）は、本書の §5 と §7 で個別に対処します。**

---

## 2. これは LINE に勝とうとする機能ではありません

**チャットとしては LINE に勝てません。** そこは §8 のままです。

**勝てるのは別のところです。**

```
LINE で「遅れます」    → 会話が流れて、消える
La Voce で「遅れます」 → その日の出欠の記録になる
```

**連絡が、そのまま運営の記録になる。** ここが教室にとっての価値です。
月謝の計算、振替の判断、出席の確認。いま手作業で管理されているものが、自動で残ります。

そして**先生は、連絡を見るために開いたついでに、その生徒の今週の状態を見ます。**
指導者プラン実装仕様 §7 で書いた「日程は導線である」と、同じ構造です。

## 3. 定型連絡の一覧（この通りに実装してください）

### 3-1｜生徒 → 先生

| key | 文言 | 追加入力 |
|---|---|---|
| `departed` | 出発しました | — |
| `late` | ◯分ほど遅れます | **5 / 10 / 15 / 30 から選ぶ** |
| `arrived` | 到着しました | — |
| `early` | 少し早く着きました | — |
| `absent` | 今日は伺えません | **理由は聞かない**（§4-2） |
| `thanks` | ありがとうございました | — |

### 3-2｜先生 → 生徒

| key | 文言 | 追加入力 |
|---|---|---|
| `comeSafe` | 気をつけてきてください | — |
| `confirmed` | 到着を確認しました | — |
| `running` | 少し押しています（◯分） | 5 / 10 / 15 / 30 |
| `teacherAbsent` | 本日はお休みします | — |
| `wellDone` | お疲れさまでした | — |
| `goHomeSafe` | 気をつけて帰ってください | — |

### 3-3｜羊のスタンプ（5種）

```
smile   にっこり
bow     おじぎ
wave    手を振る
sleep   寝ている
cheer   がんばれ
```

**文字では出せない温度が、ここで出ます。**
そして**スタンプに悪意を込めることはできません。**
「気をつけて帰ってね」の空気を、自由記述なしで作れる唯一の方法です。

**画像は羊のおうちの3Dアセットから書き出します**（羊のおうち仕様の表情差分と同じ素材）。
**新しいキャラクターを描き起こさないこと。**

### 3-4｜文言の追加について

**この一覧に文言を足す場合は、必ず坂本さんの承認を取ってください。**
Sonnet の判断で選択肢を追加しないこと。**1つ足すごとに、
「その言葉で人を傷つけられないか」の判断が必要になります。**

**i18n キーで持ち、全言語に用意してください**（多言語対応の完成 §7）。

## 4. ★ 守るべき線

### 4-1｜自由記述欄を、絶対に作らない

```
★2026年8月31日 追記
　ここで禁じているのは「生徒 ↔ 先生 の1対1の自由記述」です。ここは変わりません。

　lavoce-判断-門下の連絡板（8月31日）.md で、門下の全員が読む連絡板を作りますが、
　★欠席・遅刻・体調の連絡を、連絡板に書かせてはいけません。
　　それは定型連絡（§3）の役目です。定型連絡は先生1人にしか届きませんが、
　　連絡板は門下の20人に届きます。ここを混ぜると、体調が門下に漏れます。
　　連絡板に「休みます」の導線を作らないでください。
```

**「ひとこと添える」を1つ足した瞬間に、これはメッセージ機能になります。**
そうなったら指導者プラン実装仕様 §8 の5つの理由が全部戻ってきます。

```
❌ テキスト入力欄
❌ 「その他」を選ぶと自由入力
❌ スタンプに文字を重ねられる機能
❌ 数字の入力欄（遅刻の分数は「選択肢」であって入力欄ではない）
```

### 4-2｜★ 欠席の理由を選ばせない

**これが最も見落とされやすい落とし穴です。**

```
❌ 「体調不良のため欠席」  → 要配慮個人情報の取得になります
❌ 「風邪のため」「喉の調子が悪いため」
✅ 「今日は伺えません」    → 理由は聞かない
```

理由が必要なら、レッスンで口頭で話せば済みます。**アプリが記録すべきものではありません。**

**Sonnet が「理由の選択肢があると先生が助かります」と提案してきたら、
この項を根拠に断ってください。**

### 4-3｜集計して評価に使わない

出欠は記録に残しますが、**スコア化・ランク付けをしないこと。**

```
❌ 「遅刻率 12%」
❌ 「今月いちばん遅刻が多い生徒」
❌ 生徒一覧に遅刻回数のバッジを出す
✅ 出欠の履歴を、日付の一覧として見られる
```

**記録は運営のためのものであって、生徒を採点するためのものではありません。**

### 4-4｜1対1の非公開にしない

**教室の管理者にも見える形にしてください**（教室プラン仕様 §3 の「運営の面」）。

担当の先生と生徒だけの非公開にすると、結局そこが閉じた場になります。
**見られている場であることが、安全装置です。**

内容は定型文とスタンプだけなので、見られて困るものは何もありません。

## 5. 通知

### 5-1｜出し分ける

| 内容 | 通知 |
|---|---|
| `late` / `absent` / `running` / `teacherAbsent` | **すぐ通知（LINE連携があればLINE）** |
| `departed` / `arrived` / `early` / `thanks` / `comeSafe` / `confirmed` / `wellDone` / `goHomeSafe` / スタンプ | **通知しない。**次にアプリを開いたときに見える |

**「到着しました」で毎回プッシュが飛ぶと、2週間でうるさくなります。**
**そして通知が多いアプリは、通知ごと切られます。**

### 5-2｜時間の制限

```
・22:00〜07:00 は通知しない（翌朝まとめて）
・ただし「本日はお休みします」だけは、当日のレッスン開始2時間前までなら通知する
```

### 5-3｜既読表示を作らない

**「既読」を作ると、既読がついたかどうかを気にする関係が生まれます。**
そして**未読のまま遅刻した場合の責任**が発生します。

```
✅ 送った側に「届いています」とだけ出す
❌ 「既読」「未読」「◯時に読みました」
```

### 5-4｜届かなかったときの責任

**規約とヘルプに、次を明記してください。**

> レッスンの連絡は、確実な到達を保証するものではありません。
> 急ぎの連絡は、電話など確実な手段をお使いください。

**この一文がないまま出さないこと。**

## 6. 画面

### 6-1｜どこに出るか

**レッスンの詳細画面の中だけです。** 独立したタブや受信箱を作らないこと。

```
┌───────────────────────────────┐
│ ‹ 9月3日(火) 15:00             │
│ 山田先生 ・ ◯◯音楽教室        │
├───────────────────────────────┤
│                               │
│  15:12  出発しました      あなた│
│  15:14  🐑 手を振る       先生 │
│  15:38  10分ほど遅れます  あなた│
│  15:39  気をつけてきて…   先生 │
│                               │
├───────────────────────────────┤
│ ┌────────┬────────┬─────────┐ │
│ │ 出発   │ 到着   │ 遅れます │ │  ← 定型のボタン
│ ├────────┼────────┼─────────┤ │
│ │早く着いた│ありがとう│伺えません│ │
│ └────────┴────────┴─────────┘ │
│ 🐑 🐑 🐑 🐑 🐑                 │  ← スタンプ5種
└───────────────────────────────┘
```

**入力欄はどこにもありません。** ボタンとスタンプだけです。

### 6-2｜いつ操作できるか

```
レッスン開始の 24時間前 から、終了の 6時間後 まで
```

**それ以外の時間は、ボタンを出さないこと。**
**常時使える連絡手段にした瞬間に、チャットになります。**

履歴は残り、あとから読めます。**ただし追記はできません。**

### 6-3｜押し間違い

```
・送信の直後 60秒だけ「取り消す」が押せる
・取り消したものは履歴から消える（相手の通知は取り消せないと明示）
```

## 7. 出欠の記録（この機能の本当の価値）

**定型連絡から、出欠の状態を自動で決めてください。**

```ts
type Attendance = 'attended' | 'late' | 'absentStudent' | 'absentTeacher' | 'unknown'
```

| 判定 | 条件 |
|---|---|
| `absentStudent` | 生徒が `absent` を押した |
| `absentTeacher` | 先生が `teacherAbsent` を押した |
| `late` | 生徒が `late` を押した／`arrived` が開始時刻より後 |
| `attended` | `arrived` があり、遅刻でない |
| `unknown` | 何も押されなかった |

**`unknown` を「欠席」と扱わないこと。** 押し忘れは必ず起きます。
**先生が後から手で直せるようにしてください。**

**この記録は教室プラン仕様 §3 の「運営の面」に属します。**
健康の面ではありません。**staff にも見えて構いません。**

## 8. データモデル

```ts
type SignalKind =
  | 'departed' | 'late' | 'arrived' | 'early' | 'absent' | 'thanks'
  | 'comeSafe' | 'confirmed' | 'running' | 'teacherAbsent'
  | 'wellDone' | 'goHomeSafe'
  | 'stamp'

interface LessonSignal {
  id: string
  lessonId: string
  orgId: string
  senderId: string
  senderRole: 'teacher' | 'student'
  kind: SignalKind
  minutes?: 5 | 10 | 15 | 30        // late / running のときだけ
  stamp?: 'smile' | 'bow' | 'wave' | 'sleep' | 'cheer'   // kind==='stamp'
  createdAt: string
  retractedAt?: string              // 60秒以内の取り消し
}
```

**この型に `text` や `body` のような文字列フィールドを足さないこと。**
**足された瞬間に、この設計は崩れます。**

`minutes` は**列挙型**です。`number` にしないでください。任意の数値を入れられると入力欄になります。

## 9. スコープ外

| やらないこと | 理由 |
|---|---|
| **自由記述・チャット・DM** | §4-1 |
| 受信箱・メッセージ一覧タブ | 常時使える連絡手段になる（§6-2） |
| 既読表示 | §5-3 |
| 画像・音声・ファイルの送信 | モデレーションが必要になります |
| 欠席理由の選択 | §4-2 |
| グループ（複数の生徒への一斉連絡） | 別の設計。需要が出てから |
| 通話・ビデオ通話 | 既存ツールで足ります |
| 遅刻率・出席率のスコア表示 | §4-3 |

## 11. 禁止事項

- ❌ **自由記述欄をどこにも作らない**（§4-1）
- ❌ `LessonSignal` に文字列のフィールドを足さない（§8）
- ❌ **欠席の理由を選ばせない**（§4-2）
- ❌ 遅刻の分数を、自由に入力できる欄にしない（列挙型のまま）
- ❌ 定型文を、Sonnet の判断で追加しない（§3-4）
- ❌ **既読表示を作らない**（§5-3）
- ❌ 到着・お礼・スタンプで通知を飛ばさない（§5-1）
- ❌ 22:00〜07:00 に通知しない（§5-2）
- ❌ レッスンの前後の時間帯以外に、ボタンを出さない（§6-2）
- ❌ 独立した受信箱・メッセージタブを作らない
- ❌ **出欠をスコア化・ランク付けしない**（§4-3）
- ❌ `unknown` を欠席として扱わない（§7）
- ❌ 担当の先生と生徒だけの非公開にしない（§4-4）
- ❌ 到達を保証する表現を書かない（§5-4）

## 12. Claude Sonnet 5 への依頼のコツ

- **§8 の型を、そのまま実装させてください。** 特に `text` フィールドが増えていないかを、
  実装が上がるたびに目視で確認すること
- **「理由の選択肢があると先生が助かります」という提案が来たら、§4-2 を根拠に断る**
- **「既読があると安心です」という提案が来たら、§5-3 を根拠に断る**
- **「メッセージタブがあると探しやすいです」という提案が来たら、§6-2 を根拠に断る**
- 通知は**必ず出し分けさせる**（§5-1）。全部通知する実装が来たら差し戻すこと
- 日時は **UTC ＋ tz**（国際展開仕様 §2.3）
- 文言は **i18n キー**で持たせる。ハードコードさせない

## 注意書き

本書は指導者プラン実装仕様 §8 を書き換えます。
**§8 の「自由記述のメッセージ機能を作らない」という結論は維持されます。**
変わったのは「定型の連絡までは作ってよい」という部分だけです。

レッスンの連絡は、確実な到達を保証するものではありません。
その旨を規約とヘルプに明記してください（§5-4）。

**欠席の理由を記録しないこと。** 体調に関する理由を選ばせると、
それは要配慮個人情報の取得にあたり、同意と安全管理措置の対象が広がります（§4-2）。

未成年の利用者が含まれることを前提に設計してください。
**1対1の非公開のやり取りを作らないこと**が、この設計の核です。
