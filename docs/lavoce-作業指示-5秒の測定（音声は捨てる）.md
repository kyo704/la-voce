# La Voce ／ 週に一度、5秒の測定（★音声は捨てる）

**Claude Sonnet 5 へ。主観だけのモデルに、外から測った柱を1本立てます。**

読む順番：レッスンモードの解体.md §2〜§3（なぜ録音しないか）→ 本書。

---

## 0. 前の決定と矛盾しません

**「1時間のレッスン録音を作らない」という決定は、そのままです。**

```
レッスンの録音   先生の声が入る／要配慮個人情報が混入する
                 保存が持たない／聴き返さない
★本書の5秒       本人だけ／★端末の中だけで解析／★その場で捨てる
                 残るのは数字1つ
```

**別の機能です。混同しないでください。**

**★この機能の中心は「測ること」ではなく「捨てること」です。**

---

## 1. 何を測るか

### 1-1｜CPPS（ケプストラムピーク顕著性）

**持続母音から出る数値で、声のかすれ具合と関係することが
繰り返し確認されている指標です。**

```
・高いほど、周期性のはっきりした声
・低いほど、息もれ・かすれの多い声
```

**自己申告の「今日は調子が悪い」に、外から測った数字が並びます。**

### 1-2｜★絶対値を人と比べてはいけない

```
・端末のマイクで値が変わります
・口からの距離で変わります
・部屋の残響と騒音で変わります
・声の高さと大きさで変わります
```

```
★だから守る規則

・比べるのは★同じ人の、時間をまたいだ変化だけ
・★他人と比べない。平均も、順位も、偏差値も出さない
・★「正常」「異常」「基準値」という語を1つも使わない
・端末を変えたら、★そこで系列を切る（別の系列として扱う）
```

**基準値を出した瞬間に、これは診断の道具になります。**

## 2. 測り方

### 2-1｜手順（30秒で終わること）

```
① 静かな場所かどうかを、先に測る（★2秒）
     騒がしければ「静かな場所でお願いします」で中止
② 端末を、口から★20cm。画面の枠に顔を合わせる
③ 楽な高さ・楽な大きさで「あー」を5秒
④ 端末の中で解析（★1〜2秒）
⑤ ★音声を破棄。数値だけ保存
```

### 2-2｜画面

```
┌──────────────────────────────┐
│ 今週の測定                                  │
│                                            │
│   ○ ← この丸に、口を20cm近づけて           │
│                                            │
│   楽な高さで「あー」と伸ばしてください      │
│                                            │
│         ●●●●●○○○○○  5秒              │
│                                            │
│  ★録音は保存されません。                    │
│  ★数値だけを残して、音は消えます。          │
└──────────────────────────────┘
```

**★この2行を、毎回出してください。** 一度きりの説明では信用されません。

### 2-3｜条件をそろえる

```
・★曜日と時刻を固定する（既定：週1回、起床後2時間以内）
・測る前に、声を使っていないこと
・同じ部屋を勧める（★強制はしない）
・毎回、同じ端末（変わったら §1-2 の規則）
```

**そろわない日は、測らないほうがましです。**

## 3. 実装

### 3-1｜★音声を一度も外に出さない

```
・getUserMedia → AudioContext → 解析 → ★即座に破棄
・★Blob を作らない
・★IndexedDB / localStorage / Cache に書かない
・★fetch / WebSocket に音声データを渡さない
・MediaRecorder を★使わない（使うと録音になります）
・解析後に track.stop() でマイクを確実に閉じる
```

**★テストで固定してください（§7）。**
**「送っていないつもり」ではなく「送れない」ことを、コードで示します。**

### 3-2｜解析

```
① 48kHz / モノラルで取得
② 中央の★3秒だけを使う（最初と最後の1秒は不安定）
③ 40ms 窓・10ms ホップでフレームに切る
④ 各フレーム：ハミング窓 → FFT → 対数パワースペクトル
      → もう一度 FFT → ケプストラム
⑤ 基本周波数に対応する範囲（★3.3〜16.7ms = 60〜300Hz）の
   最大ピークを取る
⑥ ケプストラム全体に回帰直線を引き、
   ★ピーク値 − 同じ位置の回帰直線の値 ＝ そのフレームの CPP（dB）
⑦ 時間方向・ケフレンシー方向に平滑化して CPPS
⑧ 全フレームの★中央値を、その日の値にする
```

```
・FFT は自前実装か、★音声を送らない小さなライブラリだけ
・★外部APIに送って解析しない（1件も例外を作らない）
```

### 3-3｜品質の判定（★これがないと数字がゴミになります）

```
測る前   環境騒音が閾値以上   → 中止
測定中   クリッピングがある   → やり直し
         5秒に満たない        → やり直し
         F0 が途中で 1オクターブ跳ぶ → やり直し
解析後   有効フレームが7割未満 → ★保存しない
```

**★「とりあえず保存」をしないでください。**
悪い数字が1つ混ざると、その後の判定が全部おかしくなります。

## 4. 何に使うか

### 4-1｜表示

```
・★その日の値を、単独で見せない（「今日は◯◯でした」を出さない）
・8回以上たまってから、折れ線で見せる
・★上下の帯（その人の過去の散らばり）を一緒に描く
・帯の外に出た週だけ、印を付ける
```

**単独の数字を見せると、人は毎回それに一喜一憂します。**
**測っているのは「その週の値」ではなく「動き」です。**

### 4-2｜分析

```
・★中核5項目には入れない
・「測定の族」として独立させる（周期・逆流・仕事と同じ扱い）
・N-of-1 試験の★指標として選べるようにする（本書のいちばんの使い道）
```

**★3ゲートは例外なく適用します。**

### 4-3｜★言ってはいけないこと

```
✗ 「声帯に問題があるかもしれません」
✗ 「受診をおすすめします」
✗ 「正常範囲です」「基準を下回っています」
✗ 「先週より悪化しています」
```

```
○ 「先週より低めでした」
○ 「この6週間、ふだんの幅の中にあります」
```

**★「悪化」「改善」ではなく「低め」「高め」。**
表示規約と同じ線です。

## 5. データモデル

```ts
interface VoiceMeasure {
  id: string
  userId: string
  measuredAt: string
  cpps: number
  f0Median: number
  durationMs: number
  noiseFloorDb: number
  validFrameRatio: number
  deviceKey: string        // ★端末が変わったら系列を切るための鍵
  // ★音声データを持つフィールドを作らない
  // ★波形・スペクトル画像も持たない
}
```

```
・★RLS は本人のみ。教師・管理者のポリシーを作らない
・★先生に見せない（合計も、傾向も、1つも）
・書き出しには含める
```

**守りのテスト3本の禁止キーに追加してください。**

```js
'cpps','f0Median','noiseFloorDb','validFrameRatio','deviceKey','voiceMeasure',
```

## 6. ★法律まわり（作る前に読むこと）

```
・声から本人を識別できる特徴量を保存すると、
  ★米国イリノイ州 BIPA などの生体情報規制に触れ得ます
・★本書の設計は、音声を保存せず、話者を識別できる特徴量も持たないため、
  この線を踏みません
・★だからこそ、あとから「音声も保存しておこう」としないでください
  そこが規制の境界です
```

```
・同意画面に1行入れる
   「測定のとき、音声は端末の中だけで処理され、保存されません」
・★録音していると誤解されない文言にする
```

## 7. テストで必ず固定すること

```
□ MediaRecorder が★1か所も使われていない（静的検査）
□ 測定の前後で、IndexedDB / localStorage のサイズが増えない
□ 測定中に発生する通信が★0件（ネットワークを監視して確認）
□ 騒音が閾値以上のとき、保存されない
□ 有効フレーム7割未満のとき、保存されない
□ 教師のトークンで VoiceMeasure が1行も読めない
□ 出力の文言に「正常」「異常」「基準」「悪化」「改善」が含まれない
□ 測定が8回未満のとき、グラフが出ない
```

## 10. Sonnet への依頼のコツ

**この機能で、いちばん越えやすい線は「もったいない」です。**

実装中に、次を思いつくはずです。

```
・せっかく録ったのだから、音声も残しておこう
・あとで見返せるように、波形の画像だけ保存しよう
・精度が上がるので、サーバーの解析APIに送ろう
・他のユーザーの平均と比べて、位置を見せよう
・値が低い週に「受診を検討しては」と出そう
```

**5つとも禁止しています。**

**★この機能が信用に値するのは、捨てるからです。**
**残した瞬間に、La Voce は「声を集めるアプリ」になります。**
**それは、この製品が絶対に名乗ってはいけないものです。**

```
★迷ったときの基準

その実装は、音を1バイトでも残しますか？
　→ 残すなら、やめてください。
```
