# La Voce ／ 教師間コミュニケーション（教室プランの有料機能）

**教室プラン仕様 §12 のスコープ外から「教師間のやり取り」を外し、本書に置き換えます。**
**レッスン連絡パッチ（生徒との定型連絡）とは、別の機能です。混ぜないでください。**

| | |
|---|---|
| 統合実行ルート v4 での位置 | **G4 の 28（レッスンの連絡）の後。29 として追加** |
| 前提 | `Organization` / `Membership` / `Lesson` が実装済み |
| 課金 | **教室プラン（¥12,800）以上。指導者プラン（¥3,980）には含めない**（§8） |

---

## 0. 結論

| 機能 | 判断 |
|---|---|
| **教師間のやり取り（自由記述あり）** | **作る** |
| **教室全体のスレッド（会議室）** | **作る** |
| **プロジェクトのスレッド（発表会・イベント）** | **作る** |
| **レッスンの開始／終了の記録** | **作る。オプションではなく、既定でオン**（§5） |
| 生徒の参加 | **作らない。恒久的に**（§3-1）★ |
| 先生同士の1対1のDM | **作らない**（§3-4） |
| 画像・ファイルの添付 | **v1では作らない**（§3-2） |
| 生徒との自由記述のやり取り | **作らない。恒久的に**（レッスン連絡パッチ §4-1） |

---

## 1. なぜ、これは作れるのか

**指導者プラン実装仕様 §8 で自由記述を止めた最大の理由は、
「大人と未成年が1対1でやり取りできる非公開の場を作ってしまうこと」でした。**

**教師間のやり取りは、大人同士です。** この理由が当てはまりません。

```
生徒 ↔ 先生   … 未成年が含まれる  → 自由記述は作らない（定型連絡のみ）
先生 ↔ 先生   … 全員が大人・業務  → 自由記述を作ってよい
```

**この境界を、実装の型レベルで守ります（§3-1）。**

---

## 2. 汎用チャットとしては、LINE にも Slack にも勝てません

**正直に書きます。** 「教室の連絡はLINEグループでやっている」ところは、たぶん移りません。

**勝てるのは、文脈が入っていることだけです。**

```
LINE   「田中さんの水曜、代わってもらえますか」
        → 田中さんが誰で、水曜に何があるかは、各自の記憶の中

La Voce 同じ発言が、その生徒のページと、そのレッスンの隣にある
        → タップすれば、担当の先生はその生徒の状態を見られる
```

**だから、汎用のチャットを作らないでください。**
**すべてのスレッドは、必ず何かに紐づきます（§4）。**

「何にも紐づかない雑談チャンネル」を作った時点で、この機能はLINEの劣化版になります。

## 3. ★ 絶対に守る4つの線

### 3-1｜生徒を、1人も入れない ★最重要

```
参加できる  … Membership（owner / admin / teacher / staff）
参加できない … Enrollment（生徒）
```

**型レベルで不可能にしてください。**

```ts
// ✅ こう書く
participantIds: string[]   // Membership.userId のみ
// 参加者の追加時に、その userId が当該 org の Membership に存在することを必ず検証する

// ❌ こう書かない
participantIds: string[]   // 誰でも入れられる
```

**生徒を1人でも入れられるようにした瞬間に、
これは「大人と未成年が自由記述でやり取りする場」になります。**
指導者プラン実装仕様 §8 の理由が、そこから全部戻ってきます。

**「保護者だけ入れたい」「成人の生徒なら入れたい」という提案も断ってください。**
例外を1つ作ると、判定が複雑になり、いつか間違えます。

```
★2026年8月31日 追記 ── ここは今も有効です。緩めていません。

　lavoce-判断-門下の連絡板（8月31日）.md で「門下の連絡板」を作りますが、
　あれは §3-1 の例外ではありません。

　§3-1 が止めているのは ①未成年 ②1対1 ③非公開 が揃った場です。
　連絡板は 一対多・公開・成人のみ で、3つとも当てはまりません。

　★スレッド（この文書の対象）に生徒を入れることは、引き続き禁止です。
　　連絡板は別の器で、1対1のやり取りも、一部の人にだけ見える投稿も持ちません。
```

### 3-2｜画像・ファイルの添付を、v1では作らない

**理由は容量ではありません。**

**分析画面のスクリーンショットを貼れてしまうからです。**

```
先生Aが「田中さんの偏差値41です」の画面を撮ってスレッドに貼る
   ↓
田中さんが共有を許可していない先生にも、健康データが見える
   ↓
生徒が設定した共有範囲が、迂回される
```

**共有範囲の設定が、画像1枚で無意味になります。**

v1 は**文字だけ**にしてください。
将来つける場合は、**先に「生徒の健康データを転載しない」を規約に書き、
分析画面に「共有」ボタンを作らないこと**を前提とします。

### 3-3｜生徒の健康データを、スレッドに流し込む機能を作らない

**生徒の名前を出すこと自体は、業務上必要です**（「田中さんの代講をお願いします」）。
**禁じるのは、健康データの転載です。**

```
❌ 「この生徒の分析をスレッドに共有」ボタン
❌ 生徒の記録を引用するテンプレート
❌ スレッドから分析データを自動で読み込む
✅ 生徒の名前へのリンク（タップ先で canView() が効く）
```

**リンク先で必ず `canView()` を通してください。**
担当していない先生がリンクを踏んでも、健康の面は見えません（教室プラン仕様 §3）。

### 3-4｜1対1のDMを作らない（v1）

大人同士なので安全上の問題はありませんが、**作らない理由が2つあります。**

1. **1対1の私的なやり取りは、LINEで足りています。** ここで勝負しても意味がありません
2. **業務の記録として残す価値が低い。** 代講の相談は、担当が変わる話なので
   **管理者にも見えているほうが健全**です

**必要ならメンションで足ります。**

## 4. スレッドの種類（すべて何かに紐づく）

| 種類 | 紐づく先 | 参加できる人 | 用途 |
|---|---|---|---|
| **生徒スレッド** | `studentId` | **その生徒の担当の先生 ＋ 管理者** | 引き継ぎ、方針の相談 |
| **レッスンスレッド** | `lessonId` | 担当の先生 ＋ 管理者 ＋ staff | 代講、時間変更の相談 |
| **教室スレッド** | `orgId` | **教室の全メンバー**（staff含む） | 全体連絡、会議室 |
| **プロジェクトスレッド** | 自由に作る | 作成者が選んだメンバー | 発表会、イベント、合宿 |

**「どこにも紐づかないスレッド」を作れないようにしてください。**
プロジェクトスレッドも `orgId` には必ず紐づきます。

### 4-1｜生徒スレッドの参加者

**担当していない先生は入れません。** 担当が変わったら、

```
新しく担当になった先生  → その時点から参加でき、過去の投稿も読める
担当を外れた先生        → その時点から見えなくなる（過去も含めて）
```

**教室プラン仕様 §9 の `Assignment.endedAt` と同じ扱いです。**
「担当だった期間の分は読める」を作らないこと。

### 4-2｜プロジェクトスレッド

```
・owner / admin / teacher が作れる（staff は作れない）
・作成者がメンバーを選ぶ（その教室の Membership から）
・管理者は、すべてのプロジェクトスレッドを見られる（運営の面）
・終わったら「終了」にできる（読めるが、投稿できない）
```

**上限**

| プラン | 進行中のプロジェクト |
|---|---|
| 教室 | 10 |
| 事業者 | 50 |

**上限は課金の壁ではなく、散らからないための制限です。** 終了すれば枠が空きます。

## 5. ★ レッスンの開始／終了

**「オプション」ではなく、既定でオンにしてください。** ここは価値が大きい機能です。

### 5-1｜押すもの

```
レッスンの詳細画面に

  [ 開始 ]  →  押した時刻を記録
  [ 終了 ]  →  押した時刻を記録  ／  実所要時間が出る
```

**押し忘れは必ず起きます。** 後から手で入れられるようにしてください。
**押されなかったレッスンを「未実施」と扱わないこと。**

### 5-2｜何が得られるか

| | |
|---|---|
| **実レッスン時間** | 予定30分／実施42分。**月謝と振替の判断材料になります** |
| 出欠 | レッスン連絡パッチ §7 の判定を補強する |
| 教室の稼働 | 管理者が「運営の面」で見る |
| **★ 先生自身の発声記録** | 下記 |

### 5-3｜★ 先生も、声のプロです

**これがこの機能のいちばん面白いところです。**

職業別項目の再設計 §2-1 で、**「本番外の発話時間」を共通コアへ引き上げました。**
その中に、こう書いてあります。

> 声楽家 → **レッスンをする側の時間。1日6時間教える人がいます**

**レッスンの開始／終了を押すと、その時間が、
その先生自身の「本番外の発話時間」として自動で記録されるようにしてください。**

```
先生が5コマ教えた日
   ↓
自動で「本番外の発話 4時間10分」が、その先生の記録に入る
   ↓
その先生の発声負荷・声の予報・ACWR が正確になる
```

**先生は「教えているだけだから休養日」と記録しがちです。**
**そこがこのアプリの発見のひとつになります。**

**必須の条件**

- 自動で入った値には「レッスンから」のラベルを付ける
- **先生が手で上書きできる**
- 先生の設定でオフにできる（既定はオン）

## 6. 通知

**先生の多くは個人事業主です。深夜の通知は、それだけで嫌われます。**

| 種別 | 通知 |
|---|---|
| **自分がメンションされた** | **通知する** |
| 生徒スレッド・レッスンスレッドの新規投稿 | **通知する**（担当者のみ） |
| 教室スレッドの新規投稿 | **通知しない**（バッジのみ） |
| プロジェクトスレッドの新規投稿 | 参加者が個別に選ぶ（既定：通知しない） |

**共通の規則**

```
・22:00〜08:00 は通知しない（翌朝まとめる）
・先生ごとに「通知を受け取らない時間帯」を設定できる
・1スレッドにつき、5分以内の連投はまとめて1通知
```

**「全部通知」を既定にしないこと。** 通知が多いアプリは、通知ごと切られます。

## 7. 記録の扱い

### 7-1｜これは業務の記録です

```
・投稿は教室に帰属する（書いた人が退職しても残る）
・退職した先生の表示名は残る（「（退職）山田」のような表示にしない。名前のまま）
・本人は、自分の投稿をいつでも削除できる（「削除されました」だけが残る）
・本人は、自分の全投稿を書き出せる（開示請求への対応）
```

### 7-2｜保存期間

```
・進行中の教室：無期限
・教室が解約されたら：90日後にスレッドを削除
・削除の前に、owner に書き出しを促す
```

### 7-3｜管理者ができること

```
✅ すべてのスレッドを読む（運営の面）
✅ スレッドを終了にする
✅ 不適切な投稿を非表示にする（削除ではなく非表示。ログは残す）
❌ 他人の投稿を編集する
❌ 投稿を完全に消す（本人だけができる）
```

## 8. 課金

**教室プラン（¥12,800）以上に含めます。指導者プラン（¥3,980）には付けません。**

**理由は、売り方ではなく、意味です。**

```
指導者プラン = 先生1人
   ↓
1人しかいない教室で、教師間チャットは意味を持ちません
```

**別売りのオプションにしないでください。** 説明が増えるだけです。

| プラン | 教師間コミュニケーション |
|---|---|
| 指導者 ¥3,980 | ✕ |
| **教室 ¥12,800** | **✓**（プロジェクト10件） |
| **事業者 ¥29,800** | **✓**（プロジェクト50件） |

**「レッスンの開始／終了」だけは、指導者プランでも使えるようにしてください。**
それは1人でも意味があり、しかも §5-3 のとおり**先生自身の記録**につながるからです。

## 9. データモデル

```ts
type ThreadKind = 'student' | 'lesson' | 'org' | 'project'

interface Thread {
  id: string
  orgId: string                 // ★必ず紐づく
  kind: ThreadKind
  studentId?: string            // kind==='student'
  lessonId?: string             // kind==='lesson'
  title?: string                // kind==='project' のときだけ
  createdBy: string
  status: 'open' | 'closed'
  createdAt: string
}

interface ThreadMember {
  threadId: string
  userId: string                // ★Membership.userId のみ。Enrollment は不可
  notify: boolean               // 既定は kind による（§6）
  joinedAt: string
  leftAt?: string
}

interface Post {
  id: string
  threadId: string
  authorId: string
  body: string                  // 上限 2000 文字。★添付は無し（§3-2）
  mentions: string[]            // userId の配列
  createdAt: string
  editedAt?: string
  deletedAt?: string            // 本人のみ。本文は消し、行は残す
  hiddenBy?: string             // 管理者が非表示にした場合
}

interface LessonRun {
  lessonId: string
  startedAt?: string
  endedAt?: string
  actualMinutes?: number
  enteredManually: boolean      // 後から手で入れた場合 true
  voiceLogWritten: boolean      // ★§5-3 で先生の記録に反映済みか
}
```

**`Post` に `attachments` を足さないこと（§3-2）。**
**`ThreadMember.userId` に生徒を入れられないことを、サーバー側で必ず検証してください。**

## 10. 画面

**「レッスン」タブの中に置いてください。独立したタブを作らないこと。**

```
┌───────────────────────────────┐
│ レッスン                       │
│ [ 日程 ] [ 生徒 ] [ やりとり ] │ ← 中のタブ
├───────────────────────────────┤
│ ● 教室                         │
│   ◯◯音楽教室            ● 3  │ ← 未読バッジ
│                               │
│ ● 生徒                         │
│   田中○○                 ● 1  │
│   鈴木○○                      │
│                               │
│ ● プロジェクト                  │
│   3月の発表会            ● 5  │
│   夏合宿の下見                  │
│   ＋ 新しいプロジェクト         │

```

**生徒スレッドから、その生徒のページへリンクします。**
**リンク先では必ず `canView()` が効きます**（§3-3）。

## 11. スコープ外

| やらないこと | 理由 |
|---|---|
| **生徒の参加** | §3-1。**恒久的に** |
| **生徒との自由記述のやり取り** | レッスン連絡パッチ §4-1。**恒久的に** |
| 画像・ファイルの添付 | §3-2（v1では） |
| 1対1のDM | §3-4 |
| 音声通話・ビデオ通話 | 既存ツールで足ります |

| スレッドの検索 | v2 |
| 外部サービス連携（Slack等） | やらない |
| 生徒の健康データを流し込む機能 | §3-3。**恒久的に** |

## 12. 実装の順番

**教室プラン仕様 §13 の 18（レッスン日程）と、レッスン連絡パッチが終わってから。**

| 順 | 内容 | 規模 |
|---|---|---|
| 1 | **§5 レッスンの開始／終了**（先生の記録への反映を含む） | 3日 |
| 2 | `Thread` / `ThreadMember` / `Post` と、**生徒を入れられない検証** | 3日 |
| 3 | 教室スレッド ＋ 生徒スレッド | 3日 |
| 4 | §6 通知の出し分けと、時間帯の制限 | 2日 |
| 5 | プロジェクトスレッド | 2日 |
| 6 | レッスンスレッド | 1日 |
| 7 | §7 削除・書き出し・管理者の非表示 | 2日 |
| 8 | §8 プランによる出し分け | 1日 |

**合計 17日。**

**1 を最初に置いているのは、単独で価値があるからです。**
チャットが1行も動いていなくても、**レッスンの開始／終了だけで、
実レッスン時間と、先生自身の発声記録が手に入ります。**

## 13. 禁止事項

- ❌ **生徒（Enrollment）をスレッドに参加させない。型レベルで不可能にする**（§3-1）
- ❌ 「成人の生徒なら」「保護者なら」という例外を作らない
- ❌ **`Post` に添付ファイルのフィールドを足さない**（§3-2）
- ❌ **生徒の健康データをスレッドに転載する機能を作らない**（§3-3）
- ❌ 分析画面に「スレッドへ共有」ボタンを作らない
- ❌ **どこにも紐づかないスレッドを作れるようにしない**（§4）
- ❌ 担当を外れた先生に、生徒スレッドの過去の投稿を見せない（§4-1）
- ❌ 1対1のDMを作らない（§3-4）
- ❌ **全部の投稿で通知を飛ばさない**（§6）
- ❌ 22:00〜08:00 に通知しない
- ❌ 管理者が他人の投稿を編集・完全削除できるようにしない（§7-3）
- ❌ 独立した「チャット」タブを作らない（§10）
- ❌ レッスンの開始／終了が押されなかった回を「未実施」と扱わない（§5-1）
- ❌ **指導者プラン（¥3,980）にチャットを含めない**（§8）

## 14. Claude Sonnet 5 への依頼のコツ

- **§12 の 1 を単独で出させてください。** チャットなしでも価値が出ます
- **`ThreadMember` に生徒が入らないことの検証を、サーバー側で書かせる。**
  そしてテストを1件書かせること（「生徒の userId を追加しようとすると拒否される」）
- **「画像を添付できると便利です」という提案が来たら、§3-2 を根拠に断る。**
  容量の話ではなく、**共有範囲の迂回**の話であることを伝えてください
- **「生徒も参加できると連絡が早いです」という提案が来たら、§3-1 を根拠に断る**
- **「DMがあると相談しやすいです」という提案が来たら、§3-4 を根拠に断る**
- §5-3（先生自身の発声記録への反映）を**忘れさせないこと。**
  ここが他社にない部分です
- 日時は **UTC ＋ tz**（国際展開仕様 §2.3）
- 文言は **i18n キー**で持たせる

## 注意書き

本書は教室プラン仕様 §12 の「メッセージ・DM を作らない」を、
**「教師間は作る／生徒とは作らない」**に書き換えます。

**生徒との自由記述のやり取りは、恒久的に作りません**（レッスン連絡パッチ §4-1）。
本書で自由記述を認めるのは、**全員が大人である教師間のみ**です。

スレッドの投稿は業務の記録であり、個人情報です。
本人による削除と書き出しに対応してください（§7-1）。
