## 2. 権限モデル（最初に作る）

### 2.1 ロールと関係

```ts
type UserRole = 'student' | 'teacher'   // 1人が両方を持てる

type LinkStatus = 'pending' | 'active' | 'revoked'

interface TeacherStudentLink {
  id: string
  teacherId: string
  studentId: string
  status: LinkStatus
  shareScope: ShareScope        // §4
  invitedAt: string
  acceptedAt?: string
  revokedAt?: string
  revokedBy?: 'teacher' | 'student'
}
```

### 2.2 アクセスの規則（絶対に守ること）

```
先生が生徒のデータにアクセスできる条件（すべて満たすこと）

  1. TeacherStudentLink が存在し、status === 'active'
  2. 先生の Entitlement.plan === 'teacher' かつ status === 'active'
  3. 要求されたデータ区分が shareScope で true
```

**この3条件を1つの関数に集約してください。**

```ts
async function canTeacherRead(
  teacherId: string,
  studentId: string,
  scope: keyof ShareScope
): Promise<boolean>
```

**全APIハンドラの先頭で、この関数を通すこと。**
クライアント側の表示制御だけで隠さない。

### 2.3 やってはいけない実装

- ❌ `teacherId` だけで生徒データを引くクエリを書く
- ❌ 生徒IDを URL パラメータで受け取り、検証せずに返す（IDOR）
- ❌ 一覧APIで全生徒のデータを返し、クライアントで絞る
- ❌ `shareScope` の判定をクライアントで行う

## 3. 招待コード（双方向承認）

### 3.1 仕様

```
・先生が発行する。1コード＝1生徒（使い切り）
・有効期限は7日
・コードは推測不能（英数8桁以上、紛らわしい文字を除く：0/O/1/l/I）
・生徒が入力すると、承認画面へ（§3.2）
・生徒が承認して初めて status: 'active' になる
・先生・生徒のどちらからでも、いつでも解除できる
・解除した瞬間から、先生は一切見られなくなる
```

### 3.2 生徒側の承認画面 ★この画面が最重要

**ここで公開範囲を選ばせてください。** あとから設定画面に行かせない。

```
┌───────────────────────────────┐
│ ○○先生から招待が届いています     │
│                               │
│ つながると、先生は選んだ項目を   │
│ 見られるようになります。         │
│                               │
│ ┌───────────────────────────┐ │
│ │ ✓ 声・喉の記録             │ │
│ │ ✓ 症状                    │ │
│ │ ✓ 睡眠                    │ │
│ │ ✓ 活動・練習量             │ │
│ │ ─────────────────────     │ │
│ │ ☐ 水分・食事               │ │
│ │ ☐ 体重・身体データ          │ │
│ │ ☐ 心の余裕・日記           │ │
│ │ ☐ 稽古ノート               │ │
│ └───────────────────────────┘ │
│                               │
│ あとから変更できます。          │
│ つながりの解除もいつでもできます。│
│                               │
│ ┌─────────────┬─────────────┐ │
│ │  つながる    │  今はやめる  │ │
│ └─────────────┴─────────────┘ │
└───────────────────────────────┘
```

**「今はやめる」を同じ大きさで置くこと。**

## 4. 生徒の公開範囲設定 ★必須

**この機能が無ければ §5 以降を作らないでください。**

先生に読まれる可能性があると、生徒は**メンタルの日記に正直に書かなくなります。**
書かれなくなった瞬間に、このアプリの分析は死にます。

### 4.1 既定値

```ts
interface ShareScope {
  voice: boolean       // 喉・声の評価、音名、弱声の最高音、響き
  symptoms: boolean    // 症状
  sleep: boolean
  activity: boolean    // 活動・レパートリー・発声負荷
  hydration: boolean
  meal: boolean
  body: boolean        // 体重・BMI・エネルギー可用性
  mental: boolean      // 心の余裕・気持ちタグ・日記
  notes: boolean       // 稽古ノートの振り返り
}

const DEFAULT_SHARE_SCOPE: ShareScope = {
  voice: true,
  symptoms: true,
  sleep: true,
  activity: true,
  hydration: false,
  meal: false,
  body: false,
  mental: false,      // ★既定 false。変更しないこと
  notes: false,
}
```

### 4.2 記録画面に「先生には見えません」を常時表示する

**設定を見に行かないと分からない、では安心して書けません。**

メンタルのセクション、および共有していない項目の見出し横に、
小さく常時表示してください。

```
● 心の余裕                    🔒 先生には見えません
```

`mental: true` にした生徒には、この表示を出さない（代わりに何も出さない）。

### 4.3 mental を true にするときは確認する

```
┌───────────────────────────────┐
│ 心の余裕と日記を、先生に         │
│ 共有しますか？                  │
│                               │
│ その日の気持ちや日記の内容が、    │
│ 先生から読めるようになります。    │
│                               │
│ ［ 共有する ］  ［ やめておく ］  │
└───────────────────────────────┘
```

### 4.4 変更はいつでも、即座に反映

公開範囲を狭めたら、**その瞬間から先生に見えなくなる**こと。
過去のデータも含めて。

## 5. 生徒一覧ダッシュボード（デスクトップ想定）

**先生が最初に開く画面です。**

```
┌────────────────────────────────────────────────────────────────┐
│ 生徒（18人）        [今週▾]  [要注意のみ]  [検索          ]    │
├────────────────────────────────────────────────────────────────┤
│ 名前       記録率   偏差値  変化   発声負荷  最終記録  次回      │
│ ────────────────────────────────────────────────────────────── │
│ ⚠ 田中○○  3/7日    41    ▼-12   1.62 ⚠   2日前   明日15:00 →│
│ ⚠ 佐藤○○  7/7日    45    ▼-8    1.15     今日    金 10:00  →│
│   鈴木○○  6/7日    58    ▲+4    0.94     今日    土 14:00  →│
│   高橋○○  7/7日    62    ─      1.08     今日    —        →│
└────────────────────────────────────────────────────────────────┘
```

### 5.1 「要注意」の定義（恣意的にしないこと）

**次のいずれかを満たしたら ⚠ を付ける。**

```
・最終記録が 3日以上前
・偏差値が、その生徒の28日平均から 10 以上低下
・発声負荷 ACWR > 1.5
・同じ症状が 5日以上連続
```

**画面のどこかに、この定義を明記してください。** 先生が基準を理解できないと使えません。

### 5.2 並び順

```
1. ⚠ 要注意（上記の該当数が多い順）
2. 最終記録が古い順
3. 名前順
```

### 5.3 公開範囲でフィルタされる

`shareScope.voice` が false の生徒は、偏差値の列を「—」にする。
**空欄にせず、「共有されていません」と分かる表示にしてください。**

## 7. レッスン日程

### 7.1 位置づけ：予定管理ではなく「導線」

**日程管理そのものは売り物になりません。** 先生はすでに LINE と
Google カレンダーで予定を管理していて、そこに新しい箱を作っても使われません。

**この機能の価値は1点だけです。**

```
明日 15:00  田中さん   ← タップ
                        ↓
              田中さんの今週の状態
```

**「レッスン前に生徒の状態を見る」行動が、思い出さなくても起きるようになる。**
これがすべてです。予定管理を作り込まないでください。

### 7.2 仕様

```
・先生が登録する（生徒・日時・所要時間・場所またはオンライン）
・繰り返し（毎週◯曜◯時）に対応
・生徒側にも表示される
・生徒は「変更をお願いしたい」を1タップで送れる（通知のみ。日程は変えない）
・先生ダッシュボードの最上部に「今日・明日のレッスン」が出る
・レッスン名をタップで、その生徒の個別ページへ直行  ★本体
・前日にリマインド（LINE。生徒・先生の両方）
```

### 7.3 スコープ外

| やらないこと | 理由 |
|---|---|
| **生徒からの予約申し込み・空き枠の公開** | 予約管理SaaS の領域。規模が10倍になります |
| レッスン料の決済連動 | 会計・返金・領収書がついてきます |
| キャンセルポリシーの自動適用 | 同上 |
| 複数講師・教室単位の管理 | 需要が出てから |
| ビデオ通話 | 既存ツールで足ります |

**「レッスン管理アプリ」になろうとしないでください。**

### 7.4 カレンダー連携は「流す」だけ

先生のカレンダーを置き換えず、**iCal フィードを配信**します。

```
GET /api/calendar/{teacherToken}.ics
```

- **一方向のみ**（La Voce → 外部カレンダー）
- 双方向同期は作らない（競合の解決が必要になり、実装が跳ね上がります）
- トークンは推測不能。無効化・再発行できるようにする

## 8. 記録へのコメント（メッセージ機能は作らない）

### 8.1 なぜチャットを作らないか

| 理由 | |
|---|---|
| **LINE に勝てない** | 日本の先生と生徒のやり取りはほぼ100%が LINE。新しい箱は見られません |
| **「届いたか」の責任が生じる** | 連絡が届かずレッスンがすっぽかされたら、原因がアプリになります |
| **未成年の安全設計** ★ | 音大受験生・養成所には未成年がいます。**大人と未成年の1対1の非公開の場**を作ると、通報・ブロック・保護者同意・モデレーションが一式必要になります |
| **要配慮個人情報が増える** | メッセージに体調が書かれれば、それも要配慮情報です |
| **実装が1ヶ月級** | その1ヶ月を §5・§6 の完成度に使うほうが価値が高い |

### 8.2 代わりに：記録へのコメント

**メッセージの価値の8割を、リスクなしで得られます。**

```
・先生 → 生徒の特定日の記録、または週次振り返りに、一言コメント
・生徒 → 自分の記録に、先生宛のメモを添えられる
・返信は1往復まで。スレッドを伸ばさない
・通知は「次にアプリを開いたとき」（プッシュしない）
・双方が自分のコメントを削除できる
・上限 500 文字
```

**これはレッスンノートの延長であって、チャットではありません。**

> 先生：「今週は睡眠が短い日が続いていますね。土曜のレッスンは軽めにしましょう」
> 生徒：「本番前で焦っていました。ありがとうございます」

## 9. レッスンモード（先生プラン不要）

**生徒の端末を、そのまま先生に渡すための読み取り専用画面です。**

先生がプラットフォームにいない場合の受け皿であり、
**指導者プランへの導線**にもなります。

```
表示する：偏差値の推移（4週）／症状カレンダー／発声負荷／音域マップ／稽古ノートの目標
隠す　　：メンタルの日記・気持ちタグ／体重・体組成／食事の詳細／既往症／設定・課金
```

- 起動：おうち・分析の右上から1タップ
- 終了：3秒長押し（誤操作防止）。設定で PIN を有効化できる
- レッスンモード中はタブバーを隠す
- フッターに「先生アカウントがあれば、この画面を毎日ご覧いただけます →」

**メンタルの日記を隠すことは必須**（§4 と同じ理由）。

## 10. 指導者プランの課金

### 10.1 販売チャネルと価格

| | |
|---|---|
| 販売 | **ウェブのみ。アプリ内課金では販売しない**（アプリ配布と課金仕様 §1.1） |
| 〜15人 | ¥3,980/月 ／ $29/月 |
| 〜50人 | ¥9,800/月 ／ $69/月 |
| 50人超 | 個別見積もり |

**ティア分けしません**（価格設計仕様 §2.2）。法人予算は国差が小さく、
請求書払いや交渉も入るためです。

### 10.2 生徒側の権利

```ts
// 生徒には Stripe のオブジェクトを作らない
{
  plan: 'personal',
  status: 'active',
  source: 'teacher',     // ← Stripe / Apple / Google ではない
  teacherId: '...',
  currentPeriodEnd: '...'  // 指導者プランの有効期間に追随
}
```

### 10.3 先生が解約したとき

- 生徒の権利は**期間末で終了**（即時に切らない）
- 終了の1週間前に、生徒へ通知
- **「個人プランに移行しますか」の導線を出す** ← 自然な有料転換点です
- 移行しない場合は無料プランへ。**記録は消さない**

### 10.4 人数の上限

- 上限に達したら、新しい招待コードを発行できない
- **既存の生徒を切らせない。** 上位プランへの案内を出す

## 11. 未成年への配慮

音大受験生・養成所の生徒には**未成年が含まれます。**

```
□ 登録時に生年月日、または「18歳未満」のフラグを取得する
□ 未成年の場合、保護者の同意確認を行う（メールでの確認で可）
□ 1対1の非公開チャットを作らない（§8 のコメント方式で回避済み）
□ 「つながりを解除する」を、設定の目立つ位置に置く
□ 生徒はコメントを全件閲覧・削除できる
□ 将来、保護者アカウントを追加できる余地を残す（viewerRole を持たせる）
```

## 14. Sonnet 5 への依頼のコツ

- **§2 の `canTeacherRead()` を最初に作らせ、全APIで通させる。**
  「ミドルウェアで見ているから不要」と省略させない
- **§4 の公開範囲なしで §5 を作らせない。** 順序を入れ替えさせないこと
- **`DEFAULT_SHARE_SCOPE` の `mental: false` を変更させない**
- **メッセージ機能・チャット・DM を実装させない**（§8.1）。提案が来たら断る
- コメントを**スレッド型にさせない**（返信1往復まで）
- **予約申し込み・空き枠公開に広げさせない**（§7.3）
- **カレンダーの双方向同期を作らせない**（§7.4）。iCal 配信のみ
- `TeacherNote` と `Lesson.note` を生徒に表示させない
- 日時は必ず **UTC ＋ tz**。レッスンは時刻が本質です
- 指導者プランを **IAP で売らせない**（§10.1）
