## レーンA（Sonnet が実行する）

### A-P0-1 ｜ バックアップの復元手順を、実行可能な形にする

**なぜ最優先か**：要配慮個人情報を個人開発で預かっています。DBが失われれば
事業が終わるだけでなく、ユーザーの記録が消えます。しかも**この直後に、
声の記録の構造変更という大きな移行が控えています。**

**やること**

1. 本番DBのダンプを取得するスクリプトを書く（1コマンドで実行できること）
2. ダンプの健全性を検証するスクリプトを書く
   - テーブルごとの行数
   - 各テーブルの最新レコードの日時
   - 期待される行数を大きく下回っていたら異常終了する
3. 別環境（ローカル or ステージング）へ復元する手順を、**コマンドを含めて**文書化する
4. `docs/backup-restore.md` として残す

**完了の定義**：坂本さんが手順書を見ながら復元を実行し、
**復元先でログインして記録が読めることを確認できた**状態。

**やらないこと**：本番の認証情報を扱う操作、外部サービスの設定変更。
これらは手順書に「坂本さんが実行する」と明記してください。

**規模**：半日

### A-P0-2 ｜ 保存・読み込みのテストを6本書く

**なぜ**：曲目複数化という小さなスキーマ変更で、保存周りが何往復も壊れました。
次はもっと大きい構造変更（記録項目v2 §3.1・§3.2）です。
**同じ状態で臨めば、同じことが起きます。**

（作業計画v2 §4 で「構造変更の前提条件」としたものと同一です）

**書くテスト**

```
1. 保存 → 読み出しで、すべてのフィールドの値が一致する
2. 任意フィールドが未入力（null / undefined）でも、保存と読み出しができる
3. 過去日を編集しても、他の日のデータが変わらない
4. 同じ日に2回保存しても、レコードが重複しない
5. オフラインで入力 → オンライン復帰で同期され、重複しない
6. 配列（活動・曲目）の並べ替えと削除の後も、order が連番で整合している
```

**E2E である必要はありません。** 保存・読み出し関数への単体テストで十分です。

**完了の定義**：`npm test`（相当）で6本が緑になり、CI かローカルで
コミット前に走る状態。

**規模**：1日

### A-P1-1 ｜ 権限とアクセス制御の点検

**なぜ**：指導者ダッシュボードは**他人の健康データを見せる機能**です。
ここのバグは不具合ではなく漏えいで、1件でも個人情報保護委員会への報告義務が生じます。
**作る前に、いまの状態を点検してください。**

**やること**

1. **「この操作を誰ができるか」の表を作る**（全APIルート × ロール）
2. 全APIルートを洗い出し、**認可チェックの有無を一覧化**する
3. IDOR のテストを書く
   - 他人の `userId` / 記録ID を指定したリクエストが 403 になること
   - URL 直打ちで他人の記録ページに到達できないこと
4. **クライアント側の表示制御だけで隠している箇所**を探し、サーバ側の検証を足す
5. Supabase を使っているなら RLS ポリシーを、そうでなければサーバ側で必ず

**完了の定義**：権限表が `docs/authorization.md` にあり、
IDOR テストが緑で、表に載っていないルートが存在しない状態。

**規模**：2〜3日

### A-P2-1 ｜ 記録率を分析に併記する

**なぜ**：**調子が悪い日ほど記録されません。** 忙しい、落ち込んでいる、
記録どころではない。すると分析に使われるのは
「記録できる程度に元気だった日」に偏り、偏差値の分布も効果量もラグ相関も歪みます。

これは統計的に無視できない偏りですが、**完全には除去できません。**
できるのは、読み手に伝えることです。

**やること**

```
1. すべての分析カードに、件数 n と記録率を併記する
     例：「この期間の記録率 62%（18/29日）」

2. 記録率が 50% 未満の期間には、注意書きを出す
     「記録のある日だけの傾向です。記録が少ない期間は、
      調子の良い日に偏っている可能性があります。」

3. 記録率の計算は、期間の暦日数を分母にする
     （記録のある日だけを分母にしない）
```

**完了の定義**：分析画面のすべてのカードに記録率が出ており、
50%未満で注意書きが出る。

**規模**：1〜2日

### A-P2-2 ｜ サポート導線

**なぜ**：有料化した瞬間に必須になります。いま無いなら、課金の前に。

**やること**

- 「もっと」内に問い合わせフォーム（メール送信で十分。Resend）
- 送信時に、**環境情報を自動添付**する（ブラウザ、画面幅、アプリのバージョン、
  ユーザーID）。これが無いと原因究明のやり取りが倍になります
- 送信後の自動返信（受け付けた旨と、返信の目安）
- FAQ ページ（「もっと ＞ 学ぶ」に同居）

**完了の定義**：フォームから送信したメールが届き、環境情報が含まれている。

**規模**：1〜2日

---

### A-P2-3 ｜ 事業継続に関する記述と、データ書き出し

**なぜ**：個人開発で、ユーザーは健康データを預けています。
**ユーザーを人質にしない設計を、最初から明示すること**が誠実さであり、
同時に**音大や事務所への営業で必ず聞かれる質問**への答えになります。

**やること**

1. データの一括書き出し（JSON / CSV）を、**いつでも・無料で**
   （記録項目v2 §6.3 の実装。まだなら、ここで）
2. 利用規約に**サービス終了時の手順**を書く（ドラフトまで）
   - 何日前に告知するか（例：90日前）
   - 告知後、データ書き出しをいつまで提供するか
   - 有料プランの残期間をどう扱うか

**完了の定義**：書き出しが動作し、規約のドラフトができている状態。
**内容の妥当性の確認は坂本さん（および専門家）の担当**です。

**規模**：2〜3日

### A-P3-1 ｜ 欠測パターンを指標にする

**なぜ**：A-P2-1 の裏返しです。**「記録が途切れた」こと自体が、
疲労のサインかもしれません。** 欠測を「データがない」ではなく
「データである」と扱えます。

**やること**（データが8週間ぶん貯まってから）

```
週ごとの記録率 r_w = その週の記録日数 / 7

平常値との比較（頑健統計）
  m   = 中央値(r_w)          直近12週
  MAD = 中央絶対偏差
  z   = 0.6745 × (r_w − m) / MAD

z ≤ −1.5 の週を検出し、その前後の出来事と並べて提示する
```

**文言の注意**：「記録をサボりました」と読める表現は禁止です。

> ✓ 「先週は記録が少なめでした。忙しい時期だったのかもしれません。」

**規模**：1〜2日

### A-P3-2 ｜ LINE通知の文面を、欠測を踏まえて調整する

悪い日ほど記録されない問題に、通知の文面で対処します。

> 「調子が悪い日ほど、あとで役に立ちます。3つだけでも残しませんか。」

30秒モードへの直リンクを添えること。

**規模**：半日

## レーンB（坂本さんが実行する。Sonnet は代行しない）

### B-P0-1 ｜ 独自ドメインを取る

**なぜ今か**：`la-voce.vercel.app` のままだと、音大や事務所への営業で
「個人の趣味」に見えます。**ユーザーが増えてから変えるほうが高くつきます**
（登録メール、LINEのリンク、共有されたURLがすべて古いドメインを指すため）。

年間1,000円台の投資です。**今週やってください。**

### B-P0-2 ｜ 声のプロ3〜4人に話を聞く

**このセッションで作った仕様書は、すべて仮説です。**
「弱声の最高音が効く」「指導者が払う」「叫びテイク数が刺さる」——
どれも、坂本さん以外の声のプロに一度も確かめていません。

**聞くべきは「使いますか」ではありません。**

- 前回、喉の不調で仕事に影響が出たのはいつで、原因は何だったと思いますか
- いま、体調について何か記録していますか（していないなら、なぜ）
- （指導者に）生徒の状態で、レッスン前に知りたいことはありますか
- （声優に）収録の翌日、声が戻るまでどれくらいかかりますか

**3人聞けば、仕様書のうち2〜3本の前提が変わります。**
変わるなら、実装する前に変わったほうがいい。

### B-P1-1 ｜ 商標を確認する

**"La Voce" はイタリア語で「声」という一般名詞**です。
覚えやすい一方、**商標として弱く、既存の衝突がある可能性があります**
（イタリアには同名の新聞・飲食店が複数存在します）。

- 日本：J-PlatPat で無料検索できる
- 国際展開を本気で考えるなら、弁理士に一度相談する

**ユーザーがついてから名前を変えるのが、いちばん高くつきます。**

### B-P2-1 ｜ 健康情報の監修者を立てる

「健康情報」「発声理論」の内容を、専門家の確認なしに出すのは、
信頼性と規制の両面でリスクです。

耳鼻咽喉科医（できれば音声外来）または言語聴覚士に、
**監修という形で関わってもらえないか打診してください。**

- コンテンツの信頼性が上がる
- 「診断ではない」という線引きの妥当性を担保できる
- **音大・事務所への営業で決定的に効く**

報酬は必要ですが、指導者プラン数件分で回収できる投資です。

### B-P3-1 ｜ 競合の定点観測

調べた限り、**この領域には直接の競合がいません。**
出てくるのはボイストレーニング・発声評価のアプリばかりで、
体調記録のアプリは見当たりませんでした。

ただし「誰も作っていない」は「需要が確かめられていない」とほぼ同義です。
また、**トレーニング系アプリが体調ログ機能を足してくる**のが最も現実的な脅威です。

半年に一度、確認してください。

- **レーンBに手を出さないこと。** ドメイン取得、ヒアリング、商標調査、監修者の打診は

  記憶や推測で書かせない
- A-P2-3 の規約ドラフトは**あくまでドラフト**。
  「専門家の確認が必要」と文書内に明記させる
