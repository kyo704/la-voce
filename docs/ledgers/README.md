全128行 / 末尾は「　★「これから作る」の一覧に、作り終えたものを残さないこと。」

★7つの台帳の行き先と、★新しい表を作るときの手順です。

　★漏れたのは、★「作ったときに、どこへ登録するか」が決まっていなかったからです。

## ★新しい表を作ったときの手順

★表を1つ作るたびに、★7つとも見ること。★「関係ない」も答えです。
★答えないまま進まないこと。★漏れは、いつもここで起きます。

    ① 01 削除処理
       この表の行は、退会のとき、どうなりますか。
         消す        → USER_OWNED_TABLES に足す（user_id 列が要ります）
         個別に消す  → SPECIAL_DELETES に足す（列名を書く）
         残して外す  → NULLED_REFERENCES に足す（★null を許す列か確かめる）
         外部キー任せ → ★実物の制約を見ること。ファイルは証拠になりません
       ★2者が関わる表は、★片方ずつ考えること。答えが2つになります。

    ② 02 バックアップ
       critical ですか。★消えたら取り返せないものは true。

    ③ 03 auth 参照
       auth.users を指す列がありますか。あるなら、誰が面倒を見ますか。

    ④ 04 データ書き出し
       本人が書き出せますか。★「共有しない」と「本人も取り出せない」は
       ★別のことです。混ぜないこと。

    ⑤ 05 外に出る経路
       この表の中身が、外のサービスへ出ますか。

    ⑥ 06 起きたことの記録
       ★作るときは関係ありません。★何か起きたときに書きます。

    ⑦ 07 利用者に示している約束
       この表について、利用者に何か約束していますか。
       ★約束したなら、★守れているかをここに書きます。

    ⑧ RLS
       ★ポリシーを1本も書かずに有効にしていませんか。
       ★UPDATE のポリシーに WITH CHECK がありますか
         （★無い UPDATE のポリシーは、欠陥です。例外はありません）。
       ★列ごとの権限が要りますか（RLS は列を隠せません）。

    ⑨ 検査
       ★この表が台帳から漏れたら落ちる検査を、1本書きましたか。
