# La Voce ／ 記録画面・分析画面の「順番」の設計

**目的：入力される項目数を増やすこと。ただし、負担感を増やさずに。**

対象：**画面レイアウト仕様 §4（今日の記録）・§5（分析）の並び順**を差し替えます。
項目そのものは増やしません（**記録項目の再設計v2** の範囲を変えないこと）。

---

## 0. 結論

順番を変えるべきです。理由は4つあり、そのうち**2つ目は分析の正しさに直結する不具合**です。

| # | いまの並びの問題 | 変更 |
|---|---|---|
| 1 | 最初に**決断**（テンプレート5択）を求めている | 推測して既に選んでおく（§4） |
| 2 | **主観評価と客観記録が同じ流れに入っている** | 入口を時間帯で分ける（§3.1）★ |
| 3 | 自動で埋まる項目（環境）が**いちばん下**にある | 最上部へ（§3.2） |
| 4 | 保存したあと**何も返ってこない** | 保存の直後を報酬にする（§3.5） |

そして、**入力項目を増やす本当の方法は、記録画面をいじることではありません。**
**分析画面から「この項目が足りない」と名指しで呼ぶことです（§5.3）。**
本書でいちばん効くのはそこです。

---

## 1. 前提：なにを増やしたいのか

「もっと打ち込んでほしい」には、価値の違う3つが混ざっています。

| 増やしたいもの | 価値 | 手段 |
|---|---|---|
| **記録した日数** | ★★★ 最重要。これが無いと何も出ない | 30秒モード・罰を作らない（既存の設計で対応済み） |
| **1日あたりの項目数** | ★★ 発見の精度が上がる | **本書** |
| **詳細入力（＋詳しく）** | ★ 一部のユーザーだけでよい | 分析が要求したときだけ開く（§5.3） |

**日数を犠牲にして項目数を増やしてはいけません。**
入力が重くなって記録日数が減れば、分析はむしろ悪化します。
本書の変更はすべて「1項目あたりの心理的コストを下げる」方向で、追加を求めていません。

---

## 2. 原則（7つ）

| # | 原則 | 根拠 |
|---|---|---|
| P1 | **埋まっている状態で始める** | 進捗が最初から少し進んでいると完遂率が上がる（endowed progress） |
| P2 | **決断より確認**。選ばせず、推測して直せるようにする | 選択肢の提示は最も高コストな操作 |
| P3 | **客観 → 半客観 → 主観 → 自由記述** の順 | 調査法の定石。自由記述を先頭に置くと途中離脱が跳ね上がる |
| P4 | **重い項目は中盤**。先頭と末尾は軽く | 先頭＝着手、末尾＝印象。両端は守る |
| P5 | **1セクションにつき1つ、その場で何かを返す** | 入れる→返る、が続ける動機になる |
| P6 | **終わりを報酬にする** | 体験の記憶は「ピーク」と「終わり」でほぼ決まる（peak-end） |
| P7 | **並び順は固定する。可変にするのは開閉だけ** | 毎日同じ場所にあることが、速さの最大の要因 |

> これらは一般的な知見です。**必ず §7 の計測で確かめてください。**
> 効かなかったら戻せるよう、順序は1つの定数配列で定義すること（§8）。

## 3. 記録画面の新しい順番

### 3.1 ★ 入口を時間帯で2つに分ける

**いまの記録画面は、性質の違う2つの仕事を1枚に混ぜています。**

| | 声の記録 | 一日の記録 |
|---|---|---|
| いつ書く | **歌った直後**（日中、何度でも） | **夜、1回** |
| 中身 | 主観（喉の感覚・声の出来・音名・症状） | 事実（睡眠・水分・食事・活動・環境） |
| 遅れると | **記憶が変わって使えなくなる** | ほぼ問題ない |

**混ぜていることによる実害：**

夜にまとめて書くと、ユーザーは
「睡眠6.5時間 → じゃあ声も悪かったはず」
と**自分の理屈で辻褄を合わせて**声を評価します。

**このアプリの中心は「睡眠と声の関係を見つけること」です。**
入力の順番のせいでユーザーが片方からもう片方を推測すると、
**相関は必ず出ます。ただし、それはユーザーの思い込みの相関です。**

順番の話に見えて、**分析の正しさの話**です。

#### 実装

```
記録タブを開いたとき、時刻で出す画面を変える

  05:00〜20:59  →  A. 声の記録（その場の記録）
  21:00〜04:59  →  B. 一日の記録

どちらの画面にも、もう一方への切り替えを上部に置く（隠さない）
境界の時刻はユーザーが設定で変えられる（既定 21:00）
```

**A. 声の記録（日中）**

```
┌───────────────────────────────┐
│ [ 声の記録 ] [ 一日の記録 ]     │ ← 切り替え。現在地を強調
├───────────────────────────────┤
│ 今日の声の記録  2件            │
│ ┌───────────────────────────┐ │
│ │ 07:20 起き抜け  喉mf 声6 A3│ │
│ └───────────────────────────┘ │
│ ┌───────────────────────────┐ │
│ │ 14:10 ルーティン後 喉f 声7 │ │
│ └───────────────────────────┘ │
│                               │
│ ┌───────────────────────────┐ │
│ │  ＋ いま声の記録をつける    │ │ ← 56px。この画面の主役
│ └───────────────────────────┘ │
│                               │
│ 夜に、睡眠や食事をまとめて     │
│ 記録します                  → │ ← 予告だけ。ここでは求めない
└───────────────────────────────┘
```

**この画面には、睡眠も食事も水分も出しません。** 3秒で終わる場所にします。

**B. 一日の記録（夜）** → §3.2

### 3.2 「一日の記録」の順序

```
┌───────────────────────────────┐
│ ‹  8月25日(火)  ›   [前日をコピー]│
│ [ 声の記録 2件 ] [ 一日の記録 ] │
├───────────────────────────────┤
│ ● 今日は？   練習 ▾            │ ← 推測済み。タップで変更（§4）
├───────────────────────────────┤
│ ● 環境                  ⟳自動 ✓│ ← ①最上部。すでに埋まっている
│   甲府 31℃/38% ・ AH 12.2      │
├───────────────────────────────┤
│ ● 睡眠                         │ ← ②昨夜のこと。判断が要らない
│   6.5時間 [−][+]  就寝 01:30   │
│   → 14日平均より +0.3時間       │ ← 即座に返す（§3.3）
├───────────────────────────────┤
│ ● 活動                         │ ← ③事実。テンプレから既定値
│   自主練習 [−] 90 分 [+]       │
│   → 今週の負荷 1.12 ちょうどいい│
├───────────────────────────────┤
│ ● 水分                  1,850ml│ ← ④タップだけ
│   [＋200ml] [直接入力]          │
├───────────────────────────────┤
│ ● 食事                         │ ← ⑤チップ。即座に返る
│   夕食 19:30 → 就寝まで 3.2時間 │
│   [揚物][あっさり][炭酸]…      │
├───────────────────────────────┤
│ ● 曲目・演目                   │ ← ⑥いちばん重い。中盤に置く
│   [ 追加 ]                     │
│   → この曲は前回 8/12。出来 7   │
├───────────────────────────────┤
│ ● 症状（あれば）                │ ← ⑦ここまで来れば書ける
├───────────────────────────────┤
│ ● 心の余裕                     │ ← ⑧内省。主観は後ろ
│   緊張 ○○●○○ 穏やか           │
├───────────────────────────────┤
│ ● ひとこと（稽古ノートへ）      │ ← ⑨自由記述は必ず最後
│   [                        ]   │
├───────────────────────────────┤
│ ┌───────────────────────────┐ │
│ │      記録する（＋3pt）      │ │ ← sticky
│ └───────────────────────────┘ │
└───────────────────────────────┘
```

**いまの並びからの変更点**

| 項目 | いま | 変更後 | 理由 |
|---|---|---|---|
| 環境 | 最下部 | **最上部** | 自動で埋まっている＝「もう始まっている」（P1） |
| 声の記録 | 最上部 | **別画面へ**（§3.1） | 主観と客観を混ぜない |
| 曲目 | 活動の中 | **独立させて中盤** | 最も重い。両端に置かない（P4） |
| 心の余裕 | 活動の後 | **後ろから2番目** | 主観は後ろ（P3） |
| ひとこと | 心の余裕の中 | **独立して最後** | 自由記述は末尾（P3） |
| 症状 | 声の記録の中 | **一日の記録にも置く** | 夜に気づく症状がある |

**症状の重複について：** 声の記録シート内の症状と、一日の記録の症状は
**同じデータに書き込みます**（`symptoms` は日単位の集合）。
どちらから入れても同じ場所に入り、両方に反映されること。

### 3.3 各セクションが、その場で返すもの（P5）

**「入れたのに何も起きない」欄をゼロにしてください。** ここが項目数を増やす主動力です。

| セクション | 入力直後に、欄の下に1行で出すもの |
|---|---|
| 環境 | `絶対湿度 12.2 g/m³ ・ あなたの快適域より 乾いています` |
| 睡眠 | `14日平均より +0.3時間` |
| 活動 | `今週の発声負荷 1.12（ちょうどいい）` ※入力に応じてその場で再計算 |
| 水分 | `体重比 32 ml/kg` ／ 体重未登録なら `今週の平均より +200ml` |
| 食事 | `就寝まで 3.2時間`（既存） |
| 曲目 | `この曲は前回 8/12。そのときの声の出来 7` |
| 症状 | `同じ症状は今月 3日目` |
| 心の余裕 | 数値を返さない。`記録しました` のみ ★ |

**心の余裕だけ数値を返さないこと。**
メンタルに点数を返すと、良し悪しの判定になります。
**指標設計図の「自分比だけで語る」原則を、ここでも守ってください。**

**すべて「自分比」です。他人との比較・文献の閾値を出さないこと。**

---

### 3.4 進捗の見せ方

**「未入力」「不足」「空欄」という語をUIに出さないこと。**
罰を作らない原則（羊のおうち仕様 §1）は、記録画面にも適用します。

```
✅ 今日の記録  ●●●●●○○○○     5項目
   あと2項目で、明日の分析に「食事の影響」が加わります

❌ 未入力 4項目 / 記録が不足しています / 完了度 55%
```

- 進捗の玉は**日付ナビのすぐ下**に置く（常に見える）
- **満タンを目標に見せない。** 6/9でも「十分」と読める表現にする
- 30秒モードで終えた日も、進捗は**赤くしない**

---

### 3.5 保存の直後（P6：ここが「終わり」）

**いまは保存すると何も起きません。ここが最大の取りこぼしです。**

```
記録する を押す
        ↓  400ms
┌───────────────────────────────┐
│        ✓ 記録しました           │
│                               │
│         ＋3 pt   → 75pt        │ ← 数字が回って増える
│                               │
│  6日つづいています              │
│                               │
│  今日わかったこと：              │
│  水分が今週いちばん多い日です    │ ← 1行。無ければ出さない
│                               │
│  [ おうちで羊を見る ]  [ 閉じる ]│
└───────────────────────────────┘
```

**規則**

- **必ず3秒以内に閉じられること。** 全画面の演出で足止めしない
- 「今日わかったこと」は**出せる日だけ**出す。無い日に無理に出さない
- **連続日数が途切れた日は、連続日数を出さない**（累計だけ出す）
- `prefers-reduced-motion` で数字のアニメーションを止める
- **ここでポイントを増やす。体調の良し悪しでポイントを変えないこと**（羊のおうち仕様 §1）

## 4. テンプレートを「選ばせる」のをやめる

いまは記録の最初に **休養／練習／レッスン／リハ／本番** の5択があります。
**最初の操作が決断なのは、いちばん重い設計です。**

### 推測して、既に選んでおく

```
優先順位（上から順に、当たったものを採用）

1. 指導者プランのレッスン日程に、今日の予定がある → その種別
2. 稽古ノートに今日の予定が書かれている           → その種別
3. 直近8週の「同じ曜日」で最も多かった種別        → それ
4. 上記が無い                                    → 練習
```

```
● 今日は？   練習 ▾          ← 既に入っている。違えばタップ
```

- **推測が外れても害はありません**（表示される欄が変わるだけ）
- 「推測しました」という表示は**出さないこと**。言い訳がましく見えます
- ユーザーが変更したら、その日の推測は上書き。学習は §4 の3のみでよい

**完了の定義：** 記録画面を開いてから最初の1タップまでに、決断が挟まらない。

## 5. 分析画面の順番

### 5.1 最初に「判定」を出さない

いまは分析を開くと、いちばん上に **偏差値 62** が出ます。

**調子が悪い日は、ここが 41 です。**
そして調子が悪い日のデータこそ、このアプリが最も必要としているものです。
**開いた瞬間に低い点数を見せると、悪い日にアプリを開かなくなります。**

### 5.2 新しい順序

```
┌───────────────────────────────┐
│ 分析                           │
│ [今週][1ヶ月][1年][本番前後]    │
├───────────────────────────────┤
│ ① 今日の一言                    │ ← 発見があれば発見。無ければ事実
│ ┌───────────────────────────┐ │
│ │ 💡 睡眠不足の「2日後」に      │ │
│ │    いちばん落ちています       │ │
│ │    ρ=0.61 ・ 14日分     詳しく→│ │
│ └───────────────────────────┘ │
│  ※発見が無い日は                │
│  「記録 18日目。あと2日で        │
│    食事の分析がひらきます」      │
├───────────────────────────────┤
│ ② 今日                          │ ← 偏差値・今日の声・WU効率
├───────────────────────────────┤
│ ③ 今週の発見                    │
├───────────────────────────────┤
│ ④ 本番に向けて                  │
├───────────────────────────────┤
│ ⑤ 記録の推移                    │
├───────────────────────────────┤
│ ⑥ この分析を強くする      ★§5.3 │ ← いちばん下。ここが本題
└───────────────────────────────┘
```

**変更点は2つだけです。**

1. **① を新設**して、判定より先に「発見または前向きな事実」を置く
2. **⑥ を新設**する（§5.3）

③④⑤の中身と順番はいまのままで構いません。

**追加の規則**

- **⚠ の警告カードで画面を終わらせないこと。**
  「本番に向けて」に警告が出た日は、その下に必ず対処カードを1枚置く
  （例：`明日を休養にすると 1.20 になります`）
- 偏差値には必ず `あなたの過去◯日の中での位置` と添える。
  **他人との比較と読める表記を出さないこと**（国際展開仕様の「自分比だけ」）

### 5.3 ★ 「この分析を強くする」カード

**これが、項目数を増やす本体です。**

記録画面をいくら整えても、ユーザーは「なぜこれを入れるのか」を知りません。
**分析の側から、名指しで、理由つきで要求してください。**

```
┌───────────────────────────────┐
│ この分析を強くする               │
│                               │
│ ┌───────────────────────────┐ │
│ │ 「効いた習慣」の確度 ★★★☆   │ │
│ │                            │ │
│ │ 就寝時刻を あと5日 記録すると │ │
│ │ ★★★★ になります            │ │
│ │                            │ │
│ │        [ 今日の分を入れる ] →│ │ ← 記録画面の睡眠へ直行
│ └───────────────────────────┘ │
│                               │
│ ┌───────────────────────────┐ │
│ │ 🔒 ラグ相関マップ            │ │
│ │ あと8日、または              │ │
│ │ 水分を5日記録すると開きます   │ │
│ │        [ 今日の分を入れる ] →│ │
│ └───────────────────────────┘ │
└───────────────────────────────┘
```

**規則**

| # | 規則 |
|---|---|
| R1 | **1度に2枚まで。** 足りない項目を全部並べない |
| R2 | **必ず「何が良くなるか」を書く。** 「記録してください」だけの文言を禁止 |
| R3 | ボタンは**記録画面の該当セクションへ直行**し、その欄をハイライトして開く |
| R4 | **日数の条件と、項目の条件を両方書く**（待てば開くことを隠さない） |
| R5 | 選ぶ基準は「**足りない量が最も少なく、効果が最も大きい**もの」 |
| R6 | 一度も使っていない項目は、**3枚目以降として扱う**（いきなり新項目を要求しない） |

**選定ロジック（実装）**

```ts
// 「あと少しで確度が上がる」ものを優先する
score = (見込みの改善量) / (必要な追加記録日数)

// 見込みの改善量：
//   ロック解除 = 1.0
//   ★が1つ増える = 0.6
//   確度係数がしきい値を超える = 0.4

// 必要日数が 10日を超えるものは出さない（遠すぎて動機にならない）
```

**遷移の実装**

```
/analysis → /record?focus=sleep.bedtime&date=today
  → 記録画面を開き、該当セクションまでスクロールし、
    2秒だけ淡いハイライト。入力欄にフォーカスは当てない
    （キーボードが勝手に出ると、逆に閉じられます）
```

### 5.4 ロックカードの文言

いまの「あと8日で開きます」を、**行動できる形**にします。

```
❌ データ不足
❌ あと8日で開きます（だけ）
✅ あと8日、または 水分を5日記録すると開きます
```

**灰色の「データ不足」表示は禁止です**（画面レイアウト仕様 §1.2 で既定）。
ぼかし＋進捗バー＋**具体的な条件**の3点セットにしてください。

## 6. 変えないこと

| 項目 | 理由 |
|---|---|
| **並び順をユーザーごとに自動で入れ替えない** | 毎日同じ場所にあることが速さの最大要因（P7）。頻度で並べ替えると毎回探すことになります |
| **並び順の設定画面を作らない** | 設定が増えるだけで、ほぼ誰も使いません |
| 30秒モードの3項目 | いまのままでよい（喉／声の出来／睡眠） |
| 項目そのもの | **本書で項目を追加・削除しないこと** |
| 「前日をコピー」の対象 | いまのまま（声・症状・メンタルはコピーしない） |

**ユーザーが変えられるのは「セクションの開閉」だけです。**
閉じたセクションは、次回も閉じたまま。**ただし §5.3 のボタンから来たときは開く。**

## 7. 効果の計測（必ず入れること）

**計測とユーザー調査仕様のイベントテーブルに、次を追加してください。**

```ts
'record_open'         { entry: 'voice' | 'day', hour: number }
```

**見る指標**

| 指標 | いま | 目標 |
|---|---|---|
| 1日あたりの平均入力項目数 | 計測して基準を取る | **+2** |
| 記録の途中離脱率 | 同上 | 下げる |
| **声の出来が低い日の記録率** ★ | 同上 | **下げない** |
| §5.3 のボタン → 当日入力の到達率 | — | 40% |

**★が最重要です。**
調子が悪い日に記録が止まるなら、他の数字が全部良くても失敗です。
**この1つが悪化したら、§3.5 の演出と §3.4 の進捗表示を先に疑ってください。**

**離脱が最も多いセクションを1つ特定し、そこだけ次に手を入れる。**
全体をもう一度並べ替えないこと。

## 9. 禁止事項

- ❌ **本書を口実に、記録項目を追加しないこと**
- ❌ 「未入力」「不足」「完了度」「達成率◯%」という語をUIに出さない
- ❌ 保存直後の演出を、**閉じられない全画面**にしない
- ❌ 心の余裕に**数値のフィードバックを返さない**（§3.3）
- ❌ §5.3 のカードを**3枚以上同時に出さない**
- ❌ `?focus=` の遷移で**キーボードを自動で開かない**
- ❌ 並び順を**利用頻度で自動的に入れ替えない**（P7）
- ❌ ポイントの増減を**体調・出来の良し悪しに連動させない**
- ❌ 偏差値に**他人との比較と読める表記**を付けない
- ❌ 記録を促す**プッシュ通知を、本書を根拠に増やさない**

## 10. Claude Sonnet 5 への依頼のコツ

- **§8 の 1・2・3 を、この順で1つずつ**。まとめて出させない
- 各項目の完了時に、**変更前後のスクリーンショット**を出させる
- **「ついでに項目を整理しました」を許さない。** 項目は v2 の定義が正
- 並び順は必ず **§8 の定数配列**から描画させる（JSXに直接書かせない）
- §3.3 の計算は**すべて既存の関数を呼ぶこと**。新しい計算式を作らせない
- §5.3 の選定ロジックは**サーバー側で計算**し、画面はその結果を並べるだけにする
- **§3.1 に勝手に着手させない。** 1〜7 と計測が先です

## 注意書き

本書は画面レイアウト仕様 §4・§5 の並び順を差し替えるものです。
項目の定義は記録項目の再設計v2、指標の定義は指標設計図が正です。

本書に挙げた心理的な効果（endowed progress、peak-end、質問順序の影響）は
**一般的な知見であり、このアプリで同じ効果が出る保証はありません。**
§7 の計測を必ず入れ、**「調子が悪い日の記録率」が下がっていないこと**を
最優先で確認してください。下がった場合は §8 の 1 まで戻せるようにしてあります。

記録画面に表示するフィードバックは、すべて自分比です。
文献上の基準値・他人との比較・疾病を示唆する表現を出さないでください。
