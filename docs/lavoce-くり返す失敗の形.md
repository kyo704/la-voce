# くり返す失敗の形

★この文書は**足すだけ**です。直った項目も消しません。**同じ形が何度も出る**ことが、
いちばん大事な情報だからです。

★新しい形が出たら、いちばん下に足してください。回数も更新してください。

---

## 1. 同じ判断が、2か所にある

**形**：ひとつの決めごとが、`lib/` の module と、画面のインラインと、両方に書かれる。
あとで片方だけ直され、食い違う。

**出た回数**：7回以上（表示ゲート／権限の判定／職業の名札／`name` と `display_name`／
同意の版の定数／ポリシーの文面／`teacher_note` と `teacher_notes` 表）

**防ぎ方**：決めごとを `lib/` の1つの module に寄せ、**呼ぶ側が離れたら落ちる検査**を書く。
★「書き写さないこと」とコメントするだけでは防げません。何度もそう書いてありました。

---

## 2. コメントを外さずに、禁じた言葉を探す

**形**：「この語を書かないこと」という検査が、**その規則を説明している自分のコメント**に
当たって落ちる。あるいは、拒否リストの行そのものに当たる。

**出た回数**：6回

**防ぎ方**：`components/tests/_source.js` の `readCode`（コメント除去ずみ）を使う。
位置や順番を見るときだけ `readRaw`。

---

## 3. 窓の幅で、境界を決める

**形**：`[\s\S]{0,400}` や非貪欲マッチで構造の範囲を切り出し、**隣のものまで拾う**。
関数の本体を取るつもりが、入れ子の閉じかっこで止まる。

**出た回数**：4回以上（分析タブの並べ替え／検査ファイルからの関数削除／
`notice_batches` の定義／過去の「正規表現手術」）

**防ぎ方**：かっこを**数えて**境界を出す。数え始めるのは、引数リストが閉じた**あと**の
本体の `{` から。★完全一致の錨で置き換え、置換の前に「1件であること」を確かめる。

---

## 4. 早期 return の上を見ずに、その下だけを読む

**形**：grep で当たった行の周辺だけを読み、そこが**到達しない**ことに気づかない。
`if (!x) { return ... }` は、その下を全部無効にします。下から読むと見えません。

**出た回数**：★**4回**（2026-09-03 の1日で）
- `/billing` の `CheckoutButton`（★訂正を2度重ねました）
- 「レッスンのタブは、つながりが0件なら出ない」→ ★**誤り**。
  見ていたのは先生側の入口（`canTeachLessons`）だけで、生徒側の入口は
  別の関数（`canSeeStudentTeacherLink`）にあり、★**常に true** でした。

★**4回とも、実機で見た人が正しく、コードを読んだ私が誤っていました。**
★**画面が何を出すかは、画面を見て決めます。** コードは、なぜそうなるかを
説明するのには使えますが、★**何が起きるかを言い当てるのには足りません。**

**★合わせて足す規則**：探すときは、★**同じ問いに答える関数が
ほかにも無いか**を先に確かめる。`canTeachLessons` を見つけたところで
止めたのが、今回の原因です。

**防ぎ方**：画面が何を出すか・経路が何をするかを言う前に、**関数の1行目から**読む。
最低でも、関数の始まりから当該行までの `return` / `redirect` / `throw` / `notFound` を見る。
★検査は「存在するか」ではなく**「見張りが対象より前にあるか」**を確かめる。前者は、
見張りによって到達不能になったあとも通ってしまいます。

## 5. 「画面に入口が無い」を「安全」と読む

**形**：ボタンを隠す・定数で `false` にする、で経路が閉じたと考える。
実際には URL を直に叩けば通る。

**出た回数**：3回（`AI_ADVICE_ENABLED`／同意の撤回の強制／Stripe の3ルート）

**防ぎ方**：閉じるのは**サーバ側**。環境変数が未設定なら**閉じるほうへ倒す**
（`CRON_SECRET` が未設定なら 503、と同じ形）。★画面の定数は門ではありません。

## 6. RLS で列を隠せると考える

**形**：「先生専用」「本人だけ」と書いた列が、`select("*")` で**そのまま渡る**。
RLS は**行**単位で、列は隠せません。

**出た回数**：4回（`get_student_entries` を作った理由／`entries` の先生ポリシー／
`lessons.teacher_note`／★`profiles_connected_display_name`。
最後のものは、**本番で実際に他人の既往症が読める状態**でした）

**防ぎ方**：列を絞るなら、サーバ側で返す列を決める（`SECURITY DEFINER` の関数）か、
**その列を持たない**。★画面に出していないことは、渡していないことではありません。

## 6-2. ポリシーの名前が、列を指している

**形**：`profiles_connected_display_name` のように、ポリシーの名前が
**「この列だけ見せる」**と読める。作った人は、そのつもりだった。
★**RLS は列を絞れません。** 行が読めれば、その行の**全部**が読めます。

**出た回数**：1回（`profiles`。★`allergies` / `regular_medications` /
`conditions`（既往症）/ `health_notes` / `is_under_18` / `line_user_id` が、
つながっている相手から読める状態でした）

★**これは6番の一種ですが、別に立てます。** 6番は「作るときの誤解」で、
こちらは★**名前が、あとから読む人まで誤らせる**という害だからです。
名前を信じたことが、そのまま漏れになりました。

**★命名の規則（2026-09-03 から）**

ポリシーの名前は、★**「誰がその行を見てよいか」**を書きます。
★**「何の列を見せるつもりか」は、決して書きません。** RLS に、その力はありません。

| 書いてよい | ★書いてはいけない |
|---|---|
| `profiles_own_row` | ~~`profiles_connected_display_name`~~ |
| `profiles_connected_row` | ~~`lessons_public_note`~~ |
| `entries_own_row` | ~~`profiles_name_only`~~ |

★**列を絞りたいときは、ポリシーではなく関数を作ります**
（`get_org_member_names` / `get_connected_names` と同じ形）。
返す列を、関数の側で決めます。

**防ぎ方**：`supabase/AUDIT_policies_by_using_clause.sql` を定期的に流す。
★**名前を見ない。USING 句を見る。**

検査の出力を読んでから、次のコマンドを打つ。

## 7-2. 本番に手で当てて、リポジトリに写さない

**形**：SQL エディタでポリシーや関数を当て、リポジトリに写さないまま忘れる。
★**git には何も残りません。** あとから読む人は、**本番に何があるかを知る手立てがありません。**

**出た回数**：★**1日で3件**（2026-09-03）
- `lessons` … `(org_id IS NULL) OR …`。1対1のレッスンが全員に見えていた
- `entries` … 先生向けのポリシーが残り、行ごと読めていた
- `profiles` … `profiles_connected_display_name` と `are_connected`。
  ★**どちらもリポジトリに1文字もありません**

★**3件は偶然ではありません。** 仕組みとして、そうなっています。
`CLAUDE.md` にも「`schema.sql` を正として扱わないこと」と書いてありますが、
★**書いてあるだけでは防げませんでした。**

**★規則（2026-09-03 から）**

> **本番に手で当てない。どうしても当てたら、その日のうちにリポジトリへ写す。**

★**「あとで写す」は、写さないことと同じです。** 今日見つかった3件は、
どれも「あとで写すつもりだった」ものです。

**防ぎ方**：`supabase/AUDIT_full_schema_vs_repo.sql` を定期的に流し、
本番とリポジトリを突き合わせる。★**差が出たら、その場で写します。**

## 8. 取り返しのつかない操作の前に、確かめた数値が「戻ってきていない」

**形**：安全のための数え上げ（「中身のある行は0か」）を用意し、運営者が実行し、
**その数値が実装側まで返らないまま**、次の取り返しのつかない手順が承認される。
手順としては守られているのに、**確かめた事実を知らない者が居る**状態が残る。

**出た回数**：1回（`lessons.teacher_note` の DROP。★実際には①は0で、
順番も守られていました。返ってこなかったのは**数値そのもの**です）

★これは**コードの読み違いではなく、受け渡しの欠落**です。だから別の項目にしています。
コードを直しても、この形は防げません。

**防ぎ方**：取り返しのつかない手順（`drop column` / `delete` / 本番の設定変更）の前に、
★**その手前の確認の「実際の値」を、実装側まで一度返す。**
「進んでよい」だけでは足りません。★**何がいくつだったか**を返します。
返っていないうちは、実装側は「まだ確かめていない」として扱ってよい
（そう扱ったことで、この項目が見つかりました）。

★似た紛らわしさ：「列はもう無い（0）」と「落とす前の中身は0だった」は、**別の事実**です。
前者は後者を意味しません。

## 9. 状態を1つの列で持ち、上書きする

**形**：`status` を `'sent'` → `'opened'` と書き換える。**送った時刻が消えます。**

**出た回数**：0回（★設計の段階で避けました。TASK A）

**防ぎ方**：時刻の列を並べ、それぞれ**一度だけ**入れて消さない。
段階は、時刻から**読んで**求める。
