## 結論

**ホーム画面のアイコンから開いたときに要求される `/` が、
一度もキャッシュに入っていないためです。**

`/` はログイン済みだと**転送（307）**を返します。
sw.js は `response.ok`（200〜299）のものだけを保存するので、
**転送は、原理的にキャッシュに入りません。**

★オンラインでどれだけ使っても、`/` は永久に貯まりません。
　「事前に開いていたのに効かなかった」のは、そのためです。

```
② ログイン済み     app/page.js:123  redirect("/dashboard") → 307
③ sw.js:38        response.ok && type === "basic" のときだけ保存

⑥ standalone      ブラウザの枠が無く、オフライン用の画面も無い
                  → ★真っ白
```

★ブラウザのタブなら、同じ失敗でも「インターネットに接続できません」
　という画面が出ます。**ホーム画面のアイコンからだけ、白くなります。**

## ご指摘の3点への答え

### ① インストール済みPWAの起動経路は、タブと違うか

**違います。決定的に。**

タブは「見ていた場所」から再開します。
PWAは**毎回 start_url へ新しく navigate します。**

`start_url: "/"` は、ログイン済みの人にとって
**必ず転送になる唯一のURL**です。
そして転送は、キャッシュの条件から外れています。

### ② キャッシュに、本来あるはずの項目はあるか

**ありません。** 鍵の付け方の食い違いでも、
JSの塊が足りないのでもありません。**HTMLそのものが、一度も保存されていません。**
`Response.error()` は、設計どおりに動いています。

★`/dashboard` は保存されているかもしれません。
　しかし**PWAは起動時に `/dashboard` を要求しません。** `/` を要求します。

### ③ 今日の変更が原因か

**★いいえ。今日より前からあった不具合です。**

```
37a8930 より前  .catch(() => caches.match(event.request))
                → undefined → respondWith(undefined) が
                  「Failed to convert value to 'Response'」で例外
                → ★これも白い画面

37a8930 以降    cached || Response.error()
                → ネットワークエラー応答
                → ★これも白い画面
```

私がやったのは、**例外をきれいなエラーに変えただけ**でした。
どちらも白くなります。**直したつもりで、直っていませんでした。**

★ご指摘の2つの候補は、どちらも違います。
```
woolsong-shell-v3 への版上げ
  → 読む鍵と消す鍵が変わるだけ。今回の経路に関係しません

reloadOnceOnControllerChange
  → オフラインでは新しい Service Worker を取得できないため、
    controllerchange がそもそも起きません
```

### ★そして、形は今日のものと同じです

移行の列が無いときと、まったく同じ形でした。

**落ちないようにしただけで、機能は死んでいる。**
安全に失敗するのと、見えるように失敗するのは、別のことです。
今回は「オフラインでも起動する」が、偶然そう見えていただけでした。

## 直し方の候補（★まだ実装していません）

| | 中身 | 良い点 / 代償 |
|---|---|---|
| **A** | install のときにオフライン用の画面を焼き込み、navigate が失敗したら必ずそれを返す | ★必ず何かが出る。`/` 以外の未保存のURLにも効く／何と書くかを決める必要がある |

**Aを勧めます。** 「オフラインでも起動する」を、
偶然ではなく**本当にそうする**唯一の案です。
