## 1. 先に確かめたこと

- ★**プラン名で分岐している場所は、いま1つもありません。** まっさらな状態から始められます。
- `subscriptions` には**プランの列がありません**（`schema.sql`）。持っているのは
  `status` と Stripe の id と期限だけです。★**1種類しか想定していない形**です。
- Stripe の呼び出しは `STRIPE_PRICE_ID` という**環境変数1つ**を使っています
  （`app/api/stripe/checkout/route.js:44`）。★**値段が1つしか入りません。**
- 料金の数字は、コードにも文書にも★まだ1つも書かれていません。

★つまり、いまの決済の下地は**「1プランだけ」の形**です。3つの段には、そのままでは使えません。

## 2. ★いちばん大事なこと：プラン名で分岐しない

書いてはいけない形：

```js
if (plan === "studio") { …… }              // ★書かない
const limit = plan === "studioPro" ? 100 : 10;  // ★書かない
```

理由は、この repo で繰り返し起きてきた欠陥そのものだからです。
**同じ判断が2か所に散らばり、片方だけ直される。** 段が増えたとき、
`=== "studio"` を書いた場所を**全部見つけなければ**なりません。見落とせば、
★**新しい段の人だけ、その機能が使えません。** そして誰も気づきません。

代わりに、**できることを表に持たせます**。

```js
// ★プラン名を見ません。上限を引きます。
const limit = planLimits(plan).maxStudents;
```

段を増やすときに触るのは、**表の1行だけ**です。

## 3. 表のかたち

### 3-1 `public.plans`（何ができるか）

| 列 | 中身 |
|---|---|
| `code` | `'teacher'` / `'studio'` / `'studio_pro'`（★主キー。画面には出しません） |
| `display_name` | 画面に出す名前 |
| `monthly_yen` | 月額（★整数。円）|
| `stripe_price_id` | Stripe 側の価格の id |
| `max_students` | 生徒の上限（★`null` は「上限なし」） |
| `max_teachers` | 先生の上限（`null` は上限なし） |
| `sort_order` | 画面に並べる順 |
| `is_available` | いま申し込めるか（★行は消さない。過去のプランの人が残るため） |

★**`is_available = false` にしても行は消しません。** 消すと、そのプランで
契約している方の `plan_code` が**どこも指さなくなります**。

### 3-2 `subscriptions` に列を1つ

```sql
alter table public.subscriptions
  add column if not exists plan_code text references public.plans(code);
```

★**`not null` にしません。** いま契約している方の行は、どのプランでもありません
（無料で運用しているため）。★`null` は「プランに入っていない」です。
既定値を入れて埋め戻すと、★**「選んだ」と「まだ選んでいない」が混ざります。**

## 4. ★`lib/entitlements.js` と混ぜないこと

`entitlements.js` は、すでに **`can(viewer, feature)`** を持っています。
これと**同じもののように見えますが、別の問いです**。

| | 問い | 答えるもの |
|---|---|---|
| `entitlements` | ★その機能は、**もう出しているか** | `cohort`（テスター先行公開） |
| `plans` | ★その人の契約に、**入っているか** | `plan_code` |

「先生モードは、まだテスターにしか出していない」と
「先生モードは、studio 以上の契約に入っている」は、**別々に真になります**。

★**片方に寄せてはいけません。** 寄せると、先行公開を終えたときに
「テスターだから使えていた人」と「契約しているから使える人」の区別がつかなくなり、
★**契約していない人に、黙って使わせ続けることになります。**

★**両方が通ったときだけ使えます。** 新しいモジュール `lib/planLimits.js` が
`plans` の側だけを持ち、`entitlements` には触れません。
