# 作業指示｜学ぶ画面の「問い」を、記事の種類ごとに分ける

対象：`lavoce-作業指示-学ぶ画面を勉強できるものにする.md` の §2-4（読んだ直後の3問）と §3（間隔反復）への**追記・上書き**。
それ以外の節は、そのまま有効です。

---

## 1｜なぜ変えるか

いまの設計は、全記事に**選択式3問**を出しています。
これは**答えが一つに決まる知識**には正しい設計です（記憶科学の practice testing）。

しかし「音楽家の商い」（ビジネス編）の記事は、そうではありません。

```
・活動している土地が違う
・会場の規模も、客層も、相場も違う
・書いてあることが当てはまらない読者が、必ずいる
```

**ここで選択式を出すと、「この記事の主張＝正解」と教えてしまいます。**
それは、このアプリが分析画面で守ってきた線（断定しない・押しつけない）を、
学ぶ画面のほうで破ることになります。

**だから、記事の種類で問いの形を分けます。**

---

## 2｜二つのモード

記事のメタデータに `quizMode` を足してください。

```ts
type QuizMode = 'recall' | 'reflect'

interface Article {
  // ...既存
  quizMode: QuizMode       // 既定は 'recall'
  quiz?: Question[]        // recall のときだけ
  prompts?: string[]       // reflect のときだけ（2問）
}
```

### `recall`（選択式・従来どおり）

**対象：からだと声のしくみ、湿度、睡眠、逆流、用語、法律・制度など**
事実に正解がある記事。**§2-4 と §3 の設計をそのまま使ってください。**

`音楽家の商い 14（確定申告）` も、**制度の説明なので recall で構いません。**

### `reflect`（記述式・採点しない）

**対象：「音楽家の商い」01〜13**
正解が土地と状況で変わる記事。

```
・自由記述欄を2つ出す
・★正解を出さない。○×を出さない。点数を出さない
・「よく書けています」等の評価語も出さない
・保存だけする。あとから自分で読み返せる
```

**画面下の注記（固定文言）**

```
※ 答え合わせはありません。採点もしません。
   あなたの土地と、あなたの活動では、本文と違う答えが正しいことがあります。
   書いたものは、あなたの記録に残ります。
```

## 3｜読む前の問い（プリクエスチョン）は残す

**§2-1 の「読む前1問」は、両モードとも残してください。**
読む前に一度考えると、そのあとの本文が残りやすくなる（prequestion 効果）ためです。

ただし**選択肢に正解の印を出さないでください。**
記事本文の中で答えが明らかになる形にします。
（既存記事の `★` 付き選択肢は、記事側で外してあります）

「音楽家の商い 01」だけは、**選択肢の全部が正解になり得る**問いです。
この記事では、正解の表示自体をしないでください。

## 4｜間隔反復（§3）の扱い

```
recall  → 従来どおり。1日後・7日後・21日後・以後は月1回、選択式で再出題
reflect → ★再出題しない。代わりに「前に書いたもの」を読み返す導線を出す
```

**reflect の再訪問画面**

```
┌──────────────────────────────┐
│ 3週間前に、あなたはこう書きました        │
│                                          │
│ 「（本人の記述をそのまま表示）」          │
│                                          │
│ [ いまは同じことを思いますか ]           │
│   → 追記できる。上書きしない             │
└──────────────────────────────┘
```

**追記は履歴として積む**（`created_at` 付き）。過去の記述は消さないでください。
自分の考えが変わっていく過程が見えることが、ここでの価値です。

## 5｜データ

```ts
// 記述式の回答
interface ReflectAnswer {
  id: string
  articleId: string
  promptIndex: number      // 0 or 1
  text: string
  createdAt: string
}
```

```
・★分析にも、統計にも使わない
・★AIに渡さない
・書き出し（法定エクスポート）には含める
・削除できるようにする
```

**守りのテスト3本の禁止キーに、次を追加してください。**

```js
'reflectAnswer','reflectAnswers','promptIndex',
```

（同期・共有・集計のどのペイロードにも、記述本文が乗らないこと）

---

## 6｜無料と有料

```
無料   基本編の記事すべて／読む前の問い／recall の3問
有料   音楽家の商い（第1章・第2章）／reflect の記述と、その履歴
```

無料ユーザーにも、**reflect の入力欄は見せてください。**
書こうとした瞬間に鍵がかかるのが、いちばん嫌われます。
**鍵は記事本文の側にかけます。**

---

## 7｜受け入れ条件

```
□ 音楽家の商い 01〜13 で、選択式の設問が1つも出ない
□ 記述欄に何を書いても、○×・点数・評価語が出ない
□ 読む前の問いに、正解の印が出ていない
□ 記述が、同期・集計・AI のどのペイロードにも乗らない（テストで確認）
□ 3週間後に「前に書いたもの」が読み返せて、追記できる
□ 過去の記述が上書きされない
```
