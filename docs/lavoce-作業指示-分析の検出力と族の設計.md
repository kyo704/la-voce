# La Voce ／ 分析の検出力と「族」の設計

**Claude Sonnet 5 へ。3ゲートそのものは変更しません。**
**変えるのは「一度に何を検定するか」と「ユーザーに伝える期間」です。**

読む順番：統合実行ルート v4 §6（表示ゲート）→ 本書 → 分析画面の表示規約.md。

---

## 0. なぜこの文書があるか

3ゲート（n≥10・|g|≥0.4・BH-FDR q<0.10）が**実際にどれくらい通るのか**を、
模擬データで確かめました。結果です。

```
本当に効いている関係が2つある状況で、それを見つけられる割合

記録日数   同時に検定する数   本当の効果   見つかる割合
    60              5         g=0.5          39%
    60             20         g=0.5          21%
    60              5         g=0.8          83%
   120              5         g=0.5          69%
   120             20         g=0.5          52%
                              g=0.3 は、60日・20項目で 3%
```

**分かったことは3つです。**

```
① 60日では、中程度の効果を8割見逃す
② ★同時に検定する数を増やすほど、検出力が半分になる
③ ★「あと4日で傾向を出せます」は、正確ではない
   （n≥10 に届くだけで、3ゲート通過は3〜4か月かかる）
```

**ゲートを緩めてはいけません。**緩めれば白米の例に戻ります。
**代わりに、検定の対象を絞ります。**

## 1. ★族を2つに分ける

**いちばん効く対策です。実装も小さい。**

```
中核族（5項目）  ★BH-FDR はこの5つの中だけでかける
                  ★文章を出してよいのは、ここだけ

探索族（それ以外） ★文章を出さない。数字も出さない
                  「まだ調べています」とだけ表示
                  120日を超えたら、中核への昇格を検討する
```

**3ゲートは「文章を出す条件」でした。**
**探索族はそもそも文章を出さないので、ゲートの対象外です。**
だから族を分けても、ガードレールは1ミリも緩みません。

### 1-1｜中核5項目（全職業共通）

**全員が毎日記録するもの**から選びます。
一部の人しか使わない機能は、中核に入れません。

```
① 睡眠時間              中央値で二分
② 本番外の発話時間       中央値で二分
③ 絶対湿度              中央値で二分
④ 本番・レッスンの翌日か  二値
⑤ 起きたときのむくみ     なし / あり（1以上）
```

**この5つを選んだ理由**

```
・機序がはっきりしている（思いつきの相関ではない）
・全員が記録する（群が偏らない）
・二分したときに両群が10日以上たまりやすい
・★「絶対湿度」は、湿度そのものより機序に近い（既存の計算をそのまま使う）
```

### 1-2｜職業別・オプション機能の扱い

```
周期の位相 × 声        ★別の族。単独で BH をかける
食事と就寝 × 声        ★別の族。単独で BH をかける
職業別の項目           ★探索族。文章を出さない
```

**周期と食事と就寝を中核に混ぜないでください。**
使っている人だけの分析なので、中核族の検出力を下げてしまいます。
**それぞれ独立した小さな族として扱います。**

### 1-3｜実装

```ts
// lib/analysisFamilies.js
export const CORE_FAMILY = [
  'sleepHours', 'offStageVoiceMinutes', 'absoluteHumidity',
  'dayAfterPerformance', 'morningEdema',
]

export const FAMILIES = {
  core:    CORE_FAMILY,          // BH をこの中でかける
  cycle:   ['cyclePhase'],       // 別の族
  reflux:  ['mealToBedGap', 'refluxFlags'],
  explore: /* それ以外すべて */ [],
}
```

```
・★BH-FDR は族ごとに独立してかける（全部まとめてかけない）
・★explore は検定しない。計算もしなくてよい
・族の定義を画面ごとに書かない。この1か所だけで持つ
```

## 2. ★言葉を直す（いちばん急ぐ）

### 2-1｜いまの表示は不正確です

```
✗ 「6日分たまりました。あと4日で傾向を出せます。」
```

**10日で満たされるのは、3つのうち1つ（件数）だけです。**
効果量と多重比較を通るには、実際には**3〜4か月**かかります。

### 2-2｜直したあと

```
┌──────────────────────────────┐
│ 食後就寝までの時間と、翌朝の声              │
│                                            │
│ ●●●●●●○○○○                          │
│ 6日分たまりました。                        │
│ あと4日で、判定を始められます。            │
│                                            │
│ ※ はっきりした関係が見えるまでには、       │
│    ふつう3〜4か月かかります。              │
└──────────────────────────────┘
```

```
・「傾向を出せます」→「判定を始められます」
・★分析画面を初めて開いたときに、3〜4か月かかることを一度だけ伝える
・★それ以降は繰り返さない（毎回言われると重い）
```

**先に言ってしまうほうが、期待とのずれが起きません。**
30日目に「まだ何も出ない」と感じさせるより、
最初に「数か月かかるものです」と伝えるほうが、離脱が減ります。

## 3. 効果量の不確かさを隠さない

**n=30 と n=30 で観測した g=0.45 は、かなり幅のある推定です。**
点推定だけで「差の大きさ 中程度」と書くのは、少し言い過ぎです。

**ゲートは変えません。表示に幅を足します。**

```
・カードの本文は今のまま（「中程度」でよい）
・★「数字で見る」の表に、g の95%信頼区間を1列足す
・★「確実」「間違いなく」「証明されました」と書かない
```

```
| 群 | 日数 | 中央値 | 四分位 |
| 2時間未満 | 31 | 2.6 | 2.1–3.3 |
| 2時間以上 | 24 | 3.5 | 3.0–4.1 |
| 差の大きさ | | 0.52 | 0.11–0.93 |   ← ★この行を足す
```

## 4. ★計測する（この製品が機能しているかの指標）

```
・記録30日・60日・90日・120日の時点で、
  ★3ゲートを通ったカードを1枚以上持っている人の割合
```

**これが、この製品の約束が成立しているかどうかの唯一の指標です。**

```
120日で 0% に近ければ  → 中核族をさらに絞るか、期間の説明を変える
120日で 50%を超えれば  → 探索族から中核への昇格を検討してよい
```

## 5. 検討しておくこと（いま実装しない）

**固定順序法（fixed-sequence）という選択肢があります。**

5項目に**あらかじめ順位をつけ、上から検定して、落ちたらそこで止める。**
この方法なら**1つ目には多重比較の補正が要らず、検出力が最大**になります。

```
利点   いちばん知りたい関係を、最大の検出力で調べられる
欠点   ★順位が外れていると、2つ目以降に到達できない
```

**いまは採用しません。**BH を中核5項目の中でかけるだけで、
検出力は倍になります（21% → 39%）。まずそこまで。

**120日ぶんのデータが集まって、どの項目が効きやすいか分かってから、
順位を決めて移行するかを判断します。**

## 6. ★禁止事項

```
1. ★3ゲートの閾値を変えない（n≥10 / |g|≥0.4 / q<0.10）
2. ★族をまたいで BH をかけない
3. ★探索族に文章を出さない。数字も出さない
4. 中核5項目を、相談なく増やさない（増やすほど何も言えなくなる）
5. 周期・食事と就寝を中核族に混ぜない
6. 「あと◯日で傾向を出せます」と書かない
7. 3〜4か月かかることを、毎回言わない（初回だけ）
8. 効果量を「確実」「証明」という言葉で語らない
```

「ゲートを少し緩めれば、もっと見つかるのでは」という提案です。**

```
★それは、この製品が最初に捨てた道です。
```
