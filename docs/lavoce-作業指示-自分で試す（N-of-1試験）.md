## 0. なぜ作るのか

**いまの分析は、相関で止まっています。**

```
「うるさい場所で働いた日の翌朝は、声の調子が低めでした」
```

これは**関係**であって、**原因ではありません。**3ゲートを通しても、そこは変わりません。
順番が本人の都合で決まっているからです。

**順番を、こちらで決めれば変わります。**

```
2週間  就寝の3時間前までに食事を終える
2週間  ふだんどおり
2週間  就寝の3時間前までに食事を終える
2週間  ふだんどおり
        ★どちらから始めるかは、くじで決める
```

**8週間で、条件ごとに28日。各群 n ≥ 10 を、楽に超えます。**

そして開始順が本人の気分で決まっていないので、
**「その人にとっては効いた」と言えます。**

**★これは、検出力の問題への回答でもあります。**
60日待って何も出ないという構造的な弱さを、**待つのではなく設計で解きます。**

## 1. 結論

```
① 試すことは★決められた一覧から選ぶ。自由記述にしない。
② 見る指標は★事前に1つだけ決める。あとから増やさない。
③ 開始する条件を★くじで決める（AB か BA）。
④ ★途中で結果を見せない。見ると行動が変わります。
⑤ 各群の有効日数が10未満なら、★結果を出さない。
⑥ ★薬・受診・治療に関することは、試せる一覧に入れない。
⑦ 出すのは効果の大きさと幅だけ。★「効果があります」と断定しない。
```

## 2. 試せること（★この一覧の外は作らない）

```
生活
  □ 就寝の3時間前までに食事を終える
  □ 寝室に加湿器を使う
  □ 就寝時刻を、いつもより1時間早くする
  □ 起床後1時間、声を出さない

声の使い方
  □ 本番外の発話を、1日◯分以内にする
  □ 声を出す前に、決めた準備をしてから歌う
  □ レッスンの翌日は歌わない

飲食
  □ カフェインを1日1杯までにする
  □ 就寝前2時間、水以外を飲まない
  □ 水を1日◯リットル飲む

仕事（★「ほかの仕事」を使っている人のみ）
  □ 本番の前2日は、うるさい場所での仕事を入れない
  □ 連勤を3日までにする
```

### 2-1｜★入れてはいけないもの

```
✗ 薬を飲む／減らす／やめる
✗ 病院に行く／行かない
✗ サプリメントを摂る
✗ 特定の食品を「治療のために」摂る／やめる
✗ 発声の技術そのもの（★先生の領分です）
```

**上の4つは、医療の判断です。アプリが試験の形で誘導してはいけません。**
**最後の1つは、先生の指導と矛盾したときに生徒が壊れます。**

**★自由記述で「試すこと」を書かせないでください。**
書けるようにした瞬間、上の項目が書かれます。

## 3. 設計

### 3-1｜作り方

```
① 試すことを1つ選ぶ
② ★見る指標を1つ選ぶ（朝の声の調子／のどの違和感／CPPS など）
③ 1区間の長さを選ぶ（★既定 2週間。最短1週間）
④ 区間の数：4（AB AB または BA BA）
⑤ ★開始する条件を、アプリがくじで決める（本人に選ばせない）
⑥ 開始
```

**★②を1つに限る理由**

**あとから指標を選べると、良い結果が出たものを選べてしまいます。**
それは占いに戻るということです。**先に決めて、動かさない。**

### 3-2｜★途中で結果を見せない

```
試験中に見えるもの   今日はどちらの期間か／残り何日か／記録が付いているか
★見えないもの       途中の集計・グラフ・差・傾向
```

**途中経過を見ると、人は無意識に行動を変えます。**
**盲検ができない代わりに、ここで守ります。**

### 3-3｜画面

```
┌──────────────────────────────┐
│ 試している：就寝3時間前までに食事           │
│                                            │
│      いまは【 する 】期間です               │
│         あと 6日                            │
│                                            │
│   ●●●●○○○○   4区間のうち2つめ           │
│                                            │
│   記録   ▓▓▓▓▓▓░▓▓▓▓▓▓▓  13/14日          │
│                                            │
│              [ やめる ]                     │
└──────────────────────────────┘
```

```
・★「今日はする／しない」を、毎朝1回だけ通知（22:00〜08:00 は送らない）
・切り替わる日だけ、強調する
・★「守れましたか」は聞かない（守れなかった日も、そのまま解析します）
```

**★守れなかった日を除外しないでください。**
除外した瞬間に、都合の良い日だけを集めたことになります。

### 3-4｜やめられること

```
・いつでも [ やめる ] を押せる
・★途中でやめた試験は「未完了」として残し、結果を出さない
・責める言葉を出さない（「もう少しでした」も出さない）
```

## 4. 解析

### 4-1｜手順

```
① 各区間の、指標の日次データを集める
② ★最初の2日を除く（切り替えの持ち越しを避ける。ウォッシュアウト）
③ 群A（する）と群B（しない）に分ける
④ 有効日数：★どちらも 10 日以上。満たなければ結果を出さない
⑤ Hedges' g（J補正）を出す
⑥ ★区間単位の並べ替え検定（permutation test）で p を出す
      4区間の割り当ての取り方は限られるので、
      ★取りうる全パターンを列挙して p を出す（近似しない）
⑦ 95%の幅（ブートストラップ）を出す
```

**★通常の t 検定を使わないでください。**
日々のデータは前日と相関しており、独立ではありません。
**区間ごと入れ替える並べ替え検定なら、この問題を避けられます。**

### 4-2｜出す条件

```
① 各群の有効日数 ≥ 10
② |Hedges' g| ≥ 0.4
③ 並べ替え検定の p < 0.10
```

**★BH-FDR はかけません。**
**指標を事前に1つに決めているので、多重比較が発生しないからです。**
これが §3-1 ② の意味です。

### 4-3｜出し方

```
┌──────────────────────────────┐
│ 8週間の結果                                 │
│                                            │
│ 就寝3時間前までに食事を終えた期間のほうが、  │
│ 朝の声の調子は★高めでした。                 │
│                                            │
│   する    ▓▓▓▓▓▓▓▓  3.8                   │
│   しない  ▓▓▓▓▓▓    3.2                   │
│                                            │
│   差の大きさ  中くらい（g = 0.61）          │
│   幅          0.18 〜 1.04                  │
│                                            │
│ ★これはあなたの8週間の記録から出た結果です。 │
│ ★他の人に当てはまるとは限りません。          │
│ ★病気の有無や治療について述べるものでは      │
│   ありません。                              │
└──────────────────────────────┘
```

**条件を満たさなかったとき**

```
「差がはっきりしませんでした。
  効果がないという意味ではなく、この8週間では
  ★分からなかった、ということです。」
```

**★「効果がありませんでした」と書かないでください。**
検出できなかったことと、無いことは、違います。

### 4-4｜持ち出せるようにする

```
・結果を1枚の画像／PDFにできる
・★「これは診断ではありません」を、その紙にも書く
・先生や医師に見せるのは本人の自由。★アプリから送る機能は作らない
```

## 5. データモデル

```ts
interface Trial {
  id: string
  userId: string
  intervention: TrialInterventionKey   // ★列挙型。自由記述なし
  outcome: OutcomeKey                  // ★1つだけ
  blockDays: 7 | 14
  blockCount: 4
  startArm: 'A' | 'B'                  // ★アプリが乱数で決める
  seed: string                         // 再現できるように残す
  startedAt: string
  status: 'running' | 'completed' | 'aborted'
  endedAt?: string
  result?: {
    nA: number; nB: number
    g: number; ciLow: number; ciHigh: number
    p: number; passed: boolean
    computedAt: string
  }
}

interface TrialDay {
  trialId: string
  date: string
  arm: 'A' | 'B'
  washout: boolean       // 区間の最初の2日
  outcomeValue?: number  // ★その日の記録から引く。二重に入力させない
}
```

```
・★outcomeValue を新しく入力させない。既存の記録から引く
・★RLS は本人のみ。教師・管理者のポリシーを作らない
・書き出し（法定エクスポート）に含める
```

## 6. ★禁止事項

```
1.  ★試すことを自由記述にしない
2.  ★薬・受診・治療・サプリを、試せる一覧に入れない
3.  ★発声技術そのものを試験にしない（先生の領分）
4.  ★開始する条件を本人に選ばせない（くじで決める）
5.  ★途中経過を見せない
6.  ★指標をあとから変えさせない・増やさせない
7.  ★守れなかった日を除外しない
8.  ★「効果があります」「効果がありません」と断定しない
9.  ★他人の試験結果と比べない・平均を見せない
10. ★同時に2つの試験を走らせない（何が効いたか分からなくなります）
11. ★教師・保護者に、試験の内容も結果も見せない
12. ★試験を勧める通知を出さない（設定の中に置くだけ）
13. ★中断した人を責めない
```

### なぜ ⑩ を禁止するか

**2つ同時に走ると、どちらが効いたのか永久に分かりません。**
そして人は必ず、両方やりたがります。**一度に1つだけ、で止めてください。**

## 10. Sonnet への依頼のコツ

**この機能で、いちばん越えやすい線は「科学のふり」です。**

実装中に、次を思いつくはずです。

```
・p値が0.11でも「効果がありそうです」と書く
・指標を複数見て、いちばん差が出たものを表示する
・守れなかった日を除いて、きれいな結果にする
・他のユーザーの平均と比べて「あなたは効きやすい体質です」と出す
```

**4つとも §6 で禁止しています。**

**この機能の価値は、正しい答えを出すことではありません。**
**★間違った答えを出さないことです。**

```
★迷ったときの基準

それは、決める前に決めておいたことですか？
　→ あとから決めたなら、出してはいけません。
```
