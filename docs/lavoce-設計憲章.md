## 1. ★動かさない数値

**この節の数値を変更する提案は、坂本さんの明示的な承認なしに実装しないでください。**
理由は共通です：**変えると、過去に記録された全データの意味が変わります。**

### 1-1｜3つのゲート（分析で文章を出す条件）

```
① 各群 n ≥ 10          両群が揃っていること。片方が空なら不通過
② |Hedges' g| ≥ 0.4     相関なら |ρ| ≥ 0.3
③ BH-FDR で q < 0.10    ★族の中だけで補正する（§3-1）

境界：n=10 ／ |g|=0.40 ／ q=0.099 は通る
      n=9  ／ |g|=0.39 ／ q=0.11  は通らない
効果量は★絶対値で判定（負の方向でも通る）
```

### 1-2｜Hedges' g

```
s = √( ((n₁−1)s₁² + (n₀−1)s₀²) / (n₁+n₀−2) )
g = (x̄₁ − x̄₀) / s × J
J = 1 − 3 / (4(n₁+n₀) − 9)
95%幅 = g ± 1.96 × √( (n₁+n₀)/(n₁n₀) + g²/(2(n₁+n₀)) )

★方向は「前日の行動 → 翌日のスコア」に固定。同日相関は逆因果を拾う
```

### 1-3｜EWMA ACWR

```
L(日) = 活動時間 × 活動係数 × 曲の倍率（運動は 0.3 × 分 × 強度/3 を加算）

λa = 2/(7+1)  = 0.250     ★変更禁止
λc = 2/(28+1) = 0.069     ★変更禁止
A = λa·L + (1−λa)·A(前日)
C = λc·L + (1−λc)·C(前日)
ACWR = A / C

  < 0.80      積み足りない
0.80 – 1.30   ちょうどいい
1.30 – 1.50   増やしすぎ注意
  > 1.50      急増

★記録のない日は L=0 とせず、前日のEWMAを引き継ぐ
  （休んだのか、書き忘れたのか、区別できないため）
★rolling 7/28 に置き換えない
```

### 1-4｜曲の負荷倍率

```
center = (低い方 + 高い方) / 2
half   = (高い方 − 低い方) / 2
d      = (テッシトゥーラ − center) / half

strain = (|d| / 0.85) ^ 1.7        上方向
       = 上の値 × 0.6              下方向
songFactor = 1.0 + 1.5 × strain    → 1.00 〜 3.25

KAPPA = 0.6                        ★変更禁止
GAMMA = 1.7 ／ 基準 0.85 ／ 下方向 0.6 ／ 係数 1.5   ★変更禁止

★中心を歌っても倍率は 1.0。ゼロにしない（歌うこと自体にコストがある）
★テッシトゥーラ未入力 → 「最高音 − 5半音」で仮置き
  両方入った曲が5件たまったら、その人の実測平均に置き換える
```

### 1-6｜絶対湿度

```
e_s = 6.112 × exp( 17.67 T / (T + 243.5) )      T は ℃
AH  = 216.7 × e_s × RH / 100 / (273.15 + T)     g/m³

検算  20℃/50% → 8.64   25℃/60% → 13.81   31℃/38% → 12.18

★相対湿度で置き換えない（意図的な設計）
```

### 1-7｜CPPS（週1回の測定）

```
取得   48kHz モノラル → 中央の3秒だけ（最初と最後の1秒は不安定）
解析   40ms窓・10msホップ → ハミング窓 → FFT → 対数パワースペクトル
       → もう一度FFT → 3.3〜16.7ms（60〜300Hz）の最大ピーク
       − 同位置の回帰直線の値 = そのフレームのCPP
       → 平滑化 → ★全フレームの中央値をその日の値に

品質   環境騒音が閾値以上          → 測定中止
       クリッピング／5秒未満／F0が1オクターブ跳ぶ → やり直し
       ★有効フレームが7割未満     → 保存しない

表示   ★8回たまるまで表示しない。単独の値を見せない
       その人の過去の散らばりの帯と一緒に折れ線で
```

出す条件 各群10日以上 ／ |g| ≥ 0.4 ／ 並べ替え検定の p < 0.10
         ★BH-FDR はかけない（指標を事前に1つに固定しているため）

★t検定を使わない（日次データは前日と相関し独立でない）

## 11. ★判断の基準

### ★2026-09-01 追記｜entries.activity_type の意味

**その日最も長く続いた活動。**
「主たる活動」でも「いちばん負荷の大きい活動」でもない。**長さだけで決まる。**
負荷の大小を見たい場合はこの列を使わないこと。

- 書くのは `deriveActivityTypeForStorage`（components/VocalTracker.jsx）。
  ★この関数の意味を変えないこと。変えると、これまでの行とこれからの行で
  同じ列の意味が変わり、読む側からは見分けがつかない。
- 表示で「その日を代表する活動」が要るときは
  `lib/activityPrecedence.js` の `representativeActivityKind` を使う。
  発声負荷の重み（休養0＜自主練習1.0＜レッスン1.2＜リハーサル1.3＜本番1.6）で選ぶので、
  90分の自主練習のあとの20分の本番が消えない。
- 「その日に本番があったか」を知りたいときは `entryHasActivityKind` を使う。
  ★activity_type を見ると、短い本番が長いレッスンに隠れる。
- ★配列より前の形式で記録された日（`migrateLegacyToActivities` が
  activity_type から activities[] を組み立てた行）は、活動が1つしかない。
  「長さだけで決まる」が問題になるのは、配列形式になってからの
  **複数の活動がある日だけ**である。

### 11-1｜★記録項目を足すときの4つの問い（2026-08-31）

**新しい記録項目を足す前に、必ずこの4つに答えてください。**

```
① それは、すでにどこかで聞いていないか
② はい／いいえ で足りないか
③ 1タップで終わるか
④ ★それを足すと、ほかの項目の記録率が下がらないか
```

**★④がいちばん大事です。**

```
2項目が80%埋まる  ＞  5項目が10%ずつ埋まる
```

3ゲートは、群ごとに **n ≥ 10** を要求します。
**項目を増やして記録率が下がると、どの項目も判定に届かなくなります。**
足したのに、何も言えなくなる。**増やすことが、減らすことになります。**

**★医学的な根拠の強さは、除外する理由になりません。**
根拠の弱いものは「探索の族」に入れます（図だけ、文章も数字も出さない）。
除外と探索は別の扱いです。混同しないでください。

**★新しい項目を提案するときは、同時に「外す項目」を1つ挙げてください。**
足す一方だと、画面と記録率の両方が静かに悪くなります。
