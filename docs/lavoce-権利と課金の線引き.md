## 1. データモデル

```ts
type PlanId =
  | 'free'
  | 'premium'      // 個人
  | 'teacher'      // 指導者
  | 'studio'       // 教室
  | 'studioPro'    // 教室（上位）
  | 'founder'      // ★試運転からの利用者。全開放

interface Subscription {
  userId: string
  plan: PlanId
  source: 'trial' | 'self' | 'grantedByOrg'   // 教室からの一括付与
  grantedByOrgId?: string
  startedAt: string
  expiresAt?: string        // founder は null（無期限）
  updatedAt: string
}
```

**★`founder` は課金レコードを持ちません。** 期限も付けません。
将来やめる判断をするときは、そのとき改めて決めます。

## 2. 権利の判定

### 2-1｜★サーバー側で判定する

```ts
// lib/entitlements.ts
export const FEATURES = [
  'analysis.relations',      // 3ゲートを通った関連の表示
  'analysis.range',          // 30日を超える期間の指定
  'analysis.cycle',          // 周期の分析
  'analysis.reflux',         // 食事と就寝の分析
  'export.doctorSheet',      // 受診のときに持っていく1枚
  'metrics.history',         // CPPS / MPT / s-z の履歴
  'repertoire.multi',        // レパートリーの複数管理
  'learn.advanced',          // 学ぶ記事の応用編
  'teacher.viewStudents',
  'teacher.lessonRun',
  'studio.multiTeacher',
  'studio.opsDashboard',
  'studio.calendarFeed',
  'studio.makeup',
  'studio.ledger',
  'studio.threads',
] as const

export function can(plan: PlanId, feature: Feature): boolean
```

```
・★すべての保護対象APIの入口で can() を呼ぶ
・★クライアント側の分岐は「見せ方」だけ。データは返さない
・RLS だけに頼らない（RLS は所有者判定、can() は権利判定。別物）
・can() の単体テストを、機能 × プランの全組み合わせで書く
```

### 2-2｜★やってはいけない実装

```
✗ フロントで <PremiumOnly> に包むだけ（APIを直接叩けば取れる）
✗ 課金状態を localStorage に持つ
✗ 「プレミアムではない」を理由にデータを削除する
✗ 期限切れで過去の記録を見えなくする（★記録は常に本人のもの）
```

**期限が切れても、記録そのものは必ず読めます。**
消えるのは**読み解き（分析）**だけです。

## 3. ★絶対にゲートしないもの

**この一覧のものを有料にしないでください。** 例外はありません。

```
記録のすべて
  声・体調・環境・レッスン・周期・食事と就寝・ノート・メモ
  今日の記録／前日をコピー／過去の記録の閲覧と編集と削除

続けるための仕組み
  羊とおうち（ポイント・成長・アイテム・表情）
  通知・リマインド
  週次の振り返り

権利に関わるもの
  ★法定の書き出し（全データのエクスポート）
  ★アカウントの削除／この機能だけの削除
  同意の確認と撤回

最低限の見える化
  直近7日の単純な推移（数字と線だけ。関連の判定は含まない）
  今日のコンディションスコアと、その内訳
  学ぶ記事の基本編（★医学的な注意を含む記事は全部ここ）
```

**理由**

**記録を有料にすると、記録が集まらず、分析が成立しません。**
そして**症状がある人ほど記録が必要**なので、
記録に壁を置くのは、いちばん必要な人を締め出すことになります。

**羊を有料にすると、続ける動機が消えます。**
羊は売り物ではなく、**記録を続けさせるための装置**です。

**法定の書き出しは、支払いの有無にかかわらず無料です。**
個人情報保護法・GDPR の権利です。
「受診のときに持っていく1枚」は診察用に整形した便宜なので、これは有料で構いません。
**★この2つを同じ実装にまとめないでください。**

## 4. プレミアム（個人）に入れるもの

```
analysis.relations   3ゲートを通った関連の表示すべて
                     （相関・群比較・周期×声・食事と就寝×声）
analysis.range       30日を超える期間の指定、期間どうしの比較
analysis.cycle       周期の分析（★記録と、その日の「◯日目」表示は無料）
analysis.reflux      食事と就寝の分析（★記録と当日の差の表示は無料）
export.doctorSheet   受診のときに持っていく1枚
metrics.history      CPPS / MPT / s-z 比の履歴と推移
repertoire.multi     レパートリーの複数管理と負荷の配分
learn.advanced       学ぶ記事の応用編
```

### 4-1｜★can() は、出す最初のコミットで巻く（2026-08-30）

```
★その機能を利用者に見せる「最初のコミット」で、can() を必ず巻くこと。
  先に出しておいて、あとからゲートを足す、を★してはいけません。
```

**理由：一日でも見えてしまえば、あとから隠すのは
「あった機能を取り上げる」ことになります。**
新しく課金の線を引くのと、すでに使えていたものを引き上げるのとでは、
受け取られ方がまったく違います。前者は説明できますが、後者は説明できません。

いま作っていないのは3つです（`lavoce-テスターへの先行公開と群のラベル.md` §1-2）。

```
analysis.range   metrics.history   learn.advanced
```

**★この3つを作るときは、機能とゲートを同じコミットに入れてください。**

### 4-2｜★医療にかかわる記事は、例外なく基本編（2026-08-30）

`learn.advanced`（学ぶ記事の応用編）だけは、
**中身によって、そもそも有料にしてはいけないものがあります。**

```
★受診の目安・危険な兆候・やってはいけないこと・薬にかかわる注意
  → これらを含む記事は、例外なく「基本編」にすること。
  → ★応用編に置かないこと。
```

**理由：お金を払っていない人に「いつ医者にかかるべきか」を
見せない、という状態を作ってはいけません。**
それは課金設計の問題ではなく、安全の問題です。
記事が有料の壁の向こうにあるあいだに受診が遅れたら、
その責任は線の引き方にあります。

**★基本編か応用編かは、記事を書くときに同時に決めてください。**
あとで分類すると、「まず書いて、あとで振り分ける」ことになり、
医療にかかわる記述が応用編に紛れます。
（俳優（舞台）・俳優（映像）・司会の7記事について、
`lavoce-判断のまとめ-20260830.md` §4）

---

**線の引き方は一貫しています。**

```
★記録は無料。読み解きは有料。
```

**「今日の事実」は無料、「日をまたいだ関係」は有料**、と言い換えても同じです。

## 6. 画面の出し方

### 6-1｜印は出す。動作は止めない（founder のみ）

```
┌────────────────────────────────┐
│  食後就寝までの時間と、翌朝の声   ◆プレミアム │
│                                                │
│  （中身はふつうに表示される）                  │
└────────────────────────────────┘
```

```
・founder には ◆プレミアム の印だけ出し、中身は見せる
・free には印を出し、中身の代わりに §6-2 を出す
・★印のデザインは控えめに。金色の王冠などを使わない
```

### 6-2｜free に見せるもの

**★「使えません」と書かないでください。**

```
┌────────────────────────────────┐
│  食後就寝までの時間と、翌朝の声   ◆プレミアム │
│                                                │
│  ●●●●●●●○○○                              │
│  7日分たまっています。                         │
│  10日たまると、プレミアムで傾向を出せます。    │
│                                                │
│              [ くわしく見る ]                  │
└────────────────────────────────┘
```

**記録が進んでいることは、無料でも見せます。**
**貯まっている実感が、そのまま有料の理由になります。**

### 6-3｜★やってはいけない見せ方

```
✗ 画面を覆うモーダルで購入を迫る
✗ 起動のたびに勧誘を出す
✗ 記録の保存後に勧誘を出す（★保存直後は羊の場所）
✗ 数字をぼかして「見るには課金」と出す（★数字を出さないなら最初から出さない）
✗ 無料ユーザーの記録に上限日数を設ける
```

**ぼかし表示を作らないでください。** 3ゲートを通っていない値を
ぼかして見せるのは、「何かある」と言っているのと同じです。

## 9. Sonnet への依頼のコツ

**この作業でいちばん危ないのは、Day 1 の付与漏れです。**
1人でも漏れると、協力してくれている人が突然使えなくなります。

```
① 付与前のユーザー数を数える
② founder を付与する
③ 付与後の founder 数を数える
④ ★①と③が一致することを確認してから次へ進む
```

**そして、迷ったときの基準は1つです。**

```
その機能を止めたら、記録が止まりますか？
　→ はい なら、無料のまま。
```
