## 1. なぜ取りやめるか（実装者向けの背景）

週次カルテは「医師に見せる／先生に見せる／SNSで共有」の3用途を1枚に束ねた設計でした。
検証すると、**3つとも別の形のほうが目的を果たします。**

**医師に見せる** — 声のプロが音声外来にかかるのは年に1〜3回、しかも何か起きてから。
そこで必要なのは「先週」ではなく「症状が出てから今日まで」であり、**週次という単位が
用途と噛み合っていません。** 加えて、AMA の国際調査では **97%の医師が患者の自己計測
データを見ている一方、診療に組み込んでいるのは6%未満**で、障壁は診療フローの負担と
データの信頼性です。そして決定的なのは、**このアプリの独自指標（偏差値・ACWR・相関）
こそ、診察用の紙に載せてはいけないもの**だということ。医師に意味が伝わらない数字が
並ぶほど、その紙は読まれなくなります。

**先生に見せる** — 指導者ダッシュボードと機能が重複します。先生がプラットフォームに
いない場合も、レッスンの現場で学生がやるのは**スマホを開いて見せる**ことであり、
書き出して渡すという行為は発生しません。必要なのは PDF ではなく**読み取り専用画面**です。

**SNSで共有** — **プロにとって、自分のコンディションの公開はキャリアのリスク**です。
「あの人は喉が弱い」という印象は次の仕事に直結します。悪い週ほど共有されず、
良い週だけ出すなら、それはもうカルテではありません。共有されうるのは
**達成の形をしたもの**（音域の更新、連続記録）だけです。

**ただし「週に一度まとまって振り返る」体験自体には価値があります。**
間違っていたのは配送方法で、PDF は**プル型**（ユーザーが「書き出そう」と思わないと
何も起きない）でした。必要なのは**プッシュ型**です。

## 3. 置き換え① 週次の振り返り（アプリ内＋プッシュ）

**新規実装はほぼ不要です。** 稽古ノートの週次振り返り（画面レイアウト仕様 §6.2）に、
週のサマリーとプッシュ通知を足すだけ。

### 3.1 画面（ノート ＞ 稽古ノート の週次振り返りに追記）

```
┌───────────────────────────────┐
│ 今週の振り返り                  │
│ 8/19 – 8/25                    │
│                               │
│ ┌───────────────────────────┐ │
│ │ 記録 6/7日                 │ │  ← 週のサマリー（新規）
│ │ 偏差値 ▃▅▄▆▃▂▄  平均 54    │ │
│ │ 発声負荷 1.49 ⚠           │ │
│ │ 症状の出た日 5日            │ │
│ └───────────────────────────┘ │
│                               │
│ ┌───────────────────────────┐ │
│ │ ▁▂▃▃▄▅▄▅  弱声の最高音     │ │  ← 既存：目標タグから自動添付
│ │ D5 → E5（+2半音）          │ │
│ └───────────────────────────┘ │
│                               │
│ 今週わかったこと                │  ← 発見カードから1つだけ転記
│ 前夜7時間以上ねむれた日は、      │
│ 翌日の声が平均で1段階近く       │
│ 良くなっています。              │
│                               │
│ [ 感じたことを書く           ] │  ← 既存
└───────────────────────────────┘
```

**「今週わかったこと」は、その週の発見カードのうち優先度スコア最上位の1件を転記する。**
複数出さない。

### 3.2 プッシュ通知

**これが本体です。** 週次振り返りは、通知が届かなければ誰も開きません。

```ts
interface WeeklyDigestSettings {
  channel: 'line' | 'email' | 'none'   // 既定は line（日本）/ email（海外）
  weekday: 0 | 1 | 2 | 3 | 4 | 5 | 6   // 既定 0（日曜）
  hourLocal: number                     // 既定 20
}
```

**送信時刻はユーザーのタイムゾーンでのローカル時刻**で判定すること
（国際展開仕様 §2.3 の `tz` を使う）。Vercel Cron を1時間ごとに回し、
「そのユーザーのローカル時刻が設定時刻の枠に入ったか」で送信を決める。

文面（LINE）：

```
今週の記録がまとまりました。

記録 6/7日 ・ 偏差値の平均 54
弱声の最高音が D5 → E5 に伸びています。

▸ 振り返りを書く
https://...(ディープリンク)
```

- **数字を2つまで**。それ以上は開かせるための情報にならない
- **良い変化を1つ入れる**。悪い知らせだけの通知は開かれなくなる
- リンクは稽古ノートの週次振り返りに直接飛ばす

### 3.3 メール版

Resend で同内容を送る。HTML は最小限（数字とリンクのみ）。
画像を貼らない（読み込まれず、意味のない枠になる）。

## 4. 置き換え② レッスンモード（新規・優先度：中）

**PDF の代わりに、端末をそのまま先生に渡せる読み取り専用画面。**

### 4.1 起動

おうち／分析の右上に「レッスンモード」。ワンタップで切り替わる。

### 4.2 表示するもの／隠すもの

| 表示する | 隠す |
|---|---|
| 直近4週の偏差値の推移 | **メンタルの日記・気持ちタグ** |
| 症状カレンダー | 体重・体組成・エネルギー可用性 |
| 発声負荷（ACWR） | 食事の詳細 |
| 音域マップ | 既往症 |
| 稽古ノートの目標と直近の振り返り | 設定・アカウント・課金 |

**メンタルの日記を隠すことは必須です。** 先生に読まれる可能性があると、
生徒は正直に書かなくなり、データそのものが死にます。
「先生には見えません」と画面に明示してください。

### 4.3 抜け方

- 画面上部の「終了」を**3秒長押し**（誤操作で戻らないように）
- 設定で PIN を有効にできる（既定はオフ）
- レッスンモード中はタブバーを隠す

### 4.4 フッターの導線

```
┌───────────────────────────────┐
│ 先生アカウントがあれば、        │
│ この画面を毎日ご覧いただけます   │
│                    詳しく →    │
└───────────────────────────────┘
```

**指導者プランへの入口として機能させる。** レッスンの場で先生の目に入るので、
獲得チャネルとしても効きます。

## 5. 置き換え③ 受診用サマリー（新規・優先度：低／価値：高）

`/report/clinic`

**年1〜3回しか使われませんが、使うときの価値は非常に高い。** 小さく作ります。

### 5.1 設計方針は週次カルテと真逆

| 週次カルテ（廃止） | 受診用サマリー |
|---|---|
| 固定の1週間 | **任意期間**。既定は「症状が出た日〜今日」 |
| グラフ主体 | **テキストの時系列主体**。グラフは1つだけ |
| アプリ独自指標が中心 | **独自指標を一切載せない** |
| 見栄え重視 | **A4一枚に収まること**が最優先 |

### 5.2 期間の選択

```
┌───────────────────────────────┐
│ 受診用サマリー                  │
│                               │
│ 期間                          │
│ ◉ 症状が出てから（8/11〜8/25） │  ← 既定。自動検出
│ ○ 過去1ヶ月                    │
│ ○ 過去3ヶ月                    │
│ ○ 期間を指定                   │
└───────────────────────────────┘
```

**既定の期間は自動検出する。** 症状カレンダーを遡り、
**現在まで続いている症状の連続区間の開始日**を起点にする。
なければ過去1ヶ月。

### 5.3 載せるもの

1. **基本情報** — 年齢・性別・職業（声を使う仕事の内容と、1日あたりの平均発声時間）
2. **症状の経過（テキストの時系列）** — これが主役

```
乾燥      8/11 – 8/25（15日間、うち強い日 6日）
嗄れ      8/18 – 8/25（8日間、うち強い日 3日）
喉の張り感 8/20, 8/22, 8/24（3日）
```

3. **声の使用量** — 週あたりの発声時間の棒グラフ **1つだけ**
4. **睡眠時間の平均**（期間内）
5. **既往・服薬**（登録があれば）
6. **自由記入欄** — 受診時に手書きで足せる余白を必ず設ける

### 5.4 載せないもの

**偏差値／ACWR／ラグ相関／効果量／CPPS／エネルギー可用性。**

医師に意味が伝わらない独自指標が並ぶほど、その紙は読まれなくなります。
**この禁止リストをコード上のコメントに残してください。**
あとから「便利だから」と足されがちです。

### 5.5 出力

**PDF ライブラリは不要です。** 印刷用CSS で足ります。

```css
@media print {
  /* ナビ・ボタン・タブバーを非表示 */
  /* A4一枚に収まるフォントサイズと余白 */
  /* 背景色を落とし、罫線のみで構成 */
}
```

「印刷 / PDFで保存」ボタンは `window.print()` を呼ぶだけ。
ブラウザの「PDFとして保存」で十分です。

### 5.6 ヘッダの注記（必須）

```
本書はご本人の自己申告に基づく記録です。
医学的な診断や検査結果ではありません。
```

**症状名は記録した項目名をそのまま使い、病名を書かない。**
（国際展開仕様 §5.2 の規則に従う）

## 6. 置き換え④ 達成カード（獲得施策・優先度：中）

### 6.1 トリガは3つだけ

| トリガ | 例 |
|---|---|
| 音域の新記録 | 「自己ベストを更新しました G5 → G♯5」 |
| 連続記録の節目 | 7日 / 30日 / 100日 / 365日 |
| 稽古ノートの目標達成 | 「高音の弱声を安定させる」を達成 |

**それ以外では出さない。** 頻繁に出ると価値がなくなります。

### 6.2 絶対に載せないもの

**症状・コンディションスコア・偏差値・体重・睡眠・既往症。**

理由は §1 のとおりで、**プロにとってコンディションの公開はキャリアのリスク**だからです。
達成カードは「上振れしか含まない」ことが設計上の必須条件です。

### 6.3 カードの中身

```
┌───────────────────────────┐
│                           │
│      自己ベスト更新        │
│                           │
│        G5 → G♯5           │
│                           │
│      2026年8月25日         │
│                           │
│         La Voce           │
└───────────────────────────┘
```

数字と一言だけ。`@vercel/og` で画像生成（1200×630）。

### 6.4 共有前に必ずプレビュー

```
┌───────────────────────────────┐
│ この画像を共有します            │
│ [プレビュー画像]                │
│                               │
│ 含まれる情報：音域の記録と日付   │
│ 含まれない情報：症状・体調・体重 │  ← 明示する
│                               │
│ ┌──────────┬──────────┐      │
│ │  共有する │ 保存だけ  │      │
│ └──────────┴──────────┘      │
└───────────────────────────────┘
```

**何が含まれ、何が含まれないかを毎回明示する。**
健康アプリからの共有は、ここを曖昧にしてはいけません。

## 7. 有料ラインの見直し

収益化戦略で「週次メール」「PDF書き出し」を有料機能に置いていましたが、
**使われない機能を有料の壁にすると、払う理由が伝わりません。**

### 7.1 差し替え後の線引き

| | 無料 | 有料 |
|---|---|---|
| 記録 | 全項目・無制限 | 同じ |
| 履歴の閲覧 | 直近30日 | 無制限 |
| 指標 Lv.1〜3 | ✓ | ✓ |
| **指標 Lv.4〜6（発見・本番）** | ロック（予告のみ） | **✓ ここが有料の主軸** |
| 週次の振り返り＋通知 | **✓ 無料に変更** | ✓ |
| レッスンモード | **✓ 無料** | ✓ |
| 受診用サマリー | ✓ 無料 | ✓ |
| 達成カード | ✓ 無料 | ✓ |
| データ書き出し（JSON/CSV） | ✓ 無料（法的権利のため） | ✓ |

**変更の要点**

- **週次の振り返りと通知を無料にする。** これはリテンション機構であって、
  課金の壁ではありません。有料にすると無料ユーザーが離脱し、課金の母集団が育ちません
- **書き出し系はすべて無料。** データの書き出しは法的な権利（記録項目v2 §6.3）であり、
  有料化できません。受診用サマリーもその延長として無料にするのが自然です
- **有料の主軸は「発見（Lv.4以降）」と「本番レイヤー」に一本化する。**
  この2つは他のどこにもない価値であり、説明が要りません

## 8. 実装フェーズの差し替え

画面レイアウト仕様 §11 の Phase 9 を、以下に置き換えます。

| Phase | 内容 | 規模 |
|---|---|---|
| ~~9~~ | ~~週次カルテ（PDF・画像共有）~~ | ~~5日~~ |
| **9-a** | 週次の振り返り（稽古ノートに追記）＋LINE/メールのプッシュ | 3〜4日 |
| **9-b** | レッスンモード | 2〜3日 |
| **9-c** | 達成カード（`@vercel/og`）＋共有前プレビュー | 2日 |
| **後半** | 受診用サマリー（印刷CSS） | 2〜3日 |

**9-a を Phase 7（ノート）の直後に置いてください。** 稽古ノートと同じ画面なので、
まとめて作るほうが速い。**受診用サマリーは後回しで構いません**
（頻度が低く、他の機能の完成度が先です）。

## 9. Sonnet 5 への依頼のコツ

- **`/report/weekly` を作らない。** 既存資料に残っている記述は無効です
- **受診用サマリーに PDF ライブラリを入れさせない。** 印刷CSSで足ります。
  依存を増やさないこと
- **§5.4 の「載せないもの」をコード上のコメントに残す。**
  あとから「便利だから」と独自指標が足されがちです
- **達成カードの「載せないもの」（§6.2）も同様にコメントで残す**
- 週次通知の送信判定は**ユーザーのローカル時刻**で行う。
  UTC 固定で実装させないこと（国際展開仕様 §2.3）
- レッスンモードは**メンタルの日記を隠すことが必須要件**。
  ここを実装から漏らさせない

## 注意書き

受診用サマリーは自己申告の記録の整理であり、診断・検査結果ではありません。
病名・疾患の推測を記載しないでください。
達成カードおよび共有機能には、症状・コンディション・体重・既往症を含めないでください。
