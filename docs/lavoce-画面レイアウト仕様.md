# La Voce ／ 画面レイアウト仕様（モバイル優先）

これまでの設計（指標設計図・記録項目v2・職業別設計・収益化・国際展開）を、
実際の画面構成に落としたもの。実装は Claude Sonnet 5 を想定。

**基準幅は 390px（iPhone 標準）。** 768px 以上は 2カラムに広げる程度で、
別レイアウトは作らない。唯一の例外は**指導者ダッシュボード**（§8）。

**この文書の優先順位**

1. §2 ナビゲーションの再編 ← 現行の6タブを作り替える。ここが土台
2. §4 今日の記録 ／ §5 分析 ← 中心の2画面
3. §3 おうち ← 短いが、毎日ひらく理由はここにある
4. §6 以降 ← 順次

---

## 1. 全体の原則

### 1.1 画面ごとの役割を一文で決める

| 画面 | 一文の役割 | 滞在時間の目標 |
|---|---|---|
| **おうち** | 今日の自分を10秒で知り、記録へ送り出す | 10秒 |
| **記録** | 迷わず、途中でやめられる形で入力する | 30秒〜3分 |
| **分析** | 「見に行く」のではなく「見つかる」 | 1〜5分 |
| **ノート** | 過去を編集し、目標を振り返る | 週1回 |
| **もっと** | 設定・書き出し・学ぶ | 月1回 |

### 1.2 レイアウトの共通規則

- **ボトムタブは5つまで。** それ以上は「もっと」に入れる
- **主要な操作は画面の下半分**（親指が届く範囲）に置く
- **タップ領域は最低 44×44px。** 5段階評価のボタンは横幅を等分し、高さ 48px
- **保存ボタンは sticky**（記録画面の下端に固定）
- **横スクロールはチップ列とグラフだけ。** 本文が横に流れてはいけない
- **ロックされた機能は「ぼかし＋進捗バー」。** 灰色の「データ不足」表示は禁止
- **数値入力はステッパー＋直接入力の両方**（キーボードを出さずに済む道を残す）

### 1.3 状態の網羅（全画面で実装すること）

どの画面も次の5状態を持つ。**空状態の手抜きが離脱の最大要因**になる。

| 状態 | 出すもの |
|---|---|
| 空（記録0日） | 何が起きるかの予告。「3日記録すると◯◯が見えます」 |
| 少データ（1〜6日） | 出せるものは出す。出せないものはロック＋残り日数 |
| 通常 | 本来の表示 |
| 読み込み中 | スケルトン（スピナーではなく、形が見える灰色ブロック） |
| エラー／オフライン | **記録はローカルに保存されている**ことを明示。再送ボタン |

## 2. ナビゲーションの再編

### 2.1 現行と提案

| 現行タブ | 提案 | 理由 |
|---|---|---|
| おうち | **おうち**（名称はそのまま） | 中身を作り替え。「今日の一枚」にする（§3） |
| 今日の記録 | **記録** | 構造を作り替え（§4） |
| 分析 | **分析** | 分類軸を作り替え（§5） |
| 履歴 | **廃止** → ノート内のカレンダーへ | 独立タブに値する頻度がない |
| AIアドバイス | **廃止** → おうちと分析カードへ統合 | 独立タブだと「わざわざ見に行くもの」になり、誰も見ない |
| 健康情報 | **「もっと」へ移動** | 月1回の参照。一等地を占める必要がない |
| 発声理論（右上リンク） | **「もっと」へ移動**（健康情報と並べて「学ぶ」に） | 同上。職業別に出し分ける仕組みは残す（§7.2） |
| — | **ノート**（新規） | 稽古ノート＋カレンダー＋メモ振り返り |
| — | **もっと**（新規） | 週次カルテ・学ぶ（健康情報／発声理論）・設定・アカウント |

### 2.2 ボトムタブ（5つ）

```
┌──────┬──────┬──────┬──────┬──────┐
│  ⌂   │  ✎   │  ◫   │  ▤   │  ⋯   │
│ おうち│ 記録  │ 分析  │ ノート│ もっと│
└──────┴──────┴──────┴──────┴──────┘
```

「記録」タブには**未記録バッジ**を出す（今日まだ記録していなければ小さな点）。

## 3. おうち（今日の一枚）

### 3.1 設計意図

**スクロールなしで完結させる。** ここは情報を並べる場所ではなく、
「今日の自分」を一目で伝えて記録へ送り出す場所。

**名称は現行の「おうち」のまま**とします。毎朝ひらく画面としては、
「ホーム」より体温があり、体調管理アプリの性格に合っています。
中身だけを「今日の一枚」に作り替えます（ルートは `/`）。

### 3.2 ワイヤーフレーム（390px）

```

│ おはようございます              │  16px, muted
│ 8月25日(火) ・ 12日連続 🔥      │  13px, muted / ストリーク
│                               │
│ ┌───────────────────────────┐ │
│ │                           │ │  ← ヒーローカード
│ │       今日の声             │ │     12px muted
│ │                           │ │
│ │      ☁  2.4 / 5           │ │     48px, 数字が主役
│ │                           │ │
│ │  前夜の睡眠が5.5時間でした。│ │     14px
│ │  声が起きるのに時間が      │ │
│ │  かかるかもしれません。     │ │
│ │                           │ │
│ │  ─────────────────────    │ │
│ │  的中率 78%（直近30日）    │ │     12px muted
│ └───────────────────────────┘ │
│                               │
│ ┌───────────────────────────┐ │
│ │ 今日やるといいこと          │ │  ← 提案は必ず1つだけ
│ │ 水分をあと600ml            │ │

│                               │
│ ┌───────────────────────────┐ │
│ │     30秒で記録する          │ │  ← 主ボタン 56px
│ └───────────────────────────┘ │
│      しっかり記録する           │  ← テキストリンク
│                               │
│ ┌───────────────────────────┐ │
│ │ あと2日で「偏差値」が開きます│ │  ← 解放予告
│ │ ▓▓▓▓▓▓▓░░░                │ │
│ └───────────────────────────┘ │
└───────────────────────────────┘
```

### 3.3 規則

- **提案は必ず1つだけ。** 複数出すと、どれもやらない
- 提案の選び方：予報の回帰係数のうち、**今日いちばん改善余地の大きい項目**
  （`β × (目標値 − 現在値)` が最大のもの）
- 記録済みの日は、ヒーローカードが「今日の記録」の要約に切り替わる
- **ストリークは折れても責めない。**「12日連続」は出すが、途切れたら黙って0に戻す
  （「連続記録が途切れました」は出さない）
- AIアドバイスはこのカード内の文章として出す。独立画面にしない

### 3.4 §5.2（国際展開）の文言規則

ヒーローカードの文言は**自分比の事実のみ**。疾患名・「疑い」・文献閾値を出さない。

## 4. 今日の記録

### 4.1 設計意図

**80項目 → 実質10〜15項目に。** そのうえで、
「途中でやめても保存されている」ことを保証する。

**入力するたびに自動保存する。**「保存」ボタンは確認のためだけに置く
（押さずに離脱しても失われない）。

### 4.3 テンプレートによる出し分け

選んだテンプレートで、表示されるセクションが変わる（記録項目v2 §4.4）。

| テンプレート | 追加で出るもの | 消えるもの |
|---|---|---|
| 休養 | 休養方法の選択肢 | 活動時間、曲目 |
| 練習／レッスン／リハ | 活動時間、曲目 | — |
| 本番（声楽・ミュージカル） | 曲目、環境、**公演後の一言** | — |
| 収録（声優） | 収録種別、役名、**叫びテイク数**、ブース湿度 | 曲目 |
| 放送（アナウンサー） | 番組名、発話時間の内訳、生放送トグル | 曲目 |
| ライブ（ポップス/ロック） | セットリスト、モニター環境、連戦日目、打ち上げ | 曲目 |

**テンプレート定義は1つの定数ファイルに集約すること。**

- **音名ピッカーは鍵盤UI**。ドロップダウンより速く、表記体系が変わっても迷わない

おうちの「30秒で記録する」から開く。**3項目だけ**のシート。

```

│                               │
│ 喉の調子                       │
│ ┌────┬────┬────┬────┬────┐   │
│ │ pp │ p  │ mf │ f  │ ff │   │
│ └────┴────┴────┴────┴────┘   │
│                               │
│ 声の出来                       │
│ ┌────┬────┬────┬────┬────┐   │
│ │ 悪 │    │普通│    │ 良 │   │
│ └────┴────┴────┴────┴────┘   │
│                               │
│ 昨夜の睡眠  [ − ] 6.5 時間 [ + ]│
│                               │
│ ┌───────────────────────────┐ │
│ │        記録する             │ │
│ └───────────────────────────┘ │
│   もっと記録する →             │
└───────────────────────────────┘
```

**これで「記録した」ことになる。** 罪悪感を持たせないことが最優先。
記録率が落ちれば、どれだけ精緻な分析も表示されない。

### 4.7 「前日をコピー」

- 食事・身体データ・環境など、**変わりにくい項目だけ**をコピーする
- **声の記録・症状・メンタルはコピーしない**（その日固有の情報だから）
- コピー後は該当欄に「前日から」の小さなラベルを出し、編集を促す

## 5. 分析

### 5.1 いちばん大きな変更：分類の軸を変える

**現行は「声／身体／メンタル／全体」＝データの出どころで分かれています。**
これを **「いつ見るか」** で分け直します。指標設計図の3層と一致します。

| 現行 | 提案 |
|---|---|
| 声 / 身体 / メンタル / 全体を関連づけた分析 | **今日** / **今週の発見** / **本番に向けて** / **記録の推移** |

理由：ユーザーは「声のデータが見たい」のではなく、
「**今日どうか**」「**何かわかったか**」「**本番に間に合うか**」を知りたいから。

### 5.3 発見カードという単位

**分析結果は「グラフの羅列」ではなく「1枚1メッセージのカード」で出す。**
グラフはカードの中の脇役。モバイルではこれが決定的に効きます。

カードの構造：

```
┌───────────────────────────────┐
│ [アイコン] [カテゴリ]            │  12px
│                               │
│ 発見の一文（16px bold, 2行以内） │  ← これが主役
│                               │
│ [小さなグラフ or 数値]           │
│                               │
│ 根拠（ρ / 効果量 / 件数）12px    │
│                              → │  ← タップで /analysis/[id]
└───────────────────────────────┘
```

**カードの並び順は固定しない。** その日いちばん言うべきことを上に出す。
優先度スコアの例：

```
priority = |効果量| × 確度係数 × 新規性 × 行動可能性

  確度係数     ： ★の数 / 4
  新規性       ： 前回表示から日が経つほど高い（同じ発見を毎日出さない）
  行動可能性   ： 今日の行動で変えられるものは高く、体質・環境は低く
```

### 5.4 個別詳細ページ `/analysis/[metricId]`

発見カードをタップして開く。ここに**フルサイズのグラフ**と、
**計算方法の説明**、**注意書き**を置く。指標設計図で設計した図はここに入ります。

```
┌───────────────────────────────┐
│ ‹ 戻る                         │
│ 声の時差マップ                  │
│ 前日からの遅れ日数ごとの関係     │
│                               │
│ ┌───────────────────────────┐ │
│ │  [ヒートマップ]             │ │  ← 横スクロール可
│ │  ← スクロールできます        │ │
│ └───────────────────────────┘ │
│                               │
│ わかったこと                    │
│ あなたの声は、睡眠不足の2日後に  │
│ いちばん落ちます（ρ = 0.61）。   │
│ 本番の2日前の夜がいちばん大事、  │
│ ということかもしれません。       │
│                               │
│ ▸ 計算方法                     │  ← アコーディオン（既定は閉じる）
│ ▸ 注意書き                     │
│                               │
│ [ この発見を週次カルテに入れる ] │
└───────────────────────────────┘
```

### 5.5 グラフのモバイル対応

- **横スクロールするグラフには、必ず「← スクロールできます」を初回だけ出す**
- 凡例はグラフの上、横並び（下だと隠れる）
- タップでツールチップ。**もう一度タップで閉じる**（ホバーがないため）
- ヒートマップのセルは最低 32×32px
- 折れ線は 2px、点は直径 10px 以上

### 5.6 職業別の出し分け

「本番に向けて」セクションの中身が職業で入れ替わる（職業別設計 §第4層）。

| 職業 | このセクションに出るもの |
|---|---|
| 声楽家・ミュージカル | ピーキング曲線 / 発声負荷 / 環境の快適帯 |
| 声優 | **回復曲線 / 叫びテイク閾値** / 役ごとの負荷 |
| アナウンサー | **声のゴールデンタイム / 話声位の日内変動** / 番組別の負荷 |
| ポップス/ロック | **ツアー耐久曲線 / セットリスト診断** / モニター環境の効果 |

### 7.2 学ぶ（発声理論・健康情報）

現行の「発声理論」は右上のリンク、「健康情報」はタブにありました。
**この2つを「もっと」の中の『学ぶ』グループにまとめます。** どちらも参照頻度が
月1回程度で、一等地を占める必要がないためです。

ただし**タブから外すことは、格下げではありません。**
この2つのコンテンツには、いまより重い役割を持たせます。

#### 役割1：職業別の出し分けを維持・拡張する

現行の「選んだ職業に応じてリンク先が切り替わる」仕組みは正しく、そのまま残します。
職業別設計で対象を4職種に広げるので、**内容の分岐は今後さらに効いてきます。**

```
/health                     健康情報トップ（職業で並び順が変わる）
/health/[articleSlug]       個別記事
/theory                     発声理論トップ（職業で内容が切り替わる）
/theory/[professionKey]     声楽家 / アナウンサー / 声優 / ポップス・ロック
```

複数職業を選んでいる人には、**トップでどちらを見るか選ばせる**（既定は最初の職業）。

#### 役割2：分析からのディープリンク先になる（ここが本題）

**タブとして置いておくと誰も見に行きません。** 代わりに、
**分析の発見カードから、根拠となる解説記事へ直接飛ばします。**

```
┌───────────────────────────────┐
│ 💡 見つかりました               │
│                               │
│ あなたの喉の快適帯は            │
│ 絶対湿度 9.8〜14.2 g/m³ です    │
│                               │
│ ▸ なぜ湿度が声に効くのか →     │  ← /theory/... へ
└───────────────────────────────┘
```

自分のデータで驚いた直後が、**理論を読む気になる唯一の瞬間**です。
記事側から分析へ戻る導線（「あなたの記録で見る →」）も置きます。

各記事に `relatedMetrics: string[]` を持たせ、
発見カード側は `metricId` から関連記事を引く形にします。
**対応表は1つの定数ファイルに集約すること。**

#### 役割3：文献の閾値を置く唯一の場所

国際展開仕様 §5.2 の原則により、**分析画面には文献の閾値を出せません。**
CPPS の 14.45 dB、s/z 比の 1.4、RSI の 13点——これらは
**すべて「学ぶ」の記事側に置きます。**

記事は一般的な教育コンテンツであり、個人の記録に紐づかないため規制対象になりません。
**この分離は、法域を問わず成立する設計です。**

| 置き場所 | 書けること |
|---|---|
| 分析画面 | 自分比の事実のみ。「平常値より2.1dB低い日が3日続いています」 |
| 学ぶ（記事） | 一般論と文献値。「一般に持続母音で14.45dB未満が嗄声の目安とされます」 |

**記事から個人のデータを参照しないこと。** 参照した瞬間に、分析画面と同じ扱いになります。

#### 役割4：サポートコストを下げる

国際展開では、**問い合わせを減らす仕組み**として効きます（国際展開仕様 §11）。
FAQ もここに同居させ、UI 内で自己解決できる範囲を広げます。

#### 翻訳コストの注意

**発声理論は職業 × 言語で分岐するため、翻訳コストが最も高いコンテンツです。**
英語版では、まず**全職業共通の基礎記事だけ**を訳し、
職業別の詳細は日本語のみ（英語圏では非表示）から始めるのが現実的です。

音楽・声の専門用語は一般の翻訳で誤訳されます（chest voice, belting, onset,
passaggio, Fach など）。**下訳の後に、必ず声のプロによる用語チェックを入れてください。**

## 12. Sonnet 5 への依頼のコツ

- **記録画面は「声の記録シート」から作らせる。** ここが最も難しく、他が依存する
- テンプレート定義・詳細度の判定・発見カードの優先度計算は、
  **それぞれ1つの関数／定数ファイルに集約**させる。コンポーネントに条件分岐を散らさせない
- 発見カードは**共通コンポーネント1つ**で作り、指標ごとに data を差し替える形にする。
