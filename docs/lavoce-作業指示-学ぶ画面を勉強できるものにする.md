# La Voce ／ 学ぶ画面を「本当に勉強できる」ものにする

**Claude Sonnet 5 へ。記事を増やす前に、記事の構造を変えます。**

**いまの学ぶ画面には、学習科学で効果が薄いと分かっている方法が入っていて、
効果が高いと分かっている方法が入っていません。**

読む順番：**職業別項目の再設計と学ぶ画面.md §6〜§9** → 本書。
**§9 のガードレール（記事の中にユーザーの数値を差し込まない）は、そのまま生きています。**

---

## 0. 結論

```
① ★記事の冒頭に「読む前の問い」を置く。
   問われた内容だけが記憶に残る（g=.66 対 g=.01）。
   ★だから、覚えてほしいことを、そのまま問いにする。

② 読了直後に3問。1日後・7日後・21日後・以後は月1回で、また出す。

③ ★メモ機能を「要約」から「自分の言葉での言い換え」に変える。
   要約は効果が低く、自己説明は効果が中程度。

④ 記事ごとに「覚えるべき1文」を1つだけ決める。

⑤ ★正答率を成績として見せない。他人と比べさせない。
```

---

## 1. 効果が確かめられている方法と、そうでない方法

Dunlosky ら（2013）が10の学習法を評価した結果です。

```
高い効果   ★練習テスト（思い出す練習）
           ★分散学習（間隔をあけて繰り返す）

中程度     交互学習（違う話題を混ぜる）
           掘り下げる問い（なぜそうなるのかを自分に問う）
           自己説明（自分の言葉で説明し直す）

低い効果   再読
           ★ハイライト・下線
           ★要約
           語呂合わせ
           文章の映像化
```

**いまの学ぶ画面にあるのは「読む」と「メモ（要約）」です。**
**下2つは、いちばん効果が低い側にあります。**

**そして高い効果の2つが、どちらも入っていません。**

## 2. 記事の構造（8つのブロック）

**すべての記事を、この形にそろえてください。**

```
① 読む前の問い          1問。★答えを知らなくてよい
② 本文                  1,200〜2,000字
③ ★覚えるべき1文        記事ごとに1つだけ
④ 用語                  3〜6語。読みと意味
⑤ 自分に当てはめる問い   1問。★自由記述
⑥ 読んだ直後の3問        選択式
⑦ あとでもう一度          間隔をあけて自動で出る
⑧ つながる記事           2〜3本
```

### 2-1｜★① 読む前の問い（いちばん効く）

**読む前に問いを出すと、その内容の記憶が大きく伸びます。**

```
問われた内容      g = .66
問われなかった内容 g = .01
```

**つまり、問いを出した部分しか伸びません。**
だから**覚えてほしいことを、そのまま問いにしてください。**

```
┌──────────────────────────────┐
│ 読む前に、ひとつ考えてみてください          │
│                                            │
│ 乾いた部屋で声がかれやすくなるのは、        │
│ のどの何が変わるからだと思いますか？        │
│                                            │
│  ○ 声帯の粘液が減って、こすれやすくなる    │
│  ○ 声帯が厚くなって、重くなる              │
│  ○ 呼吸の量が増えて、息が続かなくなる      │
│                                            │
│  ★当てなくて構いません。考えることに       │
│    意味があります。                        │
│                        [ 読みはじめる ]     │
└──────────────────────────────┘
```

```
・★正解を、この時点で出さない（本文の中で明らかになる）
・★間違えても何も言わない。○×を付けない
・「当てなくて構いません」を必ず添える
・飛ばせるようにする（★必須にしない）
```

### 2-2｜③ 覚えるべき1文

**記事ごとに1つだけです。2つ書かないでください。**

```
┌──────────────────────────────┐
│ この記事で覚えておくこと                    │
│                                            │
│ 乾燥は、声帯の表面の粘液を減らし、          │
│ 振動のたびの摩擦を増やす。                  │
│                                            │
└──────────────────────────────┘
```

```
・★1記事1文。60字以内
・機序を書く（「乾燥はよくない」ではなく「なぜ悪いか」）
・★この1文が、⑥と⑦の出題の中心になる
・見た目は枠で囲むだけ。★蛍光ペンのような装飾を使わない
```

**ハイライトは効果が低い方法です。**
**「大事なところに線を引く」のではなく、「大事な1文だけを別に置く」。**

### 2-3｜★⑤ 自分に当てはめる問い

**自由記述で、1問だけ。**

```
┌──────────────────────────────┐
│ あなたの場合はどうですか                    │
│                                            │
│ 乾いた場所で歌ったあと、いちばん            │
│ 最初に気づく変化は何ですか？                │
│                                            │
│ [                                     ]    │
│                                            │
│ ★これはあなただけが読みます。              │
└──────────────────────────────┘
```

**★ここにユーザーの記録の数値を差し込まないでください。**
（職業別項目の再設計と学ぶ画面.md §9 の線）

**本人に思い出させることが目的で、アプリが教えることが目的ではありません。**
自分の経験と結びつけるのは「掘り下げる問い」にあたり、効果は中程度あります。
**そして数値を出さないので、3ゲートにも触れません。**

### 2-4｜⑥ 読んだ直後の3問

```
・選択式。3〜4択
・★1問目は必ず「覚えるべき1文」から出す
・2問目は用語、3問目は機序
・★答えたらすぐ正解と、1〜2行の解説を出す
・間違えても、点数や励ましを出さない。正解と理由だけ
```

## 3. ★間隔をあけて、また出す

Cepeda ら（2008、1,354人・最長1年の追跡）の結果です。

```
覚えていたい期間   最適な間隔
      7日            1日
     35日           11日
     70日           21日
    350日        21〜23日
```

**長く覚えていたいほど間隔を広げますが、21日あたりで頭打ちになります。**

### 3-1｜スケジュール

```
読了直後   →  1日後  →  7日後  →  21日後  →  以後は30日ごと
```

```
・★正解したら次の段階へ進める
・★間違えたら1つ前に戻す（最初には戻さない）
・1回に出すのは、全記事あわせて★3問まで
・出す場所は「学ぶ」の中。★ホームや通知に出さない
```

### 3-2｜見せ方

```
┌──────────────────────────────┐
│ 前に読んだところから、3問                   │
│                                            │
│ ●●○   2問目                               │
│                                            │
│ 声帯の粘液が減ると、何が増えますか？        │
│  ○ 振動のたびの摩擦                        │
│  ○ 息の量                                  │
│  ○ 声の高さ                                │
└──────────────────────────────┘
```

```
・★「復習しましょう」と催促しない。開いたときに出るだけ
・★連続日数を数えない
・やらなくても、何も起きない
```

**記録の催促をしない方針と同じです。**
**勉強もまた、罪悪感で続くものではありません。**

## 4. メモ機能をどうするか

**廃止しません。役割を変えます。**

```
いま   自由なメモ（＝要約になりやすい）  ← 効果が低い
これから 「自分の言葉で言い換える」欄     ← 自己説明。効果は中程度
```

```
┌──────────────────────────────┐
│ 自分の言葉で書いてみる                      │
│                                            │
│ 「乾燥は、声帯の表面の粘液を減らし、        │
│   振動のたびの摩擦を増やす」                │
│                                            │
│ これを、あとで自分が読んで分かるように      │
│ 言い換えてください。                        │
│ [                                     ]    │
└──────────────────────────────┘
```

**★既存のメモは1件も消さないでください。**
入力欄の見出しと説明文を変えるだけです。

## 5. 分量の基準

**「内容を厚く」は、字数を増やすことではありません。**

```
本文            1,200〜2,000字（読む時間 4〜7分）
覚えるべき1文    1つ・60字以内
用語            3〜6語
問い            読む前1問・直後3問・自分に当てはめる1問
つながる記事     2〜3本
```

```
★2,000字を超えるなら、記事を2本に分けてください。
★1本の記事に「覚えるべき1文」が2つ必要なら、それは2本ぶんです。
```

**厚みは、字数ではなく「機序の深さ」と「問いの質」で出します。**

## 6. ★ガードレールとの整合

**この機能で、いちばん越えやすい線が3つあります。**

### 6-1｜記事にユーザーの数値を差し込まない

**既存の線です（職業別項目の再設計 §9）。**
「あなたの湿度は38%でした」を記事の中に出さないこと。

### 6-2｜クイズを判定に使わない

```
✗ 正答率からユーザーの知識レベルを判定する
✗ 「あなたはまだ理解できていません」
✗ 他人との比較・偏差値・ランキング
```

**クイズは記憶のための道具であって、評価の道具ではありません。**

### 6-3｜★受診の目安の書き方

**ここは繊細です。**

```
○ 記事の中で、一般的な知識として書く
   「2週間以上つづく嗄声は、耳鼻咽喉科で診てもらうことが
     すすめられています」

✗ アプリが個人に向けて言う
   「あなたの記録では16日つづいています。受診してください」
```

**記事は一般論を書けます。機能が個人に受診を勧めることはできません。**
この違いを、記事の書き手にも伝えてください。

**そして、一般論としての受診の目安は、むしろ積極的に書いてください。**
声のプロが最も損をするのは、**受診が遅れること**です。

## 7. データモデル

```ts
interface Article {
  id: string
  professionScope: string[]      // 対象職業。空なら全員
  tier: 'basic' | 'advanced'     // basic は無料、advanced はプレミアム
  keySentence: string            // ★覚えるべき1文。60字以内
  terms: { word: string; reading: string; meaning: string }[]
  prequestion: Question          // ★読む前の1問
  quiz: Question[]               // 3問
  reflectionPrompt: string       // 自分に当てはめる問い
  relatedArticleIds: string[]
}

interface Question {
  id: string
  stem: string
  choices: string[]
  answerIndex: number
  explanation: string            // 1〜2行
  source: 'keySentence' | 'term' | 'mechanism'
}

interface ArticleProgress {
  userId: string
  articleId: string
  firstReadAt: string
  box: 0 | 1 | 2 | 3 | 4         // 0=未読 1=直後 2=1日 3=7日 4=21日以降
  nextDueAt: string
  lastAnsweredAt?: string
}

interface QuizAttempt {
  userId: string; questionId: string; correct: boolean; answeredAt: string
  // ★正答率を集計して見せない
}

interface SelfExplanation {
  userId: string; articleId: string; text: string; updatedAt: string
  // ★既存のメモをここへ移行する。消さない
}
```

```
無料   基本編の記事すべて／読む前の問い／直後の3問
       ★間隔をあけた復習（続けるための仕組みなのでゲートしない）
       自分の言葉で書く欄

プレミアム  応用編の記事
```

**復習の仕組みを有料にしないでください。**

## 9. ★禁止事項

```
1.  ★蛍光ペン・下線の機能を作らない（効果が低い方法）
2.  ★メモ欄の見出しを「要約」にしない
3.  読む前の問いに、その場で○×を付けない
4.  ★覚えるべき1文を、1記事に2つ置かない
5.  ★正答率・点数・連続日数を表示しない
6.  他人との比較・ランキングを作らない
7.  復習を通知やホームで催促しない
8.  ★記事の中にユーザーの記録の数値を差し込まない
9.  ★アプリが個人に受診を勧めない（記事の一般論としては書く）
10. 1記事を2,000字より長くしない（分ける）
11. ★復習の仕組みを有料にしない
12. 既存のメモを削除・移行漏れさせない
```

## 11. Sonnet への依頼のコツ

**この文書でいちばん反直感的なのは、次の2つです。**

```
・ハイライトとメモ（要約）は、効果が低い
・読む前に、答えを知らないまま問いに答えさせると、記憶が伸びる
```

**どちらも「勉強らしく見えるかどうか」と、実際の効果が逆になっています。**

**そして、いちばん間違えやすいのはここです。**

```
★読む前の問いは、覚えてほしい内容そのものから作ること。
　問われた内容しか伸びません（g=.66 対 g=.01）。
　「導入として面白い問い」を作らないでください。
```
