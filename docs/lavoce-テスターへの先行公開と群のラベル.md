同じファイルにまとめないでください。前者は有料でよく、後者は権利で無料です。

## 3. 群のラベル（★いま作らないと、あとから取り返せません）

```ts
type UserCohort = 'tester' | 'general' | 'founder'

tester    坂本さんが選んで先行公開した人（15〜20人）
general   自分で登録した、坂本さんと直接関係のない人
founder   坂本さんと直接関係のある既存ユーザー
```

**★なぜ必要か：画面が違う人を、同じ継続率の分母に入れられないからです。**

30日／90日の継続率は、この製品が成立しているかを見る数字です。
**分析が見える人と見えない人を混ぜると、その数字が何を測っているのか分からなくなります。**

**★そして、あとから遡って分けることはできません。**
「この人はいつからテスターだったか」を、記録に残しておく必要があります。

```
□ profiles に cohort 列（既定は 'general'）
□ ★cohort を変更したら、いつ・どちらからどちらへ を監査ログに残す
□ 分析の集計・継続率の算出で、★cohort ごとに分けられる形にする
□ ★cohort を利用者に見せない（§4）
```

---

### 3-1｜tester と founder は、排他ではありません（2026-08-30 の確認）

いまの3人（先行公開の最初の方々）は、坂本さんが個別に声をかけ、
承諾をいただいた方です。つまり §3 の定義では **tester と founder の
両方に当てはまります**。「坂本さんと直接関係がある」ことと、
「先行公開を見ている」ことは、別々の事実だからです。

**決めたこと：この3人は `cohort = 'tester'` のままにします。**
founder であることは、この文書と決定の記録に残し、DBには持たせません。

**★理由を、正確に書いておきます。**
この判断を「founder では先行公開が見えないから」と説明した記録が
ありますが、**それは実装と違います。** `lib/entitlements.js` の

```js
export const EARLY_ACCESS_VIEWERS = ["tester", "founder"];
```

のとおり、**founder は tester とまったく同じだけ先行公開が見えます。**
つまり2つのラベルは、機能の上では**いま完全に等価**です。

ではなぜ tester を選んだのか。**継続率の分母をそろえるためです**（§3）。
`tester` は「画面が違う人」の印として作りました。3人はまさにその
15〜20人の枠で入った方なので、継続率の集計では tester として
数えるのが正しく、founder として数えると枠の人数が合わなくなります。

**★この違いが効いてくる場面：**
将来 `EARLY_ACCESS_VIEWERS` から founder を外す日が来たら、
2つのラベルは等価でなくなります。そのとき、この3人を
「founder だから」と読み替えると、**先行公開を取り上げてしまいます。**
cohort 列は1つしか値を持てません。**機能の判断に使うのは cohort です。**

**★DBの変更は要りません。** 列も制約も監査ログも、いまのままで足ります。
足りないのは、この説明だけでした。

## 4. ★一般ユーザーの画面では「存在しない」

**隠すのではありません。無いのです。**

```
✗ 鍵アイコン
✗ 「テスター限定」「プレミアム」などのバッジ
✗ 「◯◯さんは対象外です」という説明
✗ 招待コードの入力欄
✗ グレーアウトした状態で置いておく
✗ 「近日公開」の予告（★今回は出さない）
```

**存在するのに開かない、が いちばん不快です。**
そして「あなたはテスターではありません」と分かる表示は、**屈辱を与えます。**

**★非テスターの画面では、カードそのものをレンダリングしないでください。**

**参考：**`lavoce-作業指示-課金の器と無料枠.md` には「先に印だけ見せておく」という
記述がありますが、**それは課金開始のときの話です。★今回の先行公開では出しません。**
理由：課金の時期も価格もまだ動くため、**動くものを予告しないためです。**

## 5. ★実装は can() で。フロントだけにしない

```
✗ フロントで <PremiumOnly> に包むだけ  → ★APIを直接叩けば取れる
✗ 課金状態を localStorage に持つ
✗ 「対象外」を理由にデータを削除する
✗ 対象外になったとき、過去の記録を見えなくする（★記録は常に本人のもの）
```

```
○ すべての保護対象APIの入口で can() を呼ぶ
○ RLS だけに頼らない（RLS は所有者判定、can() は権利判定。★別物）
○ can() の単体テストを、機能 × 群 の全組み合わせで書く
```

**★いま can() の器を正しく作れば、G3.2 の課金開始で作り直さずに済みます。**
先行公開は、その器の最初の使い道です。**使い捨ての分岐を書かないでください。**
