## ③ 記録の 2タップ（見本③）

`components/RecordV2Head.jsx` を、記録タブのいちばん上に置きました。門の中です。
**下のいつもの記録欄は、1つも変えていません。消していません。**

```
　「きょうの こえは」　［出た］［ふつう］［出づらい］
　　　　　　　　　　　［ きろくする ］
```

3択を選ばなくても「きろくする」は押せます。**止めません。**止めると、その日の
記録が丸ごと消えます。

### ★ ここが 肝でした ── 書いても 捨てられる道が ありました

3択は `throatCondition`（1〜5）の上に立てました。**新しい列を作っていません。**
作れば、**読む所が1つもない列**になるからです（★N-1の決め）。

ところが、**`formData.throatCondition` に書いても、消える道がありました。**

```
　entryToRow は、voiceEntries[]（場面ごとの声の記録）が1つでもあると、
　throat_condition を その中央値から 導き直します
　　　★deriveLegacyVoiceFieldsFromEntries
　　　★formData.throatCondition は、そこで 捨てられます
```

同じ決めを2か所に書かないため、**行き先を決めるのは `lib/recordV2.js` だけ**に
しました。見張りは、**entryToRow を実際に通して** throat_condition に届くことを
確かめています（場面が空で1つある日も、含めて）。

### すでに 場面ごとに 書いてある日は、3択を 出しません

中央値を、1つの3択で上書きすると、**その方が場面ごとに書いたものが消えます。**
その日は、3択のかわりに「場面ごとに書いてくださっています。直すときは下の
『声・のど』から」とだけ出し、**下のいつもの欄で直していただきます。**

「受け取ったもの・書いたものを、黙って消さない」という、これまでの決めのとおりです。
