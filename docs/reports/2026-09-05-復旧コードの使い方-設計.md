## §1 むずかしいところ

```
6桁の数字は、★メールに送ります。
　　→ メールが使えない人には、★届きません。

だから「復旧コードを入れたら、6桁を送ります」では、★何も解決しません。
```

★復旧コードは、**メールを迂回するもの**でなければ意味がありません。

---

## §2 提案 ── ★復旧コードは「メールアドレスを付け替える鍵」にする

```
　　［ メールが使えなくなった方へ ］

　　いままでのメールアドレス   ____________________
　　復旧コード                 WOOL-____-____-____
　　これから使うメールアドレス ____________________

　　　　　　　　［ 付け替える ］
```

★合っていれば、そのアカウントのメールアドレスを、新しいほうに付け替えます。
★そのあと、★新しいアドレスに6桁を送って、ふつうに入っていただきます。

### ★なぜ「いままでのアドレス」も聞くのか

```
★メールを失う、の中身は、たいてい ★「受け取れない」です。
　　★「アドレスを忘れた」ではありません。
　　　（会社を辞めた／携帯会社を変えた／プロバイダをやめた）

★だから、聞けます。そして聞くと、★条件が2つになります。
　　① そのアドレスを知っている
　　② コードを持っている
```

★もう1つ、実の利点があります。
　★アドレスで1行に絞れるので、★ハッシュを1回だけ照合すれば済みます。
　★総当たりの相手に、★重い計算を1回だけさせられます。

### ★この形の、正直な弱点

```
★アドレスを知っていて、コードも持っている人は、★中に入れます。
　これは、★仕様です。判断書 §3 の「コードを持っている人が本人です」そのものです。

★だから、★コードの見せ方が重要になります。
　　「どこかに書き写してください」だけでなく、
　　★「人に見せないでください」も要ります。
```

★→ ★§6 の文言に、1行足すことを提案します。

## §3 やらないこと

```
✕ 問い合わせの窓口                判断書 §2。なりすましの入口です
✕ 秘密の質問                      ★答えは、たいてい調べられます
✕ 電話番号                        ★新しい経路が1本増えます（台帳05）
✕ 「以前の記録の内容」で確かめる   ★体調のデータを、確かめに使わないこと
✕ 復旧コードだけで、そのまま中に入る ★アドレスの付け替えを挟みます（下）
```

★最後の1つだけ、理由を書きます。

```
コードだけで中に入れると、★入ったあとも、まだメールが使えないままです。
　　→ 書き出しも、削除も、できません（§4 の4操作は6桁で確かめます）
　　→ ★次に端末を変えたら、また同じことになります

★アドレスを付け替えてから入っていただければ、★そこで元通りになります。
```

## §4 旧アドレスへの通知（判断書 §7）

```
付け替えたとき
　　★新しいアドレスへ  「変わりました」
　　★古いアドレスへも  「変わりました」★受け取れないかもしれません。それでも送ります
```

★理由は、★乗っ取りに気づく唯一の手だからです。
★受け取れないかもしれない相手に送るのは、無駄ではありません。
　★★「古いアドレスがまだ生きていた」場合が、いちばん危ないからです。

★履歴は、★いつ・どのアドレスから・どこへ、を残します（台帳06）。

## §6 文言の追加（★判断を仰ぐところ ②）

判断書 §3 の文言に、★1行だけ足すことを提案します。

```
（いまの決まり）
　　メールが使えなくなったときは、これで入れます。
　　紙に書き写すか、写真に撮って、しまっておいてください。
　　この画面を閉じると、二度と出せません。

　　このコードを無くすと、メールも使えなくなったときに、入れなくなります。
　　私たちの側で、元に戻すことはできません。

（足したい1行）
★　　人に見せないでください。このコードだけで、記録を見られます。
```

★理由：§2 の形では、★コードは実質「鍵そのもの」です。
　★「無くさないでください」だけだと、★「見せてはいけない」が伝わりません。

## §7 ★先に確かめていただきたいこと（★これが止まると、④が動きません）

　既定では **{{ .ConfirmationURL }} しか入っていません。**

★お手数ですが、Supabase の画面で、次を確かめてください。

```

```

★消さずに足す理由：★いま動いているものを、先に壊さないためです。
