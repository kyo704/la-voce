## §3 どこに何を置くか

    lessons（★先生のもの）
      started_at   timestamptz  先生が「始めます」を押した時刻
      ended_at     timestamptz  先生が「終わります」を押した時刻
      ★duration は持ちません。★2つの時刻から出ます。
      ★持つと、時刻を直したのに長さが古いまま、が起きます。

    entries（★生徒のもの）
      ★先生の操作では、1列も書きません。
      ★生徒が押したときだけ、生徒自身の認証で書きます。

★取り込む先は、既存の発話時間の項目です。★新しい列を作りません。
★★ご判断：どの項目に足すか。
　　`entries` の発話・発声の時間を持つ列名を、実物で確かめてから決めます。

## §4 生徒に出す誘い（prompt）

    きのうのレッスンは60分でした。
    発話時間に足しますか？

    ［足す］  ［足さない］

★出す条件
    ・自分が student_id のレッスンで、started_at と ended_at の両方がある
    ・まだ一度も答えていない

★一度答えたら、★二度と出しません。「足さない」でも出しません。
★「あとで」を作らないこと。★宙ぶらりんの状態が1つ増えます。

### 答えを、どこに持つか

★`entries` には持ちません。★答えは生徒の記録ではなく、
★「この誘いに答えたか」という進行の状態です。

    lesson_imports（★新しい表・案）
      id
      lesson_id     … どのレッスンか
      student_id    … auth.uid() でしか入らない
      answered_at
      imported      boolean   足した／足さない
      imported_minutes int    ★足したときだけ。あとで照らせるように

★RLS は `auth.uid() = student_id` の1本だけ。
★先生に見せる道は、作りません。★「取り込んだか」は先生の情報ではありません。
★★ご判断：先生が「取り込まれたか」を知る必要がありますか。
　★私は「要らない」と考えます。★知ると、催促が始まります。

## §5 ★どこから来た値かを、区別すること

★「明示的に選んだ」と「既定のまま」を分ける、という決まりの家族です。

★2つ目の書き込み口を作らないこと。★entries への道は1本のままにします。

    案　entries の既存の列に足し、★出どころは lesson_imports が持つ
      ★entries に provenance の列を足しません。
      ★足すと、rowToEntry / entryToRow / 往復の検査の3つを
        触ることになり、★列がもう1つ増えます。
      ★lesson_imports に imported_minutes があるので、
        ★「その日の発話時間のうち、どれがレッスン由来か」は
        あとから照らせます。

★★ご判断：この形でよいか。
　★別案は entries に `speech_minutes_source` を足すことですが、
　　★分析は entries しか見ないので、★分析には出どころが要りません。
　　★要るのは「本人が押したか」の証拠で、それは lesson_imports にあります。

## §6 端の場合

    レッスンが、取り込んだあとに直された
      ★entries は変えません。★取り込みは、押した時点の写しです。
      ★lesson_imports に押した分数が残っているので、ずれは分かります。
      ★「直りました」と誘い直すのは、★催促です。やりません。

    レッスンが、取り込んだあとに取り下げられた
      ★同じです。entries は変えません。
      ★★ご判断：ここだけは知らせるべきかもしれません。
      　★私は「知らせない」を推します。生徒の記録は生徒のものです。

    1日に複数のレッスン
      ★誘いも複数出します。★1件ずつ答えます。
      ★entries は (user_id, date) が1行なので、★足し算になります。
      ★lesson_imports は1レッスン1行なので、内訳は残ります。

    日をまたぐレッスン（23:30〜00:30）
      ★started_at の日付に寄せます。
      ★`profiles.day_record_boundary_hour` があります。★そちらを使うこと。
      ★日付を2つに割らないこと。★割ると、どちらを押したか分からなくなります。

    先生が終了を押し忘れた（ended_at が無い）
      ★誘いを出しません。★推測で長さを作らないこと。
