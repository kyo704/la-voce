## 二 ── なぜ そう なるか

```
学校を 消す
  → つながって いる org_events が 一緒に 消える（ON DELETE CASCADE）
    → org_events_audit（引き金）が 動く
      → ops_audit_log に 1行 入れようと する。★org_id は いま 消して いる 学校
        → ops_audit_log_org_id_fkey に 当たる ── ★その 学校は もう 無い
```

★★`ops_audit_log.org_id` の 外部キーは `ON DELETE SET NULL` です。
　★★それは「**あとから** 消えた とき」の 話 です。
　★★★いま 入れようと して いる 行は、★**入れる その ときに** 親が 居ません。

★引き金が ある 表 …… `enrollments` / `lesson_rounds` / `memberships` /
`org_billing` / `org_events` / `org_invitations` / `org_places` / `org_posts`（★8つ）

## 五 ── 直し方（★当てて いません。★Opus に お返しします）

| | 案 | よい ところ | 心配な ところ |
|---|---|---|---|
| ㋐ | `ops_audit_log.org_id` の 外部キーを **外す** | ★記録の 表の 筋に 合います（★記録は 親より 長く 生きます） | 消えた 学校の id が 残ります（★それが 正しい とも 言えます） |
| ㋑ | 引き金が `tg_op = 'DELETE'` の ときは 書かない | 小さい 直し | ★**消した ことが 記録に 残りません**。★管理の 記録の 意味が 半分 になります |
| ㋒ | 外部キーを `deferrable initially deferred` に する | 形が きれい | ★同じ 取引の 終わりにも 親は 居ません。★**直りません** |
| ㋓ | 引き金の 中で、★親が 居る ときだけ 書く | 消す ときも 途中までは 残る | ★条件が 増えます |

★★★私の 見立ては ㋐ です。
