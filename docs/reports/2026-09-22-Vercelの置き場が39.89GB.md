## 一 ── 何が 積もって いるか

★Vercel の「Deployment Storage」は、★**残って いる デプロイ ぜんぶ** の 合計 です。
　★1回の デプロイ ＝「もとの ファイル」＋「ビルドの 出来上がり」。
　★★消さない かぎり、★出す たびに 積み上がります。

### 1回の デプロイが 運ぶ もの（★測りました）

```
git が 持って いる ファイル ……… 376.0 MB（7,931 ファイル）

  140.9 MB  docs/design        ★見くらべの 画像 と 見本
  101.0 MB  assets             ★届いた 素材（羊の 服・部屋・zip）

    6.2 MB  components
    3.8 MB  docs/reference
    2.8 MB  lib

```

★★★**296 MB が 書きもの と 素材 です。**
　★画面から 出て いません。★ビルドも 読みません。

★`main` の commit は **1,871** あります。★デプロイも それに 近い 数 です。
　★★376 MB × 100回 ＝ 37.6 GB。★39.89 GB は この 形で 説明が つきます。

## 二 ── なぜ 積もったか

★`.vercelignore` に 書いて あったのは 7行 だけ でした ──

```
node_modules / npm-debug.log / .env.local / .env.*.local
.vercelignore / supabase/.temp/ / .git / .DS_Store
```

★★`docs/` も `assets/` も 除いて いません。
★★だから、★見くらべの 画像 1枚（2MB）を 足す たびに、
　★**その あとの デプロイ ぜんぶ** が 2MB ずつ 重く なって いました。

★★★これは 誰の 手落ちでも ありません。
　★`docs/` が 大きく なったのは、★9月に 入って からです。
　★`_old-2026-09-21{a〜m}` の ように、★版を 残す 決めに した から でも あります。

★★★**まだ 確かめて いない こと** ──
　★除いた 形で 実際に ビルドが 通るか は、★手元では 試せません
　　（★フォルダを 動かす 操作が 止められました）。
　★★次の デプロイが 通る ことを、★画面で お確かめ ください。
　★★通らなかった ときは、★`.vercelignore` の 足した 13行を 消せば 元に 戻ります。

## 四 ── ★いま 39.89GB を 減らす 方法（★坂本さんの お手元で）

★★★`.vercelignore` は **これから 出す ぶん** にだけ 効きます。
　★すでに 積もって いる 39.89GB は、★これでは 減りません。

★減らすには、★古い デプロイを 消します。

```
Vercel の 画面 → プロジェクト → Deployments
  → 古い ものを 選ぶ → … → Delete
```

★★消して よい もの ──
　★`Preview` の 古い もの（★枝ごとの 試し）。★ぜんぶ 消して 構いません。
　★`Production` の 古い もの。★**いま 動いて いる 1つ だけ 残します**。

★★★消すと 何が 起きるか ──
　★そのデプロイの URL（`…-xxxxx.vercel.app`）が 開かなく なります。
　★★戻す（Rollback）先が 減ります。★直近 数本は 残す ほうが 安心 です。
　★★**いま 動いて いる 本番は、★消さない かぎり 止まりません。**

★お勧め …… ★直近 10本 ほどを 残して、★それより 古い ものを ぜんぶ 消す。
