**★これは表示の問題ではありません。**
`profiles` の行が無い人は、ログインできます。アプリも使えます。
ですが★保存がひとつも効きません。
アプリの書き込みは全部 `.update(...).eq("id", userId)` で、
INSERT のポリシーが無いためです（CLAUDE.md に経緯があります）。
★行が無ければ UPDATE は0行に当たり、PostgREST はそれを
★エラーにしません（`error` は null）。つまり★成功したように見えます。
表示名・同意の記録・オンボーディング完了・羊のポイント・LINE 連携…
どれも保存されず、★本人は気づけません。

**どうして起きうるか**（トリガーの失敗ではありません）
`handle_new_user` は AFTER INSERT で、例外を捕まえていません。
失敗すれば★登録ごと巻き戻るので、「auth.users に居て profiles が無い」は
トリガーが★動いていない場合にしか起きません。

★いちばん疑わしいのは、退会の処理です。
`lib/accountDeletion.js` は `profiles` を消してから `auth.users` を消します。
この2つは★別々の通信で、巻き戻せません。
後半だけ失敗すると、まさにこの状態が残ります。
→ 今日の「打ち間違いの試験用アカウント3件」が、
　 auth.users に居るのに profiles が無い状態でした。★同じ形です。

# 2026-09-01｜手で作った表に、RLS のポリシーが足りていなかった

## 何が起きたか

削除試験のために先生役のアカウントで招待コードを発行しようとしたところ、
**403 / 42501** で止まりました。原因は2つ重なっていました。

  from pg_class c
  join pg_namespace n on n.oid = c.relnamespace

   and not exists (
     select 1 from pg_policies p
      where p.schemaname = 'public' and p.tablename = c.relname

## ★音名の表記ゆれ｜本番で1件見つかりました（2026-09-02）

**9月28日の判断のための記録です。**いま直すものではありません。

### 見つかったもの

```
wake_note = 'h'   routine_note = 'C4'   pianissimo_high_note = null
```

該当は**1行だけ**でした。

### なぜ落ちるのか

`noteToMidi`（components/VocalTracker.jsx）が受ける形は
`^([A-Ga-g])([#♯b♭]?)(-?\d+)$` です。`'h'` は2つの理由で外れます。

- `h` は A〜G に無い（ドイツ語表記の H は英語の B にあたります）
- **オクターブの数字が無い**

読めない値は `null` になり、**そのまま黙って捨てられます**。
保存はされていますが、グラフにも分析にも一切入りません。
★利用者には、何も知らされません。

### ★「ドイツ語表記だ」と決めつけないこと

同じ行の `routine_note` は **`C4`** で、正しい形です。
つまりこの人は、書き方を知っています。ドイツ語で通している人なら、
ルーティン後も同じ流儀で書くはずで、`H2` のように
**オクターブも添えるほうが自然**です。

考えられるのは、少なくとも3つあります。

1. ドイツ語表記の H（英語の B）
2. 打ち間違い
3. 入力の途中でやめた（1文字だけ入って、確定してしまった）

**2 と 3 のほうが、ありそうに見えます。**
私は最初これを「ドイツ語表記の取りこぼし」として報告しましたが、
★同じ行の証拠がその見立てと合いません。断定しないでおきます。

### ★1件であることの意味

これは「表記ゆれが起きている」の証拠としては**弱い**ものです。
1件では、癖なのか、一度きりの事故なのか、区別がつきません。
9月28日に判断するときは、**そのときもう一度数え直してください**。

### 分かっていること（見立てではなく）

- 読めない音名は、保存されるが**分析には入らない**
- **利用者にも運営にも、何も知らせない**（黙って落ちる）
- 鍵盤で選ぶ形にすれば、この落ち方は**構造的に起きなくなる**
  （読めない値が作れなくなるため）
- ただし**既にある1件は、鍵盤を作っても直りません**

### 9月28日に見ること（Opus の条件(b)）

```sql
select wake_note, routine_note, pianissimo_high_note, count(*) as "件数"
  from public.entries
 where (wake_note is not null and wake_note <> ''
        and wake_note !~ '^[A-Ga-g][#♯b♭]?-?[0-9]+$')
    or (routine_note is not null and routine_note <> ''
        and routine_note !~ '^[A-Ga-g][#♯b♭]?-?[0-9]+$')
    or (pianissimo_high_note is not null and pianissimo_high_note <> ''
        and pianissimo_high_note !~ '^[A-Ga-g][#♯b♭]?-?[0-9]+$')
 group by 1,2,3 order by 4 desc;
```

★件数が増えていれば癖、1件のままなら事故。**そこで分かれます。**
