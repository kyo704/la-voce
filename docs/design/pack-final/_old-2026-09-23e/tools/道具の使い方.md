## 値段を変えるとき（確定文書 §9 の運用）

1. `tools/prices.json` を先に直す（ここが機械の正）
2. 確定文書・見本3本・実装・営業資料・特商法表記を同じ日に直す
3. `python3 tools/price_check.py --impl <repo>/lib/orgRoster.js` が MATCH になるまで直す
4. 古い数字を新しく探すときは `prices.json` の `stale_patterns` に1行足す
5. ④で「歴史の記録」（退避した旧見本・日付つきの評価）が当たり続けるときは、`--update-baseline --reason "理由"` で既知にする。以後は新しい当たりだけが出る。`_old-*/` は最初から見ない
   ★「題に日付が入っている文書」を一律に外さない（契約書の条・同意書など、いま使う文書にも日付が入っている）

## 裁定を書くとき

1. `ruling-NNN-*.md` を置く
2. `tools/ruling_mock_registry.json` に1件足す（mock: yes なら present／absent の印。no なら note に理由）
3. `python3 tools/ruling_mock_check.py` が OK になってから zip

## 版を上げるとき

```
python3 tools/promise_diff.py snapshot design-vNN
python3 tools/promise_diff.py diff design-v(NN-1) design-vNN
```

- 「+」＝新しい約束 → 約束の台帳に行を足す（守る処理の欄は空。Code が試験で埋める）
- 「-」＝見本から消えた約束 → 台帳の行は消さず「見本から消えた（日付）」
- 控えの件数（design-v19 で 1,145文）は Sonnet の手作業の 484件と違う。台帳は Sonnet の 484件を使い、この道具は「差分を見つける」ためだけに使う

## 終了コード（CI に入れるとき）

0＝そろっている ／ 1＝食い違い・抜けあり ／ 2＝道具の不具合（selftest の失敗を含む）
