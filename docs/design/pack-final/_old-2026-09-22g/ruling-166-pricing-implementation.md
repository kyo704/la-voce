### R1-3 学校（請求書。事業者）

```yaml
形: Stripe Invoicing（請求書）。固定の Price は作らない（名簿の人数で毎月の額が変わり、式が直線でないため）
毎月:
  - 毎月1日に、その学科の在籍の人数 n を数える（休会・招待中・先生・事務は数えない）
  - 額 = gakkoYen(n)（prices.json の式。price_check が一致を見ている）
  - 請求書に1行「名簿 n人（YYYY年M月1日時点）　M月分」。当月末締め・翌月末払い
  - 支払い: カード、または銀行振込（Stripe の日本の銀行振込）
  - ★「口座振替」: Stripe で日本の口座振替が使えるかを Code が確かめる。使えなければ、確定文書 §7 から「口座振替」を消す（Opus が版を上げ、§9 の4か所を同じ日に）
年払い:
  - 額 = gakkoYen(n) × 10。請求書1枚・銀行振込
  - 年の途中で増えた分は毎月の請求書で。減った分は返さず、次の1年から引く（確定文書 §3）
  - 途中解約: 契約書の条（未経過月 × 年額 ÷ 12）。Refund ではなく、請求書の Credit Note で
導入支援: 100,000円。名簿100人以上。★最初の有料の月の請求書に1行（導入期間中に止めたら請求しない）
インボイス: 登録の後は、請求書に登録番号を出す（Stripe の請求書の設定）
```

### R1-4 公演

```yaml
形: 公演ごとの1回払い（カード）。公演を「公開」にするときに段を決める
段: 15人まで 0円／40人 20,000／120人 50,000／300人 100,000／600人 150,000（prices.json に足す）
人数: その公演に招いた出演者の数（子どもを含む。裏方の運営は数えない）
増えたとき: 段を超える人を招こうとしたら1度たずねる → 差額の1回払い（例：40人の段から41人目 → 30,000）。断れば招かない
減ったとき: 返さない
lookup_key: koen_40・koen_120・koen_300・koen_600（差額は Checkout の金額を差で作る）
```

## R2. 学生の値段の同意

### 画面（見本 design-v22：スマホ「プラン」→「学生」→ 下から出る板）

```
学生の 値段で 買う

学生の 値段（月490円／年6,400円）に するため、学校の 名簿に あなたが 在籍しているか を 確かめます。
・確かめるのは「在籍しているか」だけです。学年・コース・記録は 見ません。
・値段を 決める ためだけ に 使います。ほかの ことには 使いません。
・学校には、あなたが 学生の 値段で 買ったことを 伝えません。
・在籍が 確かめられないときは、ふつうの 値段（ぜんぶ 月980円）の ご案内に なります。
・同意は いつでも やめられます（プラン → 学生の 値段の 同意）。やめると 次の 更新から ふつうの 値段です。いまの 期間は そのまま 使えます。

［同意して 確かめる］　［やめる］
```

### 台帳

```sql
create table public.student_price_consents (
  id            uuid primary key default gen_random_uuid(),
  user_id       uuid references auth.users(id) on delete set null,   -- 退会しても同意の事実は残す（名前は持たない）
  consented_at  timestamptz not null default now(),
  text_version  text not null,        -- 上の文面の版（例 'gakusei-2026-09-21'）。文面を変えたら版を上げる
  checked_at    timestamptz,          -- 在籍を確かめた日時
  enrolled      boolean,              -- 確かめた結果（在籍している／いない）。★どこの学校かは持たない
  withdrawn_at  timestamptz           -- 同意をやめた日時
);
alter table public.student_price_consents enable row level security;
revoke all on public.student_price_consents from anon, authenticated;
grant select on public.student_price_consents to authenticated;
create policy spc_select_own on public.student_price_consents for select to authenticated using (user_id = auth.uid());
-- insert・update は関数だけ（利用者が直接書かない。裁定161 FX8 の型）
```

```yaml
関数（security definer・search_path 固定・anon 不可・authenticated 可）:
  give_student_price_consent(p_text_version text) returns boolean
    - 行を1つ作る → すぐ在籍を確かめる → enrolled を書く → 在籍していれば true
    - 在籍の確かめ: enrollments に auth.uid() が在籍（status が在籍）の行が1つでもあるか。★学校名・学年・コースは返さない。true／false だけ
  withdraw_student_price_consent() returns void
    - いちばん新しい有効な同意に withdrawn_at を入れる
  student_price_eligible() returns boolean  ── 購入と更新のときにサーバが呼ぶ
    - 有効な同意（withdrawn_at が null）がある かつ いま在籍している
いつ確かめるか:
  - 買うとき（Checkout の前）
  - 月払いの更新のとき（毎月）: 在籍していなければ、次の月から ふつうの値段。その日付で1回だけ知らせる（「11月9日から 月980円に なります。学校の 名簿で 在籍が 確かめられなかったためです」）
  - 年払い: 買うときだけ（期間の途中では変えない）
委託データとの関係（台帳の注記）:
  - 学校から預かった名簿（委託）を、学生本人の同意のもと、本人の値段を決めることにだけ使う（裁定155 C2・design-v18）
  - プライバシーポリシーの利用目的に「学生の値段の判定（本人の同意があるときだけ・在籍の有無だけ）」（法務の点検 D8）
VERIFY:
  - 同意なしで student_price_eligible → false
  - 同意して在籍 → true／在籍なし → false（enrolled=false の行が残る）
  - 学校の人（meibo を持つ人）から student_price_consents が見えない（0行）
  - 同意をやめる → 次の更新で ふつうの値段
```

## R3. 31人目（教室 → 学校）と 6人目（無料 → 教室）

```yaml
いつ たずねるか:
  - 招く（名簿の「招く」・下から出る板・PC の招く）を押したとき
  - いまの人数 = 在籍している生徒 ＋ 招待して返事待ちの生徒（★招く前の判定では返事待ちも数える。請求の人数とは違う）
  - いまの人数 ＋ 今回招く人数 ＞ 上限 のとき
      無料: 上限 生徒5人 → 教室を たずねる
      教室: 上限 生徒30人 → 学校を たずねる
  - ★先生も数える: 無料は先生1人・教室は先生2人まで。3人目の先生を招くときも学校を たずねる（見本はまだ生徒だけ。Code は先生も）
だれに:
  - bill_pay を持つ人: たずねる
  - 持たない人: たずねない。「いまの プランでは 30人までです。プランを 変えられるのは ○○（役職の名前）です」と1行。招かない
文言（見本 design-v18 の planAskText と同じ）:
  6人目: 見出し「生徒が 6人に なります」
         「教室に しますか　月2,980円／年29,800円
          先生2人・生徒30人まで。教室ページと、40人までの 公演を 含みます。
          14日は 0円で ためせます（カード 不要）。払わなければ 無料に 戻ります（入った 方は そのままです）。」
         ボタン「14日 ためして、招く」「やめる（招かない）」
  31人目: 見出し「生徒が 31人に なります」
         「学校に しますか　名簿1人 月400円から（下限 月12,800円）
          いまは 教室です。月払いは 翌月から 学校の 額、年払いは 残りの 期間を 学校の 年額に 充当します。」
         ボタン「学校に して、招く」「やめる（招かない）」
断ったとき: 招待は送らない。★入力した宛先は消さない（取り上げない）
切り替えの お金:
  教室 月 → 学校: 今月は教室のまま（日割りしない）。翌月1日から学校の請求書
  教室 年 → 学校: 充当額 = 未経過月 × 2,490。学校の最初の請求書から差し引く（Credit）

VERIFY:
  - 教室で生徒30人・返事待ち0 → 1人招く → たずねる → 断る → 招待0・宛先は残る
  - 同じ状況で bill_pay の無い人 → たずねない・1行
  - 先生2人の教室で3人目の先生を招く → たずねる
```

## R4. 学校の導入期間（裁定156）

```yaml
台帳（学校の契約）:
  org_contracts: org_id・contract_start（契約日）・is_pilot（最初の1学科）・free_until（0円の最後の日）・paid_from（請求の始まる日）・cycle（月／年）
  ★free_until と paid_from は、契約のときに計算して保存する（あとで式を変えても、結んだ契約は変わらない）
計算:
  パイロット（is_pilot）: free_until = 2027-09-30 ／ paid_from = 2027-10-01（契約書どおり。式は使わない）
  2校目から:
    A = contract_start の月から数えて3か月目の月末（契約の月を1か月目に数える）
        例: 11月10日 契約 → 11・12・1月 → A = 1月31日
    B = contract_start より後の、最初の4月1日の前日（3月31日）
        例: 11月10日 契約 → 翌年3月31日 ／ 4月1日 契約 → 翌年3月31日
    free_until = min(A, B)
    paid_from  = free_until の翌日（必ず月の1日）
  例:
    2027-04-01 契約 → A 06-30・B 2028-03-31 → free_until 2027-06-30 ／ paid_from 2027-07-01
    2027-11-10 契約 → A 2028-01-31・B 2028-03-31 → 2028-01-31 ／ 2028-02-01
    2028-02-15 契約 → A 04-30・B 03-31 → 2028-03-31 ／ 2028-04-01（4月に稟議が要る学校は、契約を4月始まりに）
  延長しない（パイロットの1回を除く）
画面（運営のプラン・見本 design-v18）:
  導入期間中: 「導入期間です。{free_until: M月D日}まで 0円。そのあと 月{額}円（いまの 名簿 {n}人なら）」
    額 = gakkoYen(いまの在籍の人数)。「いまの 名簿なら」と必ず書く（毎月1日に数えるので変わりうる）
  導入期間の後: 「学校　名簿1人 月400円（100人以上 350円・300人以上 250円）　下限 月12,800円」＋今月の額
知らせ:
  free_until の1か月前の日に1回だけ（催促しない・日付で）:
    「{M月D日}で 0円の 期間が 終わります。{M月1日}から、毎月1日の 名簿の 人数で ご請求します（いまの 名簿なら 月{額}円）。
     止める ときは、それまでに プランから 止めてください。止めても 学生の 記録は 残ります。」
  出す相手: bill_pay を持つ人だけ
  「半年の 使われ方」1枚（裁定138 R4）に、請求が始まる額（いまの名簿なら）を載せる
0円のあいだに止めたとき: 請求なし・導入支援も請求なし・学生の記録は残る
VERIFY（計算は単体の試験で）:
  - 上の3つの例と、12か月それぞれの1日・15日・末日の契約（36通り）で free_until・paid_from を確かめる
  - パイロットは式を使わず 2027-09-30
  - 知らせが free_until の1か月前に1回だけ（2回出ない）
```
