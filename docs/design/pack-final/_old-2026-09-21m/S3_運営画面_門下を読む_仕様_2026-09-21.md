2026-09-21 ／ Opus ／ design-v21。★Code は「実装だけ」をする。調べることは下に書き切った
正：見本 design-v21（PC `P_renraku`・`paneMonka`・`P_kaita`／スマホ `SC['門下を開く']`・`SC['開いた記録']`・`opRenraku` の注記）

## 0. 見本の側で直したこと（★実装の誤った文言の出どころ）

スマホの見本が「開いた記録は **先生と学生からも見られます**」のまま残っていた（9/10 に「運営の中だけ」へ変えたのに、PC だけ直っていた）。
実装の「ご本人にも伝わります」はここから来たと考えられる。design-v21 で3本とも「運営の中だけ・求められたら30日以内」に揃えた。

## 1. 台帳の約束（本番に入っているもの ── Opus が本番を直接見て確かめた）

```yaml
rpc: public.open_monka_thread(p_org_id uuid, p_teacher_id uuid, p_reason_kind text, p_reason_note text default null)
returns: setof (id, org_id, teacher_id, author_id, title, body, created_at, withdrawn_at)  # 新しい順
errors:   # 画面は message の頭の語で分ける
  NOT_AUTHENTICATED: ログインし直してもらう
  NO_MONKA_READ:     「この 役職では、門下の やりとりを 開けません」（入口を出していないはずなので、出たら不具合）
  REASON_REQUIRED:   「なぜ 開くかを 選んでください」
  check 違反（reason_note）: 「その他は、短く 書いてください（100字まで）」
reason_kind: jiko ／ honnin ／ horei ／ sonohoka   # DB の CHECK と同じ4つ
```

## 2. 画面（PC・スマホ共通の動き）

```yaml
入口: 連絡の一覧の「門下」の行。★monka_read を持ち、かつ その門下の先生でない（monka_write の本人でない）ときだけ、この流れ
押したとき: 中身を取りに行かない。先に「なぜ 開きますか」を出す
  文言（上の帯・warn）: 「開くと 開いた 記録に 残ります（誰が・いつ・どの 門下を・理由）。消せません。」
  選択肢: 事故・苦情の 調べ ／ ご本人からの 求め ／ 法令に 基づく 求め ／ その他（短く 書く）
  その他を選んだとき: 1行の入力（maxlength=100・placeholder「短く（100字まで）」）
  ボタン: 「開く」── 選んでいなければ押しても何もせず「理由を 選んでください」
  注記（note）: 「理由を 選ばないと 開けません。開くたびに 1行 残ります。
                 記録は 運営の 中だけ で 見ます（生徒・先生の 画面には 出しません）。ご本人から 求められたら、30日以内に お見せします。
                 何を 読んだかは 残しません（開いたことと 理由だけ）。」
開くを押したとき: open_monka_thread を呼ぶ → 返った行を表示 → 小さな知らせ「開きました。開いた 記録に 残りました」
  ★rpc が失敗したら中身を出さない（前に取った中身を使い回さない・キャッシュしない）
開いた後の帯: 「この 門下を 開いたことが、開いた記録に 残りました（運営の 中だけ）。」
別の行を押したら: 開いた状態を捨てる。もう一度同じ門下を開くには、また理由を選ぶ（開くたびに1行）
書き込み欄: 出さない（読むだけ）
```

## 3. 開いた記録の一覧

```yaml
入口: PC＝ホームのお知らせ「門下を 開いた記録 N件」・連絡の札「開いた 記録 N件」／スマホ＝運営の連絡の箱「開いた 記録 N件 ›」
見られる人: monka_read を持つ人（自分の行）と master（全部）── 台帳のポリシーどおり
列: 開いた人（そのときの 役職）／いつ／どの 門下／理由／何を 読んだか＝「残していません」
注記: 「誰が・いつ・どの門下を・理由 だけ。中身は 残しません。消せません。
        この 記録は 運営の 中だけ で 見ます（先生・学生の 画面には 出しません）。ご本人から 求められたら、30日以内に お見せします。」
```

## 4. 消すもの（実装の中を文字で探して直す）

```yaml
- 「ご本人にも伝わります」「ご本人にも 伝わります」 → 上の注記に置き換え
- 「先生と 学生からも 見られます」「先生・学生からも 見えます」「先生と 学生の 画面からも」 → 同上
- org_messages を直接 select して他人の門下を出している経路（S1 で台帳は0行を返すので、画面は空になっているはず）→ rpc に置き換え
```

## 5. 確かめ（Playwright・実在の試しの利用者）

```yaml
- 事務（monka_read あり・先生でない）で門下の行を押す → 中身が出ない・理由の選択が出る
- 理由を選ばずに「開く」→ 何も起きない／記録が増えない
- その他・空欄で「開く」→ 開かない
- 事故・苦情の調べ で開く → 中身が出る・monka_read_log が1行増える（理由 jiko）
- 別の行を押して戻る → また理由を聞かれる。もう一度開くと もう1行
- 先生本人が自分の門下を押す → 理由を聞かれない（今のまま直接読める）
- 学生・先生の画面のどこにも開いた記録が出ない
- 実装の画面に「ご本人にも伝わります」が0件
```
