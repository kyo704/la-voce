# §2 ★★学校の 予定 ／ じぶんの 予定

## 2-1 ★何が 違うか

| | 学校の 予定 | ★じぶんの 予定 |
|---|---|---|
| 中身の 例 | 講義・会議・入試・行事 | 用事・通院・お休み・送りむかえ |
| ★事務に 見えるもの | ★<b>「予定あり」だけ</b> | ★<b>「予定あり」だけ</b> |
| ★名前 | ★<b>本人だけ</b> | ★<b>本人だけ</b> |
| ★行事と ぶつかったとき | ★事務が 相談に 来ます | ★★<b>来ません</b> |
| ★理由 | 聞きません | ★★<b>聞きません</b> |

```
　★★どちらも、★中身は 本人にしか 見えません。
　★★事務には「予定あり」とだけ。★学校か じぶんかも 出しません。
　★★（★「教授会」も「通院」も、事務からは 同じ 1つの 印です）
```

## 2-2 ★なぜ 分けるか

```
　★分けないと、先生は「通院」と 書けません。
　★書けないと、★★予定を 入れなく なります。
　★入れないと、★★そこに レッスンが 入ります。
　★→ ★★<b>安心して 塞げること</b>が、この 機能の 値打ちです。

　★★そして「じぶんの 予定」には、
　★★<b>事務から「動かしてください」と 言えません。</b>
　★これが、この 別を つける ★ただ1つの 実務上の 違いです。
```

## 2-3 ★★保存の しかた（★Code へ）

```
　★★名前と 種類は <b>端末の 中だけ</b>に 置いてください。
　★★サーバへ 送るのは「その コマが 塞がっているか どうか」の <b>1つの 印だけ</b>。

　★これは、生徒の 時間割と ★同じ 決まりです（★9月11日 §時間割）。
　★→ ★漏れる 経路を、そもそも 作りません。
　★→ ★事務の 画面に 名前が 出ないのは「隠している」のでは なく、
　　　 ★★<b>サーバに 無い</b>からです。
```

# §3 ★出席 ── 個人レッスンと、みんなの レッスン

## 3-1 ★きょうの レッスンの 出しかた

```
　★個人レッスン　　→ ★<b>生徒の お名前</b>を 出します
　　　　　　　　　　 （れい）9:00　高木 みなみ　／　声楽3年　第1教室

　★みんなの レッスン → ★<b>授業の 名前</b>を 出します
　　　　　　　　　　 （れい）13:00　合唱 基礎　／　<b>6人</b>（みんなの レッスン）　大ホール
```

## 3-2 ★押したら どうなるか

```
　★個人レッスンを 押す
　　→ ★★<b>その1人だけの 画面</b>。大きな 3つ（出席／休み／休講）
　　→ ★下に <b>きょうの ほかの レッスン</b>の 一覧。押すと そこへ 移ります

　★みんなの レッスンを 押す
　　→ ★★<b>その時間に 来る 全員</b>が 並びます。1人ずつ つけられます
　　→ ★「ぜんぶ 出席」→ ちがう方だけ 直す、が いちばん 速い
　　→ ★★<b>お名前を 押すと、その方 ひとりの 画面</b>に なります
　　→ ★その画面の 下に <b>この レッスンの ほかの 方</b>。押すと すぐ 移ります
　　→ ★「次の 方へ ›」で、まだ つけていない 方へ 1つずつ
```

## 3-3 ★変えていないこと

```
　★★出席を つけられるのは、担当している 先生だけ（★9月10日 §2）
　★★ほかの 先生の レッスンは、開いても お名前も 人数も 出ません
　★事務は 代わりに つけられます。★事務の 名前が 残ります
　★休講＝その回を しなかった とき。★生徒の 欠席に なりません
　★★体調・記録の 中身は 出ません。「なぜ 休んだか」の 欄も ありません
```

★**鍵は `先生／時間／お名前` に しました。**
★同じ生徒が 1日に 2つの レッスンに 出ても、★別々に つけられます。
★（★DB では `lesson_id × student_id`。★見本は 見本です）

# §4 ★連絡 ── 中身が 出た ときに 既読

```
　★これまで　押したら 既読
　★これから　★★<b>中身が 画面に 出た ときに 既読</b>。青い点は その場で 消えます

　★PC　　右に 本文が 出た ものが 既読に なります
　★スマホ　連絡を ひらいた ときに、そこに 本文が 出ている ものが 既読
　★★一覧の 行だけの もの（門下）は、★ひらくまで 点が 残ります
```

★**理由。★「読んだのに 点が 残っている」は、★数が 信じられなく なります。**
★数が 信じられないと、★★点そのものを 見なく なります。

```
　★★変えていないこと
　★誰が 読んだかを、書いた人に <b>知らせません</b>（★既読の 一覧を 作りません）
　★★「まだ 読んでいない人」の 一覧も 作りません
　★事務が 何を 開いたかは、生徒・先生に 出しません（★9月10日）
　★門下を ひらいた ことは、いまも <b>開いた記録</b>に 残ります
```

# §5 ★★スクロールが 上に 戻る のを 直しました

```
　★症状　★ボタンを 1つ 押すたび、★画面が いちばん上に 戻っていました。
　★原因　★押すと 画面ぜんぶを 描き直していて、★位置を 覚えていませんでした。

　★直し
　　★描き直す 前に <b>いま 見ている 位置</b>を 覚えます
　　★描き直した あと <b>その位置に 戻します</b>
　　★★<b>画面が 変わった ときだけ</b>（go／goo／push／pop）上に 戻します
```

★**Code へ。★これは 見本だけの 話では ありません。**

```
　★★本番でも、★「押すたび 上に 戻る」を 1つも 作らないでください。
　★★とくに 出席・日程・予定・名簿の ように、
　★★<b>下の方を 何回も 押す 画面</b>で 起きると、★使いものに なりません。

　★React などで 作る ときは、
　★★<b>リストを 丸ごと 作り直さない</b>（key を 正しく つける）
　★★状態を 上に 持ち上げすぎない
　★★どうしても 描き直す なら、★scrollTop を 覚えて 戻す
```

```
　★これまで　入っている マスを 押すと、★その場で 消えていました。
　★★これは 危ないです。★間違えて 押すと、★黙って 消えます。

　★これから
　　★押す → ★<b>直す画面（PCは 下の カード、スマホは 別の 画面）</b>が 出ます

　　★消すのは ★<b>「この 予定を 消す」を 押したときだけ</b>
　　★「そのままに する」で 閉じられます

　★空きの マスは、★これまで どおり <b>1回 押すだけ</b>で 入ります。
　★（★入れるのは かんたんに、★消すのは ひと手間。★これが 正しい 向きです）
```
