# 作業指示｜導入効果の測定（教室が更新する理由をつくる）

**Claude Sonnet 5 へ。G4 で作るものです。★いま着手しないでください。**

**最初の1件が契約してから着手します。** 本書は「そのときに何を測るか」を決めておくためのものです。

読む順番：教室運営の範囲とカレンダー書き出し.md → レッスンの希望申告と月の組み立て.md → 本書。

---

## 0. なぜ作るのか

**教室が契約を更新するかどうかは、「効果があったか」で決まります。**
そして**それを示せるのは、こちらだけです。**

```
教室が払っているのは
　★「事務の時間が減ること」への対価であって、
　　データへの対価ではありません。

したがって測るのは★教室の業務データであり、
★健康データを1件も含みません。
```

---

## 1. 結論

```
① 測るのは★教室の業務データだけ。健康の数値を1つも混ぜない。
② 導入前の数字は★システムでは取れない。契約時に人が聞き取る。
③ 測るのは★4つだけ。増やさない。
④ 年に一度、「1年の記録」を出す。★教室に返してよい唯一のもの。
⑤ ★5人未満になる集計は出さない。
```

---

## 2. 導入前の数字（★人が聞き取る。実装なし）

**契約のときに、坂本さんまたは担当者が聞き取ります。**
**これは後からは絶対に取れません。**

```
□ 来月の日程を決めるのに、いま何時間かかっていますか
□ 振替は、月に何件くらい起きますか
□ 振替の日程が決まるまで、何回やりとりしますか
□ 月謝の消化回数の確認に、月どのくらいかかりますか
□ 生徒は何人、講師は何人ですか
```

### 2-1｜保存の形

```ts
interface OrgBaseline {
  orgId: string
  recordedAt: string            // 聞き取った日
  recordedBy: string            // 聞き取った人
  schedulingMinutesPerMonth?: number   // 日程調整にかかる時間（分）
  makeupsPerMonth?: number             // 月の振替件数
  makeupRoundTrips?: number            // 振替の確定までのやりとり回数
  tuitionCheckMinutesPerMonth?: number // 月謝の確認にかかる時間（分）
  studentCount?: number
  teacherCount?: number
  note?: string
}
```

```
・★すべて任意。聞けなかった項目は空でよい
・入力は★管理者の画面から手入力（1回だけ）
・★あとから編集できるが、編集の履歴を残す
・自己申告であることを、表示に必ず書く
```

**「導入前 月3時間（教室のご申告）」と書いてください。**
**測った数字と、聞いた数字を、同じ顔で並べてはいけません。**

## 3. 導入後に測るもの（★4つだけ）

### 3-1｜① 月の組み立てにかかった時間

```
TermPlan の status が 'building' になってから 'published' になるまでの★経過時間
```

```
・実際に画面を開いていた時間ではなく、★着手から公開までの経過
・「3日かかった」ではなく「実作業は20分」と言えないので、
　★そう説明できる形で表示する（下記 §5）
```

### 3-2｜② 振替が確定するまでの日数

```
MakeupRequest の requestedAt から confirmedAt までの★日数
```

```
・中央値を使う（平均は、1件の長期案件に引っぱられます）
・expired / declined は★分母に入れない（別に件数だけ出す）
```

### 3-3｜③ 希望申告の提出率

```
締切までに提出した生徒数 ÷ 席の数
```

```
・★「出していない人が誰か」は出さない（誰が使っていないかと同じ）
・割合だけ
```

### 3-4｜④ 席の稼働率

```
直近30日に1回以上記録した人数 ÷ 付与した席の数
```

```
・★5人未満のときは数値を出さない（「—」と表示）
・★記録の中身には一切触れない。回数も出さない。「1回以上か」だけ
```

---

## 4. ★測ってはいけないもの

```
✗ 生徒の記録の中身、傾向、スコア、連続日数
✗ 誰が使っている／使っていないの一覧
✗ 欠席の理由、体調に関する何か
✗ 講師ごとの「生徒の状態」
✗ 退会・休会の予測
✗ 「よく使っている生徒」「使っていない生徒」の区別
```

**①〜④に健康の数値を1つでも混ぜたら、この仕組みは終わりです。**
**そして①〜④の価値も、一緒に消えます。**

## 5. 「1年の記録」（★教室に返す唯一のもの）

### 5-1｜出し方

```
┌────────────────────────────────────┐
│ ◯◯音楽教室　導入から1年の記録                    │
│ 2026年10月 〜 2027年9月                          │
│                                                  │
│ 月の予定を組む                                    │
│   導入前　月 約3時間（ご申告）                     │
│   いま　　着手から公開まで 中央値 1.2日            │
│           ★実際の操作時間ではありません            │
│                                                  │
│ 振替が決まるまで                                  │
│   導入前　平均4日・やりとり6回（ご申告）           │
│   いま　　中央値 1日                              │
│   期間中の振替　68件（うち成立 61件）              │
│                                                  │
│ 希望申告の提出率      平均 87%                    │
│ 席の稼働率            15席中 13人（87%）           │
└────────────────────────────────────┘
```

### 5-2｜規則

```
□ ★年に一度だけ出す（毎月出さない。数字に一喜一憂させない）
□ 導入前の数字には★必ず「ご申告」と書く
□ ★改善していない項目も、そのまま出す
□ PDFで書き出せる（★契約更新の稟議に使われます）
□ ★健康に関する語を1つも含めない（テストで固定する）
```

**改善していない項目を隠さないでください。**
**都合の良い数字だけを並べた資料は、次の更新で必ず見抜かれます。**

## 6. データモデル

```ts
interface OrgMetricsMonthly {
  orgId: string
  yearMonth: string                  // '2026-11'
  planBuildDaysMedian?: number       // ① 着手から公開まで（日）
  makeupLeadDaysMedian?: number      // ② 振替の確定まで（日）
  makeupCount: number
  makeupConfirmedCount: number
  wishSubmitRate?: number            // ③ 提出率 0〜1
  seatActiveCount?: number           // ④ 直近30日に1回以上記録した人数
  seatTotal: number
  suppressed: boolean                // ★5人未満で伏せたか
}
```

```
・★月次で確定させ、あとから遡って書き換えない
・欠測は null。★0で埋めない
・suppressed が true のとき、画面には「—」と出す
```

**RLS**

```
・その教室の管理者のみ
・★個々の生徒・講師の行に触れない集計であること
・★SECURITY DEFINER 関数から、記録の中身を参照しない
```

## 7. ★禁止事項

```
1.  ★健康に関する数値を、1つも混ぜない
2.  ★誰が使っている／使っていないを出さない
3.  ★5人未満の集計に数値を出さない
4.  ★「1年の記録」を毎月出さない
5.  ★導入前の数字を、測定値と同じ体裁で並べない（ご申告と明記）
6.  ★改善していない項目を隠さない
7.  ★退会・休会の予測を作らない
8.  月次の集計を、あとから書き換えない
9.  ★講師個人の成績のように見える出し方をしない
10. ★測る項目を4つより増やさない
```

### なぜ ⑨ を禁止するか

**「振替が確定するまでの日数」を講師ごとに出すと、講師の評価表になります。**
教室が講師を管理する道具になった瞬間、**講師が使わなくなります。**

```
○ 教室全体の中央値
✗ ★講師ごとの中央値
```

## 8. 受け入れ条件

```
□ ①〜④の4つだけが集計されている（5つ目が無い）
□ 出力に健康に関する語が1つも含まれない（★grepで0件）
□ 5人未満のとき「—」が出る
□ 誰が使っている／いないの一覧が、どの画面にも無い
□ 講師ごとの数値が、どこにも出ない
□ 導入前の数字に「ご申告」が付いている
□ 「1年の記録」がPDFで出せる
□ 月次の集計が、遡って書き換えられない
```

## 10. Sonnet への依頼のコツ

**この機能で、いちばん越えやすい線は「教室のため」です。**

実装中に、次を思いつくはずです。

```
・使っていない生徒を教室に知らせれば、声をかけられる
・記録が減った生徒を「退会の予兆」として出せる
・講師ごとの振替の速さを比べれば、指導の改善になる
・教室が生徒の調子を知っていれば、レッスンの質が上がる
```

**4つとも、教室にとっては本当に役に立ちます。**
**そして4つとも、この製品を殺します。**

```
★迷ったときの基準

その数字は、★生徒一人を指していませんか？
　→ 指しているなら、出しません。
```
