# La Voce ／ 分析画面の表示規約（グラフの型と色）

**Claude Sonnet 5 へ。分析画面の見た目を、この文書の型に統一してください。**

**新しい分析は1つも増やしません。** 既にある計算結果を、
**読み間違えようのない形**で出し直すための文書です。

添付の **`lavoce-analysis-mock4.html`** が完成見本です。
ブラウザで開いて、この文書と突き合わせながら実装してください。
見本の中の SVG は、そのまま流用して構いません。

読む順番：**統合実行ルート v4 §6（表示ゲート）** → 本書。

---

## 0. 原則

```
① 数字を大きく、飾りを小さく。
② ★色で良し悪しを言わない。赤・黄・緑の信号色を使わない。
③ ★立体にしない。遠近で差が誇張される。立体は「羊のおうち」だけの役割。
④ ★文献の基準線を引かない。引くのは、その人自身の中央値。
⑤ 平均の棒2本にせず、1日ぶんの点を全部出す。ばらつきを隠さない。
⑥ ★解釈の文章を出せるのは、3ゲートを通ったカードだけ。図に説明を添えない。
⑦ 「まだ判定できない状態」を、最初にデザインする。
```

**⑦が最も重要です。** ユーザーの大半は、最初の数週間ずっとその状態にいます。
そこが空白だと、壊れているように見えて離脱します。

## 1. 色

### 1-1｜★色は今のサイトの値をそのまま使う

**新しい色を1つも作りません。** 下の値は、実際の画面の画素から抜き出したものです。
**近い色に置き換えたり、明るさを調整したりしないでください。**

```css
:root{
  --bg:#F7F2E6;        /* 地色 */
  --card:#FFFDF8;      /* カードの面 */
  --card-2:#F7F2E6;    /* チップの面 */
  --border:#E5DDC7;    /* 枠線 */
  --grid:#E5DDC7;      /* 目盛り線 */
  --track:#E5DDC7;     /* 棒の下地 */

  --ink:#261913;       /* 本文 */
  --ink-2:#6D5D50;     /* 補助 */
  --ink-3:#76665A;     /* 目盛り・注記 */

  --wine:#840C24;      /* ブランド色（ロゴ・ボタン） */
  --s1:#840C24;        /* 系列1 = ワイン */
  --s2:#BF8722;        /* 系列2 = 山吹（今のスコアの棒の色） */
  --s3:#447862;        /* 系列3 = 深緑（今の体重の線の色） */
  --s2-pale:#DFC28D;   /* 山吹の淡いほう（既にサイトにある値） */
  --ok:#739E67;        /* スコアの数字に使われている緑 */
}
```

**すでにサイトにある3色を、そのまま系列色に昇格させただけです。**
ワインはロゴとボタン、山吹はスコアの棒、深緑は体重の線。
**新しい色が増えないので、画面がばらけません。**

### 1-2｜★色を増やさず、形で区別する

系列が3つを超えるとき、**4色目を作らないでください。**
代わりに次のどれかを使います。

```
・白抜きの丸（塗りなし＋1.4pxの輪郭）
・丸の大きさを変える（3.2px と 4.8px）
・直接ラベルを添える
・図を分ける（小さく上下に並べる）
```

見本では「低い日」を**白抜きの丸**、「今日」を**塗りつぶし**にしています。
**色は1つのまま、形だけで区別しています。**

これは色覚多様性への対応でもあります。**色だけに意味を持たせない**という原則は、
色を増やさない方針と同じ方向を向いています。

### 1-3｜★夜のモードは、いま決めません

夜の面の上では、`#840C24` は暗すぎて読めません。
**しかし、私が勝手に明るい色を作るべきではありません。**

```
・夜のモードは、坂本さんが色を決めてから実装する
・★それまでは昼のモードだけを作る
・勝手に明度を上げた「近い色」を作らないこと
```

### 1-4｜★使ってはいけない色の使い方

```
✗ 赤・黄・緑の信号色（色そのものが判定になる）
✗ メーターの「危険ゾーン」の塗り分け
✗ 値の大小で色を変える
✗ 上の6色以外の色をデータに使う
✗ 同じ色の明るさ違いを勝手に作る
```

**信号色は3ゲートを迂回します。** 文章を出していなくても、色が言っています。

## 2. カードの型

```
・面 --card、枠線 1px --border、角丸 14px、★影は使わない
・見出しは明朝（Georgia + Hiragino Mincho ProN + Yu Mincho）15px
・見出しの下に、1〜2行の説明（--ink-2、11.5px、行間1.7）
・右上に期間のチップ（--card-2 に枠線、角丸999px、10.5px）
・数値は tabular-nums
・注記は --ink-3、10.5px、上に1pxの区切り線
```

**説明の1行を省略しないでください。**
「何を見ているのか」が書いていないグラフは、読まれずに飛ばされます。

## 3. 部品（9種）

**この9種以外の図を作らないでください。** 増やしたくなったら質問してください。

### A｜数値ヒーロー ＋ スパークライン

**使う場面**：今日のスコア、中央値など、1つの数字が主役のとき。

```
・数字 36px / 単位と補足 13px --ink-2
・★右に直近14日のスパークラインを添える（96×26px、点は最新のみ）
・スパークラインに軸・目盛りを付けない
```

**数字だけでは「今日が良い日なのか」が分かりません。**
推移を横に添えるだけで、同じ数字が読めるようになります。

### B｜内訳の横棒

**使う場面**：コンディションスコアの内訳、当てはまった日数。

```
・高さ5px、角丸3px、下地 --track、塗り --s2
・★全部同じ色。値によって色を変えない
・ラベル左・数値右、数値は太字
・並び順は固定（★値の大小で並べ替えない。毎回順番が変わると読めない）
```

### C｜1次元の点列（今日の位置）

**使う場面**：直近N日の中で今日がどこか。**今のリング表示の置き換え。**

```
・横軸はスコア。点ひとつが1日
・過去の日は --muted、今日は --s1 で少し大きく、上にラベル
・目盛りは3〜4本だけ
```

**リングは「7／9日中」しか言えませんが、点列は
順位と散らばりを同時に見せます。**
良い日と悪い日がどれくらい離れているかが分かります。

### D｜推移の線＋強調点

**使う場面**：声の調子、食後就寝までの時間など、日ごとの推移。

```
・線は --s1、太さ1.8px、不透明度0.3（線は補助。主役は点）
・点は半径3.2px、面の色で1.8pxの縁取り（重なっても数えられる）
・★本番・レッスンの日だけ --s2 にして半径4.8px
   → 色と大きさの両方で区別する（色だけに頼らない）
・目盛り線は --grid、横だけ。縦の目盛り線は引かない
・★基準線を引かない。引くなら「あなたの中央値」を破線 --ink-3 で
```

### E｜2群のドットプロット（★判定が出たとき）

**使う場面**：3ゲートを通った群間比較。

```
・1日ぶんの点を全部描く（重なりは縦に±4pxずらす）
・点は不透明度0.45、面の色で1.6pxの縁取り
・★各群の中央値を縦線で示し、数値を直接ラベルする
・軸は下に1本。ラベルは「低い ← → 高い」
・★棒グラフにしない
```

**平均の棒2本にすると、差が実際より確かなものに見えます。**
点を全部出すと重なりが見え、「2時間未満でも良かった日はある」が伝わります。
**効果量が中程度、というのはそういう意味です。**

### F｜進捗ドット（★判定できないとき）

**使う場面**：件数が足りていない全ての分析カード。

```
・9px の丸を10個。たまった分だけ --s2、残りは --track
・★「今日の記録」の点と同じ形にそろえる
・文言は「◯日分たまりました。あと◯日で傾向を出せます。」
・★「データがありません」と書かない
```

### G｜期間の帯＋点（横並び）

**使う場面**：周期など、繰り返す期間どうしの比較。

```
・行は直近6件まで。横軸は「何日目か」（★日付ではない）
・帯は --band、高さ8px、角丸4px
・点は --s1（ふつう以上）／ --muted（低い）
・★この図に解釈の文章を添えない
```

**並べれば、本人が自分で気づきます。教えないでください。**

### H｜小さく並べる（単位が違うもの）

**使う場面**：カロリーと体重など、縦軸の単位が違うものを一緒に見るとき。

```
・★1枚に2つの縦軸を重ねない（交点の位置が軸の取り方で変わる）
・x軸だけ揃えて、上下に分けて並べる
・それぞれの縦軸は実際の目盛りのまま
・各図の左上に、何の図かを9pxで書く
```

**今のサイトが既にこの形を選んでいます。正しい判断なので、変えないでください。**

### I｜散布図（相関を出すとき）

```
・点のみ。★回帰直線・近似曲線を引かない
・引いた瞬間に「予測」になり、3ゲートの外に出ます
・ρ の値は数値で添える。図の上に線として描かない
```

## 4. 今ある分析 → 部品の対応

| 今ある表示 | 使う部品 | 変更点 |
|---|---|---|
| コンディションスコア（74/100） | **A ＋ B** | ★スパークラインを追加。棒は全部同色のまま |
| コンディション偏差値（リング） | **C** | ★リングを点列に置き換える |
| 栄養摂取と体重の変化 | **H** | 形はそのまま。★目標カロリーの破線を外す |
| 体重の推移 | **D** | 単独で出す場合。★基準線を引かない |
| 声の記録の推移 | **D** | ★本番・レッスンの日を --s2 で強調 |
| 群間比較（Hedges' g） | **E ＋ F** | ゲート通過で E、未通過で F |
| 相関（Spearman ρ） | **I ＋ F** | 同上 |
| 周期と声 | **G** | 解釈の文章を添えない |
| 逆流の記録（当てはまった日数） | **B** | 全部同色 |

### 4-1｜★目標カロリーの破線について

今の「栄養摂取と体重の変化」には、目標カロリーの破線が引かれています。
**これを外してください。**

**破線の下を「足りなかった日」に見せているからです。**
食後就寝までの時間に推奨の2時間の線を引かないと決めたのと、同じ話です。

そして La Voce のユーザーは、**体型の圧力が強い職業**の人たちです。
毎日「目標に届かなかった」を見せる画面を作らないでください。

**体重とカロリーは、記録として残し、声の分析には使いません。**
カードの下に「※ 声の分析には使っていません。記録として残しているだけです。」と書いてください。

## 5. 3つの状態

**すべての分析カードは、次の3状態のどれかです。**

```
① 待機   件数が足りない        → F（進捗ドット）＋「あと◯日で出せます」
② 通過   3ゲートを全部通った   → E / I ＋ 解釈の文章1〜2行
③ 不通過 件数は足りたが通らない → 「はっきりした関係は見えませんでした」
                                  ★数字も出さない。★「弱い関係があります」と書かない
```

**③を「関係なし」と書かないでください。**
「見えなかった」であって「無い」ではありません。

## 6. 実装の注意

### 6-1｜ライブラリ

**既に使っているものがあれば、そのままで構いません。**
ただし**既定の見た目をそのまま使わないでください。**

```
・既定のカラーパレットを全部 --s1/--s2/--s3 に置き換える
・既定のグリッド（縦線・濃い線）を消す
・既定のツールチップを、本書 §6-2 の形に置き換える
・既定の凡例の位置とサイズを合わせる
```

見本の SVG は依存ライブラリなしで書いてあります。**そのまま使っても構いません。**

### 6-2｜触ったときの表示

```
・点・帯・棒にふれると、値が出る（PC のホバー、スマホのタップ両方）
・当たり判定は見た目より大きく
・文字は11px、地は --ink、文字色は --card
・★ツールチップの中でも、良し悪しを言わない
```

### 6-3｜文字と数字

```
・すべての数値に font-variant-numeric: tabular-nums
・見出しは明朝、本文と数値はゴシック
・font-feature-settings:"palt"（日本語の字間）
```

### 6-4｜アクセシビリティ

```
・★色だけに意味を持たせない（形・大きさ・直接ラベルのどれかを併用）
・系列が2つ以上なら凡例を必ず置く
・「数字で見る」の折りたたみで表を出す（★--s2 を使う図では必須）
・svg に role="img" と aria-label
・prefers-reduced-motion: reduce のとき、動きを止める
・アニメーションは入場のみ、200ms まで
```

### 6-5｜多言語

```
・グラフの中の文字列も翻訳対象に含める（軸ラベル・凡例・単位）
・★数値の書式は Intl.NumberFormat を使う（小数点とけた区切りが言語で違う）
・日付は Intl.DateTimeFormat
・★ラベルの長さが2倍になっても崩れないこと（ドイツ語で確認）
```

## 7. ★禁止事項

```
1.  立体のグラフを作らない（3D棒・3D円・奥行きのある面）
2.  円グラフ・ドーナツで割合を出さない（角度は比較しにくい）
3.  赤・黄・緑の信号色を使わない
4.  メーターに危険ゾーンを塗らない
5.  値の大小で色を変えない
6.  文献の基準線・目標線を引かない（★目標カロリーの破線を含む）
7.  1枚のグラフに2つの縦軸を重ねない
8.  散布図に回帰直線を引かない
9.  3ゲートを通っていないカードに解釈の文章を出さない
10. 図の中に解釈の文章を書き込まない（文章はカードの本文だけ）
11. 「データがありません」と書かない（Fの進捗ドットにする）
12. 棒グラフの縦軸を0以外から始めない
13. 系列の並び順を値によって入れ替えない
14. ブランド色 --wine をデータの色に使わない
15. 影でカードを浮かせない（線で囲う）
16. ★勝手に新しい色を作らない（明るさ違いも含む）
```

## 10. Sonnet への依頼のコツ

**この文書は、見た目を良くする文書ではなく、
「読み間違えさせない」ための文書です。**

実装中に、次を思いつくはずです。

```
・スコアが低い日を赤くする
・目標に届いた日に緑のチェックを出す
・散布図に傾向線を引く
・「弱い相関があります」と書く
・グラフに影と奥行きを付けて立体的にする
・系列が増えたので、似た色を1つ足す
```

**5つとも §7 で禁止しています。** どれも「親切」と「かっこよさ」から出てきます。

**迷ったときの基準は2つです。**

```
① その表示は、3ゲートを通っていない何かを言っていませんか？
   → 色も、線も、形も、言葉と同じです。

② その表示は、値を実際より確かに／大きく見せていませんか？
   → 立体・二重軸・0以外の原点・回帰直線は、全部これに当たります。
```
