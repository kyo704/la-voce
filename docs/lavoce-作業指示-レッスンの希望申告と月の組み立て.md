# La Voce ／ レッスンの希望申告と「月の組み立て」

**Claude Sonnet 5 へ。教室運営の、振替より上流にある機能です。**

読む順番：教室運営の範囲とカレンダー書き出し.md §4（振替）→ 本書。

**振替は「決まったあとに壊れたもの」を直す機能です。**
**本書は「壊れにくい形で決める」機能です。上流のほうが効きます。**

---

## 0. 結論

```
① ★決めるのは先生。生徒が出せるのは「希望」だけ。自動で確定させない。
② 生徒が選ぶのは日付ではなく、★曜日と時間帯の帯（◎△×）と、月の希望回数。
③ 入力は★1タップを既定にする（前月コピー）。毎月ゼロから書かせない。
④ 先生の画面は「重なりのヒートマップ」。★探す作業をやめさせるのが目的。
⑤ ★確定するまで、生徒には何も見せない。枠の取り合いを作らない。
⑥ ★体調・声の記録を、希望にも割当にも一切使わない。
⑦ ★「ほかの仕事」の勤務パターンは送信しない。端末内で◎△×に変換する。
```

---

## 1. なぜこれを作るのか

### 1-1｜いま何が起きているか

```
先生「来月いつ空いてる？」を LINE で一斉送信
   ↓
生徒がばらばらに返信（既読だけの人、3日後に返す人、「たぶん火曜」）
   ↓
先生が手帳に書き写して、重なりを手で解く
   ↓
決まった予定を、また一人ずつ LINE で送る
   ↓
「その日は無理でした」で、一部が崩れる
```

**生徒10人で、毎月おおよそ2〜4時間が消えています。**
そして**この作業は、教える技術とまったく関係がありません。**

### 1-2｜なぜ振替より先か

```
振替あり  … 決まった予定が壊れたときだけ必要。★教室によっては制度がない
希望申告  … 予定を決めるたびに必要。★すべての教室で、毎月起きる
```

**「誰もが必要になる機能」は、こちらです。**

そして**上流で合わせておくほど、振替の発生自体が減ります。**
最初から来られない日に入れなければ、休む理由が一つ減ります。

### 1-3｜★声楽・ボーカルは、固定枠が崩れやすい

ピアノの子どもの教室は「毎週火曜17時」で回ります。
**しかし声を使う人のレッスンは、そうなりません。**

```
・本番の前は増やしたい。終わったあとは減らしたい
・喉の状態で、その週は避けたいことがある
・大人の生徒は、仕事のシフトが月ごとに変わる
・プロは、ツアーや稽古で数週間まるごと空けられない
```

**だから「毎月、希望を出し直せる」ことに意味があります。**
これは他の教室管理ソフトが持っていない前提です。

## 2. 生徒が出すもの

### 2-1｜画面

```
┌──────────────────────────────┐
│ 10月のレッスン希望                          │
│ 9月20日まで                                 │
│                                            │
│ 何回受けたいですか                          │
│      [ − ]   3回   [ ＋ ]                   │
│                                            │
│ 来られる時間帯                              │
│         朝    昼    夜                      │
│   月    ×     ×     ◎                      │
│   火    ×     ×     ×                      │
│   水    △     ◎     ◎                      │
│   木    ×     ×     ×                      │
│   金    ×     ×     △                      │
│   土    ◎     ◎     △                      │
│   日    ◎     ◎     ×                      │
│                                            │
│ この月、どうしても無理な日                  │
│   [ 10/12 ] [ 10/13 ] [ ＋ 追加 ]           │
│                                            │
│      [ 先月と同じ ]      [ 出す ]           │
└──────────────────────────────┘
```

```
朝  〜12:00     昼  12:00〜17:00     夜  17:00〜
◎ 来られる   △ 行けなくはない   × 無理
```

### 2-2｜★入力を1タップにする

**毎月この表を埋めさせたら、3か月で誰も出さなくなります。**

```
① 前月の希望を、既定値として最初から入れておく
② 変わっていなければ [ 出す ] を押すだけ（★1タップ）
③ 変わったところだけ触る
```

**「前日をコピー」と同じ考え方です。**

### 2-3｜★「ほかの仕事」から下書きを作る（端末内）

**兼業の生徒は、勤務の曜日パターンをすでに登録しています。**
それを使って、◎△×の**下書き**を作れます。

```
勤務あり（張り上げる仕事）の帯   → ×
勤務あり（それ以外）の帯         → ×
勤務なしの帯                     → 触らない（前月の値を残す）
```

```
★絶対の条件

・変換は★端末の中で行う
・保存するのは、変換後の ◎△× だけ
・★workSchedule / workHours / 勤務時間そのものを送信しない
・★source に 'work' を持たせない（内訳が漏れます）
・生徒には「仕事の予定から下書きを作りました」と表示してよい
  → 先生の画面には、その表示を出さない
```

**「ほかの仕事 §7-2」の線を、ここでも守ってください。**

### 2-4｜★聞かないこと

```
✗ 希望の理由（自由記述）
✗ 「なぜ回数を減らすのか」
✗ 体調・喉の状態
✗ 通学時間・現在地
```

**理由欄を作った瞬間に、「体調が悪くて」と書く生徒が出ます。**
**それは要配慮個人情報を先生に送らせたのと同じです。**

## 3. 先生が組み立てる

### 3-1｜画面

```
┌───────────────────────────────────┐
│ 10月を組む                    希望 8/10人 提出済  │
│                                                  │
│         月    火    水    木    金    土    日    │
│  朝     ░     ░     ▒     ░     ░     ███   ███  │
│  昼     ░     ░     ███   ░     ░     ███   ▓▓   │
│  夜     ▓▓    ▒     ███   ▒     ▓▓    ▒     ░    │
│         ↑ 色が濃いほど、来られる生徒が多い時間    │
│                                                  │
│  まだ置いていない生徒                            │
│   ・A さん   希望3回  … 0回                      │
│   ・B さん   希望2回  … 1回   ★本番が近い        │
│   ・C さん   希望4回  … 4回  ✓                   │
│                                                  │
│  [ 先月と同じ枠で埋める ]        [ 公開 ]        │
└───────────────────────────────────┘
```

### 3-2｜★やることは「探す」ではなく「置く」

**候補日を人間が探すのをやめさせるのが目的です。**

```
・生徒をドラッグして、枠に置く
・◎ の帯に置いたときは、そのまま
・★△ の帯に置くときだけ、確認を出す（「△です。よろしいですか」）
・× の帯には★置けない
・先生自身の freeBusy で埋まっている時間は、灰色にする
```

### 3-3｜★「先月と同じ枠で埋める」を必ず作る

**実際には、8割の生徒が前月と同じ枠です。**
このボタン1つで、先生の作業は「残り2割を直す」だけになります。

```
・前月の確定枠を、今月の同じ曜日に複製する
・★今月の希望と矛盾する枠は、置かずに残す（勝手に動かさない）
・矛盾した生徒だけが「まだ置いていない」に残る
```

### 3-4｜★本番が近い生徒には、印を出す

**生徒がすでに登録している本番の予定を使います。**

```
先生に見えるもの   ★「本番が近い」という印だけ
先生に見えないもの 何の本番か・どこか・体調・声の記録
```

**日付だけで足ります。** 逆算して枠を厚くするのは先生の判断です。

### 3-5｜公開

```
・[ 公開 ] を押すまで、生徒には★何も見えない
・公開で、確定したレッスンが作られる
・生徒に通知が1回だけ飛ぶ
・カレンダーのフィードに反映（書き出し §3-2 方式B。8〜24時間の遅延あり）
・★公開後の変更は、振替のフロー（教室運営 §4）に合流する
```

## 4. 締切と、出さない人

### 4-1｜締切

```
・教室ごとに設定（既定：前月の20日）
・締切の3日前に、まだ出していない生徒へ★1回だけ通知
・★それ以上は送らない
```

**「記録の催促をしない」と同じ線です。**
出さない人ほど、催促で離れます。

### 4-2｜出さなかったら

```
① 前月の希望を、そのまま今月の希望として扱う（★自動）
② 前月もなければ、「まだ出ていない」として先生の画面に残る
```

**★「今月は0回」を選んだ生徒を、退会予備軍として先生に通知しないでください。**
事実の一覧（誰が出していないか）は業務に必要なので出します。
**しかし「辞めそうです」という推定を、アプリが出してはいけません。**

## 5. データモデル

```ts
interface LessonWish {
  id: string
  orgId: string
  enrollmentId: string
  termMonth: string                  // '2026-10'
  desiredCount: number               // 0〜8
  grid: {
    dow: 0|1|2|3|4|5|6
    band: 'morning' | 'afternoon' | 'evening'
    level: 'good' | 'maybe' | 'no'
  }[]
  blockedDates?: string[]            // その月の、絶対に無理な日
  submittedAt: string
  source: 'copied' | 'manual'        // ★'work' を作らない
  guardianEntered?: boolean          // 保護者が入力した
  // ★理由・自由記述のフィールドを作らない
  // ★体調・声に関するフィールドを作らない
}

interface TermPlan {
  id: string
  orgId: string
  teacherId: string
  termMonth: string
  status: 'collecting' | 'building' | 'published'
  deadlineAt: string
  publishedAt?: string
}
```

**確定したレッスンは、既存の Lesson をそのまま使ってください。**
新しい予定の型を作らないこと。

**RLS**

```
LessonWish
  ・生徒本人：自分の行だけ読み書き
  ・担当教師：★担当している生徒の行だけ読める。書けない
  ・★他の生徒の希望は、生徒からは1行も見えない
TermPlan
  ・その教室の教師のみ
```

## 6. ★禁止事項

```
1.  ★生徒が予約を自分で確定できるようにしない
2.  ★「残り◯枠」「あと1人」を生徒に見せない（取り合いを作らない）
3.  ★他の生徒の名前・希望・枠を、生徒に見せない
4.  ★希望に理由の欄を作らない
5.  ★出していない生徒に、2回以上通知しない
6.  ★体調・声・羊の記録を、希望や割当に使わない
      （「調子が良い時間帯」を提案するのも禁止。健康情報の迂回です）
7.  ★「ほかの仕事」の勤務時間・パターンを送信しない
8.  ★自動で割り当てて自動で確定する機能を作らない
9.  ★22:00〜08:00 に通知しない
10. ★希望回数の減少から「退会しそう」を推定しない
11. 公開前の組み立て途中を、生徒に見せない
12. ★先生の画面に、生徒の欠席理由を出さない（そもそも持っていない）
```

### なぜ ⑧ を禁止するか

**最適な割当を自動で出すのは、技術的にはできます。しかし作りません。**

```
・先生は暗黙のルールを持っています
  （この2人は続けない、この生徒は最後がいい、兄弟は同じ日に）
・アプリはそれを知りません。知ろうとすれば、聞くことが増えます
・そして不満が出たとき、「アプリが決めました」と言えてしまう
```

**先生の権威は、この製品の流通経路そのものです。**
**それを削る設計をしてはいけません。**

**提案までにしてください。決めるのは人です。**

## 9. 作らないもの一覧に追記

**「教室運営の範囲とカレンダー書き出し.md §7」の表に、次を足してください。**

| 作らないもの | 理由 |
|---|---|
| 生徒による自己予約（自動確定） | 決定権は先生。流通経路を壊す（本書 §6-8） |
| 空き枠の残数表示 | 生徒どうしの取り合いと圧力を作る（同 §6-2） |
| 自動割当スケジューラ | 先生の暗黙のルールを持てない。不満の逃げ場を作る（同 §6-8） |
| 希望の理由欄 | 「体調が悪くて」と書かれる。要配慮個人情報（同 §2-4） |
| 体調から時間帯を提案 | 健康情報を先生に渡す迂回路になる（同 §6-6） |
| 退会予測の通知 | アプリが人の継続を評価しない（同 §4-2） |

## 10. Sonnet への依頼のコツ

**この機能で、いちばん越えやすい線は「便利さ」です。**

実装中に、次を思いつくはずです。

```
・生徒が空いている枠を直接押さえられるようにする
・希望が集まったら、自動で最適な割当を出す
・「この生徒は調子が良い午前が向いています」と先生に出す
・「Aさんは3か月で回数が減っています」と先生に知らせる
```

**4つとも §6 で禁止しています。**

**迷ったときの基準は2つです。**

```
① それは、先生が決めることを、アプリが決めていませんか？
② それは、生徒の体調を、先生に見せていませんか？
   → どちらかに当たるなら、事実の表示だけに戻してください。
```
