## 3. ★案B は、そのままでは採りません

**坂本さんは案B（時間割から自動判定）を選びましたが、
案Bだけでは、事実として間違った答えを出します。**

### 3-1｜授業が無い時間 ≠ レッスンに来られる時間

```
学生には、授業以外の予定があります。

  バイト ／ 伴奏合わせ ／ 練習室の予約 ／ 通学時間
  他大学の授業 ／ 実技試験の準備 ／ 家庭の事情
```

**「授業が入っていないから空いている」は、間違いです。**

そして**既存の設計は、まさにこの問題を扱っています。**
希望申告で ◎△× を聞くのは、**「来られる」と「授業が無い」が違うから**です。

### 3-2｜★正しい形：時間割は「◎△×の下書き」に使う

**これは、既にやったことと同じパターンです。**

```
lavoce-作業指示-ほかの仕事.md
  勤務パターン → ★端末内で変換 → ◎△× だけ送る
  ★workSchedule などの生データは送信しない

★大学の時間割
  時間割       → ★端末内で変換 → ◎△× だけ送る
  ★時間割そのものはサーバーに保存しない
```

**これで、あなたの (d)（データの持ちすぎ）も同時に解けます。**

```
★サーバーは、大学の時間割を1件も保存しません。
　学生の端末が変換して、◎△× だけを送ります。
　→ §1 の「他人の予定を1件も保存しない」と、そのまま揃います
```

### 3-3｜取り込みの形

```
□ 学生が、自分の時間割を取り込む（CSV / スクリーンショットではなく、
  ★大学が出せる形式。まずは CSV）
□ ★端末内で ◎△× の下書きに変換する
□ 学生が、それを見て直す（★バイトや伴奏合わせを反映できる）
□ ★送信されるのは ◎△× だけ

★大学が一括で全学生の時間割を入れる、という形にしない
★学生ごとに、自分のぶんだけ
```

**あなたの絞り込み案（門下の学生が履修している授業だけ）より、さらに絞れます。**
**サーバーには1件も入りません。**

### 3-4｜坂本さんへの説明

**案Bを否定しているのではありません。**
**時間割を使うこと自体は採用します。使う場所が違うだけです。**

```
坂本さんの案   時間割 → ★サーバーで自動判定 → 空いている学生を出す
★この判断      時間割 → ★端末で下書き → 学生が直す → ◎△× → 重なりを出す
```

**結果として画面に出るものは、ほぼ同じです。**
「この時間に来られる学生の一覧」が出ます。**そして、より正確です。**

## 4. ★履修登録の肩代わり ── やりません

**坂本さんの「過剰だと思うのであれば無しでもいい」に対して、★過剰です。**

### 4-1｜理由

```
① ★間違えたら、学生の卒業が危うくなります
   単位認定・卒業要件に関わる。★取り返しがつかない種類の間違いです

② 大学ごとに学則が違います
   カレンダー連携が「大学の数だけ個別対応」なら、
   ★履修登録は「大学の数だけ学則の解釈」です

③ ★一人で作っているアプリが背負える責任ではありません
   10月からイタリアにいて、時差のある場所から、
   ★学生の卒業に関わるシステムを保守することになります

④ 教務システムは、既に各大学にあります
   ★置き換えるのは Woolsong の仕事ではありません
```

### 4-2｜恒久的に作らないものに追加

`lavoce-設計憲章.md` §10 に、次を足してください。

```
★大学の教務システムの肩代わり（履修登録・単位認定・成績・卒業要件）
　理由：間違えたときの害が、この製品が背負える範囲を超えるため
```

**★「将来の理想像として記録する」のもやめてください。**
**記録すると、いつか誰かが作ろうとします。**
**「やらないと決めた」ことと、その理由だけを残してください。**

## 7. ★売り方に、弱点があります（設計より先に確かめること）

**痛みを感じている人と、払う人が違います。**

```
教室プラン   ★先生の事務時間が減る → ★先生（教室）が払う      繋がっている
大学         ★門下代表（学生）の時間が減る → ★大学が払う？   ★繋がりが弱い
```

**大学の事務から見ると、門下のレッスン日程調整は
「学生が勝手にやっていること」で、大学の業務コストではない可能性があります。**

### 7-1｜繋げる言い方

**教員の時間も減ります。そして教員の時間は、大学のコストです。**

```
✗ 「学生の代表が楽になります」        → ★大学は払いません
○ 「教員が日程調整に取られる時間が減ります」  → ★大学のコストです
○ 「学科全体の枠の埋まり方が見えます」        → ★教務の関心事です
```

### 7-2｜★確かめてほしいこと（坂本さんへ）

```
□ 門下のレッスン日程調整に、★教員は何時間くらい関わっていますか
□ それは大学の業務として認識されていますか
□ ★それとも、完全に学生の自主運営ですか
```

**完全に学生の自主運営なら、これは大学に売れる機能ではありません。**
**「あると嬉しいが、金を出す理由がない」機能になります。**

**★訪問のとき、この3つを聞いてください。**
そこで初めて、この機能を作る価値が決まります。
