# La Voce ／ 価格設計 実装仕様

国内・国際の価格ティア、日本向けの割引、Stripe での持ち方をまとめた仕様。
実装は Claude Sonnet 5 を想定。

## 0. 原則（これだけは崩さない）

1. **価格オブジェクトは少なく、割引で調整する。**
   通貨 × ティア × プラン × 期間の組み合わせは、放っておくと爆発します
2. **契約時の価格を固定する（グランドファザリング）。**
   価格改定は新規契約者にのみ適用し、既存契約者は永久に契約時価格
3. **既存契約者を値上げしない。** 制度上ほぼ不可能で、信頼も失います（§7）
4. **為替に自動連動させない。** 価格は購買力（遅い変数）に合わせ、年1回だけ見直す
5. **ティアの段差は浅く。** La Voce はプロ向けの道具で、対象は「声で稼いでいる人」です。
   その国の平均所得より上の層なので、消費者向けアプリほど深く割り引く必要はありません

## 1. 為替について（実装者への注意）

本書の円換算は **2026年8月時点、1 USD ≒ 159 JPY** のスナップショットです。

**この数字をコードに書かないでください。** 価格は各通貨で固定の数値として持ち、
為替から計算しません。レートが動いても価格は動きません。

## 2. 価格表

### 2.1 個人プラン

| 区分 | 月額 | 年額 | 備考 |
|---|---|---|---|
| **日本** | **¥580** | **¥5,800** | 国際 Tier 1（$4.99 ≒ ¥794）より約27%安い。ホーム市場としての意図的な設定 |
| **Tier 1** | $4.99 / €4.99 / £3.99 | $49.99 / €49.99 / £39.99 | 北米・西欧・英国・豪州・NZ・韓国・台湾・シンガポール・香港・湾岸 |
| **Tier 2** | $2.99 | $29.99 | 中東欧・南欧の一部・中南米・東南アジア・トルコ・南アフリカ |
| **Tier 3** | $1.99 | $19.99 | 南アジア・アフリカの多く |

年額はいずれも**月額10ヶ月分**（2ヶ月分無料）。

### 2.2 指導者プラン

**ティア分けしません。** 法人・教育機関の予算は個人の可処分所得ほど国差がなく、
請求書払いや個別交渉も入るためです。

| プラン | 日本 | 国際 |
|---|---|---|
| 〜15人 | ¥3,980/月 | $29/月 |
| 〜50人 | ¥9,800/月 | $69/月 |
| 50人超 | 個別見積もり | 個別見積もり |

**販売はウェブのみ。** アプリ内課金では販売しません（アプリ配布と課金仕様 §1.1）。

## 3. ティアの決め方

### 3.1 基準

**世界銀行の所得分類**を基準にグループ化し、**年1回だけ見直す**。
分類自体が毎年更新されるので、レビューの周期が自然に揃います。

```ts
type PriceTier = 'JP' | 'T1' | 'T2' | 'T3'

interface PricingConfig {
  /** ISO-3166-1 alpha-2 → ティア。未登録の国は 'T1' にフォールバック */
  tierByCountry: Record<string, PriceTier>
  reviewedAt: string          // 最後に見直した日
  nextReviewAt: string        // 次回の見直し予定日
}
```

**未登録の国は Tier 1（最も高い）にフォールバックさせること。**
低いほうに倒すと、未登録国からの契約が意図せず安くなります。

### 3.2 ティアの判定は「支払い手段の発行国」で

**IP アドレスで判定しないでください。** VPN で簡単に回避でき、
出張中の正規ユーザーを誤判定します。

```
判定の優先順位
  1. 支払い手段（カード）の発行国    ← 主。偽装しにくく、税務上の根拠にもなる
  2. 請求先住所の国
  3. どちらも取れない場合 → Tier 1

1 と 2 が食い違う場合は、高いほうのティアを採用する
```

段差が浅ければ、抜けるインセンティブ自体が小さくなります。**過度な対策は不要です。**

## 4. 通貨の扱い（Stripe）

### 4.1 明示的に価格を持つ通貨と、フォールバック

| | 方法 | 対象 |
|---|---|---|
| **明示的に価格を持つ** | Price の `currency_options`（Manual currency prices） | **JPY / USD / EUR / GBP** |
| **フォールバック** | Adaptive Pricing | それ以外の国 |

**この2つは共存します。** `currency_options` を設定した通貨には
Adaptive Pricing が適用されないため、意図した価格が守られます。

### 4.2 Adaptive Pricing についての注意

**Adaptive Pricing は PPP 価格ではありません。単なる為替換算です。**

- 顧客が **2〜4% の換算手数料**を負担します（事業者側の負担は0%）
- **クロスボーダーのサブスクでは、カード・Link・Apple Pay・Google Pay のみ対応**
- 有効化は Dashboard の payment settings から

つまり、ティアで価格を決めた通貨は必ず `currency_options` を持たせてください。
Adaptive に任せると、**現地通貨での価格が意図より割高になります。**

### 4.3 最初は3通貨で始める

通貨を増やすと、対応する決済手段・返金・会計・税務がすべて増えます。
**JPY / USD / EUR の3つで始め、実際に契約が来た国を見てから追加**してください。

## 5. 割引

**価格を分けるのではなく、Coupon で調整します。**

| 割引 | 内容 | Stripe での持ち方 | 対象 |
|---|---|---|---|
| **早期割引** | **35% OFF・永久** | `percent_off: 35, duration: 'forever'` | 開発期間中に契約した方。個人プランのみ |
| **学生割引** | **50% OFF・永久** | `percent_off: 50, duration: 'forever'` | 音大・専門学校・養成所の在籍者 |
| **指導者経由の生徒** | **無料** | **Stripe を使わない**（§5.3） | 指導者プランに紐づく生徒 |

`percent_off` を使う理由：**1つの Coupon が全通貨・全期間で機能する**ためです。
`amount_off` だと通貨ごと・月額/年額ごとに Coupon を作ることになります。

### 5.1 早期割引

定価は ¥580 のまま、開発期間中の契約者に 35% OFF を永久適用します。

```
日本    ¥580 → ¥377/月     ¥5,800 → ¥3,770/年
Tier 1  $4.99 → $3.24/月
```

**定価を下げないこと。** 定価は錨で、一度下げると上げられません。
割引なら、いま Instagram で告知している「**いま、育てています**」という文脈と
そのまま噛み合います。**開発中であることが、割引の理由になります。**

終了条件を最初に決めて明示してください（例：先着300名、または正式版リリースまで）。

### 5.2 学生割引

在籍確認は手動でかまいません（学生証の画像を受け取る等）。

**`duration: 'forever'` にして、毎年の再確認はしない。**
卒業後もプロとして使い続ける人は長期顧客なので、
再確認の運用コストに見合いません。**漏れは許容してください。**

日本市場ではこの割引が特に効きます。いま無料に近い価格で使う音大生が、
数年後に指導者プランを契約する側になる——という流れが作れます。

### 5.3 指導者経由の生徒は Stripe を通さない

**これは割引ではなく、権利の付与です。** Stripe のオブジェクトを作らないでください。

```ts
// Entitlement（アプリ配布と課金仕様 §2）で表現する
{
  plan: 'personal',
  status: 'active',
  source: 'teacher',        // ← Stripe / Apple / Google ではない
  teacherId: '...',
  currentPeriodEnd: '...'   // 指導者プランの有効期間に追随する
}
```

指導者プランが解約されたら、紐づく生徒の権利も期間末で終了します。
**そのとき生徒に「個人プランに移行しますか」と案内する導線**を用意してください。
ここは自然な有料転換ポイントになります。

## 6. グランドファザリング（契約時価格の固定）

**Stripe の仕様上、これは自動的に成立します。**
Price オブジェクトは不変で、Subscription は作成時の Price と Discount を保持し続けるためです。

実装側でやることは1つだけ。

```ts
interface Entitlement {
  // ...
  priceTier: PriceTier
  billingCountry: string     // ISO alpha-2
  stripePriceId?: string     // 契約時の Price ID を記録
  discountCode?: string      // 適用した Coupon
}
```

**契約時の `priceTier` と `stripePriceId` を保存してください。**
あとから「この人はどのティアで契約したか」を追えるようにするためです。

## 7. 価格改定の手順

### 7.1 新規契約者向けの改定（通常の運用）

```
1. 新しい Price オブジェクトを作成する（既存の Price は編集しない。Stripe では不変）
2. チェックアウトの参照先を新しい Price に切り替える
3. 既存の Subscription は自動的に旧価格のまま
4. 告知は不要（誰の価格も変わっていないため）
```

**年1回、世界銀行の所得分類の更新に合わせて見直す。** それ以上の頻度でやらない。

### 7.2 既存契約者を値上げする場合（原則やらない）

制度上の制約が重く、実質的に困難です。**グランドファザリングで回避してください。**

**Apple（IAP）の場合**、更新時の値上げ幅が次を超えると
**利用者の明示的な同意が必要**になり、同意がなければ更新されません。

| 地域 | 月額など | 年額 |
|---|---|---|
| 米国 | $5 | $50 |
| 日本 | ¥800 | ¥8,000 |
| 英国 | £5 | £50 |
| **ドイツ・オーストリア** | **どんな値上げでも同意必須** | 同上 |

判定は**更新時点**で行われます。

**ウェブ（Stripe）の場合**も、日本の特定商取引法や EU の消費者法により、
事前通知と解約機会の提供が必要です。加えて、EU では価格変更が
SCA の再認証を誘発する場合があります。

## 8. データモデルまとめ

```ts
type PriceTier = 'JP' | 'T1' | 'T2' | 'T3'
type PlanKey   = 'free' | 'personal' | 'teacher'

interface PricingConfig {
  tierByCountry: Record<string, PriceTier>
  reviewedAt: string
  nextReviewAt: string
}

interface Entitlement {
  userId: string
  plan: PlanKey
  status: 'active' | 'grace' | 'canceled' | 'expired'
  source: 'stripe' | 'apple' | 'google' | 'teacher' | 'manual'
  currentPeriodEnd: string
  cancelAtPeriodEnd: boolean

  // 価格まわり
  priceTier: PriceTier
  billingCountry: string
  stripePriceId?: string
  discountCode?: string

  // 指導者経由のとき
  teacherId?: string

  updatedAt: string
}
```

**価格・プランの定義はサーバから配信する。** クライアント（ウェブ／アプリ）に埋め込まない
（アプリ配布と課金仕様 §2.2）。

## 9. 実装の順番

| 順 | 内容 | 規模 |
|---|---|---|
| 1 | `PricingConfig` と `tierByCountry` の定義（まず JP / T1 のみ） | 半日 |
| 2 | Price を JPY / USD / EUR で作成（`currency_options`） | 半日 |
| 3 | ティア判定（支払い手段の発行国 → 請求先 → T1） | 1日 |
| 4 | Checkout でティアに応じた Price を選択 | 1日 |
| 5 | 早期割引 Coupon（35% forever）＋ Promotion Code | 半日 |
| 6 | `Entitlement` に価格情報を記録（グランドファザリング） | 半日 |
| 7 | 指導者経由の生徒への権利付与（`source: 'teacher'`） | 1〜2日 |
| 8 | 学生割引（手動確認 ＋ Coupon 付与の管理画面） | 1日 |
| 9 | Adaptive Pricing を有効化（フォールバック） | 半日 |
| 10 | Tier 2 / Tier 3 の追加（実際に契約が来てから） | 半日 |

**1〜6 で日本向けの課金が完結します。** 7以降は必要になってからで構いません。

## 10. Sonnet 5 への依頼のコツ

- **価格オブジェクトを増やさせない。** 「割引は Coupon で表現する」を明示的な要件に
- **Price を編集させない。** 改定は必ず新規作成（Stripe では Price は不変です）
- **ティア判定に IP を使わせない。** 支払い手段の発行国を主にする、と明記する
- **為替レートをコードに書かせない。** 価格は各通貨で固定の数値
- 未登録の国のフォールバックは **Tier 1（高いほう）**。低いほうに倒させない
- `percent_off` を使う理由（全通貨・全期間で1つの Coupon が効く）を伝えると、
  `amount_off` で作り始めるのを防げます
