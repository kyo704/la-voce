# La Voce ／ カレンダー連携パッチ

**教室プラン仕様-複数教師と複数生徒.md の §5 に「§5.5 カレンダー連携」を追加します。**
あわせて §12（スコープ外）と、指導者プラン実装仕様 §7 の iCal の記述を差し替えます。

---

## 0. 結論

| 方向 | 判断 |
|---|---|
| **外部カレンダーから読む** | **作る。ただし「空いているかどうか」だけ。予定の中身は取得しない** ★ |
| **外部カレンダーへ書く** | **作らない。** 購読フィードと「カレンダーに追加」ボタンで足ります |
| 双方向同期 | **作らない**（§9） |

### なぜこの設計なのか

**「レッスンだけが入っているカレンダー」は、普通のカレンダーに勝てません。**
カレンダーの価値は全部が入っていることで、一部しか入っていない箱は、
見に行く場所が増えるだけです。しかも他の用事とのブッキングを防げません。

**La Voce はカレンダーになろうとしません。**
**カレンダーに「空いていますか」と聞き、レッスンを「渡す」だけです。**

---

## 1. ★ 読むのは freeBusy だけ

### 1.1 取得するもの・しないもの

Google Calendar API には **`https://www.googleapis.com/auth/calendar.freebusy`** という
専用のスコープがあります（「予定が入っている時間帯を見る」）。

```
取得できるもの   →  「2026-09-03 15:00-16:00 は埋まっている」
取得できないもの →  予定の名前 ／ 場所 ／ 参加者 ／ 説明 ／ 添付
```

**必ずこのスコープだけを要求してください。**
`calendar` や `calendar.readonly` を要求しないこと。**予定の中身が取れてしまいます。**

### 1.2 これが「見せない設計」の本体です

要望は「オーナーや他の先生に、先生個人の予定が見えない構造」でした。

**権限で隠すのではありません。La Voce のデータベースに、その情報が最初から存在しません。**

```
❌ 中身を保存して、見せない設定で守る    → 設定の間違い・バグ・照会で漏れます
✅ 中身をそもそも受け取らない            → 漏らしようがありません
```

**この差は決定的です。実装の都合で 1.1 のスコープを広げないでください。**

### 1.3 保存しない

**取得した busy の時間帯を、データベースに保存しないでください。**

```
必要になったときに問い合わせる
サーバーのメモリ（またはRedis）に 15分だけ置く
15分で捨てる。永続化しない
```

**保存しなければ、書き出し要求も、漏えいも、削除依頼も発生しません。**

## 2. 先生の設定（3段階）

```
┌───────────────────────────────────────┐
│ カレンダー連携                          │
│                                       │
│ ○ 連携しない                           │
│ ● 自分だけ                    （既定）  │
│     重なりの警告に使います。            │
│     教室の誰にも表示されません。         │
│ ○ 教室にも「予定あり」を伝える           │
│     管理者の週表示に、名前のない          │
│     灰色の枠が出ます。                   │
│     何の予定かは伝わりません。           │
│                                       │
│ 見るカレンダー                          │
│ ☑ 仕事      ☐ 家族      ☐ 誕生日       │
│                                       │
│           連携を解除する               │
└───────────────────────────────────────┘
```

**必須の条件**

- **既定は「自分だけ」。** 教室に伝えるかどうかは先生が選ぶ
- **見るカレンダーを先生が選べる**（仕事用だけを対象にしたい人がいます）
- **「連携を解除する」を、探さないと見つからない場所に置かない**
- 解除したら**トークンを即座に失効させ、キャッシュを捨てる**

## 3. 読む方向の実装

### 3.1 対応するサービス

| | 空き時間の取得 | 優先度 |
|---|---|---|
| **Google** | `freebusy.query`（専用スコープあり） | **★ まずこれだけ作る** |
| Microsoft / Outlook | `getSchedule`（空き時間API） | 次点 |
| Apple / iCloud | 公開APIが無い。購読URLを貼ってもらう | **後回し**（§3.4） |

**最初のリリースは Google だけにしてください。**

### 3.2 問い合わせの仕方

```
対象期間 : 今日から 8週間
まとめて : 複数の先生ぶんを1回のリクエストで（freebusy.query は複数カレンダーを取れます）
頻度     : 画面を開いたとき。ただし15分キャッシュ
上限     : 1人あたり 1分に1回まで
```

**レッスンを1件表示するたびに問い合わせないこと。** 週表示なら1回で足ります。

### 3.3 トークンの扱い

- **暗号化して保存。** 平文で置かない
- リフレッシュに失敗したら、**黙って諦めて「連携が切れています」と1行出す**
- **失敗しても、レッスンの表示は止めないこと。** 空き時間は補助情報です

### 3.4 Apple / 購読URL方式の注意

Apple には空き時間だけのAPIがありません。購読URL（.ics）を貼ってもらう形になりますが、
**この方式では予定の中身も届いてしまいます。**

```
サーバーで時間帯（DTSTART / DTEND）だけを抜き出す
SUMMARY・DESCRIPTION・LOCATION・ATTENDEE は読み込んだ時点で捨てる
本文をログにもデータベースにも書かない
```

**Google のような構造的な保証にはなりません。**
**だから後回しにしてください。** Google だけで十分に価値が出ます。

## 4. 書く方向

### 4.1 ★ iCal 購読は「遅い」ことを前提にする

**Google カレンダーの外部購読の更新は 8〜24時間に1回で、ユーザーが早められません。**

**今日レッスンを動かしても、先生のカレンダーに反映されるのは翌日です。**

指導者プラン実装仕様 §7 の「iCal フィードを配信すれば導線になる」という記述は、
**この点で楽観的でした。訂正します。**

購読フィードは残しますが、画面に必ずこう書いてください。

```
このURLを購読すると、レッスンが普段のカレンダーに表示されます。
反映まで半日〜1日ほどかかります。
すぐに入れたいときは、各レッスンの「カレンダーに追加」を使ってください。
```

### 4.2 1件ずつ「カレンダーに追加」（即時）

**レッスンの詳細画面に置いてください。これが即時性の担保です。**

```
[ カレンダーに追加 ]
   → Google カレンダーの新規予定画面を開く（テンプレートURL）
   → または .ics を1件ダウンロード（Apple / Outlook 用）
```

**日時は UTC ＋ tz から、その先生の表示タイムゾーンで生成すること**（国際展開仕様 §2.3）。

### 4.3 リマインド

**前日のリマインドは LINE で送ります**（既存の設計のまま）。
**カレンダーの通知に頼らないこと。** 購読が遅れていると届きません。

## 5. 重なりの警告

教室プラン仕様 §5.3 に、**外部カレンダー由来の重なり**を足します。

| 検出するもの | 誰に出すか | 表示 |
|---|---|---|
| 同じ生徒のレッスンが重なった | 生徒と両方の先生 | 相手の教室名と先生名を出す |
| 同じ先生のレッスンが重なった | その先生と管理者 | 同上 |
| **先生の外部カレンダーと重なった** | **その先生だけ**（既定） | **「この時間は予定が入っています」** |
| 生徒の外部カレンダーと重なった | その生徒だけ | 同上 |

**外部カレンダー由来の警告に、予定の名前を出さないこと。** そもそも持っていません。

```
⚠ この時間は予定が入っています
    9/3（火）15:00-16:00
```

**警告を出すだけです。登録を拒否しないこと。** 本当に重なることがあります。

## 6. 管理者の週表示での見え方

**先生が「教室にも伝える」を選んだときだけ**、灰色の枠が出ます。

```
┌──────────────────────────────────────────────┐
│ ◯◯音楽教室 ・ 9月3日(火)                      │
│                                              │
│      山田先生        佐藤先生      鈴木先生   │
│ 14:00 田中○○        ▨▨▨▨▨▨    高橋○○     │
│ 15:00 田中○○        ▨▨▨▨▨▨    ―           │
│ 16:00 ―             渡辺○○      伊藤○○     │
│                                              │
│ ▨ 予定あり（内容は共有されていません）         │
└──────────────────────────────────────────────┘
```

**必須の条件**

- **枠にラベルを付けない。** ツールチップも出さない
- 凡例に **「内容は共有されていません」** と明記する
- **クリックしても何も開かない**
- 「自分だけ」を選んでいる先生の列には、**枠そのものを出さない**

## 7. 生徒側

**同じ仕組みを生徒にも用意してください。** 生徒も学校や仕事で埋まっています。

**ただし条件があります。**

| | |
|---|---|
| 既定 | **オフ**。こちらから促さない |
| **未成年** | **カレンダー連携の項目そのものを表示しない** ★ |
| 教室への共有 | **選択肢を出さない。** 生徒の空き時間は先生に見せない |

> **未成年に出さない理由**：保護者の同意の範囲が一気に広がります。
> 学校の予定・通院・家族の予定が絡む領域で、
> 「時間帯だけ」であっても、未成年から取得する設計にしないでください。

## 8. データモデル

```ts
interface CalendarConnection {
  id: string
  userId: string
  provider: 'google' | 'microsoft' | 'ics'
  scopeLevel: 'freebusy'          // ★これ以外を作らない
  accessTokenEnc: string          // 暗号化して保存
  refreshTokenEnc: string
  calendarIds: string[]           // 先生が選んだカレンダー
  visibility: 'none' | 'self' | 'org'   // 既定 'self'
  lastSyncedAt?: string
  lastError?: string
  connectedAt: string
  revokedAt?: string
}
```

**busy の時間帯を保存するテーブルを作らないでください。**
必要なときに問い合わせ、15分だけメモリに置き、捨てます（§1.3）。

---

## 9. スコープ外

| やらないこと | 理由 |
|---|---|
| **外部カレンダーへの自動書き込み** | 広い権限が必要になり、削除・変更の同期が腐ります |
| **双方向同期** | 競合の解決を作ることになり、規模が跳ね上がります |
| 予定の中身の取得・表示・保存 | §1.2 |
| 空き枠の公開・生徒からの予約申し込み | 教室プラン仕様 §12 のまま |
| 会議室・設備の予約 | 同上 |
| 外部カレンダーの予定を La Voce 内で編集 | カレンダーアプリになろうとしないこと |

## 10. 実装の順番

**教室プラン仕様 §13 の 6（レッスン日程）が終わってから着手してください。**

| 順 | 内容 | 規模 |
|---|---|---|
| 0 | **Google OAuth の審査申請**（坂本さん） | 申請から承認まで日数がかかります。**先に出す** |
| 1 | §4.2 「カレンダーに追加」ボタン | **半日。連携なしで今すぐ作れます** |
| 2 | §4.1 購読フィードの文言を直す | 半日 |
| 3 | §2 設定画面（連携なしでも作れる） | 1日 |
| 4 | §3 Google の freeBusy 取得とキャッシュ | 3日 |
| 5 | §5 重なりの警告に反映 | 2日 |

**1 を先にやってください。** 半日で、外部連携なしに、いちばん困っている点が解消します。

> **0 は坂本さんの作業です。** Google の OAuth は、公開アプリで審査が必要です。
> **実装を待たずに申請してください。** 承認までの時間が全体の律速になります。

## 11. 禁止事項

- ❌ **`calendar.freebusy` 以外のスコープを要求しない**（§1.1）
- ❌ **予定の名前・場所・参加者・説明を、取得も保存も表示もしない**
- ❌ **busy の時間帯を永続化しない**（§1.3）
- ❌ 「自分だけ」を選んでいる先生の予定を、管理者に見せない
- ❌ 灰色の枠にラベル・ツールチップを付けない（§6）
- ❌ **外部カレンダーへ自動で書き込まない**（§9）
- ❌ 双方向同期を作らない
- ❌ 重なりを検出したときに、**登録を拒否しない・自動で動かさない**
- ❌ **未成年にカレンダー連携を表示しない**（§7）
- ❌ 生徒の空き時間を先生に見せない
- ❌ 購読フィードが「すぐ反映される」と書かない（§4.1）
- ❌ 連携が切れたときに、レッスンの表示まで止めない

## 12. Claude Sonnet 5 への依頼のコツ

- **§10 の 1 を単独で出させる。** 半日で効果が出ます
- **スコープの実装を必ず目視で確認してください。**
  「実装が楽なので `calendar.readonly` にしました」が起きやすい場所です。
  そうなった瞬間に、この設計の意味が全部消えます
- busy を保存するテーブルの提案が来たら、**§1.3 を根拠に断ること**
- 日時は **UTC ＋ tz**（国際展開仕様 §2.3）。**レッスンは時刻が本質です**
- 外部APIの失敗を、**レッスン表示の失敗に伝播させない**
- **§9 のスコープ外を実装前に読ませる。** 双方向同期の提案が来たら断ること
